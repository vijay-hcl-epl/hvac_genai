# Software Low-Level Design (SWE.3): HVAC Flap Actuator

## Overview
This SWE.3 document details the full low-level design (LLD) for the HVAC Flap Actuator system, derived from software requirements (SWE.1) and the modular logical architecture. No new units, code, or execution/scheduling decisions are introduced. No hardware or register details are included. All elements map to SWE.1 requirements.

---

## Software Unit: UART Command Handler

### 1. Responsibilities
- Receive user commands via UART.
- Validate, filter, and flag acceptance of commands (0-5) per SWE-REQ-001, 002.
- Provide 'new valid command' notification to state/config unit.
- Ignore duplicate commands or those matching the last position (SWE-REQ-006).
- Do NOT process invalid commands, non-numerics, or manage hardware explicitly.

### 2. Internal Data Design
- Buffer for received ASCII characters (fixed-length, static)
- Last valid command (uint8_t)
- Received command flag (bool)
- UART receive state (enum: IDLE, RECEIVING, COMPLETE)

### 3. State Machine
No explicit multi-state machine; logic: IDLE –> RECEIVING –> COMPLETE/FILTER as receiving characters; resets each command.

### 4. Algorithms and Control Flow
- On RX interrupt/event
  - Store char in receive buffer (if within length)
  - On EOL/termination, validate buffer as single ASCII digit (0–5)
  - If valid and not same as last command, set received flag, update as new command
  - Else, ignore/reset buffer

### 5. Interfaces (APIs)
- void UARTCommandHandler_Init(void)
- void UARTCommandHandler_RxISR(uint8_t rxChar)
- bool UARTCommandHandler_HasNewCmd(void)
- uint8_t UARTCommandHandler_GetCmd(void)
- void UARTCommandHandler_ClearFlag(void)
(Uses: UART hardware RX, Configuration & State manager for current position/last command)

### 6. Error Handling
- Non-numeric, out-of-range, or duplicate commands are ignored per SWE-REQ-003/005/006; no error signaling

### 7. Resource and Timing Considerations
- Invoked on UART RX
- Static buffer only
- Not re-entrant (ISR+main access must use volatile/atomic)
- Deterministic: Single command at a time

### 8. Traceability to SWE Requirements
- SWE-REQ-001, 002, 003, 004, 005, 006, 025, 043, 055, 059

## Software Unit: Position Feedback Processor

### 1. Responsibilities
- Sample potentiometer via ADC
- Map ADC value to logical position (0–5)
- Flag out-of-range/invalid readings
- Supply current position data to state/config unit
- Do NOT perform actuation or command handling

### 2. Internal Data Design
- Last ADC value (uint16_t)
- Logical position (int8_t; -1 if invalid)
- ADC threshold table (const uint16_t[6])
- Out-of-range flag (bool)

### 3. State Machine
No classical state machine; sequence:
- ADC sample –> threshold compare –> range result

### 4. Algorithms and Control Flow
- On sample trigger:
  - Read ADC (blocking or callback)
  - Compare to thresholds:
    - If within threshold[i], assign position = i
    - Else, set out-of-range flag, logical position = -1
- Provide position on request

### 5. Interfaces (APIs)
- void PosFb_Processor_Init(void)
- void PosFb_Processor_TriggerSample(void)
- int8_t PosFb_Processor_GetPosition(void)
- bool PosFb_Processor_IsOutOfRange(void)
(Uses: ADC hardware, static config)

### 6. Error Handling
- Out-of-range sets flag and invalid position
- No recovery/alert; handled by upper layers

### 7. Resource and Timing Considerations
- Sampled on demand (per control cycle)
- All statically allocated
- Deterministic, not re-entrant

### 8. Traceability
- SWE-REQ-007, 016, 017, 018, 019, 026, 041, 044, 051, 055

## Software Unit: Flap Control Logic

### 1. Responsibilities
- Compare current and target positions
- Determine direction and sequence move requests
- Manage move-in-progress logic
- Signal completion/abort
- Do NOT manage hardware directly or update LEDs

### 2. Internal Data Design
- Target position (uint8_t; from command handler)
- Last position (uint8_t)
- Move active flag (bool)
- Direction (enum: CLOCKWISE, COUNTER)
- Abort/complete flag

### 3. State Machine
Not explicit; event-driven logic:
- WAIT_CMD -> MOVE_REQUEST -> WAIT_FB -> COMPLETE/ABORT

### 4. Algorithms and Control Flow
- On new command:
  - If position != target, set direction; assert move active
  - While move active:
    - Trigger sample, check feedback
    - If at target (within threshold): clear move, complete
    - If out-of-range: abort
- Await next command

### 5. Interfaces (APIs)
- void FlapCtrlLogic_Init(void)
- void FlapCtrlLogic_NewCmd(uint8_t pos)
- void FlapCtrlLogic_RunCycle(void)
- bool FlapCtrlLogic_MoveActive(void)
(Uses: PosFb Processor, Actuator Driver, State Manager)

### 6. Error Handling
- On abort, sends stop to actuator, clears active
- No recovery; waits for next valid command

### 7. Resource and Timing
- Drives control loop, called periodically/event
- Not re-entrant

### 8. Traceability
- SWE-REQ-007, 008, 009, 010, 013, 014, 030, 034, 037, 038, 041, 055

## Software Unit: Actuator Driver

### 1. Responsibilities
- Drive motor enable/disable
- Set motor direction (CW/CCW)
- Immediate stop on request
- Do NOT decide when/why to move; executes request only

### 2. Internal Data Design
- Last command (struct: enable, direction)

### 3. State Machine
No state machine: Set/reset direction/enable based on caller parameters

### 4. Algorithms and Control Flow
- On Move(cmd):
  - If enable, set GPIOs as per direction param
  - If disable, clear enable GPIO
- On Stop():
  - Clear enables

### 5. Interfaces (APIs)
- void ActuatorDrv_Init(void)
- void ActuatorDrv_Move(bool enable, uint8_t direction)
- void ActuatorDrv_Stop(void)
(Uses: GPIO/PWM)

### 6. Error Handling
- Hardware errors not handled; assumes hardware is functional

### 7. Resource/Timing
- Called only from control logic each event
- Static only, not re-entrant

### 8. Traceability
- SWE-REQ-011, 012, 013, 014, 015, 027, 041, 055

## Software Unit: LED Indicator Controller

### 1. Responsibilities
- Illuminate status LED on power
- Illuminate position LED matching logical position
- Update LEDs on position change
- Do NOT interpret hardware faults or modify control flow

### 2. Internal Data Design
- Last indicated position (uint8_t)
- Status LED GPIO, Position LED array (const mapping)

### 3. State Machine
None; direct: On status change, update corresponding LED, clear previous

### 4. Algorithms/Flow
- On init, set status LED ON
- On position update:
  - Set corresponding LED ON, others OFF
- On out-of-range, all position LEDs OFF

### 5. Interfaces (APIs)
- void LEDCtrl_Init(void)
- void LEDCtrl_IndicatePosition(uint8_t pos)
- void LEDCtrl_StatusLED_Set(bool on)
(Uses: GPIOs)

### 6. Error Handling
- Out-of-range: all position LEDs off
- Hardware faults not detected

### 7. Resource/Timing
- Invoked on status/pos change
- Not re-entrant

### 8. Traceability
- SWE-REQ-020, 021, 022, 023, 024, 028, 035, 051, 054, 055

## Software Unit: Configuration & State Manager

### 1. Responsibilities
- Store config/calibration data (thresholds, positions)
- Maintain system state: last/target position, flags
- Provide read APIs to other units
- Update state based on triggers/events (never from user)
- Do NOT contain any control or scheduling logic

### 2. Internal Data Design
- Calibration/threshold tables (const)
- State struct: current position, target pos, flags

### 3. State Machine
None – pure data repository, with update/set/get routines

### 4. Algorithms/Flow
- On init, load static config
- APIs to get/set state/flags

### 5. Interfaces (APIs)
- void ConfigState_Init(void)
- int8_t ConfigState_GetCurrentPos(void)
- void ConfigState_SetCurrentPos(int8_t p)
- uint8_t ConfigState_GetTargetPos(void)
- void ConfigState_SetTargetPos(uint8_t p)
- [Other get/set for flags as needed]

### 6. Error Handling
- No direct error detection; out-of-range handled per data

### 7. Resource/Timing
- Used only via API; static only
- Not re-entrant

### 8. Traceability
- SWE-REQ-039, 040, 041, 042, 051, 057, 058
