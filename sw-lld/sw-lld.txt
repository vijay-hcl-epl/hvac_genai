SOFTWARE UNITS - LOW LEVEL DESIGN
==============================

-------------------------------------
Software Unit: Command Handler Unit
-------------------------------------
1. Responsibilities
   - Handles: Receiving, validating, and dispatching user commands from UART
   - Does not handle: Direct actuation, error handling beyond command validation

2. Internal Data Design
   - UART_rx_buffer: Fixed-size char array for received UART data
   - valid_command_flag: Indicates if latest command is valid
   - command_position_idx: Integer, holds decoded and validated position (0-5) or INVALID
   - Uses static position map from Static Configuration Unit

3. State Machine
   - State: None (event-driven, simple flow)
   - Flow: On UART receive event, parse character, check range, set flag and output to Flap Control Unit

4. Algorithms & Control Flow
   - On UART receive interrupt or polling:
     If received character in ['0'-'5']:
       - Convert to integer, set valid_command_flag, store position_idx
     Else:
       - Set flag invalid, take no action
     - Output valid commands to Flap Control via API

5. Interfaces (APIs)
   - Provided: GetValidCommand(void) -> int (returns validated position idx or INVALID)
   - Required: UART_receive(), access to position mapping table
   - Error reporting: Outputs only valid commands, others ignored

6. Error Handling
   - Ignores invalid commands (does not dispatch)

7. Resource & Timing Considerations
   - Invoked: On UART receive event/poll
   - WCET: Negligible (buffer parse and integer check)
   - Re-entrancy: Not re-entrant (single command processed at a time)

8. Traceability
   - SWE-REQ-001, SWE-REQ-002, SWE-REQ-015, SWE-REQ-027, SWE-REQ-030

-------------------------------------
Software Unit: Flap Control Unit
-------------------------------------
1. Responsibilities
   - Handles: Flap position state transitions, targets, motion sequencing, control requests
   - Does not handle: Direct motor drive or feedback acquisition

2. Internal Data Design
   - target_position: Integer 0-5 (requested)
   - current_position: Integer 0-5 (from Feedback Unit)
   - movement_in_progress: Boolean
   - state enum: {IDLE, MOVING, ERROR}

3. State Machine
   - States: IDLE (waiting), MOVING (in transit), ERROR (invalid feedback)
   - Events: Valid Command, Position Reached, ADC Error
   - Transitions: On valid command, moves to MOVING; on position reached, returns to IDLE; on error, enters ERROR
   - Actions: Issues motor start/stop to Motor Control, updates LED status

4. Algorithms & Control Flow
   - On valid command:
      If not moving and not error:
         - Set target, set movement_in_progress
         - Issue command to Motor Control (dir/enable)
   - While moving:
         - Poll Feedback Unit, compare to target
         - On match, stop motor, clear flag, update LED state
   - On ADC error: Stop motor, enter ERROR state

5. Interfaces (APIs)
   - Provided: StartMovement(int target), StopMovement(), GetState()
   - Required: MotorControl.Start/Stop, Feedback.GetPosition, Indication.Update
   - Error reporting: Error status exported

6. Error Handling
   - If ADC out of range or feedback error: Stop motor, enter ERROR
   - Ignores further commands while in ERROR

7. Resource & Timing Considerations
   - Invoked only on valid commands, periodic polling for position
   - WCET: Low (decision logic and state compare)
   - Re-entrancy: Not re-entrant

8. Traceability
   - SWE-REQ-003, SWE-REQ-004, SWE-REQ-020, SWE-REQ-021, SWE-REQ-022, SWE-REQ-023, SWE-REQ-024, SWE-REQ-029, SWE-REQ-031

-------------------------------------
Software Unit: Motor Control Unit
-------------------------------------
1. Responsibilities
   - Handles: GPIO/PWM for motor direction/enable, ensures motor OFF/startup/emergency
   - Does not handle: High-level movement or command decisions

2. Internal Data Design
   - motor_enabled: Boolean
   - direction: Enum (CW, CCW, OFF)
   - error_flag: Boolean

3. State Machine
   - State: None (actions on request)
   - Flow: On request from Flap Control, sets direction/enable via GPIO/PWM

4. Algorithms & Control Flow
   - Start(direction): Set GPIO/PWM to target direction, enable
   - Stop(): Disable motor enable pin
   - On init or error: Motor always OFF

5. Interfaces (APIs)
   - Provided: Start(direction), Stop(), IsActive()
   - Required: GPIO_set, PWM_set
   - Error reporting: Error flag set/cleared as needed

6. Error Handling
   - On any error or init, ensures motor is disabled

7. Resource & Timing Considerations
   - Invoked on command from Flap Control
   - WCET: Negligible (GPIO/PWM)
   - Re-entrancy: Not re-entrant

8. Traceability
   - SWE-REQ-005, SWE-REQ-006, SWE-REQ-007, SWE-REQ-017, SWE-REQ-025, SWE-REQ-029, SWE-REQ-031

-------------------------------------
Software Unit: Feedback (ADC Acquisition & Mapping) Unit
-------------------------------------
1. Responsibilities
   - Handles: ADC reading, mapping to logical position (0-5), error if out-of-range
   - Does not handle: Motor or LED control, command validation

2. Internal Data Design
   - adc_raw: uint16
   - position: Integer 0-5
   - out_of_range_flag: Boolean
   - thresholds[]: Array of min/max ADC values for each pos (from Static Config)

3. State Machine
   - State: None (periodic data acquisition)
   - Flow: Reads ADC, checks thresholds, maps to position (0-5 or invalid)

4. Algorithms & Control Flow
   - On periodic read:
       adc_raw = ADC_read();
       for each threshold:
           if (adc_raw in range):
               set position, clear error;
               break;
           else: set out_of_range_flag=true;
   - Position exported to Flap Control

5. Interfaces (APIs)
   - Provided: GetPosition(), IsValid()
   - Required: ADC_read(), access to thresholds config
   - Error reporting: out_of_range_flag

6. Error Handling
   - If adc_raw out of all valid ranges, set error, inform Flap Control

7. Resource & Timing Considerations
   - Invoked periodically
   - WCET: Low (table lookup)
   - Re-entrancy: Not re-entrant

8. Traceability
   - SWE-REQ-008, SWE-REQ-009, SWE-REQ-010, SWE-REQ-016, SWE-REQ-026, SWE-REQ-031

-------------------------------------
Software Unit: Indication (LED Management) Unit
-------------------------------------
1. Responsibilities
   - Handles: Power/status/position LED indication changes
   - Does not handle: Movement, command validation

2. Internal Data Design
   - power_led_on: Boolean
   - position_leds[6]: Boolean array

3. State Machine
   - State: None (stateless, only reflects inputs)
   - Flow: Called to update after startup or control event

4. Algorithms & Control Flow
   - Update(power, position):
       Set/clear power LED
       Set only one position_leds[x]=ON (others OFF)
   - Ensures only one position indicator at a time

5. Interfaces (APIs)
   - Provided: Update(power, position)
   - Required: GPIO_set
   - Error reporting: None (reflects only input)

6. Error Handling
   - Always ensures one (or none) position LED ON, others OFF

7. Resource & Timing Considerations
   - Invoked synchronously on events
   - WCET: Negligible
   - Re-entrancy: Not re-entrant

8. Traceability
   - SWE-REQ-011, SWE-REQ-012, SWE-REQ-013, SWE-REQ-018, SWE-REQ-021,
     SWE-REQ-037, SWE-REQ-038

-------------------------------------
Software Unit: Static Configuration Unit
-------------------------------------
1. Responsibilities
   - Handles: Stores ADC thresholds, position map tables for build-time configuration
   - Does not handle: Any runtime processing or data mutation

2. Internal Data Design
   - adc_thresholds[6][2]: Array of min/max for each position
   - position_map[6]: Maps command index to real position, if required
   - All values const/static, set at compile time only

3. State Machine
   - State: None
   - Flow: N/A (provides data only)

4. Algorithms & Control Flow
   - None; no processing aside from static table reads

5. Interfaces (APIs)
   - Provided: GetThresholds(), GetPositionMap()
   - Required: None
   - Error reporting: None

6. Error Handling
   - N/A

7. Resource & Timing Considerations
   - Accessed at init or read from any other unit
   - WCET: Not applicable (read-only)
   - Re-entrancy: N/A

8. Traceability
   - SWE-REQ-026, SWE-REQ-027, SWE-REQ-028
