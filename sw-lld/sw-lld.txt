=============================
SOFTWARE LOW-LEVEL DESIGN (LLD) — HVAC FLAP ACTUATOR (TLE9851QXW)
=============================

NOTE: No units added/removed; architecture unchanged. All design is traceable to SWE.1 and follows the component-based structure defined in architecture. No software scheduling or code is specified.
Target: Embedded C (MISRA), static allocation only.

--------------------------------------------------------------------------------
Software Unit: Command Interface Unit

1. Responsibilities
   - Handles: Receiving, decoding, and range/format validation of user commands via UART.
   - Does not handle: Storage, error logging, actuation logic, or direct hardware/motor access.

2. Internal Data Design
   - Command buffer (volatile)
   - Decoded command struct {target_position, validity_flag, error_code}
   - Config: Acceptable command ranges/limits

3. State Machine
   - States: Idle, Receiving, Decoding, Validating, Error
   - Events: UART receive, decode error, validation pass/fail
   - Actions: Buffer RX, parse, set flags/errors, notify output

4. Algorithms & Control Flow
   - On UART receive: buffer -> decode -> validate format/range
   - If valid: set output, else: set error flag/notify
   - Pseudocode: "if uart_rx_flag then decode(); if decode_ok then validate(); ..."

5. Interfaces (APIs)
   - Provided: get_validated_command() {returns struct, error status}
   - Required: uart_read(), uart_status()
   - Error: Returns status code per failure type

6. Error Handling
   - Invalid command: set error, signal status unit
   - Framing error: discard, status notification

7. Resource & Timing Considerations
   - Invoked per command RX; WCET << 10 ms
   - Reentrant: no global state beyond buffer

8. Traceability
   - SWE-REQ-001, SWE-REQ-002, SWE-REQ-003, SWE-REQ-015, SWE-REQ-020

--------------------------------------------------------------------------------
Software Unit: Flap Position Controller

1. Responsibilities
   - Handles: Position tracking/limit, generating move requests, enforcing calibration
   - Does not handle: Direct motor/ADC access, non-functional logging

2. Internal Data Design
   - Current_position, Target_position, Calibration_limits struct
   - Move_status (enum: idle, in_progress, done, error)

3. State Machine
   - States: Idle, Ready, Moving, LimitError, Done
   - Events: Valid command, feedback update, error/fault
   - Actions: Update targets, check limits/calibration, trigger motor unit, signal done/error

4. Algorithms & Control Flow
   - If command received: Check target in range
   - If valid: Set target, trigger motor
   - If feedback = target: Done, signal stop
   - Handle calibration/limit violations

5. Interfaces (APIs)
   - Provided: process_command(cmd_struct), get_move_status()
   - Required: get_validated_command(), feedback_status(), motor_drive()
   - Error: status enum/code

6. Error Handling
   - On limit/cali error: status update, signal status unit

7. Resource & Timing Considerations
   - Called on command or feedback event, WCET < 20 ms
   - Only one active move; not reentrant

8. Traceability
   - SWE-REQ-004, SWE-REQ-005, SWE-REQ-021, SWE-REQ-022, SWE-REQ-023, SWE-REQ-026

--------------------------------------------------------------------------------
Software Unit: Motor Control Unit

1. Responsibilities
   - Handles: Actuator forward/reverse/stop logic, limit enforcement, fault detection, output drive
   - Does not handle: Command decoding/validation, persistent logging

2. Internal Data Design
   - Motor_control_state (stopped, running_fwd, running_rev, hold)
   - Output_state, Fault_flags, Drive_config_struct

3. State Machine
   - States: Idle, Driving Forward, Driving Reverse, Fault
   - Events: move_request(pos/dir), stop, fault_detected
   - Actions: Set outputs, check faults/limits, trigger stop on match/fault

4. Algorithms & Control Flow
   - Step: On move_request, set direction, enable output
   - If feedback reached or fault: stop, set error
   - Pseudocode: evaluate move; drive; monitor feedback; fault check loop

5. Interfaces (APIs)
   - Provided: motor_drive(cmd), get_fault_flags()
   - Required: GPIO/PWM, config_struct
   - Error: status/error struct

6. Error Handling
   - Stop/disable on detected fault or invalid config

7. Resource & Timing Considerations
   - Invoked on movement; WCET < 30 ms; not reentrant

8. Traceability
   - SWE-REQ-006, SWE-REQ-007, SWE-REQ-008, SWE-REQ-009, SWE-REQ-016, SWE-REQ-035

Software Unit: Feedback Processing Unit

1. Responsibilities
   - Handles: Reading and validating ADC feedback, position plausibility check, error reporting
   - Does not handle: Command rx/interpretation, movement outputs

2. Internal Data Design
   - ADC_value, Valid_flag, Plausibility_state, Sensor_fault_flags

3. State Machine
   - States: Idle, Sampling, Validating, Error
   - Events: ADC sample_ready, validation pass/fail
   - Actions: Store ADC, validate, update status, flag errors

4. Algorithms & Control Flow
   - Step: Read ADC -> check plausible -> set position
   - If invalid: set error flag

5. Interfaces (APIs)
   - Provided: get_position(), get_sensor_status()
   - Required: adc_read(), config_struct
   - Error: error/state tags provided

6. Error Handling
   - Sensor out of range: set error for status unit

7. Resource & Timing Considerations
   - Invoked on ADC event; WCET < 10 ms; not reentrant

8. Traceability
   - SWE-REQ-010, SWE-REQ-011, SWE-REQ-012, SWE-REQ-017, SWE-REQ-033

Software Unit: Status Indication Unit

1. Responsibilities
   - Handles: System/user visible status on UART, LEDs; state/error indication
   - Does not handle: Command/movement logic, persistent config logging

2. Internal Data Design

3. State Machine
   - States: Off, Normal, Error, Test, Startup
   - Events: status_update, error, diag_request, power-up
   - Actions: Update LEDs/UART/status packet

4. Algorithms & Control Flow
   - On each input: Compose new status, update resources

5. Interfaces (APIs)
   - Provided: set_status(), report_error(), signal_startup()
   - Required: all status enums from other units
   - Error: error/status struct

6. Error Handling
   - Propagate all error inputs to user/LED/UART

7. Resource & Timing Considerations
   - WCET < 10 ms; stateless except output buffer

8. Traceability
   - SWE-REQ-013, SWE-REQ-014, SWE-REQ-018, SWE-REQ-030, SWE-REQ-032, SWE-REQ-039

Software Unit: Configuration & Diagnostics Unit

1. Responsibilities
   - Handles: Configuration/calibration persistence, error/event logging, self-diagnostics, test commands
   - Does not handle: Command rx/interpretation, direct actuation/feedback

2. Internal Data Design
   - Config_data, Calibration_data, Diagnostic_log[], Test_mode_flag, Error_counters

3. State Machine
   - States: Init, Ready, Update, Diagnose, Error
   - Events: config_load, update_request, test_command, error_detected
   - Actions: Check config, run self-test/diag, update logs

4. Algorithms & Control Flow
   - On power-up: load config/cal, self-diagnose
   - On error/event: log, update data
   - On test command: trigger diagnostics

5. Interfaces (APIs)
   - Provided: get_config(), log_event(), invoke_diagnostic()
   - Required: NV memory access, triggers from all units
   - Error: error/status code per event

6. Error Handling
   - On NV memory error: enter error, notify status unit

7. Resource & Timing Considerations

   - Non-reentrant; persistent buffers
