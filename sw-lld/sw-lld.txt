HVAC FLAP ACTUATOR SOFTWARE
Branch: mar-13a

Assumptions:
- No software units added or reallocated; strictly follows SWE.2 architecture
- All mapping to SWE.1 IDs complete
- MISRA-style C targeted; all structures static/global; no dynamic allocation

=======
A) Command Interface Unit (UART Handler)
=======
1. Responsibilities
- Handles: Receiving, validating, and decoding single-octet UART flap commands (0-5)
- Does not handle: Scheduling, message acknowledgment, diagnostics

2. Internal Data Design
- Command buffer (1 byte)
- RX validity flag
- UART error indicator (bit, sticky)

3. State Machine
- State: "IDLE" or "RX_PENDING". Transition to RX_PENDING on UART interrupt/flag, return to IDLE after decode.
- No multi-state decoding.

4. Algorithms & Control Flow
- On UART RX: If byte is 0-5, raise valid-command flag, store to buffer. Else, set UART error indicator
- RX_PENDING -> IDLE: After parse, clear flag

5. Interfaces (APIs)
Provided:
- PositionCommandIn(uint8_t position) [0-5]
Required:
- UART HAL RX routine

6. Error Handling
- Set error flag and discard on malformed/unsupported data

7. Resource & Timing Considerations
- Invoked by UART RX or polling
- WCET negligible; single byte
- Not re-entrant

8. Traceability
SWE-REQ-001, SWE-REQ-002, SWE-REQ-017, SWE-REQ-028

=======
B) Flap Control Logic Unit
=======
1. Responsibilities
- Handles: Arbitration/blocking, new position logic, triggers movement
- Does not handle: Motor hardware, polling, periodic execution, diagnostics

2. Internal Data Design
- target_position (uint8_t)
- current_position (uint8_t), shadowed from FeedbackProcessing
- busy_flag

3. State Machine
- States: IDLE (not moving), MOVING (command in progress)
- Events: new valid command, movement complete
- Actions: On IDLE & valid new command, set target, assert busy, request move

4. Algorithms & Control Flow
- If 
  target_position ≠ current_position and not busy:
     assert busy, issue FlapMoveRequest(direction)
- Else ignore

5. Interfaces (APIs)
Provided:
- FlapMoveRequest(direction)
Required:
- PositionCommandIn()
- FeedbackProcessing()

6. Error Handling
- Ignores repeated or out-of-range commands
- Blocks new commands in MOVING state

7. Resource & Timing Considerations
- Invoked by command event or movement completion
- WCET <100us estimate
- Not re-entrant

8. Traceability
SWE-REQ-003, SWE-REQ-004, SWE-REQ-007, SWE-REQ-021, SWE-REQ-022, SWE-REQ-023

=======
C) Motor Driver Abstraction Unit
=======
1. Responsibilities
- Handles: Motor direction/enable signal control
- Does not handle: Timing, current sensing, diagnostics, HW faults

2. Internal Data Design
- direction (enum)
- active_signal_flag

3. State Machine
- State: "OFF", "ACTIVE"
- Transition to ACTIVE on FlapMoveRequest, OFF on move complete
 
4. Algorithms & Control Flow
- On FlapMoveRequest: Assert direction/enable pins
- On completion: Deassert all pins

5. Interfaces (APIs)
Provided:
- MotorControlIF
Required:
- FlapMoveRequest

6. Error Handling
- None (only called by validated logic)

7. Resource & Timing Considerations
- Pins set/cleared atomically
- WCET single-digit us
- Not re-entrant

8. Traceability
SWE-REQ-005, SWE-REQ-008, SWE-REQ-009, SWE-REQ-019

=======
D) Position Feedback Processing Unit
=======
1. Responsibilities
- Handles: ADC-to-position mapping, invalid ADC rejection
- Does not handle: Filtering, runtime calibration

2. Internal Data Design
- adc_raw (uint16_t)
- logical_position (uint8_t)
- adc_invalid_flag
- calibration_table[] (ROM/CONST)

3. State Machine
- State: "VALID", "INVALID"
- Event: ADC sample in/out of range
- Action: Map to index or assert invalid

4. Algorithms & Control Flow
- On ADC: adc_raw -> map via calibration_table -> logical_position
- If out-of-range: set adc_invalid_flag, safe state

5. Interfaces (APIs)
Provided:
- FeedbackProcessing (CurrentFlapPosition)
Required:
- ADC HAL
- ConfigDataIF
- FlapCtrlLogic

6. Error Handling
- Asserts adc_invalid_flag on out-of-bounds

7. Resource & Timing Considerations
- Invoked by ADC event/poll
- WCET <15us
- Not re-entrant

8. Traceability
SWE-REQ-010, SWE-REQ-011, SWE-REQ-012, SWE-REQ-018, SWE-REQ-025

=======
E) Status Indication Unit
=======
1. Responsibilities
- Handles: Power-on, per-position LED control (ON/OFF only)
- Does not handle: Animation, error display

2. Internal Data Design
- led_states[] (bool, one per logical LED)

3. State Machine
- State: "OFF", "ON" per LED
- Events: Flap move, power-on
- Action: Only one position LED on

4. Algorithms & Control Flow
- On init: Power LED ON
- On feedback/event: Map flap position to index, update LEDs

5. Interfaces (APIs)
Provided:
- StatusLEDControlIF
Required:
- FlapCtrlLogic
- FeedbackProcessing

6. Error Handling
- None (if out-of-range, all LEDs OFF)

7. Resource & Timing Considerations
- Invoked by feedback/move event
- WCET ~10us
- Not re-entrant

8. Traceability
SWE-REQ-013, SWE-REQ-014, SWE-REQ-015, SWE-REQ-016, SWE-REQ-019

=======
F) Software Configuration Table
=======
1. Responsibilities
- Handles: Calibration table, supported positions, pinouts; read-only
- Does not handle: Dynamic updates, EEPROM/runtime config

2. Internal Data Design
- const calibration_table[]
- const gpio_pin_assignments[]
- position_count

3. State Machine
- State: none (pure data)
- Flow: Consumed on demand by units

4. Algorithms & Control Flow
- None (read/lookup only)

5. Interfaces (APIs)
Provided:
- ConfigDataIF
Required:
- None (static data)

6. Error Handling
- None

7. Resource & Timing Considerations
- Pure global ROM/CONST
- No WCET/applicability

8. Traceability
SWE-REQ-025, SWE-REQ-026, SWE-REQ-027

=======
G) Error Handling Unit
=======
1. Responsibilities
- Handles: Invalid UART, ADC, blocking on error, safe state logic
- Does not handle: Reporting, self-healing, external error communication

2. Internal Data Design
- error_state_flag (OR of ADC/UART/logic), sticky
- last_error_code (enum)

3. State Machine
- State: "NORMAL", "SAFE_STATE"
- Event: any error detected
- Action: Enter SAFE_STATE, inhibit moves/clear outputs

4. Algorithms & Control Flow
- On error: set safe flag, clear motor/LEDs, block new commands

5. Interfaces (APIs)
Provided:
- SafeStateTrigger
Required:
- FeedbackProcessing
- UART Handler

6. Error Handling
- Sticky error until clear condition detected (i.e., valid ADC/UART)

7. Resource & Timing Considerations
- WCET negligible
- Not re-entrant

8. Traceability
SWE-REQ-012, SWE-REQ-024, SWE-REQ-028, SWE-REQ-029, SWE-REQ-030
