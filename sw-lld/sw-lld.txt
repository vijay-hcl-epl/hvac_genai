==== LLD for Each Software Unit ====

Software Unit: Command Handler

1. Responsibilities  
   - Handles reception and validation of user and LIN commands.  
   - Does not handle direct hardware signaling or movement logic.

2. Internal Data Design  
   - Variables: uint8_t command_received, uint8_t command_validated, uint8_t command_last
   - Command mapping table (loaded at init from Flash)

3. State Machine  
   - States: IDLE, RECEIVING, VALIDATING, DISPATCHED
   - Events: RX event, parse success, out-of-range, discarded, dispatched
   - Actions: On RX event, capture; validate against table; if valid, proceed; else ignore per SWE-REQ-002

4. Algorithms & Control Flow  
   - Wait for RX event from UART/LIN  
   - Parse byte, check range [0:5], lookup in command map table
   - If valid, set command_validated; else discard/ignore (never reset/stopper)
   - Dispatch validated command to Position Control Unit

5. Interfaces (APIs)  
   - Provided: Command_Receive(uint8_t data), Command_Validate(void): returns status code
   - Required: UART/LIN input buffers. Access to config-mapped command table
   - Error reporting: status to Status Indication Unit, error code via API return

6. Error Handling
   - Invalid commands ignored, no MCU reset. Parsing errors set error code and log to status handler as per SWE-REQ-002

7. Resource & Timing Considerations
   - Invoked per RX event (UART/LIN receive interrupt/callback)
   - WCET: <2ms per command event (input-triggered only)
   - Not re-entrant (buffered serial, single-threaded assumption)

8. Traceability
   - SWE-REQ-001, 002, 017, 018

-----------------

Software Unit: Position Control Unit

1. Responsibilities
   - Handles processing of validated command, closes position control loop
   - Does not handle command validation or direct hardware output

2. Internal Data Design  
   - Variables: uint8_t target_position, uint8_t current_position, uint8_t last_position, uint8_t movement_pending
   - Status flag for holding/idle

3. State Machine
   - States: WAIT_CMD, MOVING, HOLDING
   - Events: new valid command, actual==target, fault detected
   - Actions: Issue move request to Motor Driver; on target reached or fault, update status

4. Algorithms & Control Flow
   - On new valid command, check if position change required
   - If yes, set movement_pending flag, request motor actuation
   - Monitor feedback (current_position). When actual==target, clear movement_pending, set holding
   - No further requests until next valid command

5. Interfaces (APIs)
   - Provided: Control_Request(uint8_t new_pos), Control_Status(void): returns state/enum
   - Required: Command Handler, Feedback Acquisition, Motor Driver Abstraction
   - Error reporting: set status for Status Indication Unit

6. Error Handling
   - Fault detected by Motor Driver or Feedback propagated here, system transitions to HOLDING

7. Resource & Timing Considerations
   - Invoked on new command and by feedback/motor driver update
   - WCET: <1ms per control decision
   - Not re-entrant (single control loop)

8. Traceability
   - SWE-REQ-004, 005, 006, 025, 026

-----------------

Software Unit: Motor Driver Abstraction

1. Responsibilities
   - Handles all motor driver signals (enable, direction, PWM)
   - Does not handle command/logic or feedback directly

2. Internal Data Design
   - Variables: uint8_t enable, uint8_t dir, uint8_t pwm_value, fault_flag
   - Config struct for driver parameters loaded at init

3. State Machine
   - NONE (stateless, reacts to control requests and error status)
   - Explain flow: outputs are set atomically per invocation; any fault disables motor output immediately

4. Algorithms & Control Flow
   - On request: set enable, direction, pwm_value
   - On feedback or error: clear enable, set fault_flag

5. Interfaces (APIs)
   - Provided: Motor_Set(uint8_t dir, uint8_t pwm), Motor_Disable(void)
   - Required: Position Control signals, config struct
   - Error reporting: reports status to Position Control

6. Error Handling
   - On error signal, disables outputs, logs error

7. Resource & Timing Considerations
   - Invoked when move requested, on feedback, or on error
   - WCET: <0.2ms per update
   - Not re-entrant (driver atomic updates only)

8. Traceability
   - SWE-REQ-007, 008, 009

-----------------

Software Unit: Feedback Acquisition & Processing Unit

1. Responsibilities
   - Handles ADC1 sampling, maps to discrete flap position
   - Does not handle motor or command output

2. Internal Data Design
   - Variables: uint16_t adc_sample, uint8_t mapped_position
   - Struct: thresholds[6] (Flash-loaded)

3. State Machine
   - NONE (sample maps to value; periodic or event-driven by ADC interrupt)
   - Explain flow: Each sample triggers mapping algorithm, updates mapped_position

4. Algorithms & Control Flow
   - On ADC sample: compare to threshold array, map to position 0–5
   - Update mapped_position atomically

5. Interfaces (APIs)
   - Provided: Feedback_Get(void): returns mapped_position
   - Required: ADC1 Handler, Persistence & Config Manager
   - Error reporting: ADC errors flagged to Status Indication and Position Control

6. Error Handling
   - Conversion errors -> error status, ignored sample
   - No calibration/runtime learn

7. Resource & Timing Considerations
   - Invoked per ADC conversion (<0.2ms), polled or interrupt-driven
   - Not re-entrant

8. Traceability
   - SWE-REQ-010, 011, 012, 013, 019, 021

-----------------

Software Unit: Status Indication Unit

1. Responsibilities
   - Handles status output (GPIO, UART, LIN, LED/HSS)
   - Does not handle input

2. Internal Data Design
   - Variables: uint8_t status_code, uint8_t indication_mode
   - Config: mode mapping table loaded at init

3. State Machine
   - NONE (outputs reflect status as set by other units)
   - Explain flow: On status/command/fault event, status_code and/or outputs updated

4. Algorithms & Control Flow
   - When signaled by Position Control or Feedback, set output according to indication_mode
   - Format and send UART/LIN frame if required
   - Ensure only one output mode active at a time

5. Interfaces (APIs)
   - Provided: Status_Set(uint8_t code), Status_Indicate(void)
   - Required: Position Control, Feedback, config/indication table
   - Error reporting: frame error reported via return value

6. Error Handling
   - Invalid mode: do not update outputs
   - Output failure: flag error

7. Resource & Timing Considerations
   - Invoked on status change or periodically (<1ms)
   - Not re-entrant (single output buffer)

8. Traceability
   - SWE-REQ-014, 015, 020, 021

-----------------

Software Unit: Persistence & Configuration Manager

1. Responsibilities
   - Handles static config/threshold data provision from Flash at startup
   - Does not handle runtime updates or dynamic mappings

2. Internal Data Design
   - Tables: threshold array, command map, indication settings (all const after init)

3. State Machine
   - NONE (one-time at startup)
   - Explain flow: at boot, load all config to RAM, make immutable for session

4. Algorithms & Control Flow
   - On MCU init: copy from Flash to RAM
   - APIs allow read-only access

5. Interfaces (APIs)
   - Provided: Config_GetTable(enum), returns ptr
   - Required: Flash/NVM interface
   - Error reporting: verify checksum on boot

6. Error Handling
   - Config/fault: on error, block operation, set fatal config error status

7. Resource & Timing Considerations
   - Single invocation at startup (<4ms), then resident
   - Not re-entrant (config lock after init)

8. Traceability
   - SWE-REQ-011, 021, 030, 031

-----------------

Software Unit: Interface Abstractions (UART Handler, LIN Handler, ADC1 Handler, GPIO Handler)

1. Responsibilities
   - Each abstracts HW for higher-level units. No non-required logic.

2. Internal Data Design
   - UART: RX/TX buffer, error flags
   - LIN: frame buffer, node state, error flags
   - ADC1: channel setup, result buffer
   - GPIO: state table, error flags

3. State Machine
   - NONE (event/interrupt driven, per interface logic)
   - For each: buffer/flag states only, no global states

4. Algorithms & Control Flow
   - Per invocation: buffer/flag management, input/output calls

5. Interfaces (APIs)
   - Provided: UART_RecvAsync, UART_Send, LIN_RecvAsync, LIN_Send, ADC_Read, GPIO_Set/Get as required
   - Required: Used by relevant upper units
   - Error reporting: flag via status/return

6. Error Handling
   - Per interface: buffer overrun/underrun, framing errors, bus timeout, ADC fail. Passed upward and reported, never self-repaired or reset

7. Resource & Timing Considerations
   - Invoked per event (interrupt or high-level call), each <1ms per transaction
   - Never re-entrant (serial per hardware)

8. Traceability
   - SWE-REQ-017, 018, 019, 022, 033, 034
