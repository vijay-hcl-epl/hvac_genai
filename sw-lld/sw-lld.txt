-----------------------------------
Software Unit: Command Interface Unit
-----------------------------------
1. Responsibilities
   - Handles UART/LIN command reception, input validation, error detection
   - Does NOT handle system mode switching, motor drive, or feedback acquisition
2. Internal Data Design
   - uint8_t received_cmd
   - enum CmdValidationState { VALID, INVALID }
   - const config_data *, (read-only reference)
   - Error counters, comm state flag
3. State Machine
   - States: IDLE, RECEIVING, VALIDATING, ERROR
   - Events: RX available, RX complete, RX error, validation result
   - Transitions: IDLE→RECEIVING (RX avail), RECEIVING→VALIDATING (RX done), VALIDATING→IDLE (cmd dispatch), Any→ERROR (fault)
4. Algorithms & Control Flow
   - On RX: buffer command, check for validity (range 0…5, protocol, CRC, etc). If valid: store to command_in, else flag error/ignore
   - Pseudocode:
     If RX interrupt: read RX buffer
       If in range: VALIDATE, signal State Machine
       Else: Set error, ignore command
5. Interfaces (APIs)
   - Provided: get_validated_command(void) -> uint8_t, is_command_valid(void) -> bool
   - Required: config_data_read(void), UART/LIN RX Handlers
   - Error reporting: set_cmd_error(type)
6. Error Handling
   - Detect malformed frame, invalid command (out of range), comm loss
   - Ignore faulty command, update error counter, report via both comm channel and error signaling to State Machine
7. Resource & Timing Considerations
   - Invoked: on RX Complete (interrupt or poll), not re-entrant
   - WCET: < 1ms typical per RX
   - No blocking, no dynamic allocation
8. Traceability
   - SWE-REQ-001, 002, 003, 017, 018

--------------------------------------------
Software Unit: Control State Machine
--------------------------------------------
1. Responsibilities
   - Handles system control logic, position command dispatch, manages Idle/Move/Stopped/Fault, processes valid/rejected commands
   - Does NOT handle hardware drive logic or direct ADC/status acquisition
2. Internal Data Design
   - enum ControlState { IDLE, MOVING, HOLD, FAULT }
   - uint8_t target_position, current_position
   - Fault flag, state timer, last_cmd_valid
3. State Machine
   - States: IDLE, MOVING, HOLD, FAULT
   - Events: Valid command, arrival at target, error/fault, idle timeout
   - Transitions: IDLE→MOVING (valid cmd), MOVING→HOLD (on target), Any→FAULT (on error), FAULT→IDLE (on reset)
4. Algorithms & Control Flow
   - On valid command: check if target ≠ current, update state, command Actuator Driver
   - On feedback: compare current to target, if match then stop motor, go to HOLD
   - Fault logic: If fault flag active, command Actuator stop/notify
   - Pseudocode:
     If (valid_command && target ≠ current) → MOVING → command actuator
     If (feedback == target) → HOLD → stop actuator
     On (fault) → FAULT
5. Interfaces (APIs)
   - Provided: dispatch_position_cmd(uint8_t pos), system_state(void), set_fault(uint8_t code)
   - Required: get_validated_command(), fb_in(), actuator_driver()
6. Error Handling
   - Any error: notify State Machine, propagate to status, trigger system-wide FAULT
7. Resource & Timing Considerations
   - Invoked on event (command, feedback, fault), not re-entrant
   - WCET: < 2ms typical per event
   - No dynamic memory
8. Traceability
   - SWE-REQ-004, 005, 026, 027, 028, 029

--------------------------------------
Software Unit: Actuator Driver Unit
--------------------------------------
1. Responsibilities
   - Handles motor drive signal generation, PWM logic, enable/stop execution, no command/state logic
2. Internal Data Design
   - struct MotorCtrl { uint8_t enable; uint8_t pwm_duty; enum Direction; }
   - Fault flag, last_cmd
3. State Machine
   - State: "none". Operates per direct API calls from State Machine
   - Flow: If enabled, set appropriate H-bridge/on; else disable
4. Algorithms & Control Flow
   - On position_cmd: set PWM/enable lines, manage direction, stop on command
   - Fault: on error or stop, all motor outputs OFF immediately
   - Pseudocode:
     If (enable): set bridge/output per direction, PWM duty
     If (stop): all outputs low
5. Interfaces (APIs)
   - Provided: set_motor(uint8_t pos, uint8_t duty, Direction dir), stop_motor(void)
   - Required: state_cmd(), config_data_ptr
   - Error: set_fault_flag(reason)
6. Error Handling
   - Hardware or control error: outputs OFF, fault/status update to State Machine
7. Resource & Timing Considerations
   - Invoked: on command from State Machine, not re-entrant
   - WCET: < 0.5ms typical
   - No dynamic memory
8. Traceability
   - SWE-REQ-009, 010, 036

-------------------------------------------
Software Unit: Feedback Processing Unit
-------------------------------------------
1. Responsibilities
   - Handles ADC read, position mapping, threshold checks, error detection
2. Internal Data Design
   - uint16_t adc_val, mapped_position
   - pos_thresholds[] (FLASH config)
   - Error diagnostics flags
3. State Machine
   - State: none; runs on trigger/sample interval or per State Machine
   - Flow: read ADC, map to logical position, set error if out-of-bounds
4. Algorithms & Control Flow
   - On trigger: sample ADC, apply threshold mapping, update position out
   - On fault: flag error, notify State Machine
   - Pseudocode:
     adc_val = ADC1_read();
     mapped_position = map_adc_to_pos(adc_val, pos_thresholds[]);
     if (adc_val out-of-range or noisy): set_error()
5. Interfaces (APIs)
   - Provided: get_position(void) -> uint8_t, get_error_flag(void) -> uint8_t
   - Required: ADC1_read(), config_data_ptr
   - Error: report to State Machine
6. Error Handling
   - ADC error/out-of-bounds: flag error, keep last valid position, report fault
7. Resource & Timing Considerations
   - Invoked per sampling policy, not re-entrant
   - WCET: < 1ms typical
   - No dynamic memory
8. Traceability
   - SWE-REQ-011, 012, 013, 019, 029, 032

---------------------------------------
Software Unit: Status Indication Unit
---------------------------------------
1. Responsibilities
   - Handles status/fault/channel indication via GPIO, UART, LIN, LED
2. Internal Data Design
   - enum IndicatorState { POSITION, FAULT }
   - Output channel select, last_state
3. State Machine
   - State: none; functional mapping, updates on state transitions or error
   - Flow: set indicator output per new status
4. Algorithms & Control Flow
   - On notification: set indicator as required (channel, value)
   - On fault: flag error, show FAULT state only
5. Interfaces (APIs)
   - Provided: set_indicator(IndicatorState), get_status(void)
   - Required: system_state(), config_data_ptr
   - Error: set_fault_state()
6. Error Handling
   - On ambiguity/collision: default to FAULT, single-channel active at a time
7. Resource & Timing Considerations
   - Invoked on state change or error, not re-entrant
   - WCET: < 0.2ms
   - No dynamic memory
8. Traceability
   - SWE-REQ-015, 016, 020

------------------------------------
Software Unit: Configuration Data Unit
------------------------------------
1. Responsibilities
   - Static configuration read (Flash), data access for all runtime units
2. Internal Data Design
   - struct ConfigData { UART/LIN params, position thresholds[], etc. }
   - config read/copy-on-init only, all pointers const post-init
3. State Machine
   - State: none; static
   - Flow: on startup/init: read from FLASH, distribute to units
4. Algorithms & Control Flow
   - On init: load config, sanity-check data
5. Interfaces (APIs)
   - Provided: config_data_ptr, config_valid(void)
   - Required: FLASH_read()
   - Error reporting: config_error()
6. Error Handling
   - On config/load failure: fall-back to default, flag error
7. Resource & Timing Considerations
   - Invoked at startup, never re-entrant
   - WCET: < 3ms (Flash read)
   - No dynamic memory
8. Traceability
   - SWE-REQ-012, 032, 038, 039

--------------------------------------
Software Unit: Initialization/Startup Unit
--------------------------------------
1. Responsibilities
   - Handles system bring-up, static chip/resource init, startup state entry
2. Internal Data Design
   - Initialization stage flag, error code
3. State Machine
   - Simple procedural, sequential bring-up
   - Steps: REG/CLK→Peripherals→GPIO→Config→Safe state
4. Algorithms & Control Flow
   - On power-up: step through initializations, check result, go to state machine
5. Interfaces (APIs)
   - Provided: sys_init(void), is_ready(void)
   - Required: Flash read, config, peripheral init routines
   - Error: init_error()
6. Error Handling
   - Initialization error: stay in safe state, assert error, never start actuator
7. Resource & Timing Considerations
   - Invoked only once at startup, not re-entrant
   - WCET: < 5ms
   - No dynamic memory
8. Traceability
   - SWE-REQ-021, 022, 023, 024
