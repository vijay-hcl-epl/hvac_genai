## Software Unit: User Command Handler

### 1. Responsibilities
- Receives and parses UART commands representing user-requested flap positions
- Validates received commands against configured range
- Queues/supplies valid command to Flap Control; ensures only one active command is processed at a time
- Explicitly does NOT execute positioning or activate motor; does NOT handle hardware errors

### 2. Internal Data Design
- Static buffer for latest received UART command (char array, fixed size)
- `uint16_t parsed_command_position`
- `bool new_command_pending`
- UART RX status variable
- No dynamic variables or heap allocation; configuration references only

### 3. State Machine
- States: IDLE, RECEIVING, READY
- Events: UART RX complete, parse success, parse fail
- Transitions:
  - IDLE→RECEIVING (on RX interrupt or polling detects UART line activity)
  - RECEIVING→READY (on complete receive & parse OK)
  - RECEIVING→IDLE (parse fail or invalid command)
  - READY→IDLE (on successful hand-off to Flap Control Logic)
- No concurrency; only one command at a time

### 4. Algorithms and Control Flow
- On UART RX event:
  1. Store received bytes in static RX buffer
  2. Attempt to parse integer value (target position)
  3. If in range, set `parsed_command_position`, mark new_command_pending
  4. If out of range, ignore and set error flag (unit-local, no message out)
- Pseudocode Example:
  ```
  on_uart_receive(bytes):
    if length(bytes) == expected_length:
      value = parse_integer(bytes)
      if position_min <= value <= position_max:
        parsed_command_position = value
        new_command_pending = true
      else:
        new_command_pending = false
    else:
      ignore_rx()
  ```

### 5. Interfaces (APIs)
#### Provided:
- `bool get_new_command(uint16_t* target_position)`
  - Returns true if new valid command pending
#### Used:
- UART low-level RX API
- Flap Control Logic public entry (invoke on valid command present)

### 6. Error Handling
- Silently ignores invalid/garbage UART input
- Does not alter system state or propagate errors
- Command buffer reset on error

### 7. Resource and Timing Considerations
- Invoked by UART RX interrupt or polled in main loop
- Expected runtime:<5ms per RX event (worst case parsing and validation)
- Not re-entrant (single RX buffer)

### 8. Traceability
- SWE-REQ-001, 002, 003, 004, 005, 025, 048
- Software Unit: User Command Handler

## Software Unit: Flap Control Logic

### 1. Responsibilities
- Main behavioral logic: manages position target, invokes actuator as required
- Compares command vs current feedback
- Explicitly does NOT handle direct hardware or user input

### 2. Internal Data Design
- `uint16_t current_position`
- `uint16_t target_position`
- `enum flap_state {IDLE, MOVING, COMPLETE, ERROR}`
- `bool command_in_progress`
- References to calibration data (const)

### 3. State Machine
- States: IDLE, MOVING, COMPLETE, ERROR
- Events: New valid command, feedback updated, position reached, error detected
- Transitions:
  - IDLE→MOVING (on new command)
  - MOVING→COMPLETE (target reached)
  - Any→ERROR (feedback invalid, error signaled)
- Entry/Exit:
  - On EXIT MOVING, motor is disabled

### 4. Algorithms and Control Flow
- Main loop pseudocode:
  ```
  if (command_pending):
    target_position = get_new_command()
    if position_valid(target_position):
      command_in_progress = true
      state = MOVING
  if (state == MOVING):
    feedback = get_feedback()
    if error_in_feedback(feedback):
      state = ERROR
    else if (abs(feedback - target_position) <= tolerance):
      state = COMPLETE
      command_in_progress = false
      disable_motor()
  ```

### 5. Interfaces (APIs)
#### Provided:
- `void process_command()`
#### Used:
- User Command Handler (get_new_command)
- Motor Control Driver (start/stop)
- Feedback Processing (current_position)
- LED Indication (update)
- Error/Safety Monitor

### 6. Error Handling
- On feedback error/mismatch, triggers error via Error/Safety Monitor
- Returns to safe state (motor disable)

### 7. Resource and Timing Considerations
- Event-driven: invoked on new command or feedback update
- Non-reentrant; assumes protected by main control flow

### 8. Traceability
- SWE-REQ-007, 008, 009, 010, 011, 034, 035, 040, 041
- Software Unit: Flap Control Logic

## Software Unit: Motor Control Driver

### 1. Responsibilities
- Activates or disables motor as commanded by Flap Control Logic
- Sets direction, enables/disables power
- Explicitly does NOT handle position comparison or command processing

### 2. Internal Data Design
- Static variables:
  - `enum motor_state {OFF, FORWARD, REVERSE}`
  - `uint8_t pwm_value` (static/deterministic from calibration)

### 3. State Machine
- Simple: states OFF, FORWARD, REVERSE; transitions on API calls from Flap Control Logic

### 4. Algorithms and Control Flow
  ```
  set_motor(direction):
    if direction == FORWARD:
      enable_motor_forward()
    else if direction == REVERSE:
      enable_motor_reverse()
    else:
      disable_motor()
  ```

### 5. Interfaces (APIs)
#### Provided:
- `void set_motor(enum direction)`
- `void disable_motor()`
#### Used:
- Invoked from Flap Control Logic

### 6. Error Handling
- Returns immediately if asked to enable when already in correct state
- Disables motor if input unexpected

### 7. Resource and Timing Considerations
- Event-driven (on logic instruction)
- Not re-entrant (hardware-controlled)

### 8. Traceability
- SWE-REQ-012, 013, 014, 015, 027, 031
- Software Unit: Motor Control Driver

## Software Unit: Feedback Processing

### 1. Responsibilities
- Acquires analog (ADC) feedback, maps to logical position
- Provides current position to control logic
- Explicitly does NOT perform calibration or actuation

### 2. Internal Data Design
- `uint16_t last_adc_value`
- `uint16_t computed_position`
- Static reference to calibration ADC table

### 3. State Machine
- None (periodic or event-driven acquisition)

### 4. Algorithms and Control Flow
  ```
  get_feedback():
    last_adc_value = read_adc()
    computed_position = map_adc_to_position(last_adc_value)
    return computed_position
  ```
- Called periodically or when prompted

### 5. Interfaces (APIs)
#### Provided:
- `uint16_t get_feedback()`
#### Used:
- ADC driver
- Calibration data

### 6. Error Handling
- Out-of-range ADC value triggers error handler

### 7. Resource and Timing Considerations
- Polled by control logic every main loop or by timer
- Not re-entrant

### 8. Traceability
- SWE-REQ-016, 017, 018, 026, 037, 038
- Software Unit: Feedback Processing

## Software Unit: Status Indication

### 1. Responsibilities
- Drives system and position LEDs
- Explicitly does NOT process commands, feedback, or perform actuation

### 2. Internal Data Design
- Static LED state variable (`uint8_t led_state`)
- Reference to current logical position

### 3. State Machine
- None (set-only behavior)

### 4. Algorithms and Control Flow
  ```
  update_leds(current_position):
    set_led(power_led, ON)
    set_led(position_led, position_index(current_position))
  ```

### 5. Interfaces (APIs)
#### Provided:
- `void update_leds(uint16_t position)`
#### Used:
- Called by Flap Control Logic
- GPIO driver

### 6. Error Handling
- Ignores invalid LED indices (fails safe)

### 7. Resource and Timing Considerations
- Called on command completion and initialization

### 8. Traceability
- SWE-REQ-020, 021, 022, 028, 032, 033, 048, 050
- Software Unit: Status Indication

## Software Unit: Calibration/Configuration Data

### 1. Responsibilities
- Holds calibration constants, position tables, ADC map
- Read-only (runtime); no access to core logic except to read data
- Explicitly does NOT handle execution logic or state

### 2. Internal Data Design
- Const table: `[{adc_threshold, logical_position}]` (static array)
- Min/max limits (constants)

### 3. State Machine
- None

### 4. Algorithms and Control Flow
  ```
  get_position_limits(): returns (min, max)
  get_adc_lookup(): returns pointer to table
  ```

### 5. Interfaces (APIs)
#### Provided:
- `const * get_adc_lookup(void)`
- `uint16_t get_position_limits()`
#### Used:
- Read by Feedback Processing, Flap Control Logic

### 6. Error Handling
- None (read only, static)

### 7. Resource and Timing Considerations
- Accessed on demand
- Zero run-time cost beyond static memory

### 8. Traceability
- SWE-REQ-018, 037, 038, 045, 047
- Software Unit: Calibration/Configuration Data

## Software Unit: Error/Safety Monitor

### 1. Responsibilities
- Detects and signals out-of-range input/feedback
- Forces system to safe state (motor inhibit, LEDs safe)
- Explicitly does NOT process commands or actuate

### 2. Internal Data Design
- `bool error_flag`

### 3. State Machine
- States: NORMAL, ERROR
- Transitions: set error, clear error

### 4. Algorithms and Control Flow
  ```
  set_error():
    error_flag = true
    disable_motor()
    update_leds(error_state)
  clear_error():
    error_flag = false
    restore_normal_leds()
  ```

### 5. Interfaces (APIs)
#### Provided:
- `void set_error()`
- `void clear_error()`
#### Used:
- Invoked by Flap Control, Feedback Processing

### 6. Error Handling
- Handles all out-of-range conditions as unrecoverable, disables all actuation

### 7. Resource and Timing Considerations
- Called only on error/exception event

### 8. Traceability
- SWE-REQ-014, 040, 041, 042
- Software Unit: Error/Safety Monitor
