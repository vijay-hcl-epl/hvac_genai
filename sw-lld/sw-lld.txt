=============================
SOFTWARE LOW LEVEL DESIGN (SWE.3)
=============================
Document: sw-lld/sw-lld.txt
Branch: hvdemo-142b
Scope: Requirements-traceable LLD, MISRA C, NO scheduling/RTOS assumption, NO new units

==============================================
1. INITIALIZATION/STARTUP UNIT
----------------------------------------------
1. Responsibilities
   - Handles: System/hardware startup, peripheral setup, reading initial flap position, system idle
   - Does NOT handle: Ongoing command/position processing after startup
2. Internal Data Design
   - Static struct for initialization state
   - ADC/position-buffer variables, init-complete flag
   - No dynamic allocation
3. State Machine
   - States: Init (startup), Ready (after init)
   - Transition: After all peripherals configured → Ready
   - No run-time state transitions
4. Algorithms & Control Flow
   - Stepwise:
     1) Power-up entry
     2) Configure peripherals (ADC, UART, GPIO, PWM)
     3) Read flap position via ADC
     4) Set Power-ON LED
     5) Signal other units system is ready
   - No loops post-init
5. Interfaces (APIs)
   - Provided: init_start(), init_complete_signal()
   - Required: ADC read/start(), UART setup(), GPIO config(), PWM config(), Feedback Acq Unit read()
   - Params: None (static config)
   - Returns: Status/result code
   - Error: Returns status code if peripheral/config init fails
6. Error Handling
   - Stops startup on HW/periph error, returns code
   - Sets outputs to safe idle
   - No restart/retry defined
7. Resource & Timing Considerations
   - Runs ONCE at power-up
   - WCET: < 5ms typical on STM32F4
   - Not re-entrant
8. Traceability
   - SWE-REQ-024, SWE-REQ-025, SWE-REQ-011

==============================================
2. COMMAND INPUT UNIT
----------------------------------------------
1. Responsibilities
   - Handles: UART command decode, validation/filtering
   - Does NOT handle: Flap movement/state
2. Internal Data Design
   - Static command buffer, valid-position variable
   - Range-check constants/struct
3. State Machine
   - State: Idle (waiting), Command-Decoded
   - Event: UART RX complete
   - Action: Parse/validate/set command variable or ignore
4. Algorithms & Control Flow
   - Stepwise:
     a) Wait for UART RX
     b) Parse and range-check (0-5)
     c) Set valid-command flag or ignore
   - No loops, no queuing
5. Interfaces (APIs)
   - Provided: get_decoded_command()
   - Required: UART RX ISR/callback
   - Params: None
   - Returns: Parsed position (0–5) or INVALID
   - Error: INVALID if out of range
6. Error Handling
   - Ignores invalid input, sets INVALID, does not raise
   - No UART protocol error reporting
7. Resource & Timing Considerations
   - Invoked on UART RX event
   - WCET: < 0.5ms
   - Not re-entrant
8. Traceability
   - SWE-REQ-001, SWE-REQ-002, SWE-REQ-003, SWE-REQ-004, SWE-REQ-019

==============================================
3. FEEDBACK ACQUISITION UNIT
----------------------------------------------
1. Responsibilities
   - Handles: ADC reading, mapping signal to position, validity check
   - Does NOT handle: command decode, actuation
2. Internal Data Design
   - Static ADC buffer, position variable
   - Config struct (static for ADC→position mapping)
3. State Machine
   - States: Valid, Out-of-Range
   - Events: ADC sample ready
   - Transitions: ADC in range → Valid, Out-of-range → signal idle/stop
4. Algorithms & Control Flow
   - Stepwise:
     i) Acquire ADC value
     ii) For each range, check bounds
     iii) Return position or INVALID
   - No adaptive mapping
5. Interfaces (APIs)
   - Provided: get_flap_position()
   - Required: ADC ISR/callback
   - Params: None
   - Returns: position (0–5) or OUT_OF_RANGE
   - Error: OUT_OF_RANGE code
6. Error Handling
   - OUT_OF_RANGE stops actuation
   - No diagnostic indication
7. Resource & Timing Considerations
   - Invoked on ADC ready
   - WCET: < 0.25ms
   - Not re-entrant
8. Traceability
   - SWE-REQ-012, SWE-REQ-013, SWE-REQ-014, SWE-REQ-015, SWE-REQ-020, SWE-REQ-030, SWE-REQ-033

==============================================
4. FLAP POSITION CONTROL UNIT
----------------------------------------------
1. Responsibilities
   - Handles: Command/position/state determination, movement logic
   - Does NOT handle: hardware actuation, direct UART/ADC interfacing
2. Internal Data Design
   - Target/current position, state variable
   - Static command/state struct
3. State Machine
   - States: Idle, Moving, Error-Detected
   - Events: Command received, Position reached, Feedback error
   - Transitions: Idle→Moving (cmd), Moving→Idle (pos matched), Any→Error (out-of-range)
4. Algorithms & Control Flow
   - Stepwise:
     1) Check for new command
     2) If valid, compare to current position
     3) Issue move/stop command to Motor Unit
     4) Update status LEDs
     5) Idle if complete/error
5. Interfaces (APIs)
   - Provided: position_controller_execute()
   - Required: get_decoded_command(), get_flap_position(), motor_move(), motor_stop(), set_led_state()
   - Params: None
   - Returns: Status
   - Error: Error code on out-of-range
6. Error Handling
   - If feedback = OUT_OF_RANGE: stop, set error state
   - No automated retry
7. Resource & Timing Considerations
   - Periodic/call per command/ADC event
   - WCET: < 1ms
   - Not re-entrant
8. Traceability
   - SWE-REQ-005, SWE-REQ-006, SWE-REQ-007, SWE-REQ-024, SWE-REQ-025, SWE-REQ-026, SWE-REQ-027, SWE-REQ-028, SWE-REQ-031

==============================================
5. MOTOR ACTUATION UNIT
----------------------------------------------
1. Responsibilities
   - Handles: Motor drive/stop/actuate commands from control unit
   - Does NOT handle: State logic, UART/ADC/LED management
2. Internal Data Design
   - Static state: direction, enable, signals
   - No dynamic allocation
3. State Machine
   - States: Motor-Off, Motor-On-Fwd, Motor-On-Rev
   - Events: Move command (with direction)
   - Actions: Set/clear output pins, enable/disable PWM
4. Algorithms & Control Flow
   - On motor_move():
     a) Set direction, enable
   - On motor_stop():
     b) Clear enable, all outputs off
5. Interfaces (APIs)
   - Provided: motor_move(dir), motor_stop()
   - Required: GPIO/PWM calls
   - Params: dir (FWD/REV)
   - Returns: Status
   - Error: Returns status if hardware error (optional)
6. Error Handling
   - On hardware signal error: stop
   - No report/indication
7. Resource & Timing Considerations
   - Invoked by controller only
   - WCET: < 0.25ms
   - Not re-entrant
8. Traceability
   - SWE-REQ-008, SWE-REQ-009, SWE-REQ-010, SWE-REQ-011, SWE-REQ-021

==============================================
6. STATUS INDICATION UNIT
----------------------------------------------
1. Responsibilities
   - Handles: Power and position LED indication on system state
   - Does NOT handle: command logic, ADC/motor
2. Internal Data Design
   - LED state array; current LED index/variable
3. State Machine
   - States: LEDs ON/OFF
   - Event: Position/state changes
   - Action: Set single position LED ON, all others OFF
4. Algorithms & Control Flow
   - On flap/command/state change:
     - Set power LED ON during operation
     - Set only the matching position LED ON, others OFF
5. Interfaces (APIs)
   - Provided: set_led_state(idx)
   - Required: GPIO set/reset
   - Params: idx (0–5, power)
   - Returns: none
   - Error: none
6. Error Handling
   - If invalid idx: ignore
   - No diagnostic output
7. Resource & Timing Considerations
   - Invoked on position/command event
   - WCET: < 0.15ms
   - Not re-entrant
8. Traceability
   - SWE-REQ-016, SWE-REQ-017, SWE-REQ-018, SWE-REQ-022
