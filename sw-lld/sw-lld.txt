# Software Low Level Design (LLD) — HVAC Flap Actuator (Branch: modgit-232)

This document provides the Software Low Level Design for each software unit defined in the architecture of the HVAC Flap Actuator system, fully traceable to SWE.1 requirements and architectural boundaries. No new units, scheduling or code are introduced; all decisions, interfaces, and data remain as previously specified. Implementation target: STM32F407G-DISC1, C (MISRA style), STM32 HAL drivers, L298N H-bridge.

---

## Software Unit: Main Application Control

### 1. Responsibilities
- Orchestrates initialization, sequencing, and coordination of all lower-level units.
- Enters and cycles main loop, triggering periodic evaluation of command, sensor, logic, and hardware status units in required order.
- Explicitly does not implement direct hardware access, error handling logic, or user command parsing itself.

### 2. Internal Data Design
- System state variable (enum): INIT, IDLE, MOVING, HOLDING, ERROR
- Initialization completed flag (bool)
- Step counter or heartbeat (optional)

### 3. State Machine (applies)
States: INIT → IDLE → MOVING → HOLDING → (ERROR if detected) → IDLE
Events: Init complete, valid command received, movement triggered, target reached, error detected
Transitions: As listed
Entry/Exit actions: Initialize units, reset flags, clear outputs

### 4. Algorithms/Control Flow
- On power-up: initialize all subsystems, set state INIT
- Proceed to IDLE and poll UART; on valid command, enter MOVING
- While MOVING, repeatedly issue movement control and read feedback
- On target reached or error, transition state
- In HOLDING, no movement, monitor for new user command

### 5. Interfaces (APIs)
- Calls: UART Command Handler (poll/step), Position Feedback Processor (read), Flap Movement Controller (dispatch movement/stop), LED Status Driver (update)
- Receives: Status indicators, flags, error status from below units

### 6. Error Handling
- In ERROR state, disables all actuation, can signal via LED, returns to IDLE after recovery criteria met

### 7. Resource/Timing
- Cyclic, main loop invocation
- Not re-entrant

### 8. Traceability
- SWE-REQ-026, SWE-REQ-027, SWE-REQ-028, SWE-REQ-029, SWE-REQ-031, SWE-REQ-041, SWE-REQ-042

## Software Unit: UART Command Handler

### 1. Responsibilities
- Receives user commands over UART as numeric position values (0–5)
- Validates range and syntax; sets target position if valid
- Ignores invalid/duplicate commands, notifies main control
- Does not handle actuation, ADC, or error logic

### 2. Internal Data Design
- Raw input buffer
- Last command value
- Target position variable
- Valid/invalid flag

### 3. State Machine: Not explicit. Operates event style: receive message → validate → set/ignore

### 4. Algorithm/Control Flow
- Poll UART peripheral (interrupt or polling)
- If new character, push to buffer
- If line-end/command detected: parse
- If value in 0–5: set target position and valid flag
- Else: set invalid flag, notify main control

### 5. Interfaces
- Provides: get_target_position(), is_command_valid()
- Uses: UART HW API, Main Application triggers step

### 6. Error Handling
- Invalid or out-of-range values: flag as invalid, clear buffer, do not change state

### 7. Resource/Timing
- Cyclic call, relatively infrequent (human timescale)
- Not re-entrant

### 8. Traceability
- SWE-REQ-001 to SWE-REQ-005, SWE-REQ-035

## Software Unit: Flap Movement Controller

### 1. Responsibilities
- Compares current to target position, determines if/when to move
- Requests appropriate motor actions
- Stops motor on target reached or error
- Does not access hardware directly

### 2. Internal Data Design
- Target position (input)
- Current position (input)
- Move/stop signal
- Direction flag (CW/CCW/idle)
- Movement-in-progress flag

### 3. State Machine: Simple
- States: MOVING, STOPPED
- Transitions: On command set, on target reached, on error

### 4. Algorithm/Control Flow
- If movement flag set: compare current/target
- If not at target: set direction, request movement
- If at target: request motor stop, clear movement flag

### 5. Interfaces
- Provides: request_movement(dir, enable), request_stop()
- Uses: Motor Driver Controller (API), receives position/target update

### 6. Error Handling
- Any error/invalidation: immediately request stop, clear movement

### 7. Resource/Timing
- Invoked cyclically from main
- Not re-entrant

### 8. Traceability
- SWE-REQ-006, SWE-REQ-007, SWE-REQ-008, SWE-REQ-009, SWE-REQ-029, SWE-REQ-030

## Software Unit: Motor Driver Controller

### 1. Responsibilities
- Implements motor enable/disable and direction via GPIO and PWM manipulation
- Never interprets user commands or system/application logic

### 2. Internal Data Design
- GPIO state variables (direction)
- PWM duty cycle (if speed used)
- Active/enabled flag

### 3. State Machine: None (stateless response to requests)

### 4. Algorithm/Control Flow
- Set motor enable and direction per request from Flap Movement Controller
- On disable: de-energize PWM and set all output LOW

### 5. Interfaces
- Provides: set_enable(bool on), set_direction(bool dir), set_speed(uint8_t duty)
- Uses: STM32 HAL GPIO/PWM API (not direct register)

### 6. Error Handling
- On any abnormal/unsafe request, disables motor

### 7. Resource/Timing
- Trivially short, called on change only or every cycle
- Not re-entrant

### 8. Traceability
- SWE-REQ-010, SWE-REQ-011, SWE-REQ-012, SWE-REQ-024

## Software Unit: Position Feedback Processor

### 1. Responsibilities
- Reads flap position potentiometer signal from ADC
- Maps ADC value to logical position (0–5) using table or range
- Validates range, flags if invalid

### 2. Internal Data Design
- Last ADC sample (raw)
- Last logical position value (0–5 or INVALID)
- Configured ADC threshold table [static]

### 3. State Machine: None; continuous update

### 4. Algorithm/Control Flow
- Periodically sample ADC
- For each new sample: compare to thresholds, determine position
- If valid range: update logical position
- If invalid: set INVALID flag, report to error handler

### 5. Interfaces
- Provides: get_current_position(), get_adc_status()
- Uses: STM32 HAL ADC API

### 6. Error Handling
- Out-of-range: notifies error handler, does not update position, ensures flap movement command not dispatched

### 7. Resource/Timing
- Polled or interrupt triggered

### 8. Traceability
- SWE-REQ-013, SWE-REQ-014, SWE-REQ-015, SWE-REQ-016, SWE-REQ-032, SWE-REQ-033

## Software Unit: LED Status Driver

### 1. Responsibilities
- Manages all user/status LEDs: power, position (0–5)
- Ensures only one position LED is ON at a time
- No advanced animations, only steady ON/OFF

### 2. Internal Data Design
- LED state array (6 green, 1 power)
- Requested state

### 3. State Machine: None; stateless driver

### 4. Algorithm/Control Flow
- On update request, turns ON requested position LED, all others OFF
- Sets power LED based on system state

### 5. Interfaces
- Provides: set_position_led(uint8_t pos), set_power_led(bool on)
- Uses: STM32 HAL GPIO

### 6. Error Handling
- No specific error logic, fails safe (all off or unchanged).

### 7. Resource/Timing
- Low, on-demand or periodic update

### 8. Traceability
- SWE-REQ-017 to SWE-REQ-021, SWE-REQ-025, SWE-REQ-046

## Software Unit: Configuration/Calibration

### 1. Responsibilities
- Stores all static table data (ADC thresholds, mapping values)
- Never executes logic; only accessed for calibration params

### 2. Internal Data Design
- Static configuration block (ADC threshold table)
- No state or dynamic variables

### 3. State Machine: None

### 4. Algorithm/Control Flow
- None (initialization for read-only use at startup)

### 5. Interfaces
- Provides: get_adc_thresholds(), get_valid_range()

### 6. Error Handling
- Not applicable (usage only); invalid calibration is a development fault

### 7. Resource/Timing
- Accessed at startup and at each feedback evaluation

### 8. Traceability
- SWE-REQ-032, SWE-REQ-033, SWE-REQ-034

---

## Software Unit: Error & Safe State Handler

### 1. Responsibilities
- Acts on invalid user command, ADC range violation, hardware faults
- Commands safe state for actuators and LEDs
- Never implements core logic or normal sequencing

### 2. Internal Data Design
- Error status flags
- Last error type/ID
- Safe state command flags (to other units)

### 3. State Machine: Very simple (error active/inactive)

### 4. Algorithm/Control Flow
- On error: disables motor, sets error status LED if available, clears commands
- On recovery: re-enables logic

### 5. Interfaces
- Provides: set_error(error_id), clear_error(), is_error_active()
- Uses: control flags from each calling unit

### 6. Error Handling (core function)
- Handles all abnormal/invalid requests; ensures safe fallback

### 7. Resource/Timing
- Triggered by events or cyclic checks

### 8. Traceability
- SWE-REQ-030, SWE-REQ-035, SWE-REQ-036, SWE-REQ-037, SWE-REQ-038, SWE-REQ-044
