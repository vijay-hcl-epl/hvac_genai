# Software Low-Level Design (LLD) – HVAC Flap Actuator

## Introduction
This document provides the detailed low-level design (SWE.3) for the HVAC flap actuator embedded software. The design is fully traceable to SWE.1 (Software Requirements Specification) and adheres strictly to the defined software architecture (monolithic, logically separated units). No new software units are introduced, and architectural or scheduling choices are not changed or imposed. Implementation-specific code or scheduling details are expressly excluded.

Design is for resource-constrained embedded C (MISRA-style, no dynamic allocation).

---

## Software Units and LLD

--------------------------
## Software Unit: Command Handler

### 1. Responsibilities
- Receives UART user command bytes (position requests 0-5)
- Validates received command (valid/invalid range, must be in IDLE)
- Passes valid commands (positions) to State Manager/Control Logic

**Explicitly Not Responsible For:**
- Interpreting ADC feedback or actual flap position
- Moving the motor/flap
- LED or status indication
- Reject/ack for invalid commands (silent ignore ONLY)

### 2. Internal Data Design
- Latest received UART byte (uint8_t)
- Command buffer/state (enum: NONE, RECEIVED, PENDING)
- Parsed position command (int, 0–5 if valid)

### 3. State Machine
- No explicit state machine. Operates as event-driven parser: on UART receive, parses, checks for validity, raises event.

### 4. Algorithms and Control Flow
1. On UART byte received:
    a. If system state != IDLE, discard/ignore.
    b. Parse byte to integer.
    c. If value in 0–5, mark as valid command and raise event.
    d. Else: ignore (do nothing).

### 5. Interfaces (APIs)
- receive_command(uart_byte): Called by HW abstraction on UART RX. Outputs: parsed_position (0–5 or INVALID)
- Passes valid position to State Manager/Control Logic via event/callback pattern.

### 6. Error Handling
- Invalid bytes (not 0–5): silent drop/ignore
- Commands received while not IDLE: ignore

### 7. Resource/Timing
- Invocation: event-triggered by UART
- No resource locking or re-entrancy required
- Fast path; small buffer only

### 8. Traceability
SWE-REQ-001, SWE-REQ-002, SWE-REQ-003, SWE-REQ-004, SWE-REQ-005, SWE-REQ-042, SWE-REQ-044

--------------------------
## Software Unit: State Manager

### 1. Responsibilities
- Maintains and exposes current system logical state (IDLE / MOVING / HOLDING)
- Blocks command handling if not IDLE
- Exposes state to other software units
- Supports state transitions (IDLE <-> MOVING <-> HOLDING)

**Explicitly Not Responsible For:**
- Parsing UART commands (handled by Command Handler)
- Interfacing with hardware

### 2. Internal Data Design
- Current state (enum: IDLE, MOVING, HOLDING)
- History/previous state (optional; for diagnostics only)

### 3. State Machine
- States: IDLE, MOVING, HOLDING
- Transitions: By control logic, on valid command, on completion/stop, on init
- Entry/exit: On new command (IDLE -> MOVING), on target reached (MOVING -> HOLDING), on reset (any -> IDLE)

### 4. Algorithms and Control Flow
- set_state(new_state): checks valid transition, updates state
- get_state(): returns current

### 5. Interfaces (APIs)
- set_state(state_enum)
- get_state(void): returns state_enum

### 6. Error Handling
- Invalid state transitions ignored or assert
- Always recoverable to IDLE on reset

### 7. Resource/Timing
- Called by Command Handler and Control Logic
- No concurrency or locking

### 8. Traceability
SWE-REQ-005, SWE-REQ-025, SWE-REQ-026, SWE-REQ-046, SWE-REQ-047

--------------------------
## Software Unit: Position Sensing

### 1. Responsibilities
- Reads potentiometer via ADC
- Applies hard-coded calibration mapping to logical flap position (0–5)
- Flags out-of-range ADC

**Explicitly Not Responsible For:**
- Moving motor/flap or deciding control actions

### 2. Internal Data Design
- ADC raw value (uint16_t)
- Last computed flap position (int 0–5 or INVALID)
- Calibration table (const struct/range array)

### 3. State Machine
- No explicit state-machine; executes on periodic polling or on request

### 4. Algorithms
1. Read ADC channel.
2. For value in calibration table:
    - If within threshold, assign logical position
3. If not in any threshold: mark INVALID
4. Provide latest valid position or out-of-range status

### 5. Interfaces
- get_current_position(): returns logical position (0–5 or INVALID)
- is_valid_position(): returns bool

### 6. Error Handling
- ADC out-of-range: flag; downstream disables motor

### 7. Resource/Timing
- Invocation: Periodic
- Not re-entrant

### 8. Traceability
SWE-REQ-006, SWE-REQ-009, SWE-REQ-010, SWE-REQ-016, SWE-REQ-017, SWE-REQ-018, SWE-REQ-024, SWE-REQ-031

--------------------------
## Software Unit: Control Logic

### 1. Responsibilities
- Determines required motor direction and movement
- Compares current/target position, initiates move
- Stops motor on target or error

**Explicitly Not Responsible For:**
- Receiving UART commands or feedback
- Direct GPIO/PWM access

### 2. Internal Data Design
- Target position (0–5, set by Command Handler)
- Movement in progress flag

### 3. State Machine
- Not explicit; movement is event- and state-driven

### 4. Algorithms
1. On valid new target:
    a. Compare target to current position
    b. If equal: do nothing, return HOLD
    c. If not equal: set movement direction
2. Periodically:
    - If moving, check ADC (Position Sensing)
    - If reached: stop motor, set state HOLDING
    - ADC invalid: stop motor

### 5. Interfaces
- move_to_position(target: int)
  - Calls Motor Driver (set_direction, enable/disable)
- Uses Position Sensing

### 6. Error Handling
- ADC invalid/target unreachable: disables motor, enters safe state

### 7. Resource/Timing
- Event- and polling-driven
- Not re-entrant

### 8. Traceability
SWE-REQ-007, SWE-REQ-008, SWE-REQ-011, SWE-REQ-012, SWE-REQ-013, SWE-REQ-014, SWE-REQ-015, SWE-REQ-027, SWE-REQ-036

--------------------------
## Software Unit: Motor Driver

### 1. Responsibilities
- Sets motor direction via GPIO
- Enables/disables motor driver (PWM output)
- Ensures startup/shutdown safety

**Explicitly Not Responsible For:**
- Deciding direction or when to move (done by control logic)

### 2. Internal Data Design
- Last commanded direction (enum)
- Enabled/disabled flag

### 3. State Machine
- No explicit state machine; direct hardware interface

### 4. Algorithms
- set_direction(direction): sets GPIO
- enable(): activates PWM
- disable(): deactivates PWM
- On init/reset: disables PWM

### 5. Interfaces
- set_direction(dir_enum)
- enable(void)
- disable(void)

### 6. Error Handling
- Always disables output on error/init/reset

### 7. Resource/Timing
- Invoked by Control Logic

### 8. Traceability
SWE-REQ-011, SWE-REQ-012, SWE-REQ-013, SWE-REQ-014, SWE-REQ-015, SWE-REQ-041

--------------------------
## Software Unit: Status Indication

### 1. Responsibilities
- Updates power LED and exactly one position LED per current position
- Provides simple visual feedback only

**Explicitly Not Responsible For:**
- Any motor/flap control

### 2. Internal Data Design
- Power status flag
- Array: per-position LED status (bitflags)

### 3. State Machine
- None; procedural (called after movement or at init)

### 4. Algorithms
- update_leds(power_on, pos_idx):
    - Set power LED output (GPIO)
    - For position LEDs: all off, then one ON (pos_idx)

### 5. Interfaces
- update_leds(power_on: bool, pos_idx: int)

### 6. Error Handling
- Invalid pos_idx: all position LEDs off (side effect: visible error)

### 7. Resource/Timing
- Whenever position/state changes, or always after movement

### 8. Traceability
SWE-REQ-019, SWE-REQ-020, SWE-REQ-043

--------------------------
## Software Unit: HW Abstraction

### 1. Responsibilities
- Single point for all microcontroller register/HAL access (UART, ADC, GPIO, PWM)
- Abstracts platform specifics for main logic and other units

**Explicitly Not Responsible For:**
- Business logic or command parsing

### 2. Internal Data Design
- Peripheral driver handles/structs

### 3. State Machine
- None; stateless access routines

### 4. Algorithms
- Provides HAL wrappers: uart_read(), adc_read(), gpio_set(), pwm_set()

### 5. Interfaces
- uart_read(), uart_write()
- adc_read()
- gpio_set(pin, state), pwm_set(channel, duty)

### 6. Error Handling
- Returns known error/status codes on fault

### 7. Resource/Timing
- Invoked as needed by upper layers

### 8. Traceability
SWE-REQ-021, SWE-REQ-022, SWE-REQ-023, SWE-REQ-024

--------------------------
## Software Unit: Config/Constants

### 1. Responsibilities
- Stores fixed/calibrated ADC thresholds for position mapping
- Compile-time configuration (read-only at run time)

**Explicitly Not Responsible For:**
- Business logic, runtime calculation

### 2. Internal Data Design
- Const array: per-position ADC threshold (struct)
- Count of positions

### 3. State Machine
- None

### 4. Algorithms
- get_pos_thresholds(): returns pointer to lookup table
- init_config(): setup function if needed

### 5. Interfaces
- get_pos_thresholds(void)
- init_config(void)

### 6. Error Handling
- If data corrupt: position mapping always fails safe (INVALID)

### 7. Resource/Timing
- Used at startup and by Position Sensing

### 8. Traceability
SWE-REQ-009, SWE-REQ-017, SWE-REQ-031, SWE-REQ-033
