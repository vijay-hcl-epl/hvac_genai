# Software Low Level Design (SWE.3): HVAC Flap Actuator System

---
Each section strictly follows ASPICE SWE.3 and the provided architecture. No new units, no architecture/scheduling changes, and no C code is present. MISRA embedded C assumptions, no dynamic allocation.

## Software Unit: User Command Handler

### 1. Responsibilities
- Receives position commands via UART, validates command syntax and range (SWE-REQ-001, SWE-REQ-002)
- Reports valid/invalid status to control logic
- Excludes: Does NOT process command queuing, scheduling, or interpret command context; does not execute actuator or low-level motor logic

### 2. Internal Data Design
- `last_cmd_position` (uint8_t): Stores most recent valid command position [0..5]
- `cmd_valid` (bool): Flag indicating validity of current UART command
- No persistent/dynamic data
- Configuration: position min/max constants

### 3. State Machine
- States: WAIT_CMD, VALIDATE
- Events: UART RX, Data Ready
- Transitions: WAIT_CMD→VALIDATE (on UART RX); VALIDATE→WAIT_CMD (on validation complete)
- Entry: WAIT_CMD (power-on)
- Exit: on valid command, notifies Position Control Logic

### 4. Algorithms and Control Flow
- On UART RX:
  - Parse input
  - Check for valid numeric [0..5]
  - If valid: update `last_cmd_position`, set `cmd_valid`=true
  - Else: set `cmd_valid`=false
- Hand over valid (position, status) to Position Control Logic

### 5. Interfaces (APIs)
- Provided:
  - `get_last_cmd_position(void) -> uint8_t`
  - `is_cmd_valid(void) -> bool`
- Required:
  - `uart_receive(buffer, len)` (from UART HW/driver)
- Error: Return/copy zeros or error flag if UART signal loss

### 6. Error Handling
- Ignore commands outside [0..5] (SWE-REQ-003, SWE-REQ-033)
- On UART framing/parity error: ignore
- Invalid: set `cmd_valid`=false

### 7. Resource/Timing
- Invoked on UART interrupt or polling
- WCE: < 1ms/command
- Not re-entrant (single-command design)

### 8. Traceability
- SWE-REQ-001, SWE-REQ-002, SWE-REQ-003, SWE-REQ-004, SWE-REQ-033

## Software Unit: Position Control Logic

### 1. Responsibilities
- Compares `last_cmd_position` to feedback position
- Requests movement or idle to Motor Ctrl Logic
- Manages actuation state
- Excludes: no direct hardware access; no command parsing

### 2. Internal Data Design
- `target_position` (uint8_t, set by User Cmd Handler)
- `current_position` (uint8_t, from Feedback Acquisition)
- `moving_status` (bool)

### 3. State Machine
- States: IDLE, MOVING
- Events: New Command, At Target, Error
- Transitions: IDLE→MOVING (on new valid command && not at target)
                 MOVING→IDLE (on reaching target or invalid)
- No entry/exit logic beyond setting/clearing `moving_status`

### 4. Algorithms and Control Flow
- If `cmd_valid` & `target_position` != `current_position`: 
  - Trigger move (call Motor Control)
  - Update `moving_status`
- If at target: 
  - Request Motor Ctrl to stop
  - Update LEDs (Status/Indication)

### 5. Interfaces (APIs)
- Provided:
  - `position_ctrl_step(void)`
  - `get_moving_status(void)`
- Required:
  - `get_last_cmd_position` (User Command Handler)
  - `get_current_position` (Feedback Acquisition)
  - `motor_control_move(dir)` (Motor Control)
- Error: On error or no valid feedback, requests stop

### 6. Error Handling
- Ignores command unless `cmd_valid`
- On loss of feedback: issues safe stop
- Never issues simultaneous conflicting commands

### 7. Resource/Timing
- Invoked on command/feedback update
- WCE: < 2ms
- Not re-entrant

### 8. Traceability
- SWE-REQ-005, SWE-REQ-006, SWE-REQ-007, SWE-REQ-008, SWE-REQ-029

## Software Unit: Motor Control

### 1. Responsibilities
- Drives GPIO/PWM pins for motor direct/enable
- Guarantees no simultaneous forward/reverse
- Excludes: Does not parse/apply logic for state, position, or user commands

### 2. Internal Data Design
- `motor_direction` (enum: FWD/REV/OFF)
- `motor_enabled` (bool)
- `hw_error_flag` (bool)

### 3. State Machine
- No explicit state machine; always invoked on request
- Each actuation request is fully handled and idempotent

### 4. Algorithms and Control Flow
- On move request:
  - If direction valid and not `motor_enabled`: enable, set direction
  - If stop request/at target: disable
  - Never allow forward & reverse active
- Checks and clears errors each step

### 5. Interfaces (APIs)
- Provided:
  - `motor_control_move(direction)`
  - `motor_control_stop(void)`
- Required:
  - GPIO/PWM HW drivers
- Error: Deactivate all motor pins if error

### 6. Error Handling
- On conflict or error: set `hw_error_flag`, disable

### 7. Resource/Timing
- Invoked per actuation request
- WCE: <1ms
- Not re-entrant

### 8. Traceability
- SWE-REQ-010, SWE-REQ-011, SWE-REQ-012, SWE-REQ-022

## Software Unit: Feedback Acquisition & Processing

### 1. Responsibilities
- Samples ADC, validates and filters data
- Maps ADC reading to position index [0..5]
- Passes current_position to Position Control Logic and Indication
- Excludes: No direct action on commands

### 2. Internal Data Design
- `adc_raw_value` (uint16_t)
- `position_index` (uint8_t, 0–5)
- Configuration: ADC min/max/range table

### 3. State Machine
- No explicit state machine
- Sample → Map → Publish flow

### 4. Algorithms and Control Flow
- On ADC sample:
  - Validate (in range)
  - If valid: map to index (using lookup table)
  - Else: flag error, suppress position updates

### 5. Interfaces (APIs)
- Provided:
  - `get_current_position(void)`
  - `adc_feedback_update(void)`
- Required:
  - ADC HW read

### 6. Error Handling
- Invalid ADC: flag error, do not update
- Out of range: lock system in current safe state

### 7. Resource/Timing
- Invoked on periodic or event sample
- WCE: <2ms/sample
- Not re-entrant

### 8. Traceability
- SWE-REQ-013, SWE-REQ-014, SWE-REQ-015, SWE-REQ-016, SWE-REQ-021

## Software Unit: Status/LED Indication

### 1. Responsibilities
- Drives all position/status LEDs
- Updates LEDs promptly on change of position/power
- Excludes: Does not determine position itself; acts only on input

### 2. Internal Data Design
- `led_status` (bitfield mask)
- `led_position_idx` (uint8_t)

### 3. State Machine
- No explicit state machine

### 4. Algorithms and Control Flow
- On position update:
  - Set only matching green LED ON
  - Off/on as required for power/status

### 5. Interfaces (APIs)
- Provided:
  - `update_led_indication(position_idx, pwr_status)`
- Required:
  - GPIO HW drivers

### 6. Error Handling
- If out-of-range: all position LEDs off, status LED BLINK

### 7. Resource/Timing
- Invoked on feedback/position change
- WCE: <1ms

### 8. Traceability
- SWE-REQ-017, SWE-REQ-018, SWE-REQ-019, SWE-REQ-023
