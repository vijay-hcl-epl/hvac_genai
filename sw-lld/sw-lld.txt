Software Unit: Initialization/Startup Unit
---------------------------------------------------------
1. Responsibilities  
- Handles system boot-up, peripheral initialization, and power-on logic.  
- Does not handle any user command decoding, flap control, or error management.

2. Internal Data Design  
- State variable: sys_init_done (bool)
- Config: Static pin/peripheral definitions (ROM, compile constant)

3. State Machine  
- States: None; single initialization sequence at boot. 
- Flow: Startup → peripheral init → signal 'ready' to downstream units.

4. Algorithms & Control Flow  
- Pseudocode:
  - On power-up: perform peripheral setup (UART, ADC, PWM, GPIO ports).
  - Initialize all outputs to OFF.
  - Read flap feedback once and store value.
  - Set sys_init_done = true.

5. Interfaces (APIs)
- Provided: init_complete() [signal to all other units]
- Required: None (lowest level)
- Params/Returns: None
- Error reporting: None

6. Error Handling  
- Not responsible for run-time errors or diagnostics.

7. Resource & Timing Considerations
- Invoked once at power-up.  
- No reentrancy required.  
- WCET not safety-critical.

8. Traceability  
- SWE-REQ-024, SWE-REQ-025, SWE-REQ-011

Software Unit: Command Input Unit
---------------------------------------------------------
1. Responsibilities  
- Handles reception/validation of UART user commands.  
- Does not control actuators or perform error handling beyond command validation.

2. Internal Data Design 
- Variable: cmd_rx_buffer[1]
- Valid position set: (0..5)

3. State Machine  
- States: None; stateless filter/interpret.
- Flow: Check UART receive; if new data, parse and filter command.

4. Algorithms & Control Flow  
- Pseudocode:
  - On UART receive: read byte; if 0-5, forward as valid.
  - If out-of-range, ignore command.

5. Interfaces (APIs)  
- Provided: get_valid_position()  
- Required: UART rx peripheral  
- Params: None
- Returns: Valid position (0..5) or 'none/invalid'.
- Error Reporting: None

6. Error Handling  
- Drops invalid data. No error feedback or resets generated.

7. Resource & Timing Considerations
- Invoked on UART input event.
- Non-reentrant; buffer per-invocation is safe.

8. Traceability  
- SWE-REQ-001, SWE-REQ-002, SWE-REQ-003, SWE-REQ-004, SWE-REQ-019

Software Unit: Feedback Acquisition Unit
---------------------------------------------------------
1. Responsibilities  
- Handles continuous ADC acquisition and mapping to discrete flap position.  
- Does not directly drive actuator or status outputs.

2. Internal Data Design  
- Variable: adc_raw_value (uint16_t)
- Position map: static const adc_thresholds[6][2]; (ROM)
- Output: current_position (0..5, or invalid)

3. State Machine  
- State: Measuring/Idle.
- Transitions: triggered by periodic poll or on-move event.

4. Algorithms & Control Flow  
- Pseudocode:
  - Sample ADC.
  - Compare raw value to mapped threshold bins.
  - If in range, output position (0..5).
  - If not in any bin, output INVALID.

5. Interfaces (APIs)  
- Provided: get_current_position()
- Required: ADC input peripheral
- Params: None.
- Returns: Flap position (0..5) or INVALID.
- Error Reporting: INVALID signals out-of-range.

6. Error Handling  
- Out-of-range ADC → output INVALID, triggers motor halt.

7. Resource & Timing Considerations  
- Invoked on periodic poll or flap move.
- Possible blocking ADC; mitigated by short conversions.
- Not re-entrant.

8. Traceability  
- SWE-REQ-012, SWE-REQ-013, SWE-REQ-014, SWE-REQ-015, SWE-REQ-020, SWE-REQ-030, SWE-REQ-033

Software Unit: Flap Position Control Unit
---------------------------------------------------------
1. Responsibilities  
- Handles move command execution, idle transition, and system state enforcement.  
- Does not directly read hardware or manage peripheral errors.

2. Internal Data Design  
- Variable: target_position (0..5)
- Current position (read-only)
- Move_in_progress (bool)

3. State Machine  
- States: IDLE, EXECUTE_MOVE
- Events: new command (valid), move complete, invalid feedback.
- Transition: IDLE→EXECUTE_MOVE (on command), EXECUTE_MOVE→IDLE (on completion/invalidation).

4. Algorithms & Control Flow 
- On command: set target_position; if different from current, request motor move.
- On each feedback update, check for arrival (current == target); if so, signal motor halt, set idle.
- On invalid feedback, halt motor.

5. Interfaces (APIs)  
- Provided: process_new_command(), check_move_complete()
- Required: Command Input, Feedback Acquisition, Motor Actuation, Status Indication
- Params: target_position
- Returns: move/status signal
- Error Reporting: Does not report errors directly.

6. Error Handling 
- If feedback invalid during move, enters idle state, halts motor.

7. Resource & Timing Considerations  
- Invoked on new valid command and on feedback update.
- Single-threaded assumption; not re-entrant.

8. Traceability  
- SWE-REQ-005, SWE-REQ-006, SWE-REQ-007, SWE-REQ-024, SWE-REQ-025, SWE-REQ-026, SWE-REQ-027, SWE-REQ-028, SWE-REQ-031

---------------------------------------------------------
Software Unit: Motor Actuation Unit
---------------------------------------------------------
1. Responsibilities  
- Handles enabling, reversing, and stopping the DC motor per control signals.  
- Does not process commands, error feedback, or status output directly.

2. Internal Data Design  
- Variable: motor_enable (bool), direction (enum)
- Config: GPIO/PWM static assignment

3. State Machine 
- State: ON, OFF
- Events: enable, disable, direction change

4. Algorithms & Control Flow  
- On enable/command from Flap Position Control, set outputs per direction.
- On stop request or feedback invalid, set all outputs OFF.

5. Interfaces (APIs)  
- Provided: actuate_motor(dir), stop_motor()
- Required: GPIO/PWM output
- Params: direction
- Returns: void
- Error Reporting: None (hardware may indicate fault externally)

6. Error Handling  
- Always returns to safe (OFF) mode on error/halt request.

7. Resource & Timing Considerations  
- Invoked on position change, or at movement completion/stall.
- No reentrancy needed; short latency assumed (<1ms).

8. Traceability  
- SWE-REQ-008, SWE-REQ-009, SWE-REQ-010, SWE-REQ-011, SWE-REQ-021

---------------------------------------------------------
Software Unit: Status Indication Unit
---------------------------------------------------------
1. Responsibilities  
- Handles ON/OFF control for "power" and "flap position" LEDs via GPIO.  
- Does not interpret feedback, or confirm actuator state.

2. Internal Data Design  
- LED mapping: static const led_gpio_map[6]
- Variable: last_active_led (0..5)

3. State Machine  
- No explicit machine; simple drive logic only.

4. Algorithms & Control Flow  
- On system init: set power LED ON.
- On position change: set matched position LED ON, all others OFF.

5. Interfaces (APIs)  
- Provided: update_status_leds()
- Required: GPIO output
- Params: position (0..5).
- Returns: void
- Error Reporting: None

6. Error Handling  
- None. Fail-safe: All LEDs off if invalid state.

7. Resource & Timing Considerations  
- Invoked at init and on every position/state update.
- Not re-entrant. Latency < few ms.

8. Traceability  
- SWE-REQ-016, SWE-REQ-017, SWE-REQ-018, SWE-REQ-022
