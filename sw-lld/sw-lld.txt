==============================
1. Software Unit: Cmd Parser/Validator
==============================

1. Responsibilities:
   - Handles parsing and validation of incoming flap position commands from UART/LIN (0-5)
   - Rejects and signals malformed or out-of-range commands
   - Provides validated command to control logic
   - Does not handle hardware details or execution order

2. Internal Data Design:
   - last_cmd (uint8_t)
   - cmd_valid (bool)
   - rx_buffer[8] (uint8_t)
   - config: valid_range_min, valid_range_max (Flash const)

3. State Machine:
   - States: IDLE, CMD_RX, CMD_VALID, CMD_INVALID
   - Events: RX_UART, RX_LIN, PARSE, VALID, INVALID
   - Transitions: IDLE→CMD_RX (receive), CMD_RX→CMD_VALID or CMD_INVALID, CMD_VALID/INVALID→IDLE

4. Algorithms & Control Flow:
   - On RX event, buffer cmd; parse uint8; check within valid_range_
   - Set cmd_valid; on error set CMD_INVALID
   - Pseudocode:
         if (new_cmd in valid_range) → cmd_valid=1
         else → cmd_valid=0

5. Interfaces (APIs):
   - Provided: Validated Cmd Interface (get_last_cmd, is_cmd_valid)
   - Required: UART/LIN HW API (rx)
   - Params: position_cmd (uint8_t)
   - Errors: returns status code (OK/ERR_RANGE/ERR_FMT)

6. Error Handling:
   - On malformed/out-of-range cmd: set error, inhibit control, provide error code to interface

7. Resource & Timing Considerations:
   - Invoked on each RX event, worst-case <1ms per call
   - Not re-entrant; RX events queued if overlap occurs

8. Traceability:
   - SWE-REQ-001, SWE-REQ-002, SWE-REQ-003

==============================
2. Software Unit: Position Ctrl State Machine
==============================

1. Responsibilities:
   - Manages flap control state: IDLE, MOVING, FAULT, HOLD
   - Calls motor control and feedback units
   - Holds last known/target position
   - Does not handle direct IO or user communication

2. Internal Data Design:
   - state (enum {IDLE, MOVING, FAULT, HOLD})
   - target_pos (uint8_t)
   - current_pos (uint8_t)
   - move_timeout (uint16_t)

3. State Machine:
   - States: IDLE, MOVING, FAULT, HOLD
   - Events: valid_cmd, pos_reached, fault, error, timeout
   - Transitions:
     - IDLE→MOVING (on valid_cmd)
     - MOVING→HOLD (on pos_reached)
     - MOVING/HOLD→FAULT (on error)
     - FAULT→IDLE (fault cleared)

4. Algorithms & Control Flow:
   - On valid_cmd: check state==IDLE, set target_pos, call motor_ctrl(start)
   - Periodically call feedback; if current_pos==target_pos, call motor_ctrl(stop), update state
   - Fault: inhibit movement, log error

5. Interfaces (APIs):
   - Provided: State/Control API (set_target, get_state, reset_fault)
   - Required: Cmd Validator, Pos Feedback, Motor Driver
   - Params: target_pos (uint8_t)
   - Error: status enum (OK/ERR_FAULT/ERR_TIMEOUT)

6. Error Handling:
   - State transitions to FAULT, disables motor, error traceability

7. Resource & Timing Considerations:
   - Invoked per state event; worst-case path <2ms
   - Non-reentrant by architecture

8. Traceability:
   - SWE-REQ-004, SWE-REQ-005, SWE-REQ-006, SWE-REQ-007, SWE-REQ-008, SWE-REQ-022, SWE-REQ-023, SWE-REQ-024, SWE-REQ-025, SWE-REQ-026, SWE-REQ-027, SWE-REQ-028

==============================
3. Software Unit: Motor Driver Ctrl
==============================

1. Responsibilities:
   - Handles MCU HW enables, direction, PWM
   - Receives target_dir, enable, duty_cycle from state machine
   - Does not handle external command/state logic

2. Internal Data Design:
   - dir (enum {CW, CCW})
   - pwm_duty (uint8_t)
   - enable (bool)
   - driver_status (enum {OK, FAULT})

3. State Machine:
   - State: NONE (combinatorial, stateless)
   - Flow: Receives desired cmd, sets/clears GPIO/PWM
   - If error/fault, disables outputs

4. Algorithms & Control Flow:
   - Set/clear MCU outputs based on parameters
   - Bounds: pwm_duty [0,100], dir valid enum
   - If driver_status==FAULT, inhibit updates

5. Interfaces (APIs):
   - Provided: Motor Control API (set_dir, set_pwm, enable, disable)
   - Required: MCU PWM, GPIO
   - Params: dir, duty, enable (all typed)
   - Error: returns status, can raise FAULT flag

6. Error Handling:
   - On HW error, raises FAULT, disables outputs

7. Resource & Timing Considerations:
   - Each invocation <1ms
   - Singleton (not re-entrant)

8. Traceability:
   - SWE-REQ-009, SWE-REQ-010, SWE-REQ-011, SWE-REQ-033

==============================
4. Software Unit: Position Feedback Processing
==============================

1. Responsibilities:
   - Acquires ADC1 data, post-processes
   - Debounces/glitch filtering
   - Converts to logical pos [0-5]

2. Internal Data Design:
   - raw_adc (uint16_t)
   - filtered_adc (uint16_t[3])
   - last_pos (uint8_t)
   - filter_type (config: median/avg, Flash)
   - thresholds[6] (Flash table)

3. State Machine:
   - State: NONE (pure combinatorial)
   - Flow: On demand, read ADC, filter, map to position

4. Algorithms & Control Flow:
   - Acquire 3 ADC samples, apply median/avg filter
   - Compare to threshold; set pos
   - Out-of-bounds: set error

5. Interfaces (APIs):
   - Provided: Flap Position API (get_pos, get_raw_adc)
   - Required: ADC1 Driver
   - Params: none
   - Error: returns error code (OK/ERR_GLITCH/ERR_RANGE)

6. Error Handling:
   - On error: report via API, signal to upper logic

7. Resource & Timing Considerations:
   - Call duration <2ms
   - Not re-entrant

8. Traceability:
   - SWE-REQ-012, SWE-REQ-013, SWE-REQ-014, SWE-REQ-025, SWE-REQ-036

==============================
5. Software Unit: ADC1 Driver
==============================

1. Responsibilities:
   - Triggers/converts analog flap feedback
   - No logic/algorithm, just data interface

2. Internal Data Design:
   - current_val (uint16_t)
   - status (enum {READY, BUSY, ERROR})

3. State Machine:
   - State: NONE (blocking conversion or async on HW flag)

4. Algorithms & Control Flow:
   - Start conversion, wait/interrupt for complete, read data
   - Single-sample, direct return

5. Interfaces (APIs):
   - Provided: ADC Data API (start, read, status)
   - Required: MCU ADC HW calls
   - Params: none
   - Error: returns status code

6. Error Handling:
   - Returns error, signals to feedback proc.

7. Resource & Timing Considerations:
   - Each call <2ms (worst case), not re-entrant

8. Traceability:
   - SWE-REQ-012, SWE-REQ-013, SWE-REQ-019

==============================
6. Software Unit: UART/LIN Driver
==============================

1. Responsibilities:
   - Provide RX/TX frames to/from comms
   - Protocol compliance, data package handling

2. Internal Data Design:
   - rx buffer[8], tx buffer[8]
   - lin_status (enum {OK, ERROR}), uart_status (same)

3. State Machine:
   - NONE (ISR/event driven)
   - Handles RX event, validates frames, passes to parser

4. Algorithms & Control Flow:
   - On RX event, store frame; verify checksum/type; call upper logic

5. Interfaces (APIs):
   - Provided: Cmd RX/TX API (send_cmd, recv_cmd)
   - Required: UART/LIN HW API
   - Params: buffer ptr, len
   - Error: returns status

6. Error Handling:
   - Error in frame: set error flag, report upward

7. Resource & Timing Considerations:
   - Each RX/TX <0.5 ms
   - RX not re-entrant; is event/interrupt based

8. Traceability:
   - SWE-REQ-001, SWE-REQ-017, SWE-REQ-018, SWE-REQ-040

==============================
7. Software Unit: GPIO/Status Output
==============================

1. Responsibilities:
   - Drives individual GPIO/LED for flap/fault status
   - Configurable output route (build time)

2. Internal Data Design:
   - status (enum {POS0-5, FAULT})
   - config (build-time const)

3. State Machine:
   - NONE (direct set/clear)

4. Algorithms & Control Flow:
   - On status update, set output GPIO per position/fault

5. Interfaces (APIs):
   - Provided: Status/Indication API (set_status)
   - Required: GPIO HW API
   - Params: status enum
   - Error: returns status

6. Error Handling:
   - Write fail: set error, inhibit further output

7. Resource & Timing Considerations:
   - Direct set/clear <0.2 ms
   - Not re-entrant

8. Traceability:
   - SWE-REQ-015, SWE-REQ-016, SWE-REQ-020, SWE-REQ-026, SWE-REQ-033
