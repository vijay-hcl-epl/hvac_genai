==============================
SWE.4 UNIT TEST PLAN — HVAC FLAP ACTUATOR (TLE9851QXW)
==============================

Units under test:
- Command Interface Unit
- Flap Position Controller
- Motor Control Unit
- Feedback Processing Unit
- Status Indication Unit
- Configuration & Diagnostics Unit

Unit list and responsibilities, as per LLD:

--------------------------------------------------------------------------
Unit: Command Interface Unit
Responsibility: Receiving, decoding, range/format validation of UART user commands.
SW-REQs: SWE-REQ-001, SWE-REQ-002, SWE-REQ-003, SWE-REQ-015, SWE-REQ-020

APIs: command_check_uart(), get_validated_command()

Test Cases:
1. [TC-CMD-001] Valid Command — Normal
   SW-REQ: SWE-REQ-001, SWE-REQ-002
   Objective: Confirm valid command is correctly decoded and accepted.
   Preconditions: UART receives [cmd][pos] in range
   Input: UART RX buffer with correct format (pos=50)
   Expected: get_validated_command() returns valid, error_code=CMD_NO_ERROR
   Pass Criteria: Valid true, error_code=0

2. [TC-CMD-002] Command Format Error
   SW-REQ: SWE-REQ-002
   Objective: Detect format errors
   Preconditions: UART receives packet with wrong length/structure
   Input: UART RX buffer, len!=2
   Expected: get_validated_command() valid false, CMD_FORMAT_ERROR
   Pass Criteria: Valid false, error_code=1

3. [TC-CMD-003] Command Out of Range
   SW-REQ: SWE-REQ-002, SWE-REQ-003
   Objective: Detect out of range for target_position
   Preconditions: UART receives [cmd][pos>100]
   Input: RX buffer with pos=150
   Expected: Valid false, error_code=CMD_RANGE_ERROR
   Pass Criteria: valid==false; error==CMD_RANGE_ERROR

4. [TC-CMD-004] UART Fault Handling (Mocked)
   SW-REQ: SWE-REQ-003
   Objective: Simulate UART receive failure or framing error
   Preconditions: uart_read() returns false
   Expected: valid==false, error==CMD_FORMAT_ERROR

--------------------------------------------------------------------------
Unit: Flap Position Controller
Responsibility: Position tracking, limit enforcement, movement triggering.
SW-REQs: SWE-REQ-004, SWE-REQ-005, SWE-REQ-021, SWE-REQ-022, SWE-REQ-023, SWE-REQ-026

APIs: process_command(), get_move_status()

Test Cases:
1. [TC-FPC-001] Valid Move Command
   SW-REQ: SWE-REQ-004,
   Objective: New command triggers move, in allowable range.
   Preconditions: cmd.valid=true, pos in [0,100]
   Input: process_command(cmd:pos=40)
   Expected: move_status=MOVE_IN_PROGRESS, target=40

2. [TC-FPC-002] Out-of-Range Move
   SW-REQ: SWE-REQ-005
   Objective: Move exceeds calibration/limit
   Preconditions: cmd.pos=150 (>max)
   Input: process_command(cmd)
   Expected: move_status=MOVE_LIMIT_ERROR

3. [TC-FPC-003] Target Reached
   SW-REQ: SWE-REQ-023
   Objective: move completes on target
   Preconditions: current=target
   Input: get_move_status()
   Expected: move_status=MOVE_DONE

4. [TC-FPC-004] Invalid Command
   SW-REQ: SWE-REQ-004
   Objective: Behavior on cmd.valid=false
   Preconditions: cmd.valid==false
   Input: process_command(cmd)
   Expected: move_status=MOVE_IDLE

--------------------------------------------------------------------------

- All tests shall be deterministic and repeatable (fixed input).

EXAMPLE UNIT TEST C STUB (CMD INTERFACE)
-----------------------------------------
#include "command_interface.h"
#include "mock_uart.h" // Mocks
#include <assert.h>

void test_valid_cmd_decoding() {
    uart_mock_set_receive_data((uint8_t[]){0x01, 50}, 2);
    command_check_uart();
    Command_t cmd;
    assert(get_validated_command(&cmd));
    assert(cmd.target_position==50);
    assert(cmd.error_code==CMD_NO_ERROR);
}

void test_cmd_format_error() {
    uart_mock_set_receive_data((uint8_t[]){0x01}, 1);
    command_check_uart();
    Command_t cmd;
    assert(!get_validated_command(&cmd));
    assert(cmd.error_code==CMD_FORMAT_ERROR);
}
