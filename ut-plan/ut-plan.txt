# HVAC Flap Actuator: ASPICE SWE.4 Unit Test Plan

## 1. List of Software Units
- Command Interpreter
- Flap Control
- Motor Control
- Feedback Acquisition
- Status Indication
- Hardware Interface Layer

---

## 2. Unit Test Case Details

### Software Unit: Command Interpreter
- Responsibilities: Handles UART user command reception/validation. Forwards valid requests, ignores invalid/repeated ones.
- Allocated SW-REQs: SWE-REQ-001, SWE-REQ-002, SWE-REQ-003, SWE-REQ-005, SWE-REQ-039

| Test Case ID | SW-REQ Ref | Objective                                | Preconditions | Input                      | Expected Result          | Pass/Fail           |
|--------------|------------|------------------------------------------|---------------|---------------------------|-------------------------|---------------------|
| CI_TC_001    | 001,002    | Accept valid command, forward to FlapCtl | UART ready    | Valid cmd in [0..4]       | Returns CMD_OK; forwards| CMD_OK, next state  |
| CI_TC_002    | 002,039    | Reject invalid command                   | UART ready    | Out-of-range cmd (>4,255)  | Returns CMD_INVALID     | CMD_INVALID         |
| CI_TC_003    | 003,005    | Ignore repeated command                  | Last_cmd==cmd | Cmd = last valid cmd      | Returns CMD_REPEATED    | CMD_REPEATED        |

### Software Unit: Flap Control
- Responsibilities: Sets target flap position, avoids redundant moves, checks position, initiates actuation, disables on errors.
- Allocated SW-REQs: SWE-REQ-007, SWE-REQ-008, SWE-REQ-009, SWE-REQ-013, SWE-REQ-031

| Test Case ID | SW-REQ Ref | Objective                                   | Preconditions        | Input           | Expected Result                   | Pass/Fail                   |
|--------------|------------|---------------------------------------------|----------------------|-----------------|-----------------------------------|-----------------------------|
| FC_TC_001    | 007,008    | Actuate valid new position                  | Power ON             | pos ≠ curr, in set | Calls motor_run() for direction   | Motor active, LED result    |
| FC_TC_002    | 009,031    | Ignore request for current position         | Flap at N            | pos = curr       | No action, no motor/LED change    | No actuation                |
| FC_TC_003    | 013        | Prevent actuation on invalid input/feedback | Feedback invalid     | Any             | No motor; error LED set           | Safety action, LED error    |

### Software Unit: Motor Control
- Responsibilities: Activates motor, enforces safe GPIOs, stops on command or error.
- Allocated SW-REQs: SWE-REQ-011, SWE-REQ-012, SWE-REQ-014, SWE-REQ-034

| Test Case ID | SW-REQ Ref | Objective                             | Preconditions     | Input                 | Expected Result                       | Pass/Fail       |
|--------------|------------|---------------------------------------|-------------------|-----------------------|---------------------------------------|-----------------|
| MC_TC_001    | 011,014    | Run motor correct direction           | Init, idle        | run(UP/DOWN)          | Only one GPIO dir active              | GPIO control    |
| MC_TC_002    | 012        | Stop on position match                | Motor running     | Feedback = target     | Calls gpio_clear, disables motor      | Stopped state   |
| MC_TC_003    | 034        | Stop on hardware error                | Motor running     | HW error simulated    | Calls motor_stop, error indicated     | Safety stop     |

### Software Unit: Feedback Acquisition
- Responsibilities: ADC read, maps to logical position, provides to others.
- Allocated SW-REQs: SWE-REQ-015, SWE-REQ-016, SWE-REQ-017, SWE-REQ-035

| Test Case ID | SW-REQ Ref | Objective                       | Preconditions      | Input           | Expected Result           | Pass/Fail              |
|--------------|------------|---------------------------------|--------------------|-----------------|--------------------------|------------------------|
| FA_TC_001    | 015,016    | Map valid ADC to position       | ADC in [500,3500]  | ADC value X     | Returns valid pos(0..4)  | Correct position       |
| FA_TC_002    | 035        | Use config thresholds           | Various configs    | ADC values/bounds| Positions track config   | All cases valid        |
| FA_TC_003    | 015        | Out-of-range returns boundary   | ADC <500/>3500     | Lower/upper bound| Returns lowest/highest   | No exception/crash     |

### Software Unit: Status Indication
- Responsibilities: Updates LEDs for position, shows error, only one active at a time.
- Allocated SW-REQs: SWE-REQ-019, SWE-REQ-020, SWE-REQ-021

| Test Case ID | SW-REQ Ref | Objective                           | Preconditions         | Input               | Expected Result                   | Pass/Fail           |
|--------------|------------|-------------------------------------|----------------------|---------------------|-----------------------------------|---------------------|
| SI_TC_001    | 019,021    | Show correct LED for position       | Normal op            | pos 0..4            | Only pos LED on, others off       | Correct LED state   |
| SI_TC_002    | 019,020    | Change indication on flap move      | Flap moves           | set_position(N)     | Updates to correct LED            | Update observed     |
| SI_TC_003    | 019,020    | Show error indication               | Error state          | set_error(true)     | Error LED on, clears on set_error(0)| LED sequence     |

### Software Unit: Hardware Interface Layer
- Responsibilities: Wrapper for UART, GPIO, ADC. Ensures stateless access.
- Allocated SW-REQs: SWE-REQ-022, SWE-REQ-023, SWE-REQ-024, SWE-REQ-025

| Test Case ID | SW-REQ Ref | Objective         | Preconditions     | Input  | Expected Result         | Pass/Fail |
|--------------|------------|-------------------|-------------------|--------|------------------------|-----------|
| HI_TC_001    | 022,024    | Correct ADC, UART | Normal op         | N/A    | Returns plausible value| Return OK |
| HI_TC_002    | 023,025    | Correct GPIO ctrl | Normal op         | set/clear | GPIO status reflects   | GPIO OK   |

## 5. Isolation/Test Framework/Hardware Abstraction Details
- All hardware APIs (gpio_set/clear, adc_read, uart_read) must be mocked.
- No integration or true hardware dependencies permitted.
- Tests MUST be deterministic and repeatable.
