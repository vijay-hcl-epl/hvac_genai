# SWE.4 Unit Test Plan — HVAC Flap Actuator (ASPICE Level 3)

## 1. Introduction
This SWE.4 Unit Test Plan verifies each software unit (as mapped in LLD/code) in isolation, per ASPICE and project rules. Tests are derived directly from software requirements (SWE.1) and LLD responsibilities, implemented using mocks/stubs for all external interfaces (e.g., ADC, UART, GPIO/PWM). No integration testing or hardware access is performed.

## 2. Software Units (as parsed from bundle)
1. UART Command Handler
2. Flap Actuator Controller
3. Motor Control Unit
4. Position Monitoring Unit
5. LED Indication
6. System Initialization

## 6. Example Test Stubs (C, using Mock)

// Example for UART Command Handler
#include "unity.h"
#include "uart_command_handler.h"

void test_valid_command(void) {
    uart_command_handler_init();
    uart_rx_callback('4'); uart_rx_callback('2'); uart_rx_callback('\n');
    TEST_ASSERT_TRUE(is_command_ready());
    TEST_ASSERT_EQUAL(42, get_parsed_command());
    TEST_ASSERT_EQUAL(UART_CMD_OK, get_uart_cmd_status());
}

void test_invalid_command(void) {
    uart_command_handler_init();
    uart_rx_callback('x'); uart_rx_callback('\n');
    TEST_ASSERT_FALSE(is_command_ready());
    TEST_ASSERT_EQUAL(UART_CMD_ERROR, get_uart_cmd_status());
}

// Example for Motor Control Unit
#include "motor_control_unit.h"
void test_motor_move(void) {
    motor_control_init();
    move_motor_to(10, MOTOR_DIR_FWD);
    TEST_ASSERT_EQUAL(MOTOR_MOVING, get_motor_status());
    stop_motor();
    TEST_ASSERT_EQUAL(MOTOR_STOPPED, get_motor_status());
}

## 7. Isolation/Execution Notes
- All HW/driver calls MUST be mocked (ADC, UART, GPIO, PWM).
- Each test must be deterministic, self-checking, and repeatable.
- Never call or require actual hardware/MCU.
- Test code organization should follow one test file per unit.
