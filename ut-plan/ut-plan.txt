# SWE.4 – Unit Test Plan

## Traceability to Requirement

| Requirement ID    | Requirement Text                                                                                       | Software Units Under Test                |
|-------------------|-------------------------------------------------------------------------------------------------------|------------------------------------------|
| SWE-REQ-001       | The software SHALL process all input and output signals exclusively via the defined electrical interfaces specified in the system-level signal list. | All (listed below)                       |

---

## 1. Introduction

This SWE.4 Unit Test Plan establishes and documents unit-level tests for all identified software units in the HVAC Door System as required by SWE-REQ-001. Each test is directly traceable to the requirement to demonstrate compliance per ASPICE Level 3.

---

### 3.1 command_interface

| Test Case ID | Objective                                     | Test Description                                                                  | Input(s)          | Expected Output / Result           | SWE-REQ Trace |
|--------------|-----------------------------------------------|-----------------------------------------------------------------------------------|-------------------|-----------------------------------|---------------|
| CI_TC_01     | Initialization                                | Initialize the command interface                                                  | None              | No error, proper initial state    | SWE-REQ-001   |
| CI_TC_02     | Valid UART Command                            | Simulate valid command on UART, check acceptance                                  | Valid UART frame  | get_validated_command = true      | SWE-REQ-001   |
| CI_TC_03     | Invalid UART Data                             | Feed noise/corrupted data, ensure rejection                                       | Corrupt frame     | get_validated_command = false     | SWE-REQ-001   |
| CI_TC_04     | Boundary Condition: Empty Command             | Submit empty/no-op command, check for no processing                               | NULL/boundary cmd | No processing occurs              | SWE-REQ-001   |

## 4. Coverage and Justification

This test plan ensures:
- All public APIs are exercised.
- Each module’s input/output interfaces are validated (per SWE-REQ-001).
- Nominal, boundary, invalid, and error-handling scenarios are tested.
- Traceability is maintained for ASPICE compliance.
