# SWE.4 Unit Test Plan for HVAC Flap Actuator Software

## 1. Software Units (from LLD & Code Structure)

| Unit Name             | Header                      | Source                      | Public APIs / Main Functions          | Responsibility                   |
|----------------------|-----------------------------|-----------------------------|---------------------------------------|-----------------------------------|
| Main Control Coordinator | code/inc/main_coordinator.h | code/src/main_coordinator.c | coordinator_init(), coordinator_main_loop() | Overall control, state machine   |
| UART Command Handler     | code/inc/uart_cmd_handler.h | code/src/uart_cmd_handler.c | uart_cmd_init(), uart_cmd_get()            | Parse UART, validate commands    |
| Motor Control            | code/inc/motor_control.h    | code/src/motor_control.c    | motor_control_init(), motor_move_to(), motor_stop() | GPIO/PWM for actuator           |
| Feedback Processor       | code/inc/feedback_processor.h| code/src/feedback_processor.c| feedback_processor_init(), feedback_get_position() | ADC, map feedback               |
| LED Control              | code/inc/led_control.h      | code/src/led_control.c      | led_control_init(), led_update()              | Update status/position LEDs      |

## 3. Detailed Test Cases

#### Responsibilities (LLD/LUT): Control flow, state switch, error recovery, invokes subunits

| ID      | SW-REQ      | Objective                              | Pre-conditions      | Input                         | Expected Result                                     | Pass/Fail Criteria  |
|---------|-------------|----------------------------------------|---------------------|-------------------------------|----------------------------------------------------|--------------------|
| TC-MC-001 | SWE-REQ-020,021,022 | Startup/init flows        | Power-on/reset state | None                          | All subunits' init functions called, system enters IDLE, motor off | Monitored via mocks, no HW |
| TC-MC-002 | SWE-REQ-004,005     | Valid/invalid move command| IDLE state           | valid/invalid UART command    | On valid: MOVING state, motor_move_to() called; On invalid: Stay IDLE | State trace, API call log  |

## 5. Isolation & Environment
- All hardware interactions (ADC, GPIO, UART, PWM, TIM) must be mocked/stubbed.
- No integration/hardware-in-the-loop.
- Each unit test must be deterministic and repeatable.
