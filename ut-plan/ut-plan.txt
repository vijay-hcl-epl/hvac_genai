# ASPICE SWE.4 Unit Test Plan - HVAC Flap Actuator (Branch: alag-132d)

## 1. Software Units Under Test
1. UART Command Interface (`uart_cmd_if.c/h`)
2. Command Processor (`cmd_proc.c/h`)
3. Flap Position Controller (`flap_pos_ctrl.c/h`)
4. Motor Control (`motor_ctrl.c/h`)
5. Position Feedback Acquisition (`pos_fb_acq.c/h`)
6. LED Status Provider (`led_stat.c/h`)
7. HW Abstraction Layer (`hal_*`)

## 2. Unit-wise Test Cases

### 2.1 UART Command Interface
**Responsibilities:**
- Parse position commands from UART (0-5)
- Reject invalid or out-of-range input
- Provide parsed command to application
**Allocated SW-REQs:** SWE-REQ-001, 002, 014

| Test Case ID | SW-REQ | Test Objective                        | Preconditions        | Input                 | Expected Result             | Pass/Fail Criteria      |
|--------------|--------|---------------------------------------|----------------------|-----------------------|-----------------------------|-------------------------|
| TC-UART-001  | 001    | Accept valid command ('3')            | Idle                 | UART='3\r'            | parsed_cmd=3, available=1   | Command available = PASS|
| TC-UART-002  | 002    | Ignore out-of-range ('9')             | Idle                 | UART='9\r'            | parsed_cmd=INVALID, avail=0 | Not available = PASS    |
| TC-UART-003  | 014    | Input buffer overflow                  | Receiving            | >8 valid chars        | State reset, no parse       | Not available = PASS    |
| TC-UART-004  | 002    | Invalid char input                     | Idle                 | 'a\r'                 | State reset, no parse       | Not available = PASS    |

### 2.2 Command Processor
**Responsibilities:** Ensure single active cmd, initiate flap movement, ignore when busy.
**Allocated SW-REQs:** SWE-REQ-003, 022

| Test Case ID | SW-REQ | Test Objective                 | Preconditions        | Input                            | Expected Result     | Pass/Fail Criteria          |
|--------------|--------|--------------------------------|----------------------|----------------------------------|---------------------|-----------------------------|
| TC-CMD-001   | 003    | Accept valid command when idle | IDLE, UART avail     | cmd=4                            | State->IN_PROGRESS  | State change = PASS         |
| TC-CMD-002   | 003    | Reject command when busy       | IN_PROGRESS          | Any                              | No state change     | Remains busy = PASS         |
| TC-CMD-003   | 022    | Complete on movement done      | IN_PROGRESS, done    | flap_pos_ctrl_movement_complete()| State->IDLE         | State change = PASS         |

### 2.7 HW Abstraction Layer

**Allocated SW-REQs:** SWE-REQ-016, 017

| Test Case ID  | SW-REQ | Test Objective              | Preconditions  | Input                  | Expected Result         | Pass/Fail Criteria |
|---------------|--------|-----------------------------|----------------|------------------------|------------------------|--------------------|
| TC-HAL-001    | 016    | Provide deterministic stub  | Any            | API call               | Return mock/stub value | Mock/stub return   |
| TC-HAL-002    | 017    | Handle hardware failure     | Any            | Error code injected    | API error code         | Deterministic      |

## 3. Isolation Rules
- All HAL (ADC, GPIO, PWM, UART) APIs must be mocked.
- No tests interact with real hardware. No integration tests.
- Each unit test is deterministic and repeatable.
