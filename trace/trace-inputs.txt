1.0 System Overview

The HVAC Flap Actuator System is a microcontroller-based proof-of-concept (POC) intended to control an air flap, similar to those used in automotive heating, ventilation, and air conditioning systems. The system enables the user to command the position of the flap (via UART), actuate the flap using a DC motor controlled by the microcontroller, and provide position feedback through a potentiometer wired to an ADC. Visual feedback is provided through LEDs. All interfaces and logic are implemented for demonstration, learning, and ASPICE Level 3 software process compliance.

2.0 Flap Position Control Requirements

SYS-REQ-001: The system shall allow the user to command a discrete flap position within the supported range (0-5).
SYS-REQ-002: The system shall compare the current flap position to the user-commanded target position.
SYS-REQ-003: The system shall move the flap to the commanded target position when a valid command is received.
SYS-REQ-004: The system shall stop actuating the flap once the commanded position is reached.
SYS-REQ-005: The system shall monitor the current flap position continuously while actuating toward the commanded position.
SYS-REQ-006: [Implied] The system shall reject position commands outside the valid range without changing the flap position.

3.0 Motor Control Requirements

SYS-REQ-007: The system shall control the DC motor to rotate the flap in both clockwise and counter-clockwise directions as necessary.
SYS-REQ-008: The system shall drive motor enable and direction lines using GPIO pins.
SYS-REQ-009: The system shall use PWM to enable or disable the motor and to control speed if required.
SYS-REQ-010: The system shall stop the motor when the target position is reached or if position feedback is out of expected range.
SYS-REQ-011: [Implied] The system shall ensure the motor is off at power up and during idle states.

4.0 Position Feedback Acquisition and Processing

SYS-REQ-012: The system shall acquire flap position using a potentiometer mechanically linked to the flap.
SYS-REQ-013: The system shall acquire potentiometer signals through an ADC channel on the microcontroller.
SYS-REQ-014: The system shall map ADC readings to logical flap position values (0-5) with defined ADC threshold ranges.
SYS-REQ-015: The system shall continuously update the current flap position value.
SYS-REQ-016: [Implied] The system shall ignore ADC readings outside valid calibrated ranges and stop the motor in such cases.

5.0 User Command Interface Requirements

SYS-REQ-017: The system shall receive user commands through a UART interface.
SYS-REQ-018: The system shall interpret received commands as numeric values representing target flap positions.
SYS-REQ-019: The system shall validate incoming UART commands and accept only commands representing valid flap positions (0-5).
SYS-REQ-020: The system shall ignore invalid UART commands (outside 0-5 or non-numeric) without responding or changing the flap position.
SYS-REQ-021: [Implied] The user commands shall be processed promptly after being received on UART.

6.0 Status Indication Requirements

SYS-REQ-022: The system shall provide a visual indication (LED) that power is on and the system is operational.
SYS-REQ-023: The system shall indicate the current logical flap position using a dedicated green LED for each possible flap position (0-5).
SYS-REQ-024: The system shall have at most one green LED active at any time to reflect the current flap position.
SYS-REQ-025: LED indications may be updated upon position change or at a regular refresh rate to appear responsive.
SYS-REQ-026: [Implied] LED behavior shall remain simple and unambiguous.

7.0 System Behavioral Requirements

SYS-REQ-027: On power-up, the system shall initialize all required peripherals (ADC, UART, GPIO, PWM).
SYS-REQ-028: On power-up, the system shall read the current flap position from the potentiometer.
SYS-REQ-029: On power-up, the system shall ensure the motor is not energized.
SYS-REQ-030: The system shall enter idle mode after initialization and wait for user command.
SYS-REQ-031: The system shall begin moving the flap toward the configured position as soon as a valid command is received.
SYS-REQ-032: The system shall stop moving the flap once the target position is reached, transition to position-holding mode, and update status LEDs.
SYS-REQ-033: The system shall ignore and safely handle invalid or out-of-range commands or feedback values, ensuring safe states (motor off, status LEDs consistent).
SYS-REQ-034: [Implied] The system shall follow a logical sequence of behaviors: initialize → idle → process command → move flap → hold position.

8.0 System Interface Requirements

SYS-REQ-035: The system shall use a UART hardware module to interface with a PC for receiving commands.
SYS-REQ-036: The system shall use GPIO outputs to drive the L298N motor driver control pins.
SYS-REQ-037: The system shall use an ADC input to acquire the potentiometer signal.
SYS-REQ-038: The system shall use GPIO outputs to drive status and position LEDs.
SYS-REQ-039: [Implied] PWM resources (timer) shall be used for motor enable and speed control as required.

9.0 Constraints and Assumptions

SYS-REQ-040: Only one flap and one DC motor shall be present in the system.
SYS-REQ-041: Only one user command shall be processed at a time.
SYS-REQ-042: ADC-to-position mapping/calibration values shall be defined in software and considered fixed for operation.
SYS-REQ-043: No homing or automatic calibration procedure shall be implemented in this version.
SYS-REQ-044: [Implied] Hardware is assumed to function correctly; error handling and recovery requirements are minimal.
SYS-REQ-045: [Implied] No network (CAN, LIN, etc.) or diagnostics features are included.

10.0 Non-Functional Requirements
10.1 Responsiveness Expectations

SYS-REQ-046: The system shall process UART commands promptly, with observable responsiveness to the user.
SYS-REQ-047: ADC readings and feedback processing shall be performed at intervals sufficient for correct operation (no hard real-time constraints).

10.2 Error Handling and Edge Cases

SYS-REQ-048: Invalid UART commands shall be ignored without system disruption.
SYS-REQ-049: If ADC readings are out of valid ranges, the system shall stop the motor and hold position.
SYS-REQ-050: If the motor does not reach or cannot reach the target flap position, the system shall not crash (no system resets or lock-ups).
SYS-REQ-051: [Implied] No timeout or advanced diagnostic/error reporting is required in this POC version.

10.3 Resource Constraints

SYS-REQ-052: The software implementation shall avoid unnecessary resource usage to remain lightweight and compatible with the selected microcontroller.
SYS-REQ-053: The system shall avoid dynamic memory allocation and prefer a static configuration (MISRA style).

10.4 Maintainability and Modularity

SYS-REQ-054: The system design and requirements shall support clarity of function, modularity, and ease of understanding.

10.5 Testability

SYS-REQ-055: The system shall support manual and scripted testing through the UART command interface, visual inspection of LEDs, and observation of the flap and motor responses.

Architecture-Relevant Considerations Derived from System Requirements

- The system operates in a single, simple control loop with one actuator, one sensor, and simple command processing, all local to the microcontroller.
- There are no concurrency or multi-threading needs; control logic is sequential.
- All external interfaces (UART, ADC, GPIO) are direct and MCU-hosted; network/process partitioning is not present.
- Expandability (e.g., multiple actuators, bus/networking, diagnostics) is not required or expected for this prototype.
- Simplicity and clarity are prioritized to serve as a training/learning and process-compliance demonstration.
