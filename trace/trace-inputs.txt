# HVAC Flap Actuator: System-Level Requirements

## 1.0 System Overview

SYS-REQ-001: The system SHALL control a single HVAC air flap using a DC motor based on user commands received via UART.
SYS-REQ-002: The system SHALL measure the flap’s position using a potentiometer connected to an ADC channel.
SYS-REQ-003: The system SHALL provide visual feedback of system status and flap position using LEDs.
SYS-REQ-004: The system SHALL ignore communication with vehicle networks (e.g., CAN, LIN).
[Implied] SYS-REQ-005: The system SHALL not require any dynamic calibration or network-based diagnostics.

---

## 2.0 Flap Position Control

SYS-REQ-006: The system SHALL move the flap to a commanded discrete target position (0–5), provided via UART.
SYS-REQ-007: The system SHALL only accept one user command at a time.
SYS-REQ-008: The system SHALL immediately stop the DC motor after reaching the target position.
[Implied] SYS-REQ-009: The system SHALL not overshoot past the commanded position by more than 1 logical step.

---

## 3.0 Motor Control

SYS-REQ-010: The system SHALL control the rotation direction of the DC motor (clockwise/anti-clockwise) to achieve flap movement as required.
SYS-REQ-011: The system SHALL use GPIO outputs to control the motor driver (L298N).
SYS-REQ-012: The system SHALL use a PWM signal to control motor enable and speed.
SYS-REQ-013: The system SHALL switch off the motor while idle, on power-up, or once the target position is achieved.
[Implied] SYS-REQ-014: The system SHALL limit the maximum motor speed to a safe value for all movements.

---

## 4.0 Position Feedback Acquisition & Processing

SYS-REQ-015: The system SHALL use the ADC to continuously acquire the potentiometer output signal.
SYS-REQ-016: The system SHALL convert ADC values to corresponding logical flap positions (0–5) using pre-defined, fixed software calibration values.
SYS-REQ-017: The system SHALL verify that ADC readings are within valid calibrated bounds before using them for control.
[Implied] SYS-REQ-018: If ADC readings are outside valid range, the system SHALL halt any ongoing motor movement.

---

## 5.0 User Command Interface

SYS-REQ-019: The system SHALL receive target position commands as integer values (0–5) over UART from the user.
SYS-REQ-020: The system SHALL ignore any command that is outside the 0–5 range.
SYS-REQ-021: The system SHALL not send any acknowledgment or error message for invalid user commands.
[Implied] SYS-REQ-022: The system SHALL process user commands in the order they are received, if sequential commands are issued.

---

## 6.0 Status Indication

SYS-REQ-023: The system SHALL use a status indicator LED to show that it is powered on.
SYS-REQ-024: The system SHALL indicate the current logical flap position using a dedicated LED for each position.
SYS-REQ-025: At most one (1) green flap position LED SHALL be illuminated at a time.
SYS-REQ-026: The status LED SHALL be turned ON throughout normal operation.
[Implied] SYS-REQ-027: The state of position LEDs SHALL be updated immediately after change in flap position.

---

## 7.0 System Behavior (power-up, idle, normal, target reached, invalid input)

SYS-REQ-028: On power-up, the system SHALL initialize all required peripherals (ADC, UART, GPIO, PWM).
SYS-REQ-029: On power-up, the motor SHALL remain OFF until a valid command is received.
SYS-REQ-030: The system SHALL read and display the current flap position on the relevant LED after initialization.
SYS-REQ-031: During idle, the system SHALL monitor UART for user commands or process ongoing movement if in progress.
SYS-REQ-032: The system SHALL stop the motor and hold the flap at the last valid target position after movement is completed.
SYS-REQ-033: If an invalid command is received, the system SHALL ignore it without changing state.
[Implied] SYS-REQ-034: The system SHALL not enter any undefined or unsafe state as a result of invalid input.

---

## 8.0 Interfaces (UART, motor driver, ADC, LEDs)

SYS-REQ-035: The system SHALL use UART to receive user flap position commands.
SYS-REQ-036: The system SHALL use GPIOs and PWM to control the DC motor driver.
SYS-REQ-037: The system SHALL use an ADC channel to acquire potentiometer values reflecting flap position.
SYS-REQ-038: The system SHALL use dedicated GPIOs to control LEDs for status and position.
[Implied] SYS-REQ-039: The system SHALL not require communication with external networks (CAN/LIN/etc.)

---

## 9.0 Constraints & Assumptions

SYS-REQ-040: The system SHALL assume only one HVAC flap and corresponding actuator are present.
SYS-REQ-041: The system SHALL assume hardware (motor, ADC, potentiometer, LEDs) is functioning as intended.
SYS-REQ-042: The system SHALL assume only one command is processed at a time; concurrent commands are not supported.
[Implied] SYS-REQ-043: The system SHALL rely on statically configured calibration values for ADC-to-position mapping.

---

## 10.0 Non-Functional Requirements

### 10.1 Responsiveness
SYS-REQ-044: The system SHALL respond to user commands such that perceivable delay is minimized to human users.
[Implied] SYS-REQ-045: No strict real-time requirements are imposed; system responsiveness must be user-acceptable.

### 10.2 Error Handling & Edge Cases
SYS-REQ-046: The system SHALL halt motor activity if ADC readings fall outside valid calibrated ranges.
SYS-REQ-047: The system SHALL remain functional if the target position is not achieved immediately (e.g., if flap is obstructed), but no advanced recovery is required.
[Implied] SYS-REQ-048: The system SHALL not attempt to implement fault recovery or diagnostics in case of hardware error.

### 10.3 Resource Constraints
SYS-REQ-049: The system SHALL not use dynamic memory allocation at any time.
[Implied] SYS-REQ-050: The system SHALL operate within STM32F407G-DISC1 hardware resource limits.

### 10.4 Maintainability & Modularity
SYS-REQ-051: The system SHALL organize functionalities (position acquisition, motor control, command parsing, indication) into separate, testable units.
[Implied] SYS-REQ-052: Changes in logical position count or calibration values SHALL be possible via software parameters.

### 10.5 Testability
SYS-REQ-053: The system SHALL allow manual and scripted UART-based testing for all supported flap positions and behaviors.
SYS-REQ-054: The system SHALL enable testing through observation of flap movement and visual LED indication corresponding to commanded positions.
[Implied] SYS-REQ-055: No automated HIL/SIL test hooks are required.

---

## Architecture-Relevant Considerations Derived from System Requirements

- **Concurrency presence/absence:** The system is single-actuator, single-command-at-a-time and does not require concurrent task handling.
- **Interaction complexity:** Interactions between modules (command input, motor control, acquisition, and indication) are simple, sequential, and mutually exclusive.
- **Control complexity:** The control loop is straightforward: receive command → actuate motor → monitor position → stop at target. No dynamic calibration or advanced diagnostics are in scope.
- **Expandability:** The requirements support extension to more positions or calibration points by updating software or configuration, but do not anticipate multiple flaps or users.
