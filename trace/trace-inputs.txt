1.0 System Overview

The HVAC Flap Actuator System is a microcontroller-based prototype designed to control the position of a vehicle air flap used in HVAC (Heating, Ventilation, and Air Conditioning) applications. The system moves the flap to discrete positions on user command, monitors flap position using a potentiometer, drives a DC motor via an H-Bridge driver, indicates status through LEDs, and communicates using UART with a PC interface. This implementation demonstrates embedded control, user-commanded actuation, status feedback, and basic error handling for learning and software process demonstration purposes.

2.0 Flap Position Control Requirements

SYS-REQ-001: The system shall allow the user to select a target flap position through a UART command interface.
SYS-REQ-002: The system shall compare the commanded target flap position to the current position at the system level.
SYS-REQ-003: The system shall actuate the flap such that the flap is moved to the selected target position.
SYS-REQ-004: The system shall hold the flap in the achieved target position after movement is complete.
SYS-REQ-005: The system shall support at least 6 discrete flap positions as defined in the high-level requirements (positions 0 to 5).
SYS-REQ-006: The system shall allow repeated position commands and respond to each valid command.
SYS-REQ-007: [Implied] If the target position matches the current position, the motor shall not be activated.

3.0 Motor Control Requirements

SYS-REQ-008: The system shall control motor direction (clockwise/counterclockwise) to increase or decrease the flap position as needed.
SYS-REQ-009: The system shall enable or disable the DC motor as required to perform flap actuation.
SYS-REQ-010: The system shall stop the motor when the target flap position is reached.
SYS-REQ-011: [Implied] The system shall stop the motor if the current position signal is invalid or out-of-range.
SYS-REQ-012: [Implied] The system shall ensure the motor starts from a stopped state at power-up.

4.0 Position Feedback Acquisition and Processing

SYS-REQ-013: The system shall acquire flap position feedback using a potentiometer connected to an ADC channel.
SYS-REQ-014: The system shall convert/quantize ADC values to logical flap positions as defined by fixed ranges in software.
SYS-REQ-015: The system shall continuously monitor and process potentiometer/ADC feedback while powered.
SYS-REQ-016: [Implied] The system shall detect and handle ADC readings outside the defined calibration ranges.
SYS-REQ-017: [Implied] The system shall not require dynamic calibration or self-learning for position mapping.

5.0 User Command Interface Requirements

SYS-REQ-018: The system shall receive and process flap position commands (numeric 0–5) from a UART interface.
SYS-REQ-019: The system shall validate UART commands and only accept numeric values corresponding to supported positions.
SYS-REQ-020: The system shall ignore and not act on invalid commands; no acknowledgment or error message shall be sent in response to invalid commands.
SYS-REQ-021: [Implied] The system shall process one command at a time.
SYS-REQ-022: [Implied] The system shall not require advanced protocol or error correction on the UART interface.

6.0 Status Indication Requirements

SYS-REQ-023: The system shall control a status LED to indicate system power ON state.
SYS-REQ-024: The system shall use dedicated LEDs to indicate the current logical flap position.
SYS-REQ-025: The system shall ensure only one green LED corresponding to the current position is ON at any one time.
SYS-REQ-026: [Implied] The system shall update LEDs to reflect the detected (not just commanded) position.

7.0 System Behavioral Requirements

SYS-REQ-027: The system shall initialize all peripherals (ADC, UART, GPIO, PWM) on power-up.
SYS-REQ-028: The flap actuator motor shall remain OFF upon system power-up/initialization.
SYS-REQ-029: The system shall read and display the current flap position on LEDs at startup.
SYS-REQ-030: During idle operation (awaiting UART command), the system shall not cause unintended flap movement.
SYS-REQ-031: On receiving a valid command, the system shall actively move the flap toward the target position until reached.
SYS-REQ-032: Upon reaching the requested target position, the system shall stop actuator movement and indicate position using LEDs.
SYS-REQ-033: If an invalid or unsupported command is received, the system shall ignore it and shall not change the current system state.
SYS-REQ-034: [Implied] The system shall use a simple, easily auditable control flow suitable for process demonstration and learning.
SYS-REQ-035: [Implied] The system shall not require explicit state machine modeling beyond described behaviors.

8.0 System Interface Requirements

SYS-REQ-036: The system shall implement a UART interface (USB-UART) to receive user input from a PC.
SYS-REQ-037: The system shall interface with a DC motor driver (L298N) via GPIO and PWM for flap movement.
SYS-REQ-038: The system shall receive position feedback from a potentiometer via an ADC channel.
SYS-REQ-039: The system shall control LED indicators using GPIO outputs.
SYS-REQ-040: [Implied] The system shall not implement CAN, LIN, or other in-vehicle network interfaces.

9.0 Constraints and Assumptions

SYS-REQ-041: The system shall be designed to control a single flap, a single motor, and accept a single user command at a time.
SYS-REQ-042: It shall be assumed that all hardware components operate within their nominal specification.
SYS-REQ-043: All position calibration values shall be pre-configured and fixed in software for this demonstration.
SYS-REQ-044: The target microcontroller shall be STM32F407G-DISC1, with STM32 HAL drivers, implemented in embedded C (MISRA-style; no dynamic memory allocation).
SYS-REQ-045: [Implied] The system shall not require or implement features outside the prototype's learning and demonstration scope.

10.0 Non-Functional Requirements
10.1 Responsiveness Expectations
SYS-REQ-046: The system shall ensure that UART commands result in actuator movement within a human-perceptible short delay.

10.2 Error Handling and Edge Cases
SYS-REQ-047: The system shall ignore invalid or out-of-range user commands and not take any action in response.
SYS-REQ-048: If a feedback (ADC) value falls outside configured ranges, the system shall stop the actuator and await further commands.
SYS-REQ-049: [Implied] The system shall not crash or enter undefined operation in case of feedback or command errors.

10.3 Resource Constraints
SYS-REQ-050: The system implementation shall be lightweight and ensure resource usage is predictable and bounded.

10.4 Maintainability and Modularity
SYS-REQ-051: The requirements and implementation shall maintain clear separation of concerns and logical modularity for learning and demonstration.

10.5 Testability
SYS-REQ-052: The system shall support testability by observation of LEDs, actuator position, and UART command handling.
SYS-REQ-053: The system shall be verifiable by manual and script-based test cases.

Architecture-Relevant Considerations Derived from System Requirements

- The system is single-responsibility and is expected to be simple and linear in control logic.
- All interactions are local: there is no vehicle network communication or concurrency with other control domains.
- Direct command-control-response: system responses are direct and observable, with minimal asynchrony.
- The use of discrete states and simple command handling means the architecture can avoid complexity related to multitasking or real-time operating systems.
- The prototype is intended to be easily expandable for demonstration, but does not require architectural extensibility for production.
