1.0 System Overview

The HVAC Flap Actuator system is a microcontroller-based prototype designed to control the rotational position of an HVAC air flap. The system enables a user to command the flap position using UART commands and provides feedback via LEDs. Flap position is sensed with a potentiometer and controlled by a DC motor through a motor driver. The system is for learning and software process demonstration and is not intended for production use.

2.0 Flap Position Control Requirements

SYS-REQ-001: The system shall allow a user to command a target flap position by UART command.
SYS-REQ-002: The system shall move the flap to the commanded target position.
SYS-REQ-003: The system shall monitor the current flap position using a potentiometer.
SYS-REQ-004: The system shall stop the motor once the commanded position is reached.
SYS-REQ-005 [Implied]: The system shall allow movement between all supported discrete flap positions.

3.0 Motor Control Requirements

SYS-REQ-006: The system shall control the DC motors direction via dedicated GPIO pins.
SYS-REQ-007: The system shall enable or disable the motor using a PWM-controlled enable signal.
SYS-REQ-008: The system shall stop the motor when the flap has reached the commanded position.
SYS-REQ-009: The system shall stop the motor if an invalid user command is received.
SYS-REQ-010: The system shall stop the motor if the potentiometer/ADC value is out of the defined range.
SYS-REQ-011 [Implied]: The system shall not energize the motor at power up.

4.0 Position Feedback Acquisition and Processing

SYS-REQ-012: The system shall acquire the flap position using an ADC channel connected to the potentiometer.
SYS-REQ-013: The system shall map ADC readings to logical flap positions (05) as defined by software calibration.
SYS-REQ-014: The system shall process and interpret ADC values only within the calibrated valid range.
SYS-REQ-015 [Implied]: The system shall periodically acquire ADC readings and update the current position.

5.0 User Command Interface Requirements

SYS-REQ-016: The system shall accept user commands exclusively via a UART interface.
SYS-REQ-017: The system shall interpret numeric UART commands (05) as target flap positions.
SYS-REQ-018: The system shall ignore user commands outside the valid range (e.g., not 05).
SYS-REQ-019: The system shall not produce any UART output in response to valid or invalid commands.
SYS-REQ-020 [Implied]: The system shall not process a new command until processing of a previous command is completed.

6.0 Status Indication Requirements

SYS-REQ-021: The system shall illuminate a power/status LED when the system is powered on.
SYS-REQ-022: The system shall use one green LED to indicate the current flap position; at most one green LED shall be ON at any given time.
SYS-REQ-023 [Implied]: Green LED indication shall promptly reflect the latest detected position.

7.0 System Behavioral Requirements

SYS-REQ-024: On power-up, the system shall initialize all peripherals (ADC, UART, GPIO, PWM) and set the motor to OFF.
SYS-REQ-025: On power-up, the system shall acquire the current flap position and indicate it on the corresponding green LED.
SYS-REQ-026: When idle, the system shall wait for valid user commands via UART.
SYS-REQ-027: When a valid command to move is received, the system shall move the flap to the target position and, upon arrival, stop the motor and update the LED indication.
SYS-REQ-028: If an invalid UART command is received, the system shall ignore the command and not alter flap position or indication.
SYS-REQ-029: If ADC/potentiometer values are out of range, the system shall stop the motor until valid feedback is restored.
SYS-REQ-030: The system shall not enter undefined or unsafe states in response to unexpected input or feedback.
SYS-REQ-031 [Implied]: The system shall not attempt position "homing" or calibration at power up.

8.0 System Interface Requirements

SYS-REQ-032: The system shall accept serial input commands from a PC via a UART interface.
SYS-REQ-033: The system shall drive a DC motor through a motor driver with direction and enable/pwm control.
SYS-REQ-034: The system shall receive position feedback from a potentiometer via an ADC input.
SYS-REQ-035: The system shall drive LEDs using GPIO for status and position indication.
SYS-REQ-036 [Implied]: The system shall interface only with the devices described above; no external vehicle networking is supported.

9.0 Constraints and Assumptions

SYS-REQ-037: The system shall operate a single HVAC flap actuator.
SYS-REQ-038: Hardware is assumed to function correctly; no advanced diagnostics are required.
SYS-REQ-039: Only one command shall be processed at a time.
SYS-REQ-040: ADC position ranges are considered fixed in software; no dynamic calibration is performed.
SYS-REQ-041 [Implied]: The prototype is strictly for software process demonstration and learning, not production deployment.

10.0 Non-Functional Requirements

10.1 Responsiveness Expectations
SYS-REQ-042: The system shall respond to user UART commands with a response time perceptible as quick to a human user.

10.2 Error Handling and Edge Cases
SYS-REQ-043: The system shall ignore invalid UART commands and not alter system state.
SYS-REQ-044: The system shall immediately stop the motor if potentiometer feedback falls outside the valid range.

10.3 Resource Constraints
SYS-REQ-045: The system shall be implemented in a lightweight and predictable manner without resource-intensive constructs.

10.4 Maintainability and Modularity
SYS-REQ-046: The system shall demonstrate clear and modular organization to simplify understanding and modification.

10.5 Testability
SYS-REQ-047: The system shall provide observable feedback via LEDs and UART reception for manual or scripted verification of behavior.
SYS-REQ-048: The system shall be designed such that all requirements can be directly or indirectly verified by test.

Architecture-Relevant Considerations Derived from System Requirements

- The system has a single main control responsibility (single flap/motor/user interface).
- All external interactions are local (UART, ADC, GPIO, PWM) and direct; no external network or multitasking.
- Simplicity is favored: command-response is linear, and no concurrent process requirements are imposed.
- The system is expected to be expanded or reconfigured easily for learning/demo; modularity and clear separation of interface logic are helpful.
- The control logic is simple state-driven, with linear event progression and no explicit asynchronous complexity.

# 1.0 Software Scope and Responsibility

The software for the HVAC Flap Actuator system executes on a microcontroller. Its responsibility is to receive user commands via UART, control and monitor a DC motor to achieve the commanded HVAC flap position using feedback from a potentiometer (ADC), and provide status feedback via LEDs. The software is responsible for all logic, control, and data processing required to implement the system-level requirements, excluding any architectural, scheduling, or hardware diagnostic details.

# 2.0 Software Functional Requirements

## 2.1 User Command Handling

**SWE-REQ-001** The software shall receive user commands exclusively via the UART interface. (SYS-REQ-016, SYS-REQ-032)

**SWE-REQ-002** The software shall validate received user commands and accept only numeric values corresponding to supported flap positions (0–5). (SYS-REQ-017, SYS-REQ-018)

**SWE-REQ-003** The software shall ignore user commands outside the valid range and not change system state in response. (SYS-REQ-018, SYS-REQ-028, SYS-REQ-043)

**SWE-REQ-004** The software shall interpret valid numeric UART commands as target flap positions. (SYS-REQ-017)

**SWE-REQ-005** The software shall not generate any UART output in response to user commands. (SYS-REQ-019)

**SWE-REQ-006 [Implied]** The software shall not process a new command until the current command execution is complete. (SYS-REQ-020, SYS-REQ-039)

## 2.2 Flap Position Control Logic

**SWE-REQ-007** The software shall store and track the current detected flap position, as determined from ADC feedback. (SYS-REQ-003, SYS-REQ-025, SYS-REQ-034)

**SWE-REQ-008** The software shall command the motor to move the flap to the position specified by the most recent valid user command. (SYS-REQ-002, SYS-REQ-027)

**SWE-REQ-009** The software shall evaluate the current detected position until it matches the commanded target position. (SYS-REQ-027)

**SWE-REQ-010** Upon reaching the commanded position, the software shall stop the motor. (SYS-REQ-004, SYS-REQ-008, SYS-REQ-027)

**SWE-REQ-011 [Implied]** The software shall support movement between all supported discrete flap positions. (SYS-REQ-005)

## 2.3 Motor Control Logic

**SWE-REQ-012** The software shall generate GPIO control signals for motor direction and PWM control signals for motor enable as required. (SYS-REQ-006, SYS-REQ-007, SYS-REQ-033)

**SWE-REQ-013** The software shall stop the motor if an invalid command is received. (SYS-REQ-009)

**SWE-REQ-014** The software shall stop the motor if position feedback (ADC value) falls outside the defined valid range. (SYS-REQ-010, SYS-REQ-029, SYS-REQ-044)

**SWE-REQ-015 [Implied]** The software shall ensure the motor is not energized at power up. (SYS-REQ-011, SYS-REQ-024)

## 2.4 Position Feedback Processing

**SWE-REQ-016** The software shall acquire position feedback from a potentiometer using an ADC channel. (SYS-REQ-003, SYS-REQ-012, SYS-REQ-034)

**SWE-REQ-017** The software shall map raw ADC values to logical flap positions (0–5) using calibration constants. (SYS-REQ-013)

**SWE-REQ-018** The software shall interpret only ADC values that fall within the defined valid calibrated range. (SYS-REQ-014)

**SWE-REQ-019 [Implied]** The software shall periodically acquire and process ADC values to maintain up-to-date position tracking, where the period is not fixed by requirement. (SYS-REQ-015)

## 2.5 Status Indication Control

**SWE-REQ-020** The software shall activate a power/status LED when the system is powered on. (SYS-REQ-021)

**SWE-REQ-021** The software shall illuminate a single green LED to indicate the currently sensed flap position, ensuring only one green LED is ON at any one time. (SYS-REQ-022)

**SWE-REQ-022 [Implied]** The software shall update green LED indication promptly to reflect the last detected position. (SYS-REQ-023)

# 3.0 Software Interface Requirements

**SWE-REQ-023** The software shall manage UART communications for the exclusive purpose of receiving user position commands. (SYS-REQ-016, SYS-REQ-032)

**SWE-REQ-024** The software shall acquire analog position signals from a potentiometer using an ADC interface. (SYS-REQ-012, SYS-REQ-034)

**SWE-REQ-025** The software shall generate commands to the motor driver using GPIO (for direction) and PWM (for motor enable/disable). (SYS-REQ-006, SYS-REQ-007, SYS-REQ-033)

**SWE-REQ-026** The software shall control LED outputs using GPIO. (SYS-REQ-021, SYS-REQ-022, SYS-REQ-035)

**SWE-REQ-027 [Implied]** The software shall only use UART, ADC, GPIO, and PWM interfaces for all its interactions; no other external interfaces are accessed. (SYS-REQ-036)

# 4.0 Software Behavioral Requirements

**SWE-REQ-028** On system startup, the software shall initialize UART, ADC, GPIO, and PWM interfaces and configure the motor control to the OFF state. (SYS-REQ-024, SYS-REQ-015, SYS-REQ-011)

**SWE-REQ-029** On startup, the software shall acquire and display the current flap position via the green LEDs before awaiting UART input. (SYS-REQ-025)

**SWE-REQ-030** While idle, the software shall continuously listen for new valid UART commands and process them when received. (SYS-REQ-026)

**SWE-REQ-031** After receiving and validating a command to move, the software shall control the motor to move the flap and update indications upon arrival. (SYS-REQ-027)

**SWE-REQ-032** The software shall not alter the flap position or LED display in response to invalid UART commands. (SYS-REQ-028, SYS-REQ-043)

**SWE-REQ-033** If ADC values are out of range, the software shall stop the motor until valid feedback resumes. (SYS-REQ-029, SYS-REQ-044)

**SWE-REQ-034** The software shall maintain safe and defined system states at all times, independent of the order or timing of command arrivals. (SYS-REQ-030)

**SWE-REQ-035 [Implied]** The software shall not perform automatic “homing” or calibration operations on startup. (SYS-REQ-031)

# 5.0 Software Data and Configuration Requirements

**SWE-REQ-036** The software shall store a fixed mapping from ADC values to logical flap positions using configurable constants. (SYS-REQ-013, SYS-REQ-040)

**SWE-REQ-037** The software shall use ADC threshold/configuration constants set in software and not alter them at runtime. (SYS-REQ-040)

**SWE-REQ-038** The software shall maintain in-memory variables for current commanded and detected positions. (SYS-REQ-007, SYS-REQ-039)

**SWE-REQ-039 [Implied]** The software shall not implement dynamic calibration of ADC or position mapping at runtime. (SYS-REQ-040)

# 6.0 Software Error Handling Requirements

**SWE-REQ-040** Upon receipt of invalid UART commands, the software shall ignore the input and not alter system state. (SYS-REQ-018, SYS-REQ-028, SYS-REQ-043)

**SWE-REQ-041** If position feedback (ADC value) is outside the configured range, the software shall immediately disable motor control actions and maintain the last valid state. (SYS-REQ-010, SYS-REQ-029, SYS-REQ-044)

**SWE-REQ-042** If a motor command cannot be executed as intended (e.g., due to feedback or logical state), the software shall leave the system in a safe, known state. (SYS-REQ-030)

# 7.0 Software Performance and Responsiveness Requirements

**SWE-REQ-043** The software shall respond to valid UART commands with a response time perceptible as “quick” to a typical user. (SYS-REQ-042)

**SWE-REQ-044** The software shall evaluate and update flap position and system status whenever new feedback or commands are available, without specifying periodicity. (SYS-REQ-027, SYS-REQ-015)

# 8.0 Software Resource Constraint Requirements

**SWE-REQ-045** The software shall be implemented in a lightweight manner without use of unbounded data structures or processing. (SYS-REQ-045)

**SWE-REQ-046** The software shall avoid reliance on dynamic memory allocation. (SYS-REQ-045)

**SWE-REQ-047** The software shall be organized to maximize maintainability and clarity. (SYS-REQ-046)

# 9.0 Software Testability Requirements

**SWE-REQ-048** The software shall support test and verification through user command input via UART and observation of system response via LED indicators. (SYS-REQ-047)

**SWE-REQ-049** The software shall be written such that all system requirements can be directly or indirectly verified through static or dynamic tests. (SYS-REQ-048)

# 10.0 Implied Software Requirements

**SWE-REQ-050 [Implied]** The software shall be designed as a process demonstration and learning tool and not for production or deployment in a vehicle. (SYS-REQ-041)

**SWE-REQ-051 [Implied]** The software shall only control a single HVAC flap actuator. (SYS-REQ-037)

**SWE-REQ-052 [Implied]** The software assumes that the underlying hardware is functioning correctly and does not provide advanced diagnostics. (SYS-REQ-038)
