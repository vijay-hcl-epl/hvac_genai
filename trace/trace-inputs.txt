# 1.0 System Overview
The HVAC Flap Actuator system is a microcontroller-based prototype that controls the position of an air-mixing flap, as used in automobile HVAC applications. The system receives user commands via UART, controls a DC motor to set the flap to one of several discrete positions, obtains position feedback using a potentiometer through the ADC, and provides system status and position indication via LEDs. Its primary purpose is learning and demonstration for embedded software processes.

# 2.0 Flap Position Control Requirements
**SYS-REQ-001:** The system shall allow the user to select a target flap position using a UART command.
**SYS-REQ-002:** The system shall compare the current flap position, as determined by the potentiometer ADC value, with the commanded position.
**SYS-REQ-003:** The system shall move the flap to the commanded target position by controlling the DC motor.
**SYS-REQ-004:** The system shall stop the motor once the flap reaches the target position.
**SYS-REQ-005:** The system shall hold the last commanded flap position until a new command is received.
**SYS-REQ-006:** [Implied] The system shall support at least the discrete positions 0 through 5 as logical target positions for the flap.

# 3.0 Motor Control Requirements
**SYS-REQ-007:** The system shall control the DC motor direction to achieve the commanded position using GPIO outputs.
**SYS-REQ-008:** The system shall enable or disable the motor using PWM and/or GPIO as appropriate for movement or holding positions.
**SYS-REQ-009:** The system shall stop the motor as soon as the target position is determined to be reached by position feedback.
**SYS-REQ-010:** [Implied] The system shall not rotate the motor beyond the defined position range.

# 4.0 Position Feedback Acquisition and Processing
**SYS-REQ-011:** The system shall acquire the potentiometer analog signal as input to an available ADC channel.
**SYS-REQ-012:** The system shall periodically sample the ADC channel to determine the current flap position.
**SYS-REQ-013:** The system shall map ADC readings to logical positions (e.g., 0-5), using predefined ADC value ranges for each position.
**SYS-REQ-014:** [Implied] The system shall validate the ADC reading range at power-up and during operation.

# 5.0 User Command Interface Requirements
**SYS-REQ-015:** The system shall accept user commands for flap positions through the UART interface.
**SYS-REQ-016:** The system shall validate each UART command to ensure it represents a valid position (0-5) and is correctly formatted.
**SYS-REQ-017:** The system shall ignore invalid or unrecognized commands without sending an acknowledgment.
**SYS-REQ-018:** [Implied] The system shall process only one user command at a time.

# 6.0 Status Indication Requirements
**SYS-REQ-019:** The system shall provide a power/status indicator LED that is ON while the system is powered.
**SYS-REQ-020:** The system shall provide position status by illuminating a green LED corresponding to the current flap position.
**SYS-REQ-021:** The system shall ensure no more than one green LED is illuminated at any time to represent active position.

# 7.0 System Behavioral Requirements
**SYS-REQ-022:** The system shall initialize all required peripherals (ADC, UART, GPIO, PWM) during power-up.
**SYS-REQ-023:** The system shall ensure the motor is OFF at system startup.
**SYS-REQ-024:** The system shall read and display the current flap position and indicate with the correct LED upon startup.
**SYS-REQ-025:** The system shall ignore user commands when no valid position feedback is available.
**SYS-REQ-026:** The system shall ensure idle (waiting) operation until a valid command is received.
**SYS-REQ-027:** The system shall enter normal operation, accepting user commands and moving the flap accordingly.
**SYS-REQ-028:** The system shall treat invalid input or ADC out-of-range as a stop/idle condition for safety.
**SYS-REQ-029:** [Implied] The system shall not require an explicit homing sequence at power-up.

# 8.0 System Interface Requirements
**SYS-REQ-030:** The system shall use UART for receiving user flap position commands.
**SYS-REQ-031:** The system shall use GPIO pins to control the DC motor driver for direction and enable/disable signals.
**SYS-REQ-032:** The system shall use an ADC channel for reading the potentiometer feedback.
**SYS-REQ-033:** The system shall use GPIO pins for controlling LEDs for power/status and position indication.
**SYS-REQ-034:** [Implied] The system shall use timer-based PWM to enable or disable (and optionally modulate) the motor if required.

# 9.0 Constraints and Assumptions
**SYS-REQ-035:** The system shall assume that only one flap and one motor are present and controlled.
**SYS-REQ-036:** The system shall assume only one command is processed at a time.
**SYS-REQ-037:** The system shall assume that hardware is present and working correctly for this prototype.
**SYS-REQ-038:** Calibration and ADC-to-position mapping shall be fixed in software prior to use; no dynamic calibration will be performed.

# 10.0 Non-Functional Requirements
## 10.1 Responsiveness Expectations
**SYS-REQ-039:** The system shall process UART commands and respond to user input in a manner that is responsive from a human perspective.
**SYS-REQ-040:** [Implied] No specific real-time deadline or interval is required unless explicitly stated elsewhere.

## 10.2 Error Handling and Edge Cases
**SYS-REQ-041:** The system shall ignore invalid or unrecognized UART commands with no adverse effect.
**SYS-REQ-042:** The system shall stop the motor if the potentiometer (ADC) feedback is out of valid range.
**SYS-REQ-043:** [Implied] The system shall ensure no system crash or uncontrolled state if motor movement fails; the system may simply hold last state.

## 10.3 Resource Constraints
**SYS-REQ-044:** The implementation shall avoid unnecessary use of memory or CPU and be compatible with resource limits of the STM32F407 microcontroller.
**SYS-REQ-045:** The implementation shall be predictable, with bounded delays and no dynamic allocation.

## 10.4 Maintainability and Modularity
**SYS-REQ-046:** The system architecture and requirements shall maintain clear separation of concerns between interfaces, logic, and indication for ease of understanding, modification, and demonstration.

## 10.5 Testability
**SYS-REQ-047:** The system shall provide sufficient observability of its internal state through LEDs and UART such that behavior can be manually or script-tested without special equipment.

# Architecture-Relevant Considerations Derived from System Requirements
- The system handles only one set of commands and actuator at a time (no concurrency required).
- All interfaces are local, direct, and simple (UART, ADC, GPIO, LEDs), with no complex network communication or distributed system aspects.
- Control logic is event-driven (by user commands or ADC updates), with no requirement for time-driven concurrency or task scheduling.
- Expandability assumptions (e.g., multiple actuators, networked commands, diagnostics) are not required for this scope.
- Design focus is clarity, modularity, and separation of interfaces, logic, and indication, but not for high scalability or safety.

# 1.0 Software Requirements for HVAC Flap Actuator (SWE.1)
This document covers all decomposed software-level requirements derived from the system requirements (SYS-REQ-001 to SYS-REQ-047) for the HVAC Flap Actuator system, structured for completeness and ASPICE Level 3 compliance. Each software requirement is:
- Atomic, clear, unambiguous, testable, and measurable
- Mapped to one or more originating system requirement IDs
- Expressed as a formal "shall" statement
- Free of architectural, scheduling, OS, or code-structure assumptions
- [Implied] requirements are clearly marked

## 2.0 Flap Position Command Processing
**SWE-REQ-001:** The software shall receive user commands for target flap position using the UART interface. [SYS-REQ-001, SYS-REQ-015, SYS-REQ-030]
**SWE-REQ-002:** The software shall validate each UART command to ensure it specifies a legal, in-range position (0-5). [SYS-REQ-016]
**SWE-REQ-003:** The software shall disregard and not act on any UART command that is invalid, out of range, or incorrectly formatted. [SYS-REQ-017, SYS-REQ-041]
**SWE-REQ-004:** [Implied] The software shall queue or process user commands sequentially and shall not execute more than one command at a time. [SYS-REQ-018, SYS-REQ-036]

## 3.0 Flap Positioning and State Transition
**SWE-REQ-005:** The software shall initiate a flap movement using the DC motor only if a valid new position command is received and the position differs from current. [SYS-REQ-003, SYS-REQ-027]
**SWE-REQ-006:** The software shall compare the real-time flap position (from ADC) with the requested position. [SYS-REQ-002]
**SWE-REQ-007:** The software shall hold the flap at the last valid commanded position until a new command is processed. [SYS-REQ-005]
**SWE-REQ-008:** [Implied] The software shall map each discrete command (0-5) to a unique ADC range and position label as configured. [SYS-REQ-006, SYS-REQ-013, SYS-REQ-038]

## 4.0 DC Motor and Motor Driver Control
**SWE-REQ-009:** The software shall generate motor control outputs (direction, enable/disable) via dedicated GPIOs to achieve target flap motion. [SYS-REQ-007, SYS-REQ-031]
**SWE-REQ-010:** The software shall use PWM drive for the enable signal to the motor driver for motion and to allow deterministic speed control as defined. [SYS-REQ-008, SYS-REQ-034]
**SWE-REQ-011:** When the current position matches the target, the software shall immediately disable the motor driver to prevent overshoot. [SYS-REQ-004, SYS-REQ-009, SYS-REQ-023]
**SWE-REQ-012:** The software shall prevent the motor from movement beyond the valid flap position range. [SYS-REQ-010]

## 5.0 ADC and Position Feedback
**SWE-REQ-013:** The software shall use the STM32 ADC peripheral to acquire the flap position potentiometer value at a periodic interval suitable for responsive behavior. [SYS-REQ-011, SYS-REQ-012]
**SWE-REQ-014:** The software shall digitally map ADC readings to a logical position (0-5) using configured min/max thresholds for each position. [SYS-REQ-013, SYS-REQ-038]
**SWE-REQ-015:** The software shall validate ADC readings both at startup and during operation and treat out-of-range feedback as a stop/idle/safe condition. [SYS-REQ-014, SYS-REQ-025, SYS-REQ-028, SYS-REQ-042]

## 6.0 Status Indication and LEDs
**SWE-REQ-016:** The software shall illuminate the power/status LED upon system power-up and for as long as the software is running. [SYS-REQ-019]
**SWE-REQ-017:** The software shall illuminate only the single green LED corresponding to the current detected flap position. [SYS-REQ-020, SYS-REQ-021, SYS-REQ-024]
**SWE-REQ-018:** [Implied] The software shall turn off all other green position LEDs to ensure only one is ON at a time. [SYS-REQ-021]

## 7.0 Startup, Idle and Default State Handling
**SWE-REQ-019:** The software shall on startup initialize all required hardware peripherals and ensure the motor is OFF. [SYS-REQ-022, SYS-REQ-023]
**SWE-REQ-020:** The software shall read and indicate the current position via LEDs as soon as possible after initialization. [SYS-REQ-024]
**SWE-REQ-021:** The software shall remain idle and not move the flap unless a valid user command is received and valid position feedback is present. [SYS-REQ-026]
**SWE-REQ-022:** [Implied] The software shall not implement a homing sequence during startup. [SYS-REQ-029]

## 8.0 Error and Constraint Handling
**SWE-REQ-023:** The software shall ignore or safely handle any invalid UART command or communication error so that system safety, operation, and state are not adversely affected. [SYS-REQ-017, SYS-REQ-025, SYS-REQ-028, SYS-REQ-041]
**SWE-REQ-024:** The software shall stop or prevent motor movement if ADC feedback is outside defined safe boundaries. [SYS-REQ-042]
**SWE-REQ-025:** [Implied] The software shall hold existing state if motor movement fails or position cannot be reached. [SYS-REQ-043]
**SWE-REQ-026:** The software shall operate within the constraints of available memory, CPU, and peripherals, and use no dynamic memory allocation. [SYS-REQ-044, SYS-REQ-045, SYS-REQ-037]

## 9.0 Maintainability and Testability
**SWE-REQ-027:** The software design shall maintain separation of responsibilities and interfaces for easy tracing and change. [SYS-REQ-046]
**SWE-REQ-028:** The software shall provide observability into state and behavior using LEDs and, when appropriate, UART feedback, for manual and script-based verification. [SYS-REQ-047]

## 10.0 Non-Functional and Assumption Management
**SWE-REQ-029:** The software shall maintain responsiveness suited to user-operated systems but shall not implement specific periodic or real-time deadlines unless further specified. [SYS-REQ-039, SYS-REQ-040]
**SWE-REQ-030:** The software shall assume only one flap, one motor, and one user in operation at any time. [SYS-REQ-035, SYS-REQ-036]
**SWE-REQ-031:** The software shall not include production diagnostics, networking, or security mechanisms. [SYS-REQ-037, SYS-REQ-016 boundary]
