# 1.0 System Overview

The HVAC flap actuator system is a microcontroller-based proof-of-concept designed for learning and software process demonstration. It controls a single air flap used for air direction or mixing, as typically found in automotive HVAC systems. A DC motor adjusts the flap position based on user commands, the position is monitored using a potentiometer connected to an ADC, and LEDs indicate power/status and current flap position. The system communicates with a user via UART and emphasizes clarity, simplicity, and ASPICE Level 3 traceability.

# 2.0 Flap Position Control Requirements

SYS-REQ-001: The system shall allow the user to select a target flap position via UART command.
SYS-REQ-002: The system shall move the flap to the requested target position when a valid command is received.
SYS-REQ-003: The system shall continuously compare the measured flap position against the current target position.
SYS-REQ-004: The system shall stop the motor once the requested flap position has been reached.
SYS-REQ-005: The system shall maintain the flap at the achieved target position following successful movement.
SYS-REQ-006: The system shall support a fixed set of discrete flap positions, as defined in software calibration. 
SYS-REQ-007: [Implied] The system shall perform no movement when the user command matches the current position.

# 3.0 Motor Control Requirements

SYS-REQ-008: The system shall control the direction of the DC motor to achieve the commanded flap position.
SYS-REQ-009: The system shall enable or disable the motor via GPIO and/or PWM signals.
SYS-REQ-010: The system shall stop the motor immediately upon reaching the desired position.
SYS-REQ-011: The system shall stop the motor if ADC feedback values fall outside the expected position range.
SYS-REQ-012: [Implied] The motor shall remain off except during active movement to a new position.

# 4.0 Position Feedback Acquisition and Processing

SYS-REQ-013: The system shall acquire the flap position using a potentiometer connected to an ADC input.
SYS-REQ-014: The system shall periodically sample the ADC channel to obtain the latest flap position.
SYS-REQ-015: The system shall map acquired ADC values to the supported logical flap positions (e.g., 0–5).
SYS-REQ-016: The system shall use software calibration values for ADC-to-position mapping.
SYS-REQ-017: [Implied] No dynamic calibration or self-learning shall be performed during operation.

# 5.0 User Command Interface Requirements

SYS-REQ-018: The system shall receive user commands through a UART interface connected to a PC or laptop.
SYS-REQ-019: The system shall interpret received commands as numeric values corresponding to target flap positions.
SYS-REQ-020: The system shall ignore any command with a value outside the valid flap position range.
SYS-REQ-021: The system shall not transmit acknowledgments or errors in response to an invalid command.
SYS-REQ-022: [Implied] Only one position command shall be processed at a time; additional commands are queued or ignored until current motion is complete.

# 6.0 Status Indication Requirements

SYS-REQ-023: The system shall indicate power-on status by illuminating a dedicated LED.
SYS-REQ-024: The system shall indicate the current logical flap position by illuminating one green LED corresponding to that position.
SYS-REQ-025: At most one position-indicating LED shall be illuminated at any time.
SYS-REQ-026: LED indications shall always reflect the latest available system state.
SYS-REQ-027: [Implied] No blinking or complex visual feedback shall be implemented for status or position LEDs.

# 7.0 System Behavioral Requirements

SYS-REQ-028: On power-up, the system shall initialize all necessary peripherals, including ADC, UART, GPIO, and PWM modules.
SYS-REQ-029: The system shall ensure the motor is disabled upon initialization.
SYS-REQ-030: The system shall determine and display the initial flap position (via LEDs) at start-up.
SYS-REQ-031: While idle and awaiting user command, the system shall reflect current position using the LEDs.
SYS-REQ-032: While moving to a new target, the system shall update position feedback and stop the motor when the ADC value matches the requested position.
SYS-REQ-033: Upon reaching target position, the system shall disable the motor and update LED indication.
SYS-REQ-034: The system shall safely ignore invalid user inputs and maintain safe state (motor off, LEDs valid).
SYS-REQ-035: [Implied] The system shall never enter an undefined operational state even if unexpected input is received.

# 8.0 System Interface Requirements

SYS-REQ-036: The system shall provide a UART interface for receiving position commands from a user.
SYS-REQ-037: The system shall provide motor control signals to an external driver module (e.g., L298N).
SYS-REQ-038: The system shall acquire potentiometer feedback through a dedicated ADC input on the microcontroller.
SYS-REQ-039: The system shall control individual GPIO outputs for LEDs to indicate power and flap position.
SYS-REQ-040: [Implied] All interface pins used shall be statically configured during system initialization.

# 9.0 Constraints and Assumptions

SYS-REQ-041: Only one flap actuator is present in the system.
SYS-REQ-042: Only one DC motor is used and directly controlled by the microcontroller.
SYS-REQ-043: Only one user command is handled at a time (no concurrency).
SYS-REQ-044: Hardware is assumed to function correctly for all intended operations.
SYS-REQ-045: [Implied] No vehicle CAN or advanced diagnostic interfaces shall be implemented.

# 10.0 Non-Functional Requirements
## 10.1 Responsiveness Expectations
SYS-REQ-046: The system shall respond to each valid UART command with a user-perceivable change (movement or LED change) shortly after receipt.
SYS-REQ-047: The system shall update ADC readings and LED indications in a manner that appears responsive to human users.

## 10.2 Error Handling and Edge Cases
SYS-REQ-048: The system shall ignore invalid UART commands and not alter motor or LED state in response.
SYS-REQ-049: If position feedback (ADC) values fall outside expected range, the system shall stop the motor and hold safe state.
SYS-REQ-050: The system shall never generate an error message or warning for any invalid command or sensor reading.

## 10.3 Resource Constraints
SYS-REQ-051: The implementation shall be lightweight and avoid unnecessary complexity or memory use.
SYS-REQ-052: The software shall not use dynamic memory allocation.
SYS-REQ-053: All behaviors shall be predictable and bounded at all times.

## 10.4 Maintainability and Modularity
SYS-REQ-054: The system shall maintain clear separation of concerns among modules (command handling, motor control, feedback processing, indication).
SYS-REQ-055: The system shall be easily understandable and modifiable for educational purposes.

## 10.5 Testability
SYS-REQ-056: The system shall support manual testing by allowing command entry via UART and electrical observation (LEDs, motor).
SYS-REQ-057: The system shall allow script-driven testing through the UART interface.
SYS-REQ-058: The observable system behavior (motor and LEDs) shall enable verification of all specified requirements.

# Architecture-Relevant Considerations Derived from System Requirements

- The system is designed for single-threaded, direct control of one actuator and user interface at a time.
- All external interactions (UART, ADC, GPIO) are local and synchronous.
- No concurrency or multitasking is implied or required.
- Control logic is simple, state-dependent, and does not require advanced scheduling or RTOS features.
- Expandability is limited by assumption: only one actuator, one command channel (UART), and one set of indicators are supported for demonstration purposes.
- Complexity is intentionally minimized to maintain clarity, testability, and learning value.
