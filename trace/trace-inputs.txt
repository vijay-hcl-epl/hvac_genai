1.0 System Overview
-------------------
The system is an HVAC air flap actuator prototype for automotive HVAC demonstration or learning use. It consists of a DC motor-actuated air flap, a position-sensing potentiometer, STM32 microcontroller, L298N motor driver, UART-based command input, ADC-based feedback, and LEDs for status/feedback. The system interprets human user commands and physically moves the air flap accordingly.

2.0 Flap Position Control
-------------------------
SYS-REQ-001: The system SHALL allow a user to command the HVAC flap to any supported discrete position via UART command input.
SYS-REQ-002: The system SHALL move the HVAC flap to the user-requested target position within the supported range (e.g., 0 to 5).
SYS-REQ-003: The system SHALL stop the flap movement once the flap has reached the commanded position as determined by position feedback.
SYS-REQ-004: The system SHALL enforce that only one flap move command is handled at a time. [Implied]

3.0 Motor Control
------------------
SYS-REQ-005: The system SHALL control the DC motor to move the HVAC flap in both clockwise and anti-clockwise directions as required for target position selection.
SYS-REQ-006: The system SHALL stop motor actuation upon reaching the commanded flap position or detecting an unsafe/invalid condition (e.g., ADC out of range).
SYS-REQ-007: The motor SHALL only be actuated when a valid flap move command has been received and a position change is required. [Implied]

4.0 Position Feedback Acquisition & Processing
----------------------------------------------
SYS-REQ-008: The system SHALL use an ADC channel to acquire the potentiometer voltage that indicates the HVAC flap’s current position.
SYS-REQ-009: The system SHALL map the ADC readings to logical flap position indices (e.g., 0–5) according to software-defined calibration values.
SYS-REQ-010: The system SHALL continuously monitor and process the potentiometer signal during system operation. [Implied]

5.0 User Command Interface
--------------------------
SYS-REQ-011: The system SHALL accept user flap position commands as numeric values over UART.
SYS-REQ-012: The system SHALL ignore and take no action for commands received over UART that are out of the valid position range. [Implied]
SYS-REQ-013: The system SHALL accept only one command at a time and disregard further inputs until the requested operation is completed or aborted. [Implied]

6.0 Status Indication
----------------------
SYS-REQ-014: The system SHALL turn ON a power/status LED when main power is applied.
SYS-REQ-015: The system SHALL indicate the current flap position using one (and only one) of multiple green LEDs corresponding to the discrete positions.
SYS-REQ-016: The system SHALL update the green LED indication to reflect any change in detected flap position.
SYS-REQ-017: The system SHALL use only simple steady ON/OFF LED indications, with no blinking or animation required. [Implied]

7.0 System Behavior (power-up, idle, normal, target reached, invalid input)
--------------------------------------------------------------------------
SYS-REQ-018: On power-up, the system SHALL initialize all required peripherals (ADC, UART, GPIO, PWM) and turn OFF motor actuation.
SYS-REQ-019: On power-up, the system SHALL read and interpret the potentiometer input to determine and indicate the initial flap position.
SYS-REQ-020: When in idle state (waiting for user command), the system SHALL continue to monitor the potentiometer and indicate the current flap position. [Implied]
SYS-REQ-021: Upon receiving a valid user command, the system SHALL actuate the motor to move the flap until the commanded position is reached or an unsafe/invalid condition is detected.
SYS-REQ-022: Upon reaching the commanded position, the system SHALL stop the motor and update the LED indication accordingly.
SYS-REQ-023: If an invalid command is received, the system SHALL ignore the command and maintain safe operation of the actuator and indication.

8.0 Interfaces (UART, motor driver, ADC, LEDs)
----------------------------------------------
SYS-REQ-024: The system SHALL use UART for receiving user commands from an external PC or terminal.
SYS-REQ-025: The system SHALL use GPIOs for motor direction and enable (via L298N driver), and for controlling LED status/position outputs.
SYS-REQ-026: The system SHALL use ADC input for potentiometer signal acquisition.
SYS-REQ-027: The system SHALL implement PWM output for motor enable/speed control as required by the driver electronics.

9.0 Constraints & Assumptions
-----------------------------
SYS-REQ-028: The system SHALL assume that only a single HVAC flap, a single motor, and a single instance of each interface are present in the configuration. [Implied]
SYS-REQ-029: The system SHALL assume that all hardware connections and calibration values are correct and fixed prior to operation. [Implied]
SYS-REQ-030: The system SHALL NOT require homing or dynamic calibration procedures at start-up. [Implied]

10.2 Error Handling & Edge Cases

1.0 Software Architecture Style Selection
----------------------------------------
Candidate Styles Evaluated:
- Monolithic
- Layered (high-level separation only)
- Component-Based (SW units/modules with explicit interfaces)

Evaluation Criteria:
- System complexity: Simple, single actuator, limited I/O
- HW interaction: Several direct drivers/interfaces
- Testability: SW units must allow mapping to requirements
- Maintainability: ASPICE L3 separation for future expandability

Selected Architecture Style: Component-Based (modular)
Justification:
- Enables explicit mapping between software requirements and SW units
- Simplifies testability and maintainability via clear separation
- Layered approach not necessary due to system simplicity, but high-level layering is preserved informally
- Monolithic rejected: does not allow traceable separation or testability

2.0 Software Architecture Definition
--------------------------------------

Software Units and Responsibilities (all traceable to SWE.1):

1. Command Interface Unit
   - Responsibilities: Receives, validates, and parses UART commands. Ensures only one command is acted upon at a time. Passes valid target position requests to control logic. (SWE-REQ-001, SWE-REQ-002, SWE-REQ-003, SWE-REQ-016)
   - Interfaces Provided: FlapCommandRequest (to Control Logic)
   - Interfaces Used: UART Peripheral

2. Position Feedback Processing Unit
   - Responsibilities: Acquires ADC readings, maps to position index using calibration, supplies current position to other SW units. (SWE-REQ-010, SWE-REQ-011, SWE-REQ-012, SWE-REQ-018, SWE-REQ-027)
   - Interfaces Provided: CurrentFlapPosition
   - Interfaces Used: ADC Peripheral

3. Flap Movement/Motor Control Unit
   - Responsibilities: Drives motor driver signals (GPIO, PWM) to move and stop flap. Responds to position feedback and control logic. (SWE-REQ-005, SWE-REQ-006, SWE-REQ-007, SWE-REQ-008, SWE-REQ-009, SWE-REQ-017, SWE-REQ-019)
   - Interfaces Provided: MotorDrive (to hardware)
   - Interfaces Used: FlapCommandRequest, CurrentFlapPosition

4. Status Indication Unit
   - Responsibilities: Controls status/power LED and green position LEDs per current position and system state. (SWE-REQ-013, SWE-REQ-014, SWE-REQ-015, SWE-REQ-017)
   - Interfaces Provided: StatusLEDOutputs, PositionLEDOutputs
   - Interfaces Used: CurrentFlapPosition

5. Control Logic Unit
   - Responsibilities: Implements state management between idle, moving, target reached, error; orchestrates units above using clear inputs/outputs. (SWE-REQ-004, SWE-REQ-021, SWE-REQ-022, SWE-REQ-023, SWE-REQ-024, SWE-REQ-025)
   - Interfaces Provided: None (internal)
   - Interfaces Used: FlapCommandRequest, CurrentFlapPosition

6. Calibration Data Handler
   - Responsibilities: Stores and provides calibration parameters/lookup for ADC mapping. (SWE-REQ-027, SWE-REQ-028)
   - Interfaces Provided: CalibrationData
   - Interfaces Used: Flash/ROM storage

7. Error Handler
   - Responsibilities: Receives error flags from all units, handles safe state, ensures correct system outputs on fault. (SWE-REQ-030, SWE-REQ-031, SWE-REQ-032, SWE-REQ-025)
   - Interfaces Provided: ErrorFlag, SafeOutputs
   - Interfaces Used: Position Feedback Processing Unit, Motor Control Unit, Control Logic Unit

No additional units present. No new requirements, behaviors, or mechanisms introduced.

1.0 Low-Level Design for HVAC Flap Actuator Software (SWE.3)
============================================================

All units, responsibilities, and flows are fully traceable to SWE.1. No architecture or interface changes, no new logic, no OS/scheduling, no unit test hooks, and no embedded C code.

-----------------------
Software Unit: Command Interface Unit
-----------------------
1. Responsibilities
   - Handles user (UART) command parsing, validation, single-command-in-flight constraint

2. Internal Data Design
   - Buffer for input UART bytes
   - Flag: command_in_progress (bool)
   - Last command seen (uint8_t)

3. State Machine
   - States: Idle, Receiving, Validating, CommandInProgress
   - Events: UART RX complete, buffer full, validate pass/fail, command processed

4. Algorithms & Control Flow
   - On UART RX: append to buffer until EOL/expected length
   - Validate buffer (range, format)
   - If invalid: discard, set safe state
   - If valid and !command_in_progress: set command_in_progress, forward to Control Logic
   - On operation complete: clear command_in_progress, reset buffer

5. Interfaces (APIs)
   - Provided: SendFlapCmdRequest(uint8 position)
   - Required: UART_Receive(uint8 *buf, uint8 len)
   - Returns: status enum (OK, INVALID, BUSY)

6. Error Handling
   - Reports INVALID on malformed/unsupported data
   - Ignores new commands if command_in_progress
   - Always leaves actuator in safe state upon error

7. Resource & Timing Considerations
   - Only activated on UART RX event
   - Assumes <2ms per UART parse
   - Not re-entrant (single-threaded constraint)

8. Traceability
   - SWE-REQ-001, -002, -003, -016, -031
   
-----------------------------
Software Unit: Position Feedback Processing Unit
-----------------------------
1. Responsibilities
   - Handles all ADC acquisition, position calculation, broadcasts current physical flap position

2. Internal Data Design
   - ADC value buffer (uint16[])
   - Position index (uint8_t)
   - Calibration table (ROM)

3. State Machine
   - "None" (periodic one-shot sample or triggered acquisition)
   - Flow: Sample ADC → lookup table → compute index

4. Algorithms & Control Flow
   - On trigger: Sample ADC channel
   - Use calibration data to map ADC to position index
   - Debounce if required (N out of M rule)
   - Update public position value

5. Interfaces (APIs)
   - Provided: GetCurrentFlapPosition(void): uint8_t
   - Required: ADC_Read(void): uint16_t
   - Returns: logical index

6. Error Handling
   - On out-of-range ADC: flag error to Error Handler
   - On noisy/unmappable samples: hold last valid output

7. Resource & Timing Considerations
   - Activated per ADC complete (~50–200us typical)
   - Not re-entrant, state held per invocation

8. Traceability
   - SWE-REQ-010, -011, -012, -018, -027, -030

-----------------------------
Software Unit: Flap Movement/Motor Control Unit
-----------------------------
1. Responsibilities
   - Interprets target position, actuates GPIO/PWM to move flap
   - Stops/halt on target reached or error

2. Internal Data Design
   - TargetPosition variable (uint8_t)
   - MotorState (enum: IDLE, MOVING, ERROR)
   - Output enable/dir bits

3. State Machine
   - States: IDLE, MOVING, STOPPED, ERROR
   - Events: new command, position arrived, error signal
   - Actions: assert/release relevant GPIO/PWM

4. Algorithms & Control Flow
   - On command: check if target!=current position
   - If yes: set direction, enable PWM, mark MOVING
   - Monitor feedback; if pos==target, disable drive
   - If error, go to STOPPED and disable all output

5. Interfaces (APIs)
   - Provided: SetMotor(uint8_t direction, uint8_t enable)
   - Required: GetCurrentFlapPosition(), SendFlapCmdRequest()

6. Error Handling
   - On feedback loss or error: immediately set outputs to idle

7. Resource & Timing Considerations
   - Invoked on command and on each feedback update
   - WCET per call <1ms

8. Traceability
   - SWE-REQ-005, -006, -007, -008, -009, -017, -019, -030

-----------------------------
Software Unit: Status Indication Unit
-----------------------------
1. Responsibilities
   - Controls status LED (power) and green position LEDs

2. Internal Data Design
   - LED output state (bitfield)
   - Maps logical position to GPIO bits

3. State Machine
   - "None" (stateless, aliases input to output)
   - Flow: write LED output based on position/condition

4. Algorithms & Control Flow
   - On power-up: set status LED ON
   - On feedback update: set one green LED ON to match position; all others OFF
   - No blinking or patterns

5. Interfaces (APIs)
   - Provided: SetStatusLED(uint8_t on_off), SetPositionLED(uint8_t pos)
   - Required: GetCurrentFlapPosition()

6. Error Handling
   - LEDs default to OFF on error (except power LED)

7. Resource & Timing Considerations
   - Fast (<10us), no timing constraints

8. Traceability
   - SWE-REQ-013, -014, -015, -017

-----------------------------
Software Unit: Control Logic Unit
-----------------------------
1. Responsibilities
   - Orchestrates overall state machine (idle, moving, complete, error), delegates to lower units

2. Internal Data Design
   - SystemState (enum: IDLE, CMD_PENDING, MOVING, ERROR)
   - Sub-unit flags: cmd_pending, motion_active

3. State Machine
   - States: IDLE, CMD_PENDING, MOVING, ERROR
   - Events: command, feedback update, error
   - Actions: issue move, wait for arrived, indicate/status update

4. Algorithms & Control Flow
   - On valid command: set CMD_PENDING, update target
   - If CMD_PENDING and target != feedback, set MOVING
   - If MOVING and position == target, set IDLE
   - On error, enter ERROR state

5. Interfaces (APIs)
   - (Internal only)
   - Consumes: SendFlapCmdRequest(), GetCurrentFlapPosition()

6. Error Handling
   - Passes error to Error Handler, disables activities

7. Resource & Timing Considerations
   - All events <1ms handling

8. Traceability
   - SWE-REQ-004, -021, -022, -023, -024, -025, -026

-----------------------------
Software Unit: Calibration Data Handler
-----------------------------
1. Responsibilities
   - Stores/serves calibration for ADC-to-position

2. Internal Data Design
   - Calibration table (const struct)
   - ROM pointer or loaded-on-init

3. State Machine
   - "None" (lookup only)

4. Algorithms & Control Flow
   - On request: lookup ADC threshold range for input

5. Interfaces (APIs)
   - Provided: MapAdcToPosition(uint16_t adc): uint8_t

6. Error Handling
   - On unmappable: returns special value (e.g., 0xFF)
   - Flags error for upstream

7. Resource & Timing Considerations
   - ROM, <1us lookup time

8. Traceability
   - SWE-REQ-027, -028

-----------------------------
Software Unit: Error Handler
-----------------------------
1. Responsibilities
   - Receives errors, ensures actuator safe outputs

2. Internal Data Design
   - Error flag/state
   - Error source indicator

3. State Machine
   - States: NO_ERROR, ERROR_DETECTED, RECOVERY_ATTEMPTED
   - Events: error input, resolved/cleared

4. Algorithms & Control Flow
   - On error in any unit: set safe outputs in all controls
   - Optionally disables selected outputs until reset

5. Interfaces (APIs)
   - Provided: SetErrorState(flag), ClearErrorState(void)

6. Error Handling
   - Centralized error state/dispatch

7. Resource & Timing Considerations
   - Fast, single-event driven, <5us typical

8. Traceability
   - SWE-REQ-025, -030, -031, -032

###### FILE: code/src/command_interface.c ######
#include "command_interface.h"
#include "control_logic.h"
#define UART_BUFFER_SIZE 8
static uint8_t uart_buffer[UART_BUFFER_SIZE];
static uint8_t uart_buffer_idx = 0;
static uint8_t command_in_progress = 0;
static uint8_t last_command = 0xFF;
CmdStatus_t SendFlapCmdRequest(uint8_t position) {
    if (command_in_progress) return CMD_BUSY;
    if (position > 5) return CMD_INVALID;
    command_in_progress = 1;
    last_command = position;
    ControlLogic_OnCommand(position);
    return CMD_OK;
}
void CommandInterface_UartRxHandler(uint8_t data) {
    if (uart_buffer_idx < UART_BUFFER_SIZE) {
        uart_buffer[uart_buffer_idx++] = data;
        if (data == '\n') {
            uint8_t val = 0xFF;
            // Minimal convert: expect '0'-'5' as ASCII
            if (uart_buffer[0] >= '0' && uart_buffer[0] <= '5')
                val = uart_buffer[0] - '0';
            CmdStatus_t s = SendFlapCmdRequest(val);
            // Clear buffer on any outcome
            uart_buffer_idx = 0;
        }
    } else {
        uart_buffer_idx = 0;
    }
}
void CommandInterface_Init(void) {
    uart_buffer_idx = 0;
    command_in_progress = 0;
    last_command = 0xFF;
}
// Called when command done
void CommandInterface_CommandComplete(void) {
    command_in_progress = 0;
    uart_buffer_idx = 0;
}

void PositionFeedback_AdcInterruptHandler(uint16_t adc_value) {
    if (adc_value == 0xFFFF || adc_value < 50 || adc_value > 4000) {
        ErrorHandler_SetErrorState(1);
        return;
    }
    adc_history[idx++] = adc_value;
    if (idx >= FEEDBACK_HISTORY) idx = 0;
    uint8_t pos = MapAdcToPosition(adc_value);
    if (pos == 0xFF) {
        ErrorHandler_SetErrorState(2);
        return;
    }
    last_position = pos;
}
uint8_t GetCurrentFlapPosition(void) { return last_position; }
