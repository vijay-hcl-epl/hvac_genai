1.0 System Overview
==================
SYS-REQ-001: The system SHALL provide automatic control of an HVAC air flap to support discrete air direction or air mixing positions, as commanded by a user via a UART interface.
SYS-REQ-002: The system SHALL be implemented on a single microcontroller, supporting one air flap actuator only.
SYS-REQ-003: The system SHALL operate standalone, without interaction with any vehicle network (CAN, LIN, etc) or additional ECUs.

[Implied]
SYS-REQ-004: The system SHALL support prototype demonstration requirements and constraints as described in the project scope.

2.0 Flap Position Control
========================
SYS-REQ-005: The system SHALL allow a user to command the flap to one of six discrete positions (0–5).
SYS-REQ-006: The system SHALL move the flap to the user-requested position.
SYS-REQ-007: The flap SHALL stop moving once the target position is reached.

[Implied]
SYS-REQ-008: The system SHALL ensure the flap is not moved unless a valid position command is received.

3.0 Motor Control
=================
SYS-REQ-009: The system SHALL control the direction of the DC motor via GPIO outputs, supporting both clockwise and anti-clockwise rotation for position control.
SYS-REQ-010: The system SHALL stop the motor immediately once the flap reaches the requested position, as determined by position feedback.
SYS-REQ-011: The system SHALL provide PWM control for motor enable and basic speed regulation as needed for smooth operation.

4.0 Position Feedback Acquisition & Processing
=============================================
SYS-REQ-012: The system SHALL acquire flap position feedback from a potentiometer using an ADC input.
SYS-REQ-013: The system SHALL map ADC values to logical flap positions (0–5) based on fixed calibration ranges defined in software.
SYS-REQ-014: The system SHALL monitor position feedback continuously while the motor is active.
SYS-REQ-015: The system SHALL treat ADC values outside the valid calibration range as invalid feedback, and SHALL stop the motor in such case.

5.0 User Command Interface
==========================
SYS-REQ-016: The system SHALL receive user commands via UART from a connected PC.
SYS-REQ-017: The system SHALL only accept integer commands between 0 and 5 as valid target positions.
SYS-REQ-018: The system SHALL ignore invalid UART commands without providing error responses or acknowledgment.

6.0 Status Indication
====================
SYS-REQ-019: The system SHALL use one LED to indicate power/operational status.
SYS-REQ-020: The system SHALL use up to six green LEDs to indicate the current flap position, with only the LED corresponding to the actual position being ON at any time.

7.0 System Behavior
==================
Power-up:
SYS-REQ-021: On power-up, the system SHALL initialize all required peripherals (ADC, UART, GPIO, PWM).
SYS-REQ-022: On power-up, the flap motor SHALL be OFF until a valid command is received.
SYS-REQ-023: On power-up, the system SHALL read the current flap position using ADC and indicate it using the corresponding green LED.

Idle:
SYS-REQ-024: In the absence of valid user commands, the system SHALL not drive the flap motor and SHALL maintain current position.

Normal Operation:
SYS-REQ-025: During flap movement, the system SHALL continuously monitor current position until the target position is reached.
SYS-REQ-026: Upon reaching the target position, the system SHALL switch off the motor.

Target Reached:
SYS-REQ-027: When the target position is reached, the system SHALL indicate the new flap position via the correct green LED.

Invalid Input Handling:
SYS-REQ-028: On receipt of an invalid user command, the system SHALL ignore the input without taking unsafe actions or altering system state.
SYS-REQ-029: If position feedback is invalid during movement, the system SHALL stop the motor and maintain a safe state.

8.0 Interfaces
==============
SYS-REQ-030: The system SHALL use UART for user command input from a PC.
SYS-REQ-031: The system SHALL use a motor driver module (e.g., L298N) to interface the microcontroller with the DC motor.
SYS-REQ-032: The system SHALL use an ADC channel to acquire feedback from the position potentiometer.
SYS-REQ-033: The system SHALL use GPIOs to control status and position LEDs.

[Implied]
SYS-REQ-034: The system SHALL use GPIOs for DC motor direction and enable/PWM control.

9.0 Constraints & Assumptions
============================
SYS-REQ-035: The system SHALL not require dynamic calibration or self-learning capabilities.
SYS-REQ-036: All calibration values (ADC ranges) SHALL be statically defined in software and assumed correct for prototype purposes.
SYS-REQ-037: Only one user command SHALL be processed at a time; simultaneous commands SHALL not be supported.
SYS-REQ-038: The system SHALL operate under the assumption that all hardware components function correctly.

10.0 Non-Functional Requirements
===============================
10.1 Responsiveness
SYS-REQ-039: The system SHALL process UART commands and begin flap movement within a period perceptible as "responsive" to a human user (e.g., typically within 100–250 ms).

10.2 Error Handling & Edge Cases
SYS-REQ-040: The system SHALL ignore invalid UART commands (out of 0–5 range, or malformed data).
SYS-REQ-041: The system SHALL stop the flap motor if position feedback is lost or is outside expected ADC range, and SHALL not crash if the motor cannot reach a commanded position.

10.3 Resource Constraints
SYS-REQ-042: The system SHALL operate within the resource limitations of the STM32F407G-DISC1 microcontroller development board.

10.4 Maintainability & Modularity
SYS-REQ-043: The system SHALL structure software to separate position control logic, motor actuation logic, feedback processing, user interface processing, and status indication to allow maintainable development.

10.5 Testability
SYS-REQ-044: The system SHALL support functional testability by means of simple command issuance, visual feedback via LEDs, and observation of actuator response, in line with manual or script-based test approaches for prototypes.

===
Architecture-Relevant Considerations Derived from System Requirements
=================================================
Concurrency: The system is predominantly event-driven (user command or ADC change), with limited need for concurrent processing. Only single actuator movement and user command are supported at a time, minimizing concurrency needs.

Interaction Complexity: Interactions among user commands, actuator motion, feedback acquisition, and status indication are simple and direct. No complex cross-subsystem coordination is required.

Control Complexity: Control is simple sequential logic — command acquisition, movement, feedback monitoring, and indication. No real-time, multi-axis synchronization, or advanced arbitration is required.

Expandability: While software is organized for maintainability and modularity, requirements limit to a single flap actuator and user, restricting expandability in this scope.
