# sys-reqs.txt

---

## 1.0 System Overview

The HVAC Flap Actuator System is a microcontroller-based proof-of-concept demonstrating automotive air flap control, akin to systems used in car HVAC setups. It enables a user to select discrete air flap positions via UART commands, drives a DC motor to adjust the flap, monitors the position using a potentiometer with ADC feedback, and indicates status with LEDs. The system’s boundaries include only the actuator and its immediate local interfaces; production-level diagnostic, networking, or advanced features are excluded.

---

## 2.0 Flap Position Control Requirements

**SYS-REQ-001**: The system shall allow the user to select a target flap position using commands received via the UART interface.

**SYS-REQ-002**: The system shall compare the current flap position to the target position to determine when motor actuation is necessary.

**SYS-REQ-003**: The system shall move the flap to the user-specified target position by controlling the motor’s direction and operation.

**SYS-REQ-004**: The system shall hold the flap at the target position once it is reached by disabling motor actuation.

**SYS-REQ-005**: The system shall ensure the flap can reach and hold any of the discrete positions defined (positions 0 to 5).

**SYS-REQ-006**: The system shall only attempt to move the flap when a new, valid target position command is received.

**SYS-REQ-007 [Implied]**: The system shall not drive the flap if the current position is already at the target position.

---

## 3.0 Motor Control Requirements

**SYS-REQ-008**: The system shall drive the DC motor in either clockwise or anti-clockwise direction, based on whether the current position is below or above the target position.

**SYS-REQ-009**: The system shall control the motor on/off and its direction exclusively using GPIO or PWM signals to the motor driver.

**SYS-REQ-010**: The system shall stop the motor immediately when the target flap position is achieved as determined by position feedback.

**SYS-REQ-011**: The system shall be able to disable the motor output at any time by removing the enable signal.

**SYS-REQ-012 [Implied]**: The system shall stop the motor if flap position feedback (ADC value) is detected to be out of the valid expected measurement range.

**SYS-REQ-013 [Implied]**: The motor shall not start on power-up or reset unless a valid move command is received and the current position does not match the target.

---

## 4.0 Position Feedback Acquisition and Processing

**SYS-REQ-014**: The system shall acquire flap position feedback by reading a potentiometer connected to an ADC channel.

**SYS-REQ-015**: The system shall use the ADC to convert the potentiometer’s analog output to a digital value representing flap position.

**SYS-REQ-016**: The system shall map ADC values to corresponding logical flap positions (positions 0 through 5) according to defined ranges.

**SYS-REQ-017**: The system shall use the mapped logical position, not raw ADC values, for comparison and control logic.

**SYS-REQ-018 [Implied]**: The system shall periodically or continuously update the current flap position based on potentiometer feedback.

**SYS-REQ-019 [Implied]**: The ADC mapping ranges for each flap position shall be fixed and only changeable in software.

---

## 5.0 User Command Interface Requirements

**SYS-REQ-020**: The system shall accept flap position commands from the user exclusively via the UART interface.

**SYS-REQ-021**: The system shall validate each received UART command to ensure it represents a valid flap position (e.g., integer values 0-5 inclusive).

**SYS-REQ-022**: The system shall ignore any UART command that is not an integer within the valid position range without sending any response or error indication.

**SYS-REQ-023**: The system shall process only the most recently received valid command; previous commands shall be disregarded if superseded.

**SYS-REQ-024 [Implied]**: The system shall not process partial or corrupted UART inputs.

---

## 6.0 Status Indication Requirements

**SYS-REQ-025**: The system shall provide a power/status indicator LED which is ON whenever the system is powered and operational.

**SYS-REQ-026**: The system shall use up to six green LEDs to indicate the current logical flap position (positions 0 through 5).

**SYS-REQ-027**: The system shall illuminate only the LED corresponding to the current logical flap position at any given time.

**SYS-REQ-028**: The system shall ensure at most one green LED is ON to indicate position at any time.

**SYS-REQ-029 [Implied]**: LED indications shall update promptly whenever flap position changes.

---

## 7.0 System Behavioral Requirements

**SYS-REQ-030**: Upon power-up, the system shall initialize all required peripherals (ADC, UART, GPIOs, PWM drivers).

**SYS-REQ-031**: Upon power-up, the motor shall be disabled and remain off until a flap movement is required.

**SYS-REQ-032**: Upon power-up, the system shall read the potentiometer and set the initial status and position LEDs accordingly.

**SYS-REQ-033**: During idle operation, the system shall monitor the UART for user input and flap feedback for any deviation from the target position.

**SYS-REQ-034**: During normal operation, the system shall start the motor if the flap needs to move and stop when the target position is achieved.

**SYS-REQ-035**: The system shall treat receiving an invalid command as a safe, non-disruptive event (i.e., the command is ignored and system safely continues operation).

**SYS-REQ-036**: The system shall ignore additional commands while a flap move is in progress, until the flap reaches its new target.

**SYS-REQ-037 [Implied]**: The system shall not enter a fault or undefined state if the motor fails to reach the target (e.g., no infinite retries, no system halt).

**SYS-REQ-038 [Implied]**: If the current position cannot be determined due to out-of-range ADC feedback, the system shall stop motor actuation.

---

## 8.0 System Interface Requirements

**SYS-REQ-039**: The system shall receive user commands through a UART interface compliant with the expected voltage and timing requirements.

**SYS-REQ-040**: The system shall interface with a motor driver module (e.g., L298N or equivalent) using digital IO (GPIO/PWM) for direction and enable control.

**SYS-REQ-041**: The system shall interface with a rotary potentiometer via an ADC channel for position feedback acquisition.

**SYS-REQ-042**: The system shall provide digital outputs to control LEDs for status and flap position indication.

---

## 9.0 Constraints and Assumptions

**SYS-REQ-043**: The system shall control only one HVAC flap with one DC motor and one potentiometer.

**SYS-REQ-044**: Only one command from the user is expected and processed at a time.

**SYS-REQ-045**: The system shall not require a homing procedure or dynamic calibration at power-up.

**SYS-REQ-046**: Only locally connected user, actuator, and sensor interfaces are considered; no vehicle or network communications are to be supported.

**SYS-REQ-047 [Implied]**: System correctness assumes underlying hardware is operating according to specification.

---

## 10.0 Non-Functional Requirements

### 10.1 Responsiveness Expectations

**SYS-REQ-048**: The system shall process and act upon UART commands with responsiveness that is observable and acceptable to a typical human user. 

**SYS-REQ-049**: The system shall update LED indications promptly in response to position changes.

### 10.2 Error Handling and Edge Cases

**SYS-REQ-050**: The system shall ignore invalid UART commands without acknowledgment or error response.

**SYS-REQ-051**: The system shall stop the motor if potentiometer feedback (ADC value) is outside all defined valid position ranges.

**SYS-REQ-052 [Implied]**: The system shall ensure predictable behavior if unexpected operating conditions are detected (e.g., do not crash or hang).

### 10.3 Resource Constraints

**SYS-REQ-053**: The system shall implement only the minimum required features for demonstration and learning, ensuring predictable and bounded execution behavior at all times.

### 10.4 Maintainability and Modularity

**SYS-REQ-054**: The system shall separate motor control, input handling, feedback processing, and status indication logic in a way that is clear and logically organized. 

**SYS-REQ-055 [Implied]**: Requirement and software artifacts shall be simple, clear, and modifiable for educational/demonstration purposes.

### 10.5 Testability

**SYS-REQ-056**: The system shall support testability by providing observable outputs via LEDs (position and power/status) and responding to UART user commands during manual or script-based testing.

**SYS-REQ-057**: The system shall allow the operator to observe actual motor actuation for each executed command.

**SYS-REQ-058**: The system shall allow repeated and independent test cycles without requiring a system reset.

---

# Architecture-Relevant Considerations Derived from System Requirements

- The HVAC flap actuator system is a single-responsibility control system with no requirements for concurrent tasks beyond basic actuator feedback/control and user interface management.
- External interaction complexity is minimal; all interfaces are local and direct (UART, GPIO, ADC, LEDs); no CAN, LIN, or networked diagnostic/OTA capabilities are required or supported.
- Control logic is simple and sequential: user command → position feedback → motor actuation → indication. There are no requirements for multitasking, time partitioning, or inter-process communication.
- Expandability is explicitly limited; only one user flap, motor, and user at a time are assumed, with no provision for network extension, additional actuators, or scalability features.
- The structure and clarity of requirements support software architectures that are cleanly partitioned (input, control, feedback, indication), aiding maintainability and learning, but do not imply any specific scheduling or concurrency model.
