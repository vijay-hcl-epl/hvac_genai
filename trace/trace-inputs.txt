1.0 System Overview
-------------------
The HVAC Flap Actuator System is a microcontroller-based prototype intended for learning, demonstration, and software process education. The system controls a single automotive air flap, driven by a DC motor, and provides feedback through a potentiometer and LEDs. Commands are issued by a user via UART from a PC. The system requires clear, safe, and observable behavior and is not intended for production use.

2.0 Flap Position Control Requirements
--------------------------------------
SYS-REQ-001: The system shall accept user commands to select a target flap position by numeric value over UART.
SYS-REQ-002: The system shall compare the current flap position with the target position.
SYS-REQ-003: The system shall actuate the flap to move from the current position to the selected target position.
SYS-REQ-004: The system shall stop actuating the flap motor once the target position is reached and held.
SYS-REQ-005 [Implied]: The system shall maintain the current position once it is reached, with no drift beyond defined tolerances.

3.0 Motor Control Requirements
------------------------------
SYS-REQ-006: The system shall control the direction of the DC motor to achieve the shortest path towards the requested position.
SYS-REQ-007: The system shall enable or disable the motor through GPIO or PWM as required by the desired motion.
SYS-REQ-008: The system shall stop the motor when the target flap position is reached.
SYS-REQ-009 [Implied]: The system shall ensure the motor does not operate continuously without position error.

4.0 Position Feedback Acquisition and Processing
------------------------------------------------
SYS-REQ-010: The system shall acquire potentiometer signals via an ADC channel to determine the current flap position.
SYS-REQ-011: The system shall map ADC values to defined logical flap positions (0–5).
SYS-REQ-012: The system shall detect and ignore feedback values outside expected ADC ranges, stopping the motor as a safe reaction.

5.0 User Command Interface Requirements
----------------------------------------
SYS-REQ-013: The system shall receive target position commands as numeric values (0–5) via UART from the user/PC.
SYS-REQ-014: The system shall validate command values and accept only numeric values corresponding to valid positions.
SYS-REQ-015: The system shall safely ignore and not acknowledge invalid commands.
SYS-REQ-016 [Implied]: The system shall not permit buffer overflows, framing, or UART RX errors to cause a system crash.

6.0 Status Indication Requirements
-----------------------------------
SYS-REQ-017: The system shall turn on a status LED during power-on indication.
SYS-REQ-018: The system shall indicate the current flap position using six distinct green LEDs, with only one green LED ON at a time.
SYS-REQ-019 [Implied]: The system shall ensure status indications are always mutually exclusive.

7.0 System Behavioral Requirements
-----------------------------------
SYS-REQ-020: The system shall initialize all required peripherals (ADC, UART, GPIO, PWM) during power-up.
SYS-REQ-021: The system shall ensure the motor is OFF during startup/init.
SYS-REQ-022: The system shall read and display the current flap position at startup using the corresponding green LED.
SYS-REQ-023: The system shall remain idle, monitoring for user command input, when not processing a valid command.
SYS-REQ-024: The system shall actuate the flap in response to user command until the target position is reached or an error is detected.
SYS-REQ-025: The system shall not enter a fault or reset state due to invalid command or transient ADC error.
SYS-REQ-026 [Implied]: The system shall prevent motor overheating due to extended failed movements (if feasible in prototype test context).

8.0 System Interface Requirements
----------------------------------
SYS-REQ-027: The system shall receive and transmit data over UART for user command handling.
SYS-REQ-028: The system shall control motor direction and enable signals using dedicated GPIO and PWM outputs linked to the L298N driver.
SYS-REQ-029: The system shall read analog voltage from the potentiometer using microcontroller ADC input channel(s).
SYS-REQ-030: The system shall control LEDs via GPIO outputs.
SYS-REQ-031 [Implied]: The system shall ensure no unintended conflicts on any shared peripheral pins.

9.0 Constraints and Assumptions
-------------------------------
SYS-REQ-032: The system shall operate assuming the calibration values for ADC mapping are correct and fixed in software.
SYS-REQ-033: The system shall control only a single HVAC flap actuator.
SYS-REQ-034: The system shall process only one user command at a time.
SYS-REQ-035: The system shall assume hardware is in a functional and working state.
SYS-REQ-036 [Implied]: The system shall clearly state in user/engineering documentation all intended exclusions and scope boundaries.

10.0 Non-Functional Requirements
-------------------------------
10.1 Responsiveness Expectations
SYS-REQ-037: The system shall provide perceptibly responsive operation to user commands, with reaction time suitable for direct interaction (typically less than 0.5 seconds).

10.2 Error Handling and Edge Cases
SYS-REQ-038: The system shall ignore invalid commands and not acknowledge or act upon them.
SYS-REQ-039: The system shall stop the motor safely in the event ADC readings are out of range or invalid.
SYS-REQ-040: The system shall remain recoverable and operable after any handled error condition.

10.3 Resource Constraints
SYS-REQ-041: The system shall use only resources available within a STM32F407G-DISC1 MCU with no dynamic memory allocation.
SYS-REQ-042: The system shall exhibit deterministic and bounded behavior at all times.

10.4 Maintainability and Modularity
SYS-REQ-043: The system shall separate main subsystems in code and documentation for clear understanding and modification.

10.5 Testability
SYS-REQ-044: The system shall support testing by sending UART commands and visually observing motor and LED behaviors.
SYS-REQ-045 [Implied]: The system shall provide observable consequences for every valid/invalid user interaction and operation state.


Architecture-Relevant Considerations Derived from System Requirements
--------------------------------------------------------------------
- The system manages only a single actuator and all control is single-threaded, sequential, and user-initiated; there are no concurrency or reentrancy concerns.
- The system interacts only with direct peripherals—no complex network protocols, scheduling, or interrupt-driven controls are required beyond typical microcontroller configuration.
- System logic is simple state-based (idle, move, reached, error) with clear transitions dictated by external commands or feedback.
- The number of external interfaces is minimal (UART, ADC, PWM/GPIO, LEDs) and each has a clearly defined purpose.
- Expandability is deliberately minimal; changes would typically be limited to increasing positions, changing feedback mapping, or modifying test interfaces. There are no strict architectural demands for scalability or extension.
- No inference of software scheduling, multi-threading, or time partitioning models required by these system requirements.

1.0 Software Requirements Overview
----------------------------------
This document contains the software requirements (SWE.1 level) for the HVAC Flap Actuator System, mapped to the system requirements. Requirements are atomic, clear, testable, and implementation-neutral. Where necessary, implied requirements are explicitly marked. All requirements serve as the primary input to architecture and detailed design.

2.0 Command Decoding and Validation
------------------------------------
SWE-REQ-001: The software shall receive UART data and buffer input from the PC.
SWE-REQ-002: The software shall validate UART data as a single numeric value from 0 to 5 before accepting as a command.
SWE-REQ-003: The software shall reject and ignore any command that is not a single number in [0..5].
SWE-REQ-004: The software shall not crash or hang if invalid, out-of-range, or malformed UART data is received. [SYS-REQ-013, SYS-REQ-014, SYS-REQ-015, SYS-REQ-016]
SWE-REQ-005 [Implied]: The software shall ensure UART RX buffer is cleared only after processing a valid or invalid command. [SYS-REQ-013, SYS-REQ-014]

3.0 Flap Target and Position Tracking
-------------------------------------
SWE-REQ-006: The software shall store the currently-commanded target position as an integer in [0..5]. [SYS-REQ-001, SYS-REQ-013]
SWE-REQ-007: The software shall acquire and store the latest ADC value from the potentiometer. [SYS-REQ-010, SYS-REQ-011]
SWE-REQ-008: The software shall map each valid ADC value to a logical flap position [0..5] using a configuration table. [SYS-REQ-011, SYS-REQ-032]
SWE-REQ-009: If ADC values fall outside the configured ranges, the software shall treat the position as unknown and stop the motor. [SYS-REQ-012, SYS-REQ-039]
SWE-REQ-010 [Implied]: The software shall not attempt to actuate the motor if a valid position cannot be determined. [SYS-REQ-005, SYS-REQ-012]

4.0 Flap Motion Control
----------------------
SWE-REQ-011: When a valid new command is received, the software shall compute the direction of movement required to reach the target. [SYS-REQ-002, SYS-REQ-006]
SWE-REQ-012: The software shall set appropriate direction GPIO outputs for the L298N motor driver. [SYS-REQ-028, SYS-REQ-007]
SWE-REQ-013: The software shall enable the motor (via PWM output) only while the flap is not at target position and position is known. [SYS-REQ-007, SYS-REQ-008, SYS-REQ-009, SYS-REQ-010]
SWE-REQ-014: When the current position matches the target, the motor enable shall be deactivated and direction outputs shall hold steady. [SYS-REQ-004, SYS-REQ-008]
SWE-REQ-015 [Implied]: The software shall tolerate a small pre-defined position tolerance for achieving target. [SYS-REQ-005, SYS-REQ-041]

5.0 Status Indication
---------------------
SWE-REQ-016: The software shall activate the power/status LED on system startup and leave it ON continuously. [SYS-REQ-017]
SWE-REQ-017: The software shall activate exactly one position indicator LED according to the last mapped logical flap position. [SYS-REQ-018, SYS-REQ-019]
SWE-REQ-018: LEDs shall update synchronously whenever the logical flap position changes. [SYS-REQ-018]
SWE-REQ-019 [Implied]: The software shall ensure only one of the six position indicator LEDs is ON at any instant. [SYS-REQ-019]

6.0 System Initialization and State Management
----------------------------------------------
SWE-REQ-020: On startup, the software shall initialize all MCU peripherals (UART, ADC, GPIO, PWM) before accepting commands. [SYS-REQ-020]
SWE-REQ-021: The motor enable (PWM) output shall be set to OFF at startup. [SYS-REQ-021]
SWE-REQ-022: On power-up, the flap position shall be read and the corresponding position indicator LED set. [SYS-REQ-022]
SWE-REQ-023: The software shall enter an idle wait-state after boot and between commands. [SYS-REQ-023]
SWE-REQ-024: New UART commands shall be accepted only when not already handling a pending command. [SYS-REQ-034]
SWE-REQ-025: The software shall not undergo any system reset, crash, or watchdog trigger due to command or ADC anomalies. [SYS-REQ-025]
SWE-REQ-026 [Implied]: The software shall prevent excessive current/motor activation by disabling enable output in case of persistent command or feedback error. [SYS-REQ-026]

7.0 Constraints, Assumptions & Resource Management
--------------------------------------------------
SWE-REQ-027: The software shall not use dynamic memory allocation at runtime. [SYS-REQ-041]
SWE-REQ-028: The software shall require only MCU hardware resources available on STM32F407G-DISC1, documented in source and user notes. [SYS-REQ-041, SYS-REQ-043]
SWE-REQ-029: The software shall avoid introducing multi-threading, task scheduling, or non-deterministic processing. [SYS-REQ-042]
SWE-REQ-030: The software shall ensure all I/O writes are deterministic and bounded in execution time. [SYS-REQ-042, SYS-REQ-043]
SWE-REQ-031 [Implied]: All configuration tables (position mapping, tolerances) shall be implemented as compile-time constants for maintainability. [SYS-REQ-032, SYS-REQ-043]

8.0 Testability Requirements
----------------------------
SWE-REQ-032: The software shall permit observing all software states and transitions through UART output messages (for engineering modes only) and LED indicators. [SYS-REQ-044, SYS-REQ-045]
SWE-REQ-033: All testable functions (UART parser, position mapping, motion logic) shall be accessible via integration test modes or manual stimulation. [SYS-REQ-044]
SWE-REQ-034 [Implied]: Sufficient comments and documentation shall be provided to allow learning/test use by engineering students. [SYS-REQ-045]

9.0 Error Handling
-----------------------
SWE-REQ-035: The software shall always halt motor movement if any critical error or out-of-range input is detected. [SYS-REQ-012, SYS-REQ-039]
SWE-REQ-036: The software shall prevent buffer overflows, overrun, and framing errors from causing system instability. [SYS-REQ-016]
SWE-REQ-037: Upon invalid UART data or feedback, the software shall cleanly discard relevant buffers and resume idle waiting with no crash state. [SYS-REQ-015, SYS-REQ-025, SYS-REQ-040]
SWE-REQ-038 [Implied]: The software shall ensure recoverability without MCU reset upon all handled error cases. [SYS-REQ-025, SYS-REQ-040]
