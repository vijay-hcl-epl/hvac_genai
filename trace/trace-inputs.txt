# sys-reqs.txt

---

## 1.0 System Overview

The HVAC Flap Actuator system is a microcontroller-based prototype designed to control the angular position of an air flap in a manner similar to automotive HVAC systems. The system enables user selection of a discrete flap position via UART, actuates a DC motor accordingly, senses position using a potentiometer connected to an ADC, and provides user feedback via LEDs. It is intended for educational and software process demonstration, not for automotive production use.

---

## 2.0 Flap Position Control Requirements

**SYS-REQ-001:** The system shall allow the user to select the target flap position via a UART command.

**SYS-REQ-002:** The system shall compare the current flap position to the target position and determine the required direction of movement.

**SYS-REQ-003:** The system shall actuate the motor to move the flap toward the selected target position.

**SYS-REQ-004:** The system shall stop the motor once the flap reaches the commanded position.

**SYS-REQ-005:** The system shall continuously monitor the current flap position until the target is reached.

**SYS-REQ-006:** The system shall hold the flap at the last commanded position after the target position is achieved.

**SYS-REQ-007:** The system shall ignore any new position command if the requested position matches the current flap position. [Implied]

---

## 3.0 Motor Control Requirements

**SYS-REQ-008:** The system shall drive the DC motor in clockwise or anti-clockwise direction as required to reach the target flap position.

**SYS-REQ-009:** The system shall control the direction of the motor using GPIO outputs.

**SYS-REQ-010:** The system shall enable or disable (stop) the motor by controlling the motor driver 'Enable' line.

**SYS-REQ-011:** The system shall stop the motor when the ADC position feedback indicates the target position has been reached within defined ADC thresholds.

**SYS-REQ-012:** The system shall stop the motor if an ADC position reading is out of the defined calibration range.

**SYS-REQ-013:** The system shall ensure motor is off by default at system startup until a command is processed.

---

## 4.0 Position Feedback Acquisition and Processing

**SYS-REQ-014:** The system shall acquire the flap position via a potentiometer mechanically linked to the flap.

**SYS-REQ-015:** The system shall sample the potentiometer voltage using an ADC input.

**SYS-REQ-016:** The system shall map the sampled ADC value to a logical flap position in a configured range (e.g., 0-5).

**SYS-REQ-017:** The system shall define precise ADC thresholds for each discrete logical flap position.

**SYS-REQ-018:** The system shall treat any ADC reading outside the valid range as “out-of-range” and halt the motor.

**SYS-REQ-019:** The system shall initialize and calibrate ADC readings using static configuration data defined in software.

---

## 5.0 User Command Interface Requirements

**SYS-REQ-020:** The system shall receive user commands via a UART interface connected to a PC.

**SYS-REQ-021:** The system shall support user commands as single ASCII numeric values (0–5), with each value representing a discrete flap position.

**SYS-REQ-022:** The system shall validate incoming UART commands against allowed values.

**SYS-REQ-023:** The system shall ignore and not process any UART command that is not a valid position code (0–5).

**SYS-REQ-024:** The system shall not send any acknowledgment or error message in response to invalid or out-of-range commands.

**SYS-REQ-025:** The system shall process only one user command at a time; further commands received during motion shall be ignored until the flap reaches its target. [Implied]

---

## 6.0 Status Indication Requirements

**SYS-REQ-026:** The system shall use one status LED to indicate system power-ON state.

**SYS-REQ-027:** The system shall use a separate green LED to indicate the current logical flap position.

**SYS-REQ-028:** The system shall ensure only one green LED corresponding to the logical position is ON at a given time.

**SYS-REQ-029:** The system shall update the green LED indication immediately upon a change in detected flap position.

**SYS-REQ-030:** The system shall maintain a simple indication scheme with no blinking, dimming, or color-mixing logic. [Implied]

---

## 7.0 System Behavioral Requirements

**SYS-REQ-031:** At power-up, the system shall initialize all peripherals (ADC, UART, GPIO, PWM), default motor to OFF, and read the current flap position.

**SYS-REQ-032:** During idle, the system shall wait for valid user command input via UART.

**SYS-REQ-033:** When a valid target position is commanded, the system shall move the flap to the new position and then return to idle.

**SYS-REQ-034:** When the target position is reached, the system shall stop the motor and indicate the current position via LED.

**SYS-REQ-035:** Upon receiving an invalid user command, the system shall ignore it without affecting system state.

**SYS-REQ-036:** If, during movement, the ADC returns a value out of the defined range, the system shall stop the motor and enter idle state.

**SYS-REQ-037:** The system shall operate solely as a command/execute/indicate loop, with no explicit state machine implemented in software. [Implied]

---

## 8.0 System Interface Requirements

**SYS-REQ-038:** The system shall support UART connectivity to a PC or laptop for user command input.

**SYS-REQ-039:** The system shall support output control signals to an external motor driver module for DC motor actuation.

**SYS-REQ-040:** The system shall use an ADC input channel to read the potentiometer feedback.

**SYS-REQ-041:** The system shall provide output signals for driving at least one status LED and one LED per logical flap position.

**SYS-REQ-042:** The system shall use only the following physical interfaces: UART (user input), ADC (position sensing), GPIO (motor and LED control), PWM/timer (motor enable). [Implied]

---

## 9.0 Constraints and Assumptions

**SYS-REQ-043:** Only one flap is controlled by the system.

**SYS-REQ-044:** Only one motor is controlled by the system.

**SYS-REQ-045:** Only one user command shall be processed at any given time.

**SYS-REQ-046:** No vehicle network (e.g., CAN, LIN) or external communication is required.

**SYS-REQ-047:** Calibration values for ADC position mapping are statically defined and assumed to be correct.

**SYS-REQ-048:** No dynamic configuration or self-calibration of ADC or position mapping is required.

**SYS-REQ-049:** The hardware (microcontroller, motor, driver, potentiometer, power supplies) is presumed to be functioning correctly; only basic software-level error handling is provided. [Implied]

---

## 10.0 Non-Functional Requirements

### 10.1 Responsiveness Expectations

**SYS-REQ-050:** The system shall respond to user UART commands in a manner that feels immediate to a human user under typical operating conditions.

**SYS-REQ-051:** The system shall update LED indicators promptly when flap position changes.

**SYS-REQ-052:** The system shall not attempt to guarantee real-time deadlines for any operation. [Implied]

### 10.2 Error Handling and Edge Cases

**SYS-REQ-053:** The system shall ignore invalid UART input (non-numeric or out-of-range values) with no error feedback.

**SYS-REQ-054:** The system shall halt the motor if ADC feedback is out-of-range.

**SYS-REQ-055:** If the flap cannot reach the commanded position, the system shall not crash or lock up.

### 10.3 Resource Constraints

**SYS-REQ-056:** The implementation shall use only static memory allocation; no dynamic memory allocation is permitted.

**SYS-REQ-057:** System behavior shall remain deterministic and bounded, even under invalid input conditions.

### 10.4 Maintainability and Modularity

**SYS-REQ-058:** The software design shall separate interfaces and major system responsibilities (command handling, actuator control, feedback, and indication) into distinct modules where practical.

**SYS-REQ-059:** The requirements, design, and code structure shall be simple and comprehensible by engineers new to embedded control.

### 10.5 Testability

**SYS-REQ-060:** The system shall enable manual and script-based testing through visible LED outputs and bidirectional UART command input.

**SYS-REQ-061:** The system shall provide sufficient observability of status and state through LEDs and UART for the intended demonstration purposes.

---

## Architecture-Relevant Considerations Derived from System Requirements

- The system executes a single-responsibility control loop (command, move, indicate), with all actions initiated in response to direct user input.
- No concurrent responsibilities or real-time task scheduling is implied.
- All interactions with external components are direct: UART for commands, ADC for feedback, GPIO/PWM for actuation and LEDs.
- The system’s control logic is simple, bounded, and event-driven by UART input, with all feedback and indication occurring in near real-time.
- No vehicle networking or expanded communication requirements are present.
- Any expansion (e.g., more flaps, multi-user, or networking) would require revisiting the requirement structure and architecture.

# 1.0 Software Scope and Responsibility

The software for the HVAC Flap Actuator system is responsible for:

- Receiving and processing user commands for flap position via UART.
- Controlling the actuation of a DC motor to adjust the air flap to the commanded position.
- Acquiring position feedback using ADC from a potentiometer.
- Indicating system and flap position status using LEDs.
- Managing data, configuration, and error-handling logic such that the system behavior remains deterministic, bounded, testable, and implementation-neutral.

---

# 2.0 Software Functional Requirements

## 2.1 User Command Handling

SWE-REQ-001: The software shall receive user position commands via UART (trace: SYS-REQ-001, SYS-REQ-020, SYS-REQ-038).

SWE-REQ-002: The software shall validate each received UART command to ensure it is a single ASCII numeric value representing a discrete flap position within the allowed range (trace: SYS-REQ-021, SYS-REQ-022, SYS-REQ-025).

SWE-REQ-003: The software shall ignore and not process any UART command that is not a valid position code (0-5) (trace: SYS-REQ-023, SYS-REQ-035, SYS-REQ-053).

SWE-REQ-004: The software shall process only one user command at a time and ignore further commands until the execution of the previous command is complete (trace: SYS-REQ-025, SYS-REQ-045).

SWE-REQ-005: The software shall not send acknowledgments or error messages in response to invalid or out-of-range commands (trace: SYS-REQ-024).

SWE-REQ-006: The software shall ignore new position commands if the requested position matches the current flap position [Implied] (trace: SYS-REQ-007).

## 2.2 Flap Position Control Logic

SWE-REQ-007: The software shall determine the current flap position from ADC feedback and compare it to the commanded target position (trace: SYS-REQ-002, SYS-REQ-016).

SWE-REQ-008: The software shall decide the required direction of movement—clockwise or anti-clockwise—to reach the target position (trace: SYS-REQ-002, SYS-REQ-008).

SWE-REQ-009: The software shall hold the flap at the commanded position after achieving the target (trace: SYS-REQ-006).

SWE-REQ-010: The software shall ignore further position adjustment until a new valid command is received [Implied] (trace: SYS-REQ-006, SYS-REQ-025).

## 2.3 Motor Control Logic

SWE-REQ-011: The software shall control output signals to the DC motor driver to enable or disable motor movement as required (trace: SYS-REQ-003, SYS-REQ-010, SYS-REQ-039).

SWE-REQ-012: The software shall set the motor direction using GPIO outputs based on the flap's required movement (trace: SYS-REQ-008, SYS-REQ-009).

SWE-REQ-013: The software shall stop the motor when the feedback position matches the commanded target within defined tolerances (trace: SYS-REQ-004, SYS-REQ-011, SYS-REQ-034).

SWE-REQ-014: The software shall stop the motor and prevent movement if position feedback is outside the defined calibration or operating range (trace: SYS-REQ-012, SYS-REQ-018, SYS-REQ-036, SYS-REQ-054).

SWE-REQ-015: The software shall ensure the motor is off until a valid position command is received (trace: SYS-REQ-013, SYS-REQ-031).

## 2.4 Position Feedback Processing

SWE-REQ-016: The software shall acquire the analog position feedback signal from the potentiometer via ADC (trace: SYS-REQ-014, SYS-REQ-015, SYS-REQ-040).

SWE-REQ-017: The software shall convert ADC readings to discrete logical flap positions using defined thresholds (trace: SYS-REQ-016, SYS-REQ-017, SYS-REQ-019).

SWE-REQ-018: The software shall treat any ADC reading outside of configured calibration limits as “out-of-range” (trace: SYS-REQ-018, SYS-REQ-054).

SWE-REQ-019: The software shall initialize and use ADC calibration data from static configuration (trace: SYS-REQ-019, SYS-REQ-047).

## 2.5 Status Indication Control

SWE-REQ-020: The software shall control a status LED to indicate system power-on (trace: SYS-REQ-026, SYS-REQ-041).

SWE-REQ-021: The software shall control dedicated LEDs to indicate the current logical flap position (trace: SYS-REQ-027, SYS-REQ-028, SYS-REQ-041).

SWE-REQ-022: The software shall ensure that only one position LED is active at any given time (trace: SYS-REQ-028).

SWE-REQ-023: The software shall update the LED indication immediately upon detecting a change in flap position (trace: SYS-REQ-029, SYS-REQ-051).

SWE-REQ-024: The software shall implement a simple indication scheme (one LED per position, ON/OFF, no blinking or color mixing) [Implied] (trace: SYS-REQ-030).

# 4.0 Software Behavioral Requirements

SWE-REQ-030: The software shall initialize all peripherals (UART, ADC, GPIO, PWM/timers) and load static configuration data at power-up (trace: SYS-REQ-031).

SWE-REQ-031: The software shall set the motor driver to a safe/disabled state at initialization (trace: SYS-REQ-013, SYS-REQ-031).

SWE-REQ-032: The software shall detect and translate the current flap position via ADC immediately after startup (trace: SYS-REQ-031).

SWE-REQ-033: The software shall wait for valid user command input during idle state (trace: SYS-REQ-032).

SWE-REQ-034: Upon receiving a valid command, the software shall initiate position adjustment and only accept new commands after the requested position is reached (trace: SYS-REQ-033, SYS-REQ-045).

SWE-REQ-035: The software shall indicate the new position on the appropriate LED once the commanded position is reached (trace: SYS-REQ-034).

SWE-REQ-036: If an invalid command is received, the software shall ignore it and preserve the current system state (trace: SYS-REQ-035, SYS-REQ-053).

SWE-REQ-037: If, during movement, the ADC returns an out-of-range value, the software shall stop the motor and return to idle (trace: SYS-REQ-036, SYS-REQ-054).

SWE-REQ-038: The software shall operate in a command/execute/indicate logical sequence without reliance on explicit scheduling, periodicity, or state machines [Implied] (trace: SYS-REQ-037).

# 5.0 Software Data and Configuration Requirements

SWE-REQ-039: The software shall store allowable flap positions, ADC threshold values, and calibration constants in static configuration at compile time (trace: SYS-REQ-017, SYS-REQ-019, SYS-REQ-047).

SWE-REQ-040: The software shall use this configuration data for all conversions of ADC readings to logical positions (trace: SYS-REQ-016, SYS-REQ-019).

SWE-REQ-041: The software shall maintain only the minimum required internal state information to track the latest user command, current logical flap position, and direction of last movement (trace: SYS-REQ-057).

SWE-REQ-042: The software shall not allow user or run-time modification of calibration values (trace: SYS-REQ-048).

SWE-REQ-046: The software shall ensure all error handling is deterministic and cannot result in undefined or unbounded system behavior (trace: SYS-REQ-057).
