# 1.0 System Overview

The HVAC Flap Actuator System SHALL enable a user to command and control the position of an air flap, driven by a DC motor, with real-time feedback and visual status indication. It is intended for prototyping of automotive HVAC position control.

---

# 2.0 Flap Position Control

- SYS-REQ-001: The system SHALL allow the user to request the flap position using numeric commands corresponding to discrete positions.
- SYS-REQ-002: The system SHALL move the flap to the target position specified by each valid user command.
- SYS-REQ-003: The system SHALL stop the motor once the flap has reached the requested position.
- SYS-REQ-004: The system SHALL ignore invalid user commands.
- SYS-REQ-005: The system SHALL support a fixed number of logical flap positions, as defined in software.

---

# 3.0 Motor Control

- SYS-REQ-006: The system SHALL control a DC motor using GPIOs for clockwise and anti-clockwise rotation.
- SYS-REQ-007: The system SHALL stop the motor when the flap reaches the requested position.
- SYS-REQ-008: The system SHALL prevent the motor from running if the requested position or feedback signal is invalid.

---

# 4.0 Position Feedback Acquisition & Processing

- SYS-REQ-009: The system SHALL acquire flap position feedback using a potentiometer connected to the ADC.
- SYS-REQ-010: The system SHALL map ADC values to logical flap positions.
- SYS-REQ-011: The system SHALL update the detected flap position during operation.

---

# 5.0 User Command Interface

- SYS-REQ-012: The system SHALL receive user commands exclusively via UART.
- SYS-REQ-013: The system SHALL interpret each valid UART numeric command as a target flap position.
- SYS-REQ-014: The system SHALL not require acknowledgment or response to invalid user commands.

---

# 6.0 Status Indication

- SYS-REQ-015: The system SHALL use a power/status LED to indicate when the system is powered ON.
- SYS-REQ-016: The system SHALL use up to one green LED at a time to indicate the current flap position.
- SYS-REQ-017: The system SHALL update LED status in response to position changes and power events.

---

# 7.0 System Behavior (power-up, idle, normal, target reached, invalid input)

- SYS-REQ-018: On power-up, the system SHALL initialize all necessary peripherals (ADC, UART, GPIO, PWM).
- SYS-REQ-019: On power-up, the motor SHALL remain OFF until a valid command is received.
- SYS-REQ-020: On power-up, the system SHALL detect and indicate the current flap position.
- SYS-REQ-021: When idle, the system SHALL not move the motor until a valid command is received.
- SYS-REQ-022: The system SHALL safely ignore invalid input commands without system fault.

---

# 8.0 Interfaces (UART, motor driver, ADC, LEDs)

- SYS-REQ-023: The system SHALL interface with the user via a UART serial connection.
- SYS-REQ-024: The system SHALL interface with the DC motor via a motor driver module.
- SYS-REQ-025: The system SHALL interface with the potentiometer via an ADC channel for position feedback.
- SYS-REQ-026: The system SHALL use GPIO or PWM signals to control motor operations and LED indications.

---

# 9.0 Constraints & Assumptions

- SYS-REQ-027: The number of flap positions and associated ADC ranges SHALL be configurable in software.
- SYS-REQ-028: Only one flap actuator and one motor SHALL be controlled by the system.
- SYS-REQ-029: Only one user command SHALL be processed at a time.
- SYS-REQ-030: No attempt SHALL be made to recover from hardware failures. [Implied]
- SYS-REQ-031: No dynamic calibration SHALL be performed at runtime. [Implied]
- SYS-REQ-032: System operation SHALL assume hardware is functional unless error conditions are detected. [Implied]

---

# 10.0 Non-Functional Requirements

## 10.1 Responsiveness

- SYS-REQ-033: The system SHALL process UART commands and update flap position within a human-perceivable response time (≤ 200 ms typical). [Implied]

## 10.2 Error Handling & Edge Cases

- SYS-REQ-034: The system SHALL stop the motor if ADC readings fall outside defined ranges.
- SYS-REQ-035: The system SHALL ignore UART commands that are not recognized as valid positions.

## 10.3 Resource Constraints

- SYS-REQ-036: The system software SHALL use only available memory and resources of the target hardware, with no dynamic memory allocation.
- SYS-REQ-037: The system SHALL fit within the resource limits of the STM32F407G-DISC1 platform.

## 10.4 Maintainability & Modularity

- SYS-REQ-038: The system software design SHALL be modular to allow straightforward changes to position mapping, UI, or interfaces.

## 10.5 Testability

- SYS-REQ-039: The system SHALL facilitate testability by enabling flap movement and indication to be verified by UART commands and LED outputs.
- SYS-REQ-040: The system SHALL permit manual test cases for all major functions.

---

# Architecture-Relevant Considerations Derived from System Requirements

- The system exhibits simple control flow: commands are handled one-at-a-time (no explicit concurrency).
- Interaction complexity is low: communications are peer-to-peer—UART (user), ADC (feedback), GPIO/PWM (motor/LED).
- Control complexity is moderate: command validation, actuator/feedback mapping, and simple error handling.
- The design is expandability-friendly: additional positions, new indication styles, or new feedback mapping logic can be added with modular code changes.
- No assumptions are made regarding the underlying execution model or task scheduling.
