SYSTEM REQUIREMENTS DOCUMENT
HVAC FLAP ACTUATOR SYSTEM

1.0 System Overview
The HVAC Flap Actuator System is a microcontroller-based demonstration platform for educational purposes, designed to control the position of an air distribution flap in a manner analogous to automotive HVAC systems. The system consists of a DC motor-driven flap, with position feedback provided by a potentiometer, user command input via UART from a connected PC, and status indication using LEDs. Its purpose is to showcase fundamental embedded control, actuation, and feedback mechanisms.

2.0 Flap Position Control Requirements
SYS-REQ-001: The system shall allow the user to select a target flap position via UART command.
SYS-REQ-002: The system shall compare the current flap position to the commanded target position.
SYS-REQ-003: The system shall move the flap to the commanded target position.
SYS-REQ-004: The system shall stop the flap motor once the target position is achieved.
SYS-REQ-005: The system shall continuously monitor flap position for command tracking.
SYS-REQ-006: The system shall hold the flap at the target position once reached.
[Implied] SYS-REQ-007: The system shall reject commands outside the supported position range.

3.0 Motor Control Requirements
SYS-REQ-008: The system shall provide digital signals to control the direction of the DC motor.
SYS-REQ-009: The system shall enable and disable the DC motor using a digital output (PWM or GPIO).
SYS-REQ-010: The system shall stop the motor upon reaching the target position or upon receiving an invalid condition (e.g., out-of-range feedback).
[Implied] SYS-REQ-011: Motor commands shall not cause the flap to move beyond defined end positions.

4.0 Position Feedback Acquisition and Processing
SYS-REQ-012: The system shall acquire analog position feedback from a potentiometer via an ADC channel.
SYS-REQ-013: The system shall map ADC values to a set of discrete logical flap positions (e.g., 0 to 5).
SYS-REQ-014: The system shall identify flap position by comparing ADC input to predefined position ranges.
[Implied] SYS-REQ-015: The system shall update the detected flap position upon each new ADC reading.

5.0 User Command Interface Requirements
SYS-REQ-016: The system shall receive user commands from the UART interface.
SYS-REQ-017: The system shall interpret each received numeric command as a target flap position (0–5 inclusive).
SYS-REQ-018: The system shall validate incoming commands for range and syntax.
SYS-REQ-019: The system shall ignore any invalid (malformed or out-of-range) command (no response required).
[Implied] SYS-REQ-020: The system shall not acknowledge valid or invalid commands by default.

6.0 Status Indication Requirements
SYS-REQ-021: The system shall control at least one LED to indicate power/system status.
SYS-REQ-022: The system shall use distinct green LEDs to display current flap position; at most one green LED shall be ON at a time.
[Implied] SYS-REQ-023: Status LEDs shall always accurately reflect present system and flap-position state.

7.0 System Behavioral Requirements
SYS-REQ-024: On power-up, the system shall initialize all required peripherals (ADC, UART, GPIO, PWM).
SYS-REQ-025: On power-up, the system shall keep the motor OFF until commanded.
SYS-REQ-026: On power-up, the system shall determine and indicate the current flap position.
SYS-REQ-027: The system shall remain idle when no valid command is present.
SYS-REQ-028: The system shall move the flap within defined bounds only when a valid command is received.
SYS-REQ-029: The system shall stop the motor and hold if the target is reached or an invalid input/feedback is detected.
[Implied] SYS-REQ-030: The system shall prevent state transitions that could endanger hardware.

8.0 System Interface Requirements
SYS-REQ-031: The system shall use a UART interface (with USB-to-UART converter) for command receipt from PC.
SYS-REQ-032: The system shall provide control outputs to an external H-Bridge motor driver (e.g., L298N) for motor actuation.
SYS-REQ-033: The system shall input analog feedback from flap position potentiometer via ADC.
SYS-REQ-034: The system shall output control signals to LEDs for indicating status and position.
[Implied] SYS-REQ-035: All interfaces shall follow electrical and logical specifications for STM32F407G-DISC1 compatibility.

9.0 Constraints and Assumptions
SYS-REQ-036: The system shall control only a single flap and a single DC motor.
SYS-REQ-037: Only one user command is processed at a time.
SYS-REQ-038: All logical and ADC ranges for position mapping are statically defined in software.
[Implied] SYS-REQ-039: No dynamic calibration or end-stop homing is performed at runtime.

10.0 Non-Functional Requirements
10.1 Responsiveness Expectations
SYS-REQ-040: The system shall exhibit human-perceivable responsiveness to commands (less than 0.5 seconds, if measurable) [Implied: no hard real-time guarantees required].

10.2 Error Handling and Edge Cases
SYS-REQ-041: The system shall halt the motor if ADC readings fall outside valid ranges.
SYS-REQ-042: The system shall not crash or enter undefined state if invalid command or ADC is received.
SYS-REQ-043: The system shall ignore commands if motor/actuator feedback indicates a fault.

10.3 Resource Constraints
SYS-REQ-044: The system shall avoid dynamic memory allocation and run within the resources of STM32F407G-DISC1.

10.4 Maintainability and Modularity
SYS-REQ-045: The system shall keep position control, user interface, feedback acquisition, and indication logic as logically separate modules.
SYS-REQ-046: System requirements, implementation details, and tests shall be clearly documented for educational review.
[Implied] SYS-REQ-047: The system structure shall be simple enough for easy extension or adaptation.

10.5 Testability
SYS-REQ-048: System shall provide clear observability through LEDs and UART for manual/script-based testing.
SYS-REQ-049: The system shall allow verification of correct actuation and feedback response via PC and physical inspection.

ARCHITECTURE-RELEVANT CONSIDERATIONS DERIVED FROM SYSTEM REQUIREMENTS
- The system consists of a single control responsibility (one flap, one actuator), simplifying the architecture.
- External interactions are limited to direct hardware connections (no networking, LIN/CAN, or multi-node coordination).
- All control logic is single-threaded and event-driven (by UART input or periodic ADC sampling).
- System structure emphasizes logical separation of functional modules (command, actuation, feedback, indication), supporting clarity and modularity.
- Expandability is limited by single flap/motor context, but requirements are generic for adaptation to similar demonstrations.
- No recommendation or inference is made about the execution model (super-loop, RTOS, etc.) or hardware abstraction approach in this requirements document.

# Software Requirements Document
## 1.0 Software Scope and Responsibility
The software of the HVAC Flap Actuator System executes on a microcontroller, receiving user commands via UART, acquiring position feedback using ADC, controlling the motor and status LEDs through GPIO/PWM, and implementing logic to control, restrict, and report the flap position. All requirements hereafter avoid architectural, scheduling, or execution-model prescriptions.

## 2.0 Software Functional Requirements
### 2.1 User Command Handling
- SWE-REQ-001: The software shall receive flap-position commands from the UART interface. (SYS-REQ-001, SYS-REQ-016)
- SWE-REQ-002: The software shall interpret numeric user commands as target flap positions (0–5 inclusive). (SYS-REQ-017)
- SWE-REQ-003: The software shall validate received user commands for range and syntax. (SYS-REQ-018)
- SWE-REQ-004: The software shall ignore malformed or out-of-range commands with no response. (SYS-REQ-019)
- SWE-REQ-005: [Implied] The software shall not acknowledge valid or invalid commands by default. (SYS-REQ-020)

### 2.2 Flap Position Control Logic
- SWE-REQ-006: The software shall compare the actual flap position to the commanded target position. (SYS-REQ-002, SYS-REQ-013)
- SWE-REQ-007: The software shall generate control signals to move the flap to the target position. (SYS-REQ-003)
- SWE-REQ-008: The software shall stop the motor after the target position is reached. (SYS-REQ-004)
- SWE-REQ-009: The software shall update monitoring logic to track initialization, movement, and holding. (SYS-REQ-005, SYS-REQ-006)
- SWE-REQ-010: [Implied] The software shall reject move commands outside supported flap range. (SYS-REQ-007)

### 2.3 Motor Control Logic
- SWE-REQ-011: The software shall control digital output signals for motor direction. (SYS-REQ-008)
- SWE-REQ-012: The software shall enable/disable the DC motor through digital output signals. (SYS-REQ-009)
- SWE-REQ-013: The software shall stop the motor upon reaching position or invalid condition. (SYS-REQ-010)
- SWE-REQ-014: [Implied] The software shall ensure that control output does not move the flap beyond position limits. (SYS-REQ-011)

### 2.4 Position Feedback Processing
- SWE-REQ-015: The software shall acquire position feedback from the potentiometer using the ADC channel. (SYS-REQ-012)
- SWE-REQ-016: The software shall map ADC readings to discrete logical positions. (SYS-REQ-013, SYS-REQ-038)
- SWE-REQ-017: The software shall determine the current flap position by comparing the ADC value to predefined thresholds. (SYS-REQ-014, SYS-REQ-038)
- SWE-REQ-018: [Implied] The software shall update detected flap position upon each valid ADC reading. (SYS-REQ-015)

### 2.5 Status Indication Control
- SWE-REQ-019: The software shall control system status and flap position LEDs via GPIO. (SYS-REQ-021, SYS-REQ-022)
- SWE-REQ-020: [Implied] The software shall ensure that status LEDs accurately reflect flap position and system state. (SYS-REQ-023)

## 3.0 Software Interface Requirements
- SWE-REQ-021: The software shall receive user commands from a PC over UART interface. (SYS-REQ-031)
- SWE-REQ-022: The software shall output motor control signals to an H-Bridge driver via GPIO/PWM. (SYS-REQ-032)
- SWE-REQ-023: The software shall use ADC interface to acquire analog feedback from the potentiometer. (SYS-REQ-033)
- SWE-REQ-024: The software shall output GPIO signals to drive system and flap-position LEDs. (SYS-REQ-034)
- SWE-REQ-025: [Implied] All interface configurations and signal levels shall comply with STM32F407G-DISC1 requirements. (SYS-REQ-035)

## 4.0 Software Behavioral Requirements
- SWE-REQ-026: On startup, the software shall initialize UART, ADC, GPIO, and PWM peripherals. (SYS-REQ-024)
- SWE-REQ-027: On startup, the motor shall remain off until a valid command is received. (SYS-REQ-025)
- SWE-REQ-028: On startup, the software shall detect and indicate the initial flap position. (SYS-REQ-026)
- SWE-REQ-029: The software shall process commands only when a valid command is pending. (SYS-REQ-027, SYS-REQ-028)
- SWE-REQ-030: The software shall continuously monitor flap position during operation. (SYS-REQ-005)
- SWE-REQ-031: The software shall stop movement and hold if the target is reached or an invalid input/feedback is detected. (SYS-REQ-029)
- SWE-REQ-032: [Implied] Transitions between operating states shall always be deterministic and never endanger hardware. (SYS-REQ-030)

## 5.0 Software Data and Configuration Requirements
- SWE-REQ-033: The software shall store static mappings of ADC values to logical flap positions. (SYS-REQ-038)
- SWE-REQ-034: The software shall use predefined ADC thresholds for position detection. (SYS-REQ-038)
- SWE-REQ-035: The software shall provide calibration constants as static configuration data. (SYS-REQ-038)
- SWE-REQ-036: The software shall store current and target flap position as internal state variables. (SYS-REQ-006, SYS-REQ-013, SYS-REQ-017)
- SWE-REQ-037: [Implied] No runtime end-stop homing or dynamic calibration shall be performed. (SYS-REQ-039)

## 6.0 Software Error Handling Requirements
- SWE-REQ-038: The software shall deterministically reject and ignore all invalid commands. (SYS-REQ-019, SYS-REQ-042)
- SWE-REQ-039: The software shall halt the motor and not actuate if ADC values are out of valid range. (SYS-REQ-041, SYS-REQ-010)
- SWE-REQ-040: The software shall prevent movement or actuation if feedback indicates a motor or position sensing fault. (SYS-REQ-043)
- SWE-REQ-041: The software shall avoid entering undefined states following invalid ADC readings or commands. (SYS-REQ-042)

## 7.0 Software Performance and Responsiveness Requirements
- SWE-REQ-042: The software shall ensure perceptible responsiveness to valid user commands (<0.5s, human-observable). (SYS-REQ-040)
- SWE-REQ-043: The software shall evaluate position tracking and control actions with minimal perceptible delay. (SYS-REQ-040)
- SWE-REQ-044: [Implied] The software does not require or implement strict time determinism or hard real-time constraints. (SYS-REQ-040)

## 8.0 Software Resource Constraint Requirements
- SWE-REQ-045: The software shall avoid dynamic memory allocation and operate within available MCU memory. (SYS-REQ-044)
- SWE-REQ-046: The software shall perform all logic with bounded, predictable execution time. (SYS-REQ-044)
- SWE-REQ-047: [Implied] The software shall not assume use of or reference to RTOS, threads, or scheduling constructs. (SYS-REQ-044)

## 9.0 Software Testability Requirements
- SWE-REQ-048: The software shall allow verification through UART command-response interaction from PC. (SYS-REQ-048)
- SWE-REQ-049: The software shall enable manual/script-based testing of actuation and feedback using LEDs and UART. (SYS-REQ-049)

## 10.0 Implied Software Requirements
- SWE-REQ-050: [Implied] No RTOS, thread, scheduling, multitasking, or concurrency assumption is included or inferred in this requirements specification. (Multiple system-level implied constraints)
- SWE-REQ-051: [Implied] The software requirement set strictly avoids definition of execution order, control cycles, or periodicity unless explicitly mandated at the system level. (Multiple system-level implied constraints)

## Explicit Exclusions
- No architectural, execution model, task, thread, safety, cybersecurity, or diagnostic protocol requirements are included.
- No assumptions or requirements regarding scheduling policies or prioritization are included.
- No references to RTOS, interrupts, super-loop, concurrency, or cyclic execution are present.
- No requirements pertaining to system safety integrity levels or cybersecurity are included.
- No requirements for communication protocols other than those directly specified (UART for commands).
