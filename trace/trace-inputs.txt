SYS-REQ-002: The system SHALL be implemented on a single microcontroller, supporting one air flap actuator only.
SYS-REQ-003: The system SHALL operate standalone, without interaction with any vehicle network (CAN, LIN, etc) or additional ECUs.

SYS-REQ-006: The system SHALL move the flap to the user-requested position.

1.0 ARCHITECTURE STYLE SELECTION
===============================

Candidate Styles:
  - Component-Based
  - Layered
  - Monolithic

Evaluation:
- System complexity is low; all responsibilities fit one MCU; interfaces are simple (UART, ADC, GPIO/PWM).
- HW interaction occurs via explicit microcontroller peripherals and GPIOs, with discrete roles for command, actuation, feedback, and indication (trace: SWE-REQ-017, 018, 019, 020).
- SWE.1 mandates modular responsibility separation (SWE-REQ-042, SYS-REQ-043), but not strict layering.
- Testability and maintainability both favor modularization (component-based), not global monolithic design.

Selection:
  - Component-Based architecture is selected for clear separation of concerns and direct traceability to SWE.1’s modularization and separation-of-responsibility requirements.
  - Layered is rejected as excessive for scope and for offering no concrete test, maintenance, or traceability benefit per requirements.
  - Monolithic is rejected as anti-traceability and fails maintainability/testability required by SWE-REQ-042/031/043.

LOW-LEVEL DESIGN (SWE.3)
====================
HVAC Flap Actuator Prototype Embedded Software
Branch: apr164-demo

--------------------------
Software Unit: Command Interpreter
--------------------------
1. Responsibilities
   - Handles UART receiving, parses and validates position commands [0-5], ignores malformed or out-of-bounds commands, forwards valid requests to Position Controller

2. Internal Data Design
   - Input buffer (fixed, statically-allocated char array, e.g., 8 bytes)
   - Integer variable for decoded command (0-5)
   - Status/flag: command_valid (bool)

3. State Machine
   - States: Idle, Awaiting Input, Validating, Forwarding, Error
   - Transitions: Awaiting Input → Validating on RX received | Validating → Forwarding if valid | Validating → Idle if invalid | Error for unrecoverable HW issues (should not occur in prototype, SW-REQ-043)

4. Algorithms & Control Flow
   - On UART RX: buffer input until end-of-line/command terminator
   - Parse as integer, check range
   - If in range: set command_valid, forward
   - Else: discard/ignore

5. Interfaces (APIs)
   - Provided: Command_Interpreter_Validate(CommandBuffer)
     - Input: pointer to RX buffer
     - Output: Valid command value or error (none)
   - Provides to: PositionController
   - Requires: UART RX API

6. Error Handling
   - Ignores malformed or out-of-range commands (SWE-REQ-002,003,032)
   - Never returns errors externally, reports no status via UART

7. Resource & Timing Considerations
   - Invoked on UART interrupt/callback or poll
   - WCET: <<1 ms per input
   - Non-reentrant (all input serialized via UART/SW-REQ-024/025/037)

8. Traceability: SWE-REQ-001,002,003,027,032

--------------------------
Software Unit: Position Controller
--------------------------
1. Responsibilities
   - Orchestrates target position change, tracks current state, coordinates motor, feedback, indicator units according to external command

2. Internal Data Design
   - Target position (0-5, uint8)
   - Current position (0-5, uint8/cached)
   - State: {Idle, Moving, Error}
   - Command pending flag

3. State Machine
   - States: Idle → Moving on valid command; Moving → Idle if reached; Moving → Error if out-of-bounds/feedback lost
   - Events: New command, feedback update, fault/ADC error
   - Actions: command to Motor/Feedback, update Indicator

4. Algorithms & Control Flow
   - On valid command: check if current != target; if yes, command motor, enter Moving
   - While Moving: request feedback (periodic/event-driven), if at target, stop motor, go idle
   - On error: stop motor, stay until new command

5. Interfaces (APIs)
   - Provided: PositionController_RequestMove(uint8 newpos)
   - Provides to: MotorActuator, FeedbackProcessor, IndicatorManager
   - Requires: CommandInterpreter_Validate, MotorActuator_Set, FeedbackProcessor_Get, IndicatorManager_Update

6. Error Handling
   - On error from feedback (out-of-range/lost ADC): command MotorActuator_Stop, lock out further movement until valid command (SWE-REQ-033)

7. Resource & Timing Considerations
   - Event-driven from CommandInterpreter, FeedbackProcessor
   - WCET: <5 ms per event (no concurrent calls)
   - Not re-entrant (one command at a time, SWE-REQ-024)

8. Traceability: SWE-REQ-004,005,006,024,025,026,028

--------------------------
Software Unit: Motor Actuator
--------------------------
1. Responsibilities
   - Drives GPIOs for CW/CCW, activates PWM for speed, enables/stops motor as required

2. Internal Data Design
   - Motor_enable (bool)
   - Direction (enum)
   - PWM duty cycle (fixed const or table for simplicity)

3. State Machine
   - States: Off, Active (Driving), Stopping
   - Off → Active when commanded; Active → Off on stop; Active → Stopping on error/target reached

4. Algorithms & Control Flow
   - Set direction pins; enable PWM
   - On stop: disable pins and PWM
   - Simple bounds: only allows valid direction

5. Interfaces (APIs)
   - Provided: MotorActuator_Set(Direction, Enable), MotorActuator_Stop()
   - Requires: GPIO, PWM driver APIs
   - Provides to: None

6. Error Handling
   - On error (commanded): disables all motor outputs
   - No internal recovery; blocks further action until PositionController clears error

7. Resource & Timing Considerations
   - Only active on PositionController command
   - WCET: <<1 ms
   - Not re-entrant (latched action)

8. Traceability: SWE-REQ-007,008,018,023,026

--------------------------
Software Unit: Feedback Processor
--------------------------
1. Responsibilities
   - Acquires ADC value, maps to discrete position, validates feedback integrity

2. Internal Data Design
   - Last ADC reading (uint16)
   - Calibration table (const[]; static)
   - LastValidPosition (int8)

3. State Machine
   - No persistent state: Stateless per-call or “none” (as periodic sample)
   - Explanation: stateless API, invoked as needed, stores last sample for controller

4. Algorithms & Control Flow
   - Read ADC, apply calibration, map to [0-5]
   - Check bounds; if out-of-range, report error

5. Interfaces (APIs)
   - Provided: FeedbackProcessor_GetPosition()
     - Output: position (0-5) or error flag
   - Requires: ADC driver API

6. Error Handling
   - Out-of-calibration or failed ADC: sets error, notifies PositionController

7. Resource & Timing Considerations
   - Called by PositionController every movement or periodically
   - WCET: <1 ms
   - Not re-entrant, but safe for stateless call

8. Traceability: SWE-REQ-009,010,011,012,019,033

--------------------------
Software Unit: Indicator Manager
--------------------------
1. Responsibilities
   - Manages all status LEDs (power, position)

2. Internal Data Design
   - LED status (current/target position)
   - LED GPIO state cache array

3. State Machine
   - None: State is derived instantly from controller input; no retained behavior
   - Explanation: On each update, set GPIOs as per position

4. Algorithms & Control Flow
   - Set power LED ON
   - For position LED: illuminate only one corresponding to flap position

5. Interfaces (APIs)
   - Provided: IndicatorManager_Update(position)
   - Requires: GPIO API

6. Error Handling
   - Any error/fault: ensure all LEDs OUT except power; hardware error cannot be signaled in prototype

7. Resource & Timing Considerations
   - Set only on PositionController event
   - WCET: <<1 ms
   - Safe for repeated use (not re-entrant)

8. Traceability: SWE-REQ-013,014,015,016,020,031,040,041

--------------------------
Software Unit: System Init/Platform
--------------------------
1. Responsibilities
   - Initializes all MCU peripherals, setups pin muxing, loads calibration

2. Internal Data Design
   - Peripheral state config vars
   - Calibration table (as in Feedback Processor)

3. State Machine
   - None; all one-time init actions
   - Explanation: Entry procedures only

4. Algorithms & Control Flow
   - Init all clocks, GPIOs, UART, ADC, PWM, setup static config

5. Interfaces (APIs)
   - Provided: SystemInit_All(), SystemInit_GetCalibration()
   - Requires: None

6. Error Handling
   - Returns fail code on unrecoverable HW init issue (only visible for debug/dev)

7. Resource & Timing Considerations
   - Called only at boot
   - WCET: ~5ms total
   - Not re-entrant, only once

8. Traceability: SWE-REQ-021,022,029,030,037,038,039,043

#include "command_interpreter.h"
#include <string.h>
#include <stdlib.h>

static char cmd_buffer[CMD_INBUF_SIZE];
static bool command_valid = false;
static uint8_t decoded_command = 0;

void CommandInterpreter_Init(void) {
    memset(cmd_buffer, 0, CMD_INBUF_SIZE);
    command_valid = false;
    decoded_command = 0;
}

// Returns true if buffer parses to integer 0-5, sets valid_cmd_out
bool CommandInterpreter_Validate(const char* rx_buffer, uint8_t* valid_cmd_out) {
    if (!rx_buffer || !valid_cmd_out)
        return false;
    int value = atoi(rx_buffer);
    if (value >= 0 && value <= 5) {
        *valid_cmd_out = (uint8_t)value;
        command_valid = true;
        decoded_command = *valid_cmd_out;
        return true;
    }
    command_valid = false;
    return false;
}

    pos_state = POS_IDLE;
    current_pos = FeedbackProcessor_GetPosition();
    target_pos = current_pos;
    cmd_pending = false;
    IndicatorManager_Update(current_pos);
    MotorActuator_Stop();
}

// Returns true if accepted/started move request
bool PositionController_RequestMove(uint8_t tgt_position) {
    if (tgt_position > 5 || pos_state == POS_ERROR)
        return false;
    if (tgt_position == current_pos)
        return false;
    target_pos = tgt_position;
    pos_state = POS_MOVING;
    cmd_pending = true;
    return true;
}

void PositionController_MainLoop(void) {
    switch(pos_state) {
    case POS_IDLE:
        // No action
        break;
    case POS_MOVING: {
        uint8_t feedback = FeedbackProcessor_GetPosition();
        if (feedback == 0xFF) {
            pos_state = POS_ERROR;
            MotorActuator_Stop();
            break;
        }        
        if (feedback == target_pos) {
            MotorActuator_Stop();
            current_pos = feedback;
            IndicatorManager_Update(current_pos);
            pos_state = POS_IDLE;
            break;
        }
        if (feedback < target_pos)
            MotorActuator_Set(DIR_CW, true);
        else
            MotorActuator_Set(DIR_CCW, true);
        IndicatorManager_Update(feedback);
        break;
    }
    case POS_ERROR:
        // Latch error, require reset or new command
        MotorActuator_Stop();
        IndicatorManager_Update(0xFF); // Show error (all LEDs off except power)
        break;
    }
}
