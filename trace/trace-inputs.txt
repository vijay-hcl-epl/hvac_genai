# 1.0 System Overview
The HVAC Flap Actuator system is a microcontroller-based demonstration platform for controlling a single air flap typically found in automotive HVAC systems. The system allows user selection of flap position via UART commands, moves the flap accordingly by controlling a DC motor, acquires continuous position feedback via a potentiometer, and provides status indication through LEDs. It is designed for learning, experimentation, and software process demonstration as a prototype—not as a production ECU.

# 2.0 Flap Position Control Requirements
- **SYS-REQ-001:** The system shall allow selection of discrete target flap positions in response to valid user commands.
- **SYS-REQ-002:** The system shall continuously acquire the current flap position from the potentiometer/ADC.
- **SYS-REQ-003:** The system shall determine the required direction to move the flap based on the difference between the current and target positions.
- **SYS-REQ-004:** The system shall actuate the flap to reach the selected target position.
- **SYS-REQ-005:** Once the target position is reached, the system shall stop the motor and hold the flap at that position.
- **SYS-REQ-006:** The mapping of ADC ranges to logical flap positions (e.g., 0–5) shall be defined in software and fixed for the prototype.
- **SYS-REQ-007 [Implied]:** The system shall prevent unnecessary actuation if the flap is already at the requested position.

# 3.0 Motor Control Requirements
- **SYS-REQ-008:** The system shall control the DC motor direction through dedicated GPIO pins based on the target position.
- **SYS-REQ-009:** The system shall enable or disable motor movement using a dedicated enable signal (PWM or GPIO).
- **SYS-REQ-010:** The system shall stop (de-energize) the motor when the flap has reached the target position or when an error condition is detected (e.g., invalid ADC feedback).
- **SYS-REQ-011:** The system shall not attempt to move the flap outside its defined position limits.
- **SYS-REQ-012 [Implied]:** The system shall avoid excessive motor running by stopping the motor promptly on target acquisition or error.

# 4.0 Position Feedback Acquisition and Processing
- **SYS-REQ-013:** The system shall periodically initiate ADC sampling of the potentiometer to read the flap position.
- **SYS-REQ-014:** The system shall map the analog voltage (ADC value) to a defined logical flap position in software.
- **SYS-REQ-015:** The system shall detect and ignore ADC values outside valid operating ranges (those not corresponding to any supported flap position).
- **SYS-REQ-016 [Implied]:** The system shall ensure ADC readings are obtained with sufficient resolution and filtering (if required for stability in the prototype environment).

# 5.0 User Command Interface Requirements
- **SYS-REQ-017:** The system shall receive user commands via a UART interface connected to a PC.
- **SYS-REQ-018:** The system shall interpret and validate incoming UART commands as numeric values representing flap positions.
- **SYS-REQ-019:** The system shall ignore invalid or out-of-range UART commands without sending any response or error indication.
- **SYS-REQ-020:** The system shall accept only one user command at a time; no command queuing is required.
- **SYS-REQ-021 [Implied]:** The system shall process UART commands promptly upon reception to maintain responsiveness.

# 6.0 Status Indication Requirements
- **SYS-REQ-022:** The system shall use one dedicated LED to indicate power/status.
- **SYS-REQ-023:** The system shall use dedicated green LEDs to display the currently commanded or achieved flap position (one green LED ON at a time).
- **SYS-REQ-024:** The LED status shall always match the actual logical flap position as determined from ADC readings at any time.
- **SYS-REQ-025 [Implied]:** LED indication logic shall be simple, clear, and unambiguous for all allowed positions and power states.

# 7.0 System Behavioral Requirements
- **SYS-REQ-026:** On power-up, the system shall initialize all peripherals (ADC, UART, GPIO, PWM) and leave the motor OFF.
- **SYS-REQ-027:** On power-up, the system shall immediately sample and store the current flap position.
- **SYS-REQ-028:** While idle (not moving), the system shall monitor for both user commands and flap position changes.
- **SYS-REQ-029:** During normal operation, the system shall move the flap toward the requested position and detect when the target is reached.
- **SYS-REQ-030:** After reaching the target, the system shall maintain its state and ignore redundant commands unless a new target is provided.
- **SYS-REQ-031:** The system shall safely ignore invalid input conditions (invalid UART command, out-of-range feedback, etc.).
- **SYS-REQ-032 [Implied]:** No explicit state machine or production-grade diagnostic logic is required beyond safe ignoring of errors.

# 8.0 System Interface Requirements
- **SYS-REQ-033:** The system shall use a UART interface for receiving user commands from a PC.
- **SYS-REQ-034:** The system shall use GPIO outputs to control the DC motor (direction and enable), routed through an L298N motor driver.
- **SYS-REQ-035:** The system shall use an ADC interface for potentiometer readings.
- **SYS-REQ-036:** The system shall use GPIO outputs for controlling status and position indication LEDs.
- **SYS-REQ-037 [Implied]:** No CAN, LIN, or external network interfaces shall be used by the software or exposed to users.

# 9.0 Constraints and Assumptions
- **SYS-REQ-038:** Only one actuator (flap) and motor are present and controlled in the system.
- **SYS-REQ-039:** Only one user command is handled at a time.
- **SYS-REQ-040:** Hardware (ADC, motor, potentiometer, LEDs) is assumed to function correctly unless an error is explicitly detected by software rules.
- **SYS-REQ-041:** Calibration values for the ADC (flap position mapping) are static; no dynamic calibration or auto-learning is performed.
- **SYS-REQ-042 [Implied]:** System resource usage shall be lightweight and bounded, per microcontroller learning platform norms.

# 10.0 Non-Functional Requirements
## 10.1 Responsiveness Expectations
- **SYS-REQ-043:** The system shall provide observable responsiveness to user commands (flap position changes and indicator updates occur within a time frame considered prompt by a human operator).
  - No fixed timing constraints are imposed.

## 10.2 Error Handling and Edge Cases
- **SYS-REQ-044:** The system shall safely ignore invalid user commands, out-of-range feedback, and unexpected values without crashing or undefined behavior.
- **SYS-REQ-045:** If the ADC feedback is outside defined position range, the system shall stop the motor and not attempt further movement.
- **SYS-REQ-046 [Implied]:** No advanced error handling, diagnostics, or fault recovery logic (e.g., timeouts, reset) is required for this prototype.

## 10.3 Resource Constraints
- **SYS-REQ-047:** The overall software and data resource usage (RAM, code size, variables) shall be minimized to fit easily on STM32F407G-DISC1 resources.
- **SYS-REQ-048:** No dynamic memory allocation or non-volatile storage is required.

## 10.4 Maintainability and Modularity
- **SYS-REQ-049:** The system design shall separate responsibilities for command processing, position control, feedback acquisition, motor driving, and indication.
- **SYS-REQ-050:** The system design shall support ease of modification for learning and demonstration.
- **SYS-REQ-051 [Implied]:** Software shall be modular for simple addition or adjustment of commands and positions without restructuring the system.

## 10.5 Testability
- **SYS-REQ-052:** The system shall support testability by allowing UART command injection and LED observation without special tooling.
- **SYS-REQ-053:** Manual and batch/script testing using a connected PC, observed motor response, and LEDs shall be possible for all functional requirements.
- **SYS-REQ-054 [Implied]:** No automated HIL, SIL, or remote verification infrastructure is required for this prototype.

# Architecture-Relevant Considerations Derived from System Requirements
- The system does not require explicit concurrency or multi-tasking; all responsibilities (command interface, position control, feedback acquisition, indication) can be managed in a simple cyclic or main-loop structure.
- External interactions are limited and local: PC via UART (user commands), DC motor via driver IC, potentiometer ADC, on-board LEDs. No networking or remote interfaces.
- Control is simple, with all states and event progressions determined by UART input, real-time feedback, and LED state; complex scheduling or prioritization is not required or justified.
- Design should anticipate ease of expansion (e.g., adding extra positions, refining ADC calibration, or new LED patterns) while remaining simple and modular for ease of understanding and demonstration.
