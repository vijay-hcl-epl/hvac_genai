# 1.0 System Overview

The HVAC Flap Actuator System is a prototype embedded controller designed to operate an air mixing and direction flap within a simplified heating, ventilation, and air conditioning (HVAC) assembly. The system is intended for proof-of-concept, learning, and process demonstration purposes. The system uses a DC motor to rotate the flap between discrete positions; feedback is provided by a potentiometer with ADC measurement. The system is controlled via UART commands from a PC, and status (including power and flap position) is visually indicated via LEDs. The microcontroller and supporting electronics form a standalone embedded system, with no connectivity to vehicle communication networks.

# 2.0 Flap Position Control Requirements

**SYS-REQ-001**: The system shall allow the user to command a discrete target flap position in the range of 0 to 5 inclusive.

**SYS-REQ-002**: The system shall compare the current flap position to the commanded target position.

**SYS-REQ-003**: The system shall move the flap to the commanded target position as closely as possible within predefined ADC tolerance ranges.

**SYS-REQ-004**: While the flap is moving, the system shall continuously monitor current position.

**SYS-REQ-005**: The system shall stop the flap movement when the target position is reached within allowed tolerance.

**SYS-REQ-006**: The system shall hold the flap at the reached target position by disabling the motor after positioning.

**SYS-REQ-007**: The system shall ensure only one flap position command is processed at a time.

**SYS-REQ-008**: [Implied] The system shall ignore additional commands while a movement to the previous target is ongoing.

# 3.0 Motor Control Requirements

**SYS-REQ-009**: The system shall control the DC motor’s direction using two GPIO pins.

**SYS-REQ-010**: The system shall enable or disable the DC motor using a PWM signal.

**SYS-REQ-011**: The system shall set the direction rotation of the DC motor (clockwise or counterclockwise) according to difference between current and target flap position.

**SYS-REQ-012**: The system shall stop (disable) the motor once the target position is reached or if an error condition occurs.

**SYS-REQ-013**: Upon power-up, the system shall ensure the motor is OFF until a valid command is received.

# 4.0 Position Feedback Acquisition and Processing

**SYS-REQ-014**: The system shall acquire the flap position by sampling the potentiometer using an ADC input.

**SYS-REQ-015**: The system shall convert the measured ADC value into a logical flap position (0 to 5) using predefined ADC-to-position mapping ranges.

**SYS-REQ-016**: The system shall periodically sample and update the current flap position when the system is powered.

**SYS-REQ-017**: If the sampled ADC value is outside valid position ranges, the system shall stop or inhibit motor operation.

**SYS-REQ-018**: [Implied] The system shall allow for fixed, software-defined calibration of ADC-to-position mapping, adjustable by software update.

# 5.0 User Command Interface Requirements

**SYS-REQ-019**: The system shall receive target flap position commands via UART interface from an external PC.

**SYS-REQ-020**: Position commands shall be simple numeric values in the range of 0 to 5.

**SYS-REQ-021**: The system shall validate each UART command to ensure it is within the allowed value range.

**SYS-REQ-022**: If an invalid command is received, the system shall ignore the command safely without generating any UART response.

# 6.0 Status Indication Requirements

**SYS-REQ-023**: The system shall activate a power/status LED when the system is powered and initialized.

**SYS-REQ-024**: For each flap position (0 to 5), the system shall provide a dedicated green LED for visual indication.

**SYS-REQ-025**: The active flap position shall be shown by illuminating only the LED corresponding to the current logical position; all other green LEDs shall remain off.

**SYS-REQ-026**: [Implied] LED indication shall always represent the most recent flap position as determined by ADC measurement.

# 7.0 System Behavioral Requirements

**SYS-REQ-027**: Upon power-up, the system shall initialize all required peripherals (ADC, UART, GPIO, PWM, LEDs, etc.).

**SYS-REQ-028**: The system shall ensure the motor outputs are set to OFF state during system initialization.

**SYS-REQ-029**: The system shall read the current flap position after initialization and update LED status accordingly.

**SYS-REQ-030**: In idle operation, the system shall wait for user commands via UART.

**SYS-REQ-031**: Once a valid command is received, the system shall transition to "move flap" mode.

**SYS-REQ-032**: When target position is reached, the system shall return to idle mode and indicate position via LEDs.

**SYS-REQ-033**: When an invalid command is received, the system shall ignore it and remain in the previous state.

# 8.0 System Interface Requirements

**SYS-REQ-034**: The system shall provide a UART interface for receiving external user commands.

**SYS-REQ-035**: The system shall interface with a DC motor driver module (L298N or equivalent) for motor actuation.

**SYS-REQ-036**: The system shall connect the potentiometer (position sensor) to an ADC input channel on the microcontroller.

**SYS-REQ-037**: The system shall drive at least seven LEDs (one power/ status, six for positions) through GPIO for status indication.

# 9.0 Constraints and Assumptions

**SYS-REQ-038**: The system shall operate as a standalone controller with no network connectivity (e.g., no CAN, LIN, or Ethernet).

**SYS-REQ-039**: The system shall assume hardware is functioning correctly; no external diagnostics are required.

**SYS-REQ-040**: Only one flap and one actuator motor will be present in the system.

**SYS-REQ-041**: Only one user will interface with the system at a time.

**SYS-REQ-042**: [Implied] The system is not required to perform dynamic or runtime calibration of any sensors.

# 10.0 Non-Functional Requirements
## 10.1 Responsiveness Expectations

**SYS-REQ-043**: The system shall process user UART commands within a time frame perceptible as "responsive" to a human user.

**SYS-REQ-044**: The system shall update LED status shortly after flap position changes.

## 10.2 Error Handling and Edge Cases

**SYS-REQ-045**: The system shall stop the motor if the flap position feedback (ADC) value is outside the expected valid range.

**SYS-REQ-046**: The system shall not crash or hang in response to any invalid user command or sensor value.

**SYS-REQ-047**: The system shall not process further commands if a critical hardware error is detected. [Implied]

## 10.3 Resource Constraints

**SYS-REQ-048**: The system shall use only statically allocated memory (no dynamic allocation required).

**SYS-REQ-049**: The system shall operate using lightweight logic and predictable control flow for learning and demonstration purposes.

## 10.4 Maintainability and Modularity

**SYS-REQ-050**: The system architecture and requirement structure shall permit clear tracing from requirements to software design.

**SYS-REQ-051**: System modules/functions (motor control, input processing, feedback acquisition, indication) shall remain logically separated.

## 10.5 Testability

**SYS-REQ-052**: The system shall permit manual testing by sending UART commands from a PC and observing actuator and LED response.

**SYS-REQ-053**: The system shall permit simple script-based UART command testing.

**SYS-REQ-054**: All system states and behaviors shall be observable via LED or physical movement for verification.


# Architecture-Relevant Considerations Derived from System Requirements

- The system is single-responsibility, controlling only one actuator (flap), with no concurrency or multi-user aspects required.
- All external interactions are direct and simple: UART for user commands, GPIO/ADC/PWM for hardware control, no networking or asynchronous services needed.
- Control logic is fundamentally linear (idle→move→hold/idle), favoring a simple control state model.
- Expandability is limited and not a focus; requirements expressly limit scope to a single actuator and a fixed command protocol.
- The software can be modular in interface handling and functional grouping for clarity, maintainability, and educational purposes, but no elaborate software layering or scheduling model is imposed or implied.

# 1.0 Software Scope and Responsibility

The HVAC Flap Actuator software executes on a microcontroller and is solely responsible for direct digital control of a single HVAC air flap actuator via DC motor. The software accepts user commands through UART, processes and validates these commands, manages flap positioning by interacting with ADC (for feedback), GPIO and PWM (for motor and LED outputs), and maintains visible feedback through status LEDs. The software performs no networking, diagnostics, or concurrency, and operates fully standalone as per allocated system requirements.

# 2.0 Software Functional Requirements

## 2.1 User Command Handling

**SWE-REQ-001**: The software shall receive target flap position commands via UART as single numeric values. (SYS-REQ-019, SYS-REQ-020, SYS-REQ-034)

**SWE-REQ-002**: The software shall validate each received user command to ensure the commanded position is within the range 0 to 5, inclusive. (SYS-REQ-021)

**SWE-REQ-003**: The software shall safely ignore any UART command with a value outside the allowed range and produce no UART response for invalid commands. (SYS-REQ-022, SYS-REQ-033)

**SWE-REQ-004**: The software shall ensure that only one user command is processed at a time; additional commands received while processing a previous command shall be ignored until movement is complete. (SYS-REQ-007, SYS-REQ-008, SYS-REQ-041)

## 2.2 Flap Position Control Logic

**SWE-REQ-005**: The software shall compare the current flap position (from ADC) to the last valid commanded position to determine if movement is required. (SYS-REQ-002, SYS-REQ-015)

**SWE-REQ-006**: The software shall command the motor to move toward the commanded target position if the target and current positions are not already equal within the specified ADC tolerance range. (SYS-REQ-003, SYS-REQ-005, SYS-REQ-011)

**SWE-REQ-007**: The software shall update the target position only after successful completion of the previous flap movement. (SYS-REQ-008)

**SWE-REQ-008**: The software shall hold the flap at the achieved target position by disabling the motor when the target is reached within the ADC tolerance. (SYS-REQ-006)

## 2.3 Motor Control Logic

**SWE-REQ-009**: The software shall control two GPIO outputs for motor direction and one PWM output for motor enable/disable, according to current and target flap positions. (SYS-REQ-009, SYS-REQ-010, SYS-REQ-035)

**SWE-REQ-010**: The software shall ensure the motor is in OFF (disabled) state during software initialization and whenever no movement is commanded. (SYS-REQ-013, SYS-REQ-028)

**SWE-REQ-011**: The software shall immediately stop the motor and prevent further movement if any error condition is detected. (SYS-REQ-012, SYS-REQ-017, SYS-REQ-045)

## 2.4 Position Feedback Processing

**SWE-REQ-012**: The software shall acquire the flap position by sampling a designated ADC channel connected to the flap potentiometer. (SYS-REQ-014, SYS-REQ-036)

**SWE-REQ-013**: The software shall convert each ADC reading to a logical position (0 to 5) using software-configured ADC ranges. (SYS-REQ-015, SYS-REQ-018)

**SWE-REQ-014**: The software shall determine if the current ADC value lies in a valid range; if not, it shall halt the motor and inhibit further motor activity until a valid ADC value is detected. (SYS-REQ-017, SYS-REQ-045)

**SWE-REQ-015**: The software shall update its stored logical flap position value at least each time UART input or flap movement is processed. (SYS-REQ-016, SYS-REQ-032)

## 2.5 Status Indication Control

**SWE-REQ-016**: The software shall control a dedicated system power/status LED output using GPIO, turning it ON upon successful initialization. (SYS-REQ-023, SYS-REQ-037)

**SWE-REQ-017**: The software shall control six green position LEDs using GPIO outputs, such that only the LED corresponding to the current logical flap position is illuminated. (SYS-REQ-024, SYS-REQ-025, SYS-REQ-037)

**SWE-REQ-018**: The software shall ensure LED status is updated immediately after position changes or software power-up. (SYS-REQ-044, SYS-REQ-029)

# 3.0 Software Interface Requirements

**SWE-REQ-019**: The software shall configure and use the microcontroller UART interface for reception of flap position commands from an external device. (SYS-REQ-034)

**SWE-REQ-020**: The software shall configure and use a microcontroller ADC channel to acquire potentiometer position feedback. (SYS-REQ-036)

**SWE-REQ-021**: The software shall drive two GPIO outputs for setting DC motor direction and one PWM-enabled GPIO for enabling/disabling the motor. (SYS-REQ-009, SYS-REQ-010, SYS-REQ-035)

**SWE-REQ-022**: The software shall drive seven LEDs (one power, six position) via GPIO. (SYS-REQ-023, SYS-REQ-024, SYS-REQ-037)

# 4.0 Software Behavioral Requirements

**SWE-REQ-023**: At startup, the software shall initialize all relevant peripherals (ADC, UART, GPIO, PWM, and LEDs). (SYS-REQ-027)

**SWE-REQ-024**: On initialization, the software shall read the existing flap position and update the LED display before accepting any user commands. (SYS-REQ-029)

**SWE-REQ-025**: During normal operation, the software shall wait for a valid received user command via UART before initiating any flap movement. (SYS-REQ-030)

**SWE-REQ-026**: On receipt of a valid command, the software shall process the command, determine and, if needed, initiate movement to the commanded position. (SYS-REQ-031)

**SWE-REQ-027**: When the flap reaches the commanded position within ADC tolerance, the software shall stop the motor, update the current position, and update the LED indication. (SYS-REQ-005, SYS-REQ-006, SYS-REQ-025, SYS-REQ-032)

**SWE-REQ-028**: If an invalid command is received, the software shall safely ignore the command and maintain its prior state. (SYS-REQ-022, SYS-REQ-033)

# 5.0 Software Data and Configuration Requirements

**SWE-REQ-029**: The software shall store and apply a mapping from valid ADC ranges to each logical flap position (0–5), configurable via software constants. (SYS-REQ-015, SYS-REQ-018)

**SWE-REQ-030**: The software shall store a current flap position value that is internally updated after each movement, ADC sampling event, or startup. (SYS-REQ-015, SYS-REQ-016, SYS-REQ-029)

**SWE-REQ-031**: The software shall employ calibratable software constants for ADC range boundaries associated with each logical position. (SYS-REQ-018)

# 6.0 Software Error Handling Requirements

**SWE-REQ-032**: The software shall ignore and not act upon UART commands that are out of valid range, malformed, or otherwise not interpretable. (SYS-REQ-021, SYS-REQ-022, SYS-REQ-033, SYS-REQ-046)

**SWE-REQ-033**: If the ADC input value does not correspond to any valid position, the software shall stop all motor output, inhibit further movement, and maintain safe idle until a valid ADC value is subsequently detected. (SYS-REQ-017, SYS-REQ-045, SYS-REQ-046)

**SWE-REQ-034**: The software shall not process commands or restart flap movement if a persistent hardware error is indicated. [Implied] (SYS-REQ-047)

# 7.0 Software Performance and Responsiveness Requirements

**SWE-REQ-035**: The software shall process valid UART commands and initiate movements with responsiveness suitable for manual human interaction (typically sub-second latency, exact timing not strictly defined). (SYS-REQ-043)

**SWE-REQ-036**: The software shall update position LED feedback within a short interval (e.g., human-noticeable responsiveness) after position changes. (SYS-REQ-044)

# 8.0 Software Resource Constraint Requirements

**SWE-REQ-037**: The software shall use only statically-allocated memory and shall not allocate memory dynamically at runtime. (SYS-REQ-048)

**SWE-REQ-038**: The software shall execute all processing in a predictable manner, avoiding the use of unbounded loops, recursion, or blocking waits unless bounded by an explicit software constant. (SYS-REQ-049)

# 9.0 Software Testability Requirements

**SWE-REQ-039**: The software shall support manual testability by accepting user-driven UART commands and providing observable responses via motor movement and LED status. (SYS-REQ-052, SYS-REQ-054)

**SWE-REQ-040**: The software shall support script-based UART command sequences that exercise all logical positions, error cases, and expected behaviors. (SYS-REQ-053)

# 10.0 Implied Software Requirements

**SWE-REQ-041**: [Implied] The software shall not require nor perform runtime calibration of any sensors unless so updated in software configuration. (SYS-REQ-042)

**SWE-REQ-042**: [Implied] The software shall logically separate functions and modules relating to motor control, user input processing, feedback acquisition, and status indication to maintain traceability and maintainability. (SYS-REQ-051, SYS-REQ-050)
