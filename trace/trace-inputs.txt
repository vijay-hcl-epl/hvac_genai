1.0 System Overview  
The HVAC flap actuator system SHALL provide automated control of a single air flap using an electric DC motor, based on user commands issued via UART. The system SHALL indicate status via LEDs and provide real-time feedback of flap position. All operations SHALL be confined to discrete flap positions, with explicit handling of invalid user inputs and system initialization.

---

2.0 Flap Position Control  
SYS-REQ-001: The system SHALL allow the user to select a flap position by sending a numeric command via UART, where each value corresponds to a defined discrete flap position (0–5).  
SYS-REQ-002: The system SHALL move the flap to the requested position by controlling the DC motor direction and activation.  
SYS-REQ-003: The system SHALL stop the motor when the target flap position is reached.  
SYS-REQ-004: The system SHALL ignore any user command specifying a position outside the valid range.  
SYS-REQ-005: The system SHALL only allow one flap position command to be processed at a time.  
SYS-REQ-006: The system SHALL prevent movement to undefined or unsupported positions.  
[Implied] The system SHALL map UART command values to physical positions using a predefined mapping.

---

3.0 Motor Control  
SYS-REQ-007: The system SHALL drive the DC motor using GPIO and PWM signals as required to achieve the required rotation direction (clockwise/anti-clockwise).  
SYS-REQ-008: The system SHALL cease power to the motor immediately when the current flap position matches the target.  
SYS-REQ-009: The motor SHALL remain off during system initialization, except when a valid move command is received.  
[Implied] The system SHALL not activate both motor directions simultaneously.

---

4.0 Position Feedback Acquisition & Processing  
SYS-REQ-010: The system SHALL read the potentiometer value via an ADC input to determine the current flap position.  
SYS-REQ-011: The system SHALL continuously (periodically) acquire the potentiometer reading and use it to update the logical flap position state.  
SYS-REQ-012: The system SHALL use predetermined ADC value ranges to map the potentiometer signal to discrete positions (0–5).  
SYS-REQ-013: If the ADC reading falls outside all defined ranges, the system SHALL turn off the motor and indicate no position selected via position LEDs.  
[Implied] The system SHALL assume that the potentiometer is mechanically linked to the flap.

---

5.0 User Command Interface  
SYS-REQ-014: The system SHALL accept position commands in the form of single numeric values sent over UART from a PC.  
SYS-REQ-015: The system SHALL ignore any message that is not a valid numeric command within the allowed range.  
SYS-REQ-016: The system SHALL not send any acknowledgement or error response for invalid commands.  
SYS-REQ-017: The UART interface SHALL allow only one user to interact with the system at a time.

---

6.0 Status Indication  
SYS-REQ-018: The system SHALL drive one designated LED to indicate power or system ON status.  
SYS-REQ-019: The system SHALL drive up to six discrete position LEDs, in which only the LED corresponding to the current detected position is ON at any given time; all others SHALL be OFF.  
SYS-REQ-020: If no valid position is detected, all position indicator LEDs SHALL remain OFF.  
[Implied] The system SHALL not implement any LED blinking or advanced indication patterns.

---

7.0 System Behavior (power-up, idle, normal, target reached, invalid input)  
SYS-REQ-021: On power-up, the system SHALL initialize all peripherals (UART, ADC, GPIO, PWM) before any actuator movement.  
SYS-REQ-022: On initialization, the system SHALL read the current flap position from the potentiometer and set the position indicator LEDs accordingly.  
SYS-REQ-023: In idle state (no pending command), the system SHALL leave the motor OFF and monitor for new UART commands.  
SYS-REQ-024: Upon receiving a valid command, the system SHALL enter active mode, moving the flap and updating position feedback, until the target is reached.  
SYS-REQ-025: After reaching the requested position, the system SHALL return to idle mode.  
SYS-REQ-026: If an invalid command is received, the system SHALL ignore it and remain in its current state.  
[Implied] The system SHALL not require any “homing” sequence at startup.

---

8.0 Interfaces (UART, motor driver, ADC, LEDs)  
SYS-REQ-027: The UART interface SHALL support command input from an external PC or laptop.  
SYS-REQ-028: The motor driver interface SHALL allow direction and enable/disable control for the DC motor.  
SYS-REQ-029: The ADC interface SHALL support continual acquisition of the potentiometer feedback signal.  
SYS-REQ-030: The GPIO interface SHALL control all status LEDs as well as the motor driver signals.  
[Implied] The PWM output (timer-based) is used for motor enable and motor speed control if required.

---

9.0 Constraints & Assumptions  
SYS-REQ-031: The system SHALL operate a single flap using a single DC motor driven by an L298N module.  
SYS-REQ-032: The system SHALL assume fixed calibration of ADC ranges for position mapping, as defined in software.  
SYS-REQ-033: The system SHALL not implement diagnostics, CAN or LIN communication, or production-grade fault handling.  
SYS-REQ-034: All system functions SHALL assume that external hardware and wiring are functioning correctly.  
[Implied] No software measures are required for calibration or dynamic parameter updates.

---

10.0 Non-Functional Requirements

10.1 Responsiveness  
SYS-REQ-035: The system SHALL process and act on user commands within a human-perceptible short period (target: less than 1 second typical response).

10.2 Error Handling & Edge Cases  
SYS-REQ-036: The system SHALL ignore and not act upon any command that does not map to a valid logical flap position (0–5).  
SYS-REQ-037: The system SHALL stop the motor if ADC readings are out of all defined position ranges.  
SYS-REQ-038: The system SHALL continue operation even if a requested position is not reached; no required timeouts or recovery actions are needed.  

10.3 Resource Constraints  
SYS-REQ-039: All system logic and data SHALL fit within the available resource limits of the STM32F407G-DISC1 microcontroller, and SHALL NOT use dynamic memory allocation.

10.4 Maintainability & Modularity  
SYS-REQ-040: Flap position mapping, UART command parsing, and motor control SHALL be implemented as separate functional modules to allow unit-level test and update.

10.5 Testability  
SYS-REQ-041: All functional requirements SHALL be testable by manual or script-based testing using UART command input and LED/motor observation.

---

## Architecture-Relevant Considerations Derived from System Requirements

- Concurrency Presence/Absence: Although the requirements imply simultaneous management of user input, flap position feedback, and motor/LED control, the expected operational model is sequential and event-driven; concurrency beyond interrupt-driven peripheral events is neither expected nor required.
- Interaction Complexity: The system exhibits limited interaction complexity: all commands, feedback, and indications are point-to-point and state transitions are simple, with no need for queuing or asynchronous message passing.
- Control Complexity: Control logic is straightforward, with no need for advanced state machines, sophisticated error recovery, or multi-actuator coordination. All control paths are single-instance and linear.
- Expandability: The requirements enable easy expansion (e.g., to more positions, more indicators, additional error handling) by changing configuration tables or adding further logical statements; code structure must support adding further commands or indicators without breaking requirement isolation.

1.0 Software Scope & Responsibility
The software controls a single HVAC air flap actuator using a DC motor, responding to user UART commands and providing feedback via LEDs. It implements system requirements for position selection, movement, indication, and feedback, interfacing only as strictly needed with UART, ADC, GPIO and PWM, and no additional system-level behavior. Implementation is MCU-agnostic (STM32F407 context implied for driver signal assignments) and independent from OS/scheduling models.

2.0 Software Functional Requirements

2.1 User Commands
SWE-REQ-001: The software SHALL accept and parse single numeric UART commands for selecting flap position (0–5). [SYS-REQ-001, SYS-REQ-014]
SWE-REQ-002: The software SHALL ignore any UART input that cannot be parsed as an integer in the valid position range. [SYS-REQ-004, SYS-REQ-015, SYS-REQ-036]
SWE-REQ-003: The software SHALL ensure that only one flap position command is processed at any time; concurrent or queued commands SHALL be ignored until completion of the current operation. [SYS-REQ-005, SYS-REQ-017]
SWE-REQ-004: The software SHALL not acknowledge or respond to invalid commands via UART. [SYS-REQ-016]
[Implied] UART interface is logically single-user per invocation.

2.2 Flap Control
SWE-REQ-005: The software SHALL translate valid UART flap position command to a discrete target position. [SYS-REQ-001, SYS-REQ-012]
SWE-REQ-006: The software SHALL command the motor to move the flap to the requested position and update the logical position state accordingly. [SYS-REQ-002, SYS-REQ-024]
SWE-REQ-007: The software SHALL prevent motor activation for target positions outside the supported range (0–5). [SYS-REQ-006, SYS-REQ-036]
SWE-REQ-008: The software SHALL provide a defined error state for input/ADC values that do not map to any supported flap position. [SYS-REQ-013, SYS-REQ-020]

2.3 Motor Control
SWE-REQ-009: The software SHALL output GPIO signals to motor driver to achieve the required direction and enable control. [SYS-REQ-007, SYS-REQ-028, SYS-REQ-030]
SWE-REQ-010: The software SHALL immediately cease all motor outputs when the current position matches the commanded target or ADC error state is detected. [SYS-REQ-003, SYS-REQ-008, SYS-REQ-037]
SWE-REQ-011: The software SHALL NOT activate both direction controls simultaneously (H-bridge shoot-through protection). [SYS-REQ-009]
SWE-REQ-012: The motor output SHALL remain off during initialization unless a valid command triggers activation. [SYS-REQ-009, SYS-REQ-021]
[Implied] PWM duty may be statically configured or fixed if variable speed is unused.

2.4 Feedback Processing
SWE-REQ-013: The software SHALL periodically sample ADC inputs to read the potentiometer value for flap position feedback. [SYS-REQ-010, SYS-REQ-029]
SWE-REQ-014: The software SHALL map ADC values in configured ranges for flap position detection. [SYS-REQ-012, SYS-REQ-032]
SWE-REQ-015: The software SHALL update the current logical state and indicator outputs based on ADC position changes. [SYS-REQ-011, SYS-REQ-022]
[Implied] ADC sampling interval is not specified; use a deterministic, event-driven acquisition if supported by hardware.

2.5 Status Indication
SWE-REQ-016: The software SHALL drive a designated LED to indicate main power/system status. [SYS-REQ-018]
SWE-REQ-017: The software SHALL drive position indicator LEDs so that exactly the LED corresponding to the detected position is on, with all others off. [SYS-REQ-019]
SWE-REQ-018: The software SHALL turn all position indicator LEDs off if no valid position is detected (ADC out-of-range). [SYS-REQ-020]
[Implied] No advanced blinking/status patterns beyond simple on/off per indicator.

3.0 Software Interface Requirements
SWE-REQ-019: The software SHALL use UART for user command reception. [SYS-REQ-027]
SWE-REQ-020: The software SHALL use ADC for potentiometer feedback acquisition. [SYS-REQ-029]
SWE-REQ-021: The software SHALL use GPIO (and optionally PWM) output for controlling motor direction/enable. [SYS-REQ-028, SYS-REQ-030]
SWE-REQ-022: The software SHALL use GPIO for discrete LED outputs. [SYS-REQ-030]
[Implied] All interface pin assignments SHALL be defined via configuration constants or tables.

4.0 Software Behavioral Requirements
SWE-REQ-023: On system startup, the software SHALL initialize all drivers and logic modules in a defined order: UART, ADC, GPIO, PWM. [SYS-REQ-021]
SWE-REQ-024: The software SHALL read and indicate the initial flap position before responding to UART commands. [SYS-REQ-022]
SWE-REQ-025: When idle (no pending command), the software SHALL keep the motor off and monitor for UART input. [SYS-REQ-023]
SWE-REQ-026: Upon valid command receipt, the software SHALL activate the motor and responsively move the flap to the new position. [SYS-REQ-002, SYS-REQ-024]
SWE-REQ-027: After reaching the requested or last valid position, the software SHALL turn off all motor outputs and return to an idle state. [SYS-REQ-003, SYS-REQ-025]
SWE-REQ-028: If an invalid command or out-of-bounds ADC value occurs, the software SHALL not activate the motor and SHALL provide an error indicator (all LEDs off). [SYS-REQ-013, SYS-REQ-026, SYS-REQ-020]
[Implied] No homing or actuator reset sequence is necessary at startup.

5.0 Software Data & Configuration
SWE-REQ-029: The software SHALL store position mapping tables and ADC calibration constants in read-only or non-volatile variables. [SYS-REQ-032]
SWE-REQ-030: The software SHALL allow modification of calibration values only via firmware image update (no runtime changes). [SYS-REQ-032, SYS-REQ-034]
[Implied] No dynamic or over-the-air updates for configuration.

6.0 Software Error Handling
SWE-REQ-031: The software SHALL handle ADC readings outside all defined position windows by disabling motor activation and turning off all position indication LEDs. [SYS-REQ-013, SYS-REQ-037]
SWE-REQ-032: The software SHALL ignore unrecognized UART commands and maintain system state. [SYS-REQ-015, SYS-REQ-026, SYS-REQ-036]
[Implied] No hardware diagnostics, retries, or advanced error recovery implemented in software.

7.0 Performance & Responsiveness
SWE-REQ-033: The software SHALL process user commands and complete all actuator movements within a time suitable for human-machine interaction (nominally <1 s response typical). [SYS-REQ-035]
[Implied] Actual responsiveness is subject to hardware/layers below application software; no explicit cycles, schedules, or deadlines implemented.

8.0 Resource Constraints
SWE-REQ-034: The software SHALL not use dynamic memory allocation (e.g., malloc/free) and SHALL operate within the RAM/ROM of STM32F407. [SYS-REQ-039]
SWE-REQ-035: The software SHALL keep all algorithmic and variable usage bounded (no recursion/unbounded queues). [SYS-REQ-040]
[Implied] Stack and buffer sizes are fixed at compile time by configuration.

9.0 Testability
SWE-REQ-036: All functional requirements SHALL be verifiable by UART command injection and LED/motor observation (manual or automated benches). [SYS-REQ-041]
[Implied] Software shall not require internal debug/trace outputs for requirement compliance.

10.0 Implied Requirements
SWE-REQ-037 [Implied]: All system-level implied requirements are addressed in software only to the extent needed for direct functional compliance; no architectural expansion, diagnostics, or concurrency features are to be implemented outside those covered above.
