1.0 System Overview

SYS-REQ-001: The system SHALL control a single HVAC air flap using a DC motor actuated by a microcontroller, based on user input received via UART.
SYS-REQ-002: The flap position SHALL be measured with a potentiometer and provided to the system via an ADC input.
SYS-REQ-003: The system SHALL visually indicate operating status and flap position using LEDs.
SYS-REQ-004: The system SHALL be intended as a standalone proof-of-concept and not rely on any vehicle network (CAN, LIN).
SYS-REQ-005: The system SHALL support up to six discrete flap positions.

2.0 Flap Position Control

SYS-REQ-006: The system SHALL accept user requests for desired flap positions in the form of discrete position commands 0–5.
SYS-REQ-007: Upon receiving a valid command, the system SHALL move the flap to the specified target position and confirm the position is achieved.
SYS-REQ-008: The flap SHALL only occupy one of the defined discrete positions at any time.
SYS-REQ-009: ADC readings SHALL be mapped to logical positions 0–5 as defined by a fixed, preconfigured table or thresholds.

==============================
ARCHITECTURE STYLE SELECTION
==============================

Candidate Styles Considered:
1. Layered architecture
2. Component-based/modular architecture
3. Monolithic/main-loop architecture

Style Evaluation:
- System complexity is low: Only a few logical functions (UART command handling, actuator control, LED indication, ADC feedback) with simple, well-bounded interactions. [Trace: SWE-REQ-014, SWE-REQ-019]
- HW interaction is direct and dedicated; all interfaces (UART/ADC/GPIO) are statically configured. [SWE-REQ-015–SWE-REQ-019]
- Testability requires modular separation (UART/motor/feedback/LED logic). [SWE-REQ-018, SWE-REQ-037, SWE-REQ-038]
- Maintainability and ASPICE L3 expectations (SYS-REQ-046, SWE-REQ-014) require logical modularity.

Decision:
Component-based/modular architecture selected.
- Justification: Explicitly required modular separation (SWE-REQ-014, SYS-REQ-046). Main-loop or monolithic style is not chosen since modularity and explicit separation of command, actuator, feedback, and indicator logic is required for testability and maintainability.
- Other styles (layered, monolithic) are rejected because: No clear OS abstraction or stack of layers (layered); lack of required separation and encapsulation (monolithic).

==============================
ARCHITECTURE DEFINITION
==============================

Software Units Defined:

1. Command Handler Unit
   - Responsibilities: Receives, validates, and dispatches user commands from UART. [SWE-REQ-001, SWE-REQ-002, SWE-REQ-015, SWE-REQ-020]

3. Motor Control Unit
   - Responsibilities: Sets motor direction, enables/disables motor via GPIO and PWM. Ensures motor OFF at startup/error. [SWE-REQ-005, SWE-REQ-006, SWE-REQ-007, SWE-REQ-017, SWE-REQ-025, SWE-REQ-029, SWE-REQ-031]
   - Interfaces: Receives direction/enable requests from Flap Control, manages GPIO/PWM, status output for feedback/ID.

4. Feedback (ADC Acquisition & Mapping) Unit
   - Responsibilities: Periodically acquires ADC, maps to position using static config, detects out-of-range. [SWE-REQ-008, SWE-REQ-009, SWE-REQ-010, SWE-REQ-016, SWE-REQ-026]
   - Interfaces: Acquires from ADC HW, provides flap position/status/error indication to Flap Control, provides raw/mapped values as needed.

5. Indication (LED Management) Unit
   - Responsibilities: Controls all position/power LEDs; updates indicators upon state change, startup; single LED ON for position, power LED per system state. [SWE-REQ-011, SWE-REQ-012, SWE-REQ-013, SWE-REQ-018, SWE-REQ-021, SWE-REQ-037, SWE-REQ-038]
   - Interfaces: UART for optional startup/config, receives state updates from Flap Control, controls GPIO for LEDs.

6. Static Configuration Unit
   - Responsibilities: Houses all compile-time config (calibration for ADC thresholds, command-to-position mapping). [SWE-REQ-026, SWE-REQ-027, SWE-REQ-028]
   - Interfaces: Provides config/tables to Command Handler and Feedback Unit.

Error handling is local to each unit per SWE.1 error handling requirements and is realized by stopping actions, resetting outputs, or reporting state (e.g., invalid command – Command Handler ignores; ADC out of range – Feedback triggers stop on Motor Control).

No explicit execution model or scheduling policy is mandated by the requirements at this stage. All operation (acquisition, dispatch, actuation, indication) is demand-driven or periodic, with no concurrency, ISR, or timing policy imposed by SWE.1. [Explicit per instruction]

SOFTWARE UNITS - LOW LEVEL DESIGN
==============================

-------------------------------------
Software Unit: Command Handler Unit
-------------------------------------
1. Responsibilities
   - Handles: Receiving, validating, and dispatching user commands from UART
   - Does not handle: Direct actuation, error handling beyond command validation

2. Internal Data Design
   - UART_rx_buffer: Fixed-size char array for received UART data
   - valid_command_flag: Indicates if latest command is valid
   - command_position_idx: Integer, holds decoded and validated position (0-5) or INVALID
   - Uses static position map from Static Configuration Unit

3. State Machine
   - State: None (event-driven, simple flow)
   - Flow: On UART receive event, parse character, check range, set flag and output to Flap Control Unit

4. Algorithms & Control Flow
   - On UART receive interrupt or polling:
     If received character in ['0'-'5']:
       - Convert to integer, set valid_command_flag, store position_idx
     Else:
       - Set flag invalid, take no action
     - Output valid commands to Flap Control via API

5. Interfaces (APIs)
   - Provided: GetValidCommand(void) -> int (returns validated position idx or INVALID)
   - Required: UART_receive(), access to position mapping table
   - Error reporting: Outputs only valid commands, others ignored

6. Error Handling
   - Ignores invalid commands (does not dispatch)

7. Resource & Timing Considerations
   - Invoked: On UART receive event/poll
   - WCET: Negligible (buffer parse and integer check)
   - Re-entrancy: Not re-entrant (single command processed at a time)

8. Traceability
   - SWE-REQ-001, SWE-REQ-002, SWE-REQ-015, SWE-REQ-027, SWE-REQ-030

-------------------------------------
Software Unit: Flap Control Unit
-------------------------------------
1. Responsibilities
   - Handles: Flap position state transitions, targets, motion sequencing, control requests
   - Does not handle: Direct motor drive or feedback acquisition

2. Internal Data Design
   - target_position: Integer 0-5 (requested)
   - current_position: Integer 0-5 (from Feedback Unit)
   - movement_in_progress: Boolean
   - state enum: {IDLE, MOVING, ERROR}

3. State Machine
   - States: IDLE (waiting), MOVING (in transit), ERROR (invalid feedback)
   - Events: Valid Command, Position Reached, ADC Error
   - Transitions: On valid command, moves to MOVING; on position reached, returns to IDLE; on error, enters ERROR
   - Actions: Issues motor start/stop to Motor Control, updates LED status

4. Algorithms & Control Flow
   - On valid command:
      If not moving and not error:
         - Set target, set movement_in_progress
         - Issue command to Motor Control (dir/enable)
   - While moving:
         - Poll Feedback Unit, compare to target
         - On match, stop motor, clear flag, update LED state
   - On ADC error: Stop motor, enter ERROR state

5. Interfaces (APIs)
   - Provided: StartMovement(int target), StopMovement(), GetState()
   - Required: MotorControl.Start/Stop, Feedback.GetPosition, Indication.Update
   - Error reporting: Error status exported

6. Error Handling
   - If ADC out of range or feedback error: Stop motor, enter ERROR
   - Ignores further commands while in ERROR

7. Resource & Timing Considerations
   - Invoked only on valid commands, periodic polling for position
   - WCET: Low (decision logic and state compare)
   - Re-entrancy: Not re-entrant

8. Traceability
   - SWE-REQ-003, SWE-REQ-004, SWE-REQ-020, SWE-REQ-021, SWE-REQ-022, SWE-REQ-023, SWE-REQ-024, SWE-REQ-029, SWE-REQ-031

Software Unit: Motor Control Unit
-------------------------------------
1. Responsibilities
   - Handles: GPIO/PWM for motor direction/enable, ensures motor OFF/startup/emergency
   - Does not handle: High-level movement or command decisions

2. Internal Data Design
   - motor_enabled: Boolean
   - direction: Enum (CW, CCW, OFF)
   - error_flag: Boolean

3. State Machine
   - State: None (actions on request)
   - Flow: On request from Flap Control, sets direction/enable via GPIO/PWM

4. Algorithms & Control Flow
   - Start(direction): Set GPIO/PWM to target direction, enable
   - Stop(): Disable motor enable pin

5. Interfaces (APIs)

7. Resource & Timing Considerations

   - WCET: Negligible (GPIO/PWM)
   - Re-entrancy: Not re-entrant

8. Traceability
   - SWE-REQ-005, SWE-REQ-006, SWE-REQ-007, SWE-REQ-017, SWE-REQ-025, SWE-REQ-029, SWE-REQ-031

-------------------------------------
Software Unit: Feedback (ADC Acquisition & Mapping) Unit
-------------------------------------
1. Responsibilities
   - Handles: ADC reading, mapping to logical position (0-5), error if out-of-range
   - Does not handle: Motor or LED control, command validation

2. Internal Data Design
   - adc_raw: uint16
   - position: Integer 0-5
   - out_of_range_flag: Boolean
   - thresholds[]: Array of min/max ADC values for each pos (from Static Config)

3. State Machine
   - State: None (periodic data acquisition)
   - Flow: Reads ADC, checks thresholds, maps to position (0-5 or invalid)

4. Algorithms & Control Flow
   - On periodic read:
       adc_raw = ADC_read();
       for each threshold:
           if (adc_raw in range):
               set position, clear error;
               break;
           else: set out_of_range_flag=true;
   - Position exported to Flap Control

5. Interfaces (APIs)
   - Provided: GetPosition(), IsValid()
   - Required: ADC_read(), access to thresholds config
   - Error reporting: out_of_range_flag

6. Error Handling
   - If adc_raw out of all valid ranges, set error, inform Flap Control

7. Resource & Timing Considerations
   - Invoked periodically
   - WCET: Low (table lookup)
   - Re-entrancy: Not re-entrant

8. Traceability
   - SWE-REQ-008, SWE-REQ-009, SWE-REQ-010, SWE-REQ-016, SWE-REQ-026, SWE-REQ-031
