# HVAC Flap Actuator: System-Level Requirements

## 1.0 System Overview

SYS-REQ-001: The system SHALL control a single HVAC air flap using a DC motor based on user commands received via UART.
SYS-REQ-002: The system SHALL measure the flap’s position using a potentiometer connected to an ADC channel.
SYS-REQ-003: The system SHALL provide visual feedback of system status and flap position using LEDs.
SYS-REQ-004: The system SHALL ignore communication with vehicle networks (e.g., CAN, LIN).
[Implied] SYS-REQ-005: The system SHALL not require any dynamic calibration or network-based diagnostics.

---

## 2.0 Flap Position Control

SYS-REQ-006: The system SHALL move the flap to a commanded discrete target position (0–5), provided via UART.
SYS-REQ-007: The system SHALL only accept one user command at a time.
SYS-REQ-008: The system SHALL immediately stop the DC motor after reaching the target position.
[Implied] SYS-REQ-009: The system SHALL not overshoot past the commanded position by more than 1 logical step.

---

## 3.0 Motor Control

SYS-REQ-010: The system SHALL control the rotation direction of the DC motor (clockwise/anti-clockwise) to achieve flap movement as required.
SYS-REQ-011: The system SHALL use GPIO outputs to control the motor driver (L298N).
SYS-REQ-012: The system SHALL use a PWM signal to control motor enable and speed.
SYS-REQ-013: The system SHALL switch off the motor while idle, on power-up, or once the target position is achieved.
[Implied] SYS-REQ-014: The system SHALL limit the maximum motor speed to a safe value for all movements.

---

## 4.0 Position Feedback Acquisition & Processing

SYS-REQ-015: The system SHALL use the ADC to continuously acquire the potentiometer output signal.
SYS-REQ-016: The system SHALL convert ADC values to corresponding logical flap positions (0–5) using pre-defined, fixed software calibration values.
SYS-REQ-017: The system SHALL verify that ADC readings are within valid calibrated bounds before using them for control.
[Implied] SYS-REQ-018: If ADC readings are outside valid range, the system SHALL halt any ongoing motor movement.

---

## 5.0 User Command Interface

SYS-REQ-019: The system SHALL receive target position commands as integer values (0–5) over UART from the user.
SYS-REQ-020: The system SHALL ignore any command that is outside the 0–5 range.
SYS-REQ-021: The system SHALL not send any acknowledgment or error message for invalid user commands.
[Implied] SYS-REQ-022: The system SHALL process user commands in the order they are received, if sequential commands are issued.

---

## 6.0 Status Indication

SYS-REQ-023: The system SHALL use a status indicator LED to show that it is powered on.
SYS-REQ-024: The system SHALL indicate the current logical flap position using a dedicated LED for each position.
SYS-REQ-025: At most one (1) green flap position LED SHALL be illuminated at a time.
SYS-REQ-026: The status LED SHALL be turned ON throughout normal operation.
[Implied] SYS-REQ-027: The state of position LEDs SHALL be updated immediately after change in flap position.

---

## 7.0 System Behavior (power-up, idle, normal, target reached, invalid input)

SYS-REQ-028: On power-up, the system SHALL initialize all required peripherals (ADC, UART, GPIO, PWM).
SYS-REQ-029: On power-up, the motor SHALL remain OFF until a valid command is received.
SYS-REQ-030: The system SHALL read and display the current flap position on the relevant LED after initialization.
SYS-REQ-031: During idle, the system SHALL monitor UART for user commands or process ongoing movement if in progress.
SYS-REQ-032: The system SHALL stop the motor and hold the flap at the last valid target position after movement is completed.
SYS-REQ-033: If an invalid command is received, the system SHALL ignore it without changing state.
[Implied] SYS-REQ-034: The system SHALL not enter any undefined or unsafe state as a result of invalid input.

---

## 8.0 Interfaces (UART, motor driver, ADC, LEDs)

SYS-REQ-035: The system SHALL use UART to receive user flap position commands.
SYS-REQ-036: The system SHALL use GPIOs and PWM to control the DC motor driver.
SYS-REQ-037: The system SHALL use an ADC channel to acquire potentiometer values reflecting flap position.
SYS-REQ-038: The system SHALL use dedicated GPIOs to control LEDs for status and position.
[Implied] SYS-REQ-039: The system SHALL not require communication with external networks (CAN/LIN/etc.)

---

## 9.0 Constraints & Assumptions

SYS-REQ-040: The system SHALL assume only one HVAC flap and corresponding actuator are present.
SYS-REQ-041: The system SHALL assume hardware (motor, ADC, potentiometer, LEDs) is functioning as intended.
SYS-REQ-042: The system SHALL assume only one command is processed at a time; concurrent commands are not supported.
[Implied] SYS-REQ-043: The system SHALL rely on statically configured calibration values for ADC-to-position mapping.

---

## 10.0 Non-Functional Requirements

### 10.1 Responsiveness
SYS-REQ-044: The system SHALL respond to user commands such that perceivable delay is minimized to human users.
[Implied] SYS-REQ-045: No strict real-time requirements are imposed; system responsiveness must be user-acceptable.

### 10.2 Error Handling & Edge Cases
SYS-REQ-046: The system SHALL halt motor activity if ADC readings fall outside valid calibrated ranges.
SYS-REQ-047: The system SHALL remain functional if the target position is not achieved immediately (e.g., if flap is obstructed), but no advanced recovery is required.
[Implied] SYS-REQ-048: The system SHALL not attempt to implement fault recovery or diagnostics in case of hardware error.

### 10.3 Resource Constraints
SYS-REQ-049: The system SHALL not use dynamic memory allocation at any time.
[Implied] SYS-REQ-050: The system SHALL operate within STM32F407G-DISC1 hardware resource limits.

### 10.4 Maintainability & Modularity
SYS-REQ-051: The system SHALL organize functionalities (position acquisition, motor control, command parsing, indication) into separate, testable units.
[Implied] SYS-REQ-052: Changes in logical position count or calibration values SHALL be possible via software parameters.

### 10.5 Testability
SYS-REQ-053: The system SHALL allow manual and scripted UART-based testing for all supported flap positions and behaviors.
SYS-REQ-054: The system SHALL enable testing through observation of flap movement and visual LED indication corresponding to commanded positions.
[Implied] SYS-REQ-055: No automated HIL/SIL test hooks are required.

---

## Architecture-Relevant Considerations Derived from System Requirements

- **Concurrency presence/absence:** The system is single-actuator, single-command-at-a-time and does not require concurrent task handling.
- **Interaction complexity:** Interactions between modules (command input, motor control, acquisition, and indication) are simple, sequential, and mutually exclusive.
- **Control complexity:** The control loop is straightforward: receive command → actuate motor → monitor position → stop at target. No dynamic calibration or advanced diagnostics are in scope.
- **Expandability:** The requirements support extension to more positions or calibration points by updating software or configuration, but do not anticipate multiple flaps or users.

# HVAC Flap Actuator: Software Requirements

## 1.0 Software Scope & Responsibility
The HVAC Flap Actuator embedded software is responsible for implementing the command, control, and indication functions to move and report an air flap position using a DC motor, via standardized interfaces (UART, ADC, GPIO, PWM), as allocated in system requirements. The software is MCU-resident and interacts only with local peripherals—UART for command reception, ADC for position feedback, GPIO/PWM for motor and LED drive—while remaining unaware of vehicle network traffic and not implementing diagnostics or dynamic calibration. The software does not enforce scheduling, RTOS, or periodic/cyclic execution models. (SYS-REQ-001, SYS-REQ-002, SYS-REQ-003, SYS-REQ-004)

## 2.0 Software Functional Requirements
### 2.1 User Commands
SWE-REQ-001: The software SHALL parse flap position commands received as ASCII digits ('0'-'5') via UART. [SYS-REQ-019, SYS-REQ-035]
SWE-REQ-002: The software SHALL validate received UART commands and ignore values outside 0–5. [SYS-REQ-020]
SWE-REQ-003: The software SHALL not acknowledge or respond to invalid UART commands. [SYS-REQ-021]
SWE-REQ-004: The software SHALL process user commands sequentially as received. [SYS-REQ-022]
[Implied] SWE-REQ-005: The software SHALL only allow one command in process at any time. [SYS-REQ-007, SYS-REQ-042]

### 2.2 Flap Control
SWE-REQ-006: Following validation, the software SHALL initiate flap movement to the requested logical position by driving the motor as needed. [SYS-REQ-006, SYS-REQ-010]
SWE-REQ-007: The software SHALL use logical position values (0–5) mapped from ADC readings to determine and stop motor movement at the target. [SYS-REQ-016, SYS-REQ-008]
SWE-REQ-008: The software SHALL immediately stop the motor if the ADC-mapped position matches or overshoots the target by one logic step. [SYS-REQ-008, SYS-REQ-009]
[Implied] SWE-REQ-009: The software SHALL not attempt to move to undefined/unsupported (e.g., negative or >5) positions. [SYS-REQ-020]

### 2.3 Motor Control
SWE-REQ-010: The software SHALL control motor direction by setting designated GPIO outputs for L298N driver. [SYS-REQ-011]
SWE-REQ-011: The software SHALL enable/disable the DC motor using PWM output. [SYS-REQ-012, SYS-REQ-013]
SWE-REQ-012: The software SHALL turn off the motor during idle, startup, or after movement completes. [SYS-REQ-013]
SWE-REQ-013: The software SHALL limit PWM to a safe, statically configured maximum during movement. [SYS-REQ-014]
[Implied] SWE-REQ-014: No diagnostics or fault recovery for hardware errors are implemented. [SYS-REQ-048]

### 2.4 Feedback Processing
SWE-REQ-015: The software SHALL acquire ADC readings from the potentiometer and map them to 0–5 using static calibration constants. [SYS-REQ-015, SYS-REQ-016, SYS-REQ-043]
SWE-REQ-016: Prior to flap movement or position decision, the software SHALL verify ADC values are within valid configured bounds. [SYS-REQ-017]
SWE-REQ-017: If ADC readings are outside valid range, the software SHALL halt movement and ignore pending or new movement commands. [SYS-REQ-018, SYS-REQ-046]
[Implied] SWE-REQ-018: If the position cannot be confirmed within a bounded attempt window, the software SHALL not retry or excessively attempt actuation. [SYS-REQ-047]

### 2.5 Status Indication
SWE-REQ-019: The software SHALL, on initialization, set the status LED on and light the corresponding flap position LED based on current ADC-mapped value. [SYS-REQ-023, SYS-REQ-024, SYS-REQ-030]
SWE-REQ-020: The software SHALL ensure only one flap position LED is on at a time. [SYS-REQ-025]
SWE-REQ-021: The software SHALL update position LEDs immediately after any position change. [SYS-REQ-027]
[Implied] SWE-REQ-022: The software SHALL set all position LEDs to off if an ADC error is detected. [SYS-REQ-034]

## 3.0 Software Interface Requirements
SWE-REQ-023: The software interface SHALL use UART for user command input, providing a RX handler or function for ASCII digit capture only. [SYS-REQ-035]
SWE-REQ-024: The ADC SHALL be read for position feedback; only configured channel is accessed. [SYS-REQ-037]
SWE-REQ-025: GPIO and PWM outputs SHALL interface with motor driver pins for direction, enable, and speed. [SYS-REQ-036]
SWE-REQ-026: GPIO outputs SHALL drive the status and position LEDs as logic-level outputs. [SYS-REQ-038]
[Implied] SWE-REQ-027: No interface to CAN/LIN or any external network is present. [SYS-REQ-039]

## 4.0 Software Behavioral Requirements
SWE-REQ-028: On startup, the software SHALL initialize UART, ADC, GPIO, PWM peripherals in a fixed sequence, and leave the motor off. [SYS-REQ-028, SYS-REQ-029]
SWE-REQ-029: The software SHALL, after initialization, read ADC and display flap position on relevant LED. [SYS-REQ-030]
SWE-REQ-030: In idle mode, the software SHALL monitor UART for commands or complete any ongoing movement. [SYS-REQ-031]
SWE-REQ-031: After movement, the software SHALL stop the motor and hold flap at attained position. [SYS-REQ-032]
SWE-REQ-032: For invalid commands, the software SHALL ignore input with no state change or error response. [SYS-REQ-033]
[Implied] SWE-REQ-033: The software SHALL not enter undefined or unsafe states based on command or feedback input. [SYS-REQ-034]

## 5.0 Software Data & Configuration
SWE-REQ-034: Logical position (0–5) mapping thresholds for ADC SHALL be held as static, readonly configuration in software. [SYS-REQ-016, SYS-REQ-043]
SWE-REQ-035: Maximum allowed motor speed and stall limits SHALL be statically configured, not dynamic or runtime-adjusted. [SYS-REQ-014, SYS-REQ-049]
[Implied] SWE-REQ-036: Configuration parameters are modifiable only via source or pre-flash configuration. No runtime reconfiguration is supported. [SYS-REQ-052]

## 6.0 Software Error Handling
SWE-REQ-037: If ADC values are out of bounds, the software SHALL halt the motor and inhibit further actuation until restart. [SYS-REQ-018, SYS-REQ-046]
SWE-REQ-038: If command parsing fails, the software SHALL ignore the input and take no action. [SYS-REQ-033]
[Implied] SWE-REQ-039: No software action is performed for hardware faults (motor/ADC); no error reporting or diagnostics. [SYS-REQ-048]

## 7.0 Performance & Responsiveness
SWE-REQ-040: The software SHALL ensure flap response to commands is prompt and perceivable by user (human reaction scale). [SYS-REQ-044]
[Implied] SWE-REQ-041: Software does not guarantee fixed cycle or low-latency operation; ‘prompt’ is defined by end-user perception. [SYS-REQ-045]

## 8.0 Resource Constraints
SWE-REQ-042: The software SHALL avoid dynamic memory allocation in any routines. [SYS-REQ-049]
SWE-REQ-043: Software memory, flash, and compute usage SHALL remain within STM32F407G-DISC1 resource limits. [SYS-REQ-050]
[Implied] SWE-REQ-044: Algorithms and data structures SHALL be selected for bounded resource usage and execution time.

## 9.0 Testability
SWE-REQ-045: All command-handling, feedback, and indication functions SHALL be testable using UART input and observation of motor and LED state. [SYS-REQ-053, SYS-REQ-054]
[Implied] SWE-REQ-046: Software does not provide dedicated test hooks for automated SIL/HIL. [SYS-REQ-055]

# HVAC Flap Actuator: Software Architecture

## 1. Candidate Architecture Styles

**Layered**: Segregates hardware abstraction, application logic, and interface handling. 
**Component-Based**: Decomposes functionalities into independent, testable modules/interacting components.
**Monolithic**: Implements all software logic within a single block or routine.

| Style             | Complexity    | HW Interaction | Testability  | Maintainability | ASPICE L3        |
|-------------------|--------------|---------------|--------------|----------------|------------------|
| Layered           | Medium       | Clear         | High         | High           | Strong alignment |
| Component-Based   | Low/Medium   | Clear         | High         | High           | Strong alignment |
| Monolithic        | Low          | Direct        | Low/Medium   | Poor           | Weak             |

**Evaluation Outcome:**
  - All styles can realize requirements, but only Layered and Component-Based styles support explicit separation/testability per SWE-REQ-051 ("organize functionalities ... into separate, testable units").
  - Monolithic is rejected: testability, maintainability, modularity, and ASPICE expectations (traceable, separated units) are not met.
  - **Selected: Component-Based (logical software units, clearly separated responsibilities)** — most directly supports requirements (SWE-REQ-051, SWE-REQ-034, SWE-REQ-035).

## 2. Software Architecture Definition

### 2.1 Logical Units & Responsibilities

1. **Command Handler Unit**
   - Parses and validates UART input commands (SWE-REQ-001, SWE-REQ-002)
   - Rejects/ignores invalid commands (SWE-REQ-003, SWE-REQ-009, SWE-REQ-038)
2. **Flap Control Unit**
   - Supervises command-to-actuation flow (SWE-REQ-004, SWE-REQ-005, SWE-REQ-006, SWE-REQ-007, SWE-REQ-008, SWE-REQ-009)
   - Ensures single-command-at-a-time, controls actuation/hold logic
3. **Motor Control Unit**
   - Issues direction, PWM, enable signals (SWE-REQ-010, SWE-REQ-011, SWE-REQ-012, SWE-REQ-013)
   - Implements idle/active transitions, motor limit logic
4. **Feedback Acquisition & Processing Unit**
   - Reads ADC channel, maps data to logical flap position (SWE-REQ-015, SWE-REQ-016)
   - Applies bounds checking, issues out-of-range logic (SWE-REQ-017, SWE-REQ-018, SWE-REQ-037)
5. **LED Indication Unit**
   - Drives status LED (SWE-REQ-019, SWE-REQ-020, SWE-REQ-021, SWE-REQ-022)
6. **Configuration & Calibration Unit**
   - Holds calibration, speed, and mapping constants (SWE-REQ-034, SWE-REQ-035, SWE-REQ-036)

### 2.2 Interfaces
- **UART Rx Handler** (input to Command Handler)
- **Flap movement command signals** from Command Handler to Flap Control
- **Motor driver commands** from Flap Control to Motor Control (direction, PWM, enable)
- **Position feedback** from Feedback Acquisition to Flap Control
- **Status indications** from Flap Control to LEDs
- **Configuration access** (read-only) by units that need static/calibration data

### 2.3 Execution Model
"No explicit execution model or scheduling policy is mandated by the requirements at this stage."

## 3. Text-Based Architecture Diagram

                                 v
                 [ Flap Control Unit ]  <─  [ Feedback Acquisition & Processing ]
                                 |
      ┌─────────────┐            v
      |             |     [ Motor Control Unit ]────┐
      |             |                               |
      |             └─────→ [ LED Indication Unit ]─┘
      v

## 4. Architecture Table Summary

| Software Unit                  | Responsibilities                                                | Interfaces Provided          | Interfaces Used               |
|-------------------------------|----------------------------------------------------------------|-----------------------------|-------------------------------|
| Command Handler Unit           | Parse UART, validate, ignore/queue commands                    | Command signal               | UART Rx, config               |
| Flap Control Unit              | Manage flap actuation, sequence, status, single command logic  | Control signals, status      | Command Handler, Feedback, Motor, LED, config |
| Motor Control Unit             | PWM, direction, idle/enable transitions                        | Motor driver output          | Flap Control, config          |
| Feedback Acquisition & Proc.   | ADC read, pos mapping, bounds checking                         | Feedback value, error        | ADC, config                   |
| LED Indication Unit            | Drive/refresh status and flap position LEDs                    | LED outputs                  | Flap Control, config          |
| Config & Calibration Unit      | Hold calibration, thresholds, etc. (read-only to others)      | Static/config params         | -                             |

## 5. Traceability Note
- All decomposition, interface, and unitization decisions map to explicit SWE-REQs (see numbers above); no additional functionality or implicit behavior has been added. No safety, sched, or diagnostics logic is present unless in SWE-REQ-xxx.
