1.0 System Overview

The HVAC Flap Actuator System is a microcontroller-based prototype to control the position of an HVAC air flap using a DC motor, with feedback from a potentiometer. The system is intended for learning and software process demonstration. It allows a user to command a flap to one of several discrete positions via UART. The system reports its states and positions using LEDs and is designed for responsiveness, safe behavior, and ease of testability.

2.0 Flap Position Control Requirements
SYS-REQ-001: The system shall allow the user to command a target flap position via UART.
SYS-REQ-002: The system shall compare the current flap position with the target position.
SYS-REQ-003: The system shall activate the motor to move the flap towards the target position when a new position is commanded.
SYS-REQ-004: The system shall stop the motor when the flap reaches the target position.
SYS-REQ-005: The system shall hold the motor in an inactive state once the target position is achieved until another valid command is received.
SYS-REQ-006: The system shall continuously monitor the current flap position.
SYS-REQ-007: The system shall support discrete flap positions as defined by fixed ADC value ranges in software.
SYS-REQ-008: The system shall ignore requests for target positions outside the supported range.
[Implied] SYS-REQ-009: The system shall ensure the flap does not oscillate between adjacent positions due to ADC noise by using debounce logic or stable position detection.

3.0 Motor Control Requirements
SYS-REQ-010: The system shall control the DC motor direction using GPIO output signals.
SYS-REQ-011: The system shall provide the ability to enable or disable the motor via a control signal (e.g., PWM or GPIO).
SYS-REQ-012: The system shall stop the motor immediately when the flap has reached the commanded position.
SYS-REQ-013: The system shall prevent the motor from running indefinitely in case the desired position is outside feasible ADC feedback range.
SYS-REQ-014: The system shall ensure the motor is OFF at power-up and initialization.
[Implied] SYS-REQ-015: The system shall prevent both direction control signals from being active simultaneously (no shoot-through conditions).

4.0 Position Feedback Acquisition and Processing
SYS-REQ-016: The system shall acquire flap position feedback via the potentiometer connected to an ADC channel of the microcontroller.
SYS-REQ-017: The system shall map ADC values to logical flap positions using predefined, fixed ranges.
SYS-REQ-018: The system shall update the detected flap position at regular, preconfigured intervals.
SYS-REQ-019: The system shall validate the ADC value before using it for position control (e.g., check within calibrated boundaries).
[Implied] SYS-REQ-020: The system shall indicate (via status LED or other means) if the ADC value is out of the expected calibrated range.

5.0 User Command Interface Requirements
SYS-REQ-021: The system shall accept user commands to set flap target position via UART.
SYS-REQ-022: The system shall recognize and process only valid numeric commands corresponding to supported position indices.
SYS-REQ-023: The system shall ignore invalid or out-of-range UART commands and take no further action for these.
SYS-REQ-024: The system shall not send acknowledgments or error responses for invalid commands.
SYS-REQ-025: The system shall process UART commands with sufficient frequency to provide a responsive user experience.
[Implied] SYS-REQ-026: The system shall validate received UART data before processing for security and fault containment.

6.0 Status Indication Requirements
SYS-REQ-027: The system shall illuminate a status/power LED to indicate the system is powered ON.
SYS-REQ-028: The system shall use separate green LEDs to indicate the current detected flap position.
SYS-REQ-029: Only one green position LED shall be illuminated at a time to indicate the flap position.
SYS-REQ-030: The system shall indicate power and position status clearly and simply, without special flashing or patterns.
[Implied] SYS-REQ-031: In the event of position feedback loss or error, a distinctive LED state (e.g., all LEDs off or all on) shall be used to indicate a system fault.

7.0 System Behavioral Requirements
SYS-REQ-032: Upon power-up, the system shall initialize peripheral interfaces (ADC, UART, GPIO, PWM) before normal operation.
SYS-REQ-033: Upon power-up, the system shall ensure the motor is OFF.
SYS-REQ-034: After initialization, the system shall determine and display the current flap position based on the potentiometer feedback.
SYS-REQ-035: The system shall remain idle, holding current flap position, when no valid command is received.
SYS-REQ-036: Upon receiving a valid command, the system shall move the flap to the requested target and update position LEDs accordingly.
SYS-REQ-037: The system shall stop the motor and hold the flap when the target is reached.
SYS-REQ-038: Invalid commands shall be ignored without further effect.
[Implied] SYS-REQ-039: The system shall ensure safe operation in all states, preventing unintended motor operation during idle or fault conditions.

8.0 System Interface Requirements
SYS-REQ-040: The system shall receive user input commands via UART.
SYS-REQ-041: The system shall output motor drive signals to an L298N or equivalent H-Bridge motor driver module.
SYS-REQ-042: The system shall acquire position feedback from a potentiometer via an ADC interface.
SYS-REQ-043: The system shall drive LEDs for power/status and position indication via GPIO outputs.
[Implied] SYS-REQ-044: The system shall use timer-based PWM for motor speed control, as required.

9.0 Constraints and Assumptions
SYS-REQ-045: Only one flap actuator is present in the system.
SYS-REQ-046: Only one DC motor is present and controlled.
SYS-REQ-047: Only one user command is processed at a time; additional commands are queued or ignored.
SYS-REQ-048: All hardware is assumed operational (no compensation for hardware faults).
SYS-REQ-049: The system shall not perform calibration or self-learning; all configuration parameters shall be preset and static.
[Implied] SYS-REQ-050: All interfaces and configuration are hardcoded and not dynamically discoverable.

10.0 Non-Functional Requirements
10.1 Responsiveness Expectations
SYS-REQ-051: The system shall process UART commands and move the flap within a time frame that feels responsive to a human user (typically less than 250 ms from command to motor movement).
[Implied] SYS-REQ-052: The system shall not introduce unnecessary delays or blocking operations that affect responsiveness.

10.2 Error Handling and Edge Cases
SYS-REQ-053: The system shall ignore invalid or unknown UART commands silently.
SYS-REQ-054: If ADC feedback is out of the expected range, the system shall stop the motor and signal an error through LEDs.
[Implied] SYS-REQ-055: The system shall avoid crashing or entering unstable states if the motor fails to reach the target position.

10.3 Resource Constraints
SYS-REQ-056: The implementation shall be lightweight and use only necessary resources to achieve correct operation.
SYS-REQ-057: The system shall avoid dynamic memory allocation and prefer static and stack allocation for all buffers and variables.
SYS-REQ-058: The software shall ensure predictable and bounded behavior suitable for embedded systems demonstration.

10.4 Maintainability and Modularity
SYS-REQ-059: The system software shall exhibit clear separation between user interface, control logic, and hardware interface layers.
SYS-REQ-060: The system design shall be documented and simple enough for new engineers or students to understand and modify.
[Implied] SYS-REQ-061: Code and requirements shall support easy traceability for learning and ASPICE compliance demonstration.

10.5 Testability
SYS-REQ-062: The system shall be testable by sending UART commands and observing LEDs and motor movement.
SYS-REQ-063: The system shall support manual and script-based testing.
[Implied] SYS-REQ-064: The system design shall allow observation and logging (through UART or other means) for verification purposes where reasonable without complicating the design.


Architecture-Relevant Considerations Derived from System Requirements

The system is simple, with a single actuator and one-user command at a time. It has no need for OS-level concurrency or complex scheduling, as there are no competing or overlapping real-time responsibilities. External interactions are limited to UART, LEDs, PWM/GPIO, and ADC, reducing the need for robust interface management. Control logic is straightforward, with direct mapping of inputs (commands) to state transitions and outputs, emphasizing expandability for only one actuator per system instance. The overall solution is deliberately designed for clarity and learning, prioritizing maintainability, predictability, and traceability, with a low barrier for future enhancement or adaptation.

# 1.0 Software Scope and Responsibility

The software is responsible for controlling the position of an HVAC air flap using a DC motor under microcontroller control. It interacts with peripherals (ADC, UART, GPIO) to acquire user commands, monitor flap position feedback, control the motor, and indicate system status via LEDs. All logical decisions, validation, and control actions to satisfy the system-level requirements are to be realized solely in software.

# 2.0 Software Functional Requirements

## 2.1 User Command Handling
- SWE-REQ-001: The software shall receive commands for target flap position via UART. (SYS-REQ-001, SYS-REQ-021, SYS-REQ-040)
- SWE-REQ-002: The software shall validate received UART commands, accepting only those corresponding to supported numerical flap position indices. (SYS-REQ-022)
- SWE-REQ-003: The software shall ignore invalid, out-of-range, or unknown UART commands without further effect or error response. (SYS-REQ-023, SYS-REQ-038, SYS-REQ-053)
- SWE-REQ-004 [Implied]: The software shall validate UART data before processing for security and fault containment. (SYS-REQ-026)

## 2.2 Flap Position Control Logic
- SWE-REQ-005: The software shall compare the current flap position to the commanded target position. (SYS-REQ-002)
- SWE-REQ-006: The software shall activate the motor to move the flap when a new position is commanded. (SYS-REQ-003, SYS-REQ-036)
- SWE-REQ-007: The software shall stop the motor when the flap reaches the commanded position and hold the motor inactive until the next valid command is received. (SYS-REQ-004, SYS-REQ-005, SYS-REQ-037)
- SWE-REQ-008: The software shall prevent motor operation for target positions outside the supported position range. (SYS-REQ-008)
- SWE-REQ-009 [Implied]: The software shall prevent undesired oscillation between adjacent positions due to ADC noise, using debounce or stable value logic. (SYS-REQ-009)

## 2.3 Motor Control Logic
- SWE-REQ-010: The software shall provide logical control signals for motor direction and enable/disable control, without specifying hardware driver details. (SYS-REQ-010, SYS-REQ-011, SYS-REQ-041)
- SWE-REQ-011: The software shall immediately deactivate motor outputs when the target position is reached or the system is powered up or reset. (SYS-REQ-012, SYS-REQ-014, SYS-REQ-033)
- SWE-REQ-012: The software shall prevent both direction control signals from being active simultaneously. [Implied] (SYS-REQ-015)
- SWE-REQ-013: The software shall detect when motor actuation cannot reach the requested position and stop the motor to prevent indefinite operation. (SYS-REQ-013, SYS-REQ-054)

## 2.4 Position Feedback Processing
- SWE-REQ-014: The software shall acquire the flap position via ADC from the potentiometer. (SYS-REQ-016, SYS-REQ-042)
- SWE-REQ-015: The software shall map ADC values to logical flap positions according to predefined, fixed boundaries. (SYS-REQ-017)
- SWE-REQ-016: The software shall validate ADC values are within calibrated, expected ranges before processing. (SYS-REQ-019)
- SWE-REQ-017: The software shall indicate via software output if an out-of-range or fault ADC value is detected. [Implied] (SYS-REQ-020)

## 2.5 Status Indication Control
- SWE-REQ-018: The software shall control status/power LEDs and individual position LEDs using logical state decisions. (SYS-REQ-027, SYS-REQ-028, SYS-REQ-043)
- SWE-REQ-019: The software shall ensure only one green LED for position is illuminated at a time. (SYS-REQ-029)
- SWE-REQ-020: The software shall drive LEDs for status indication as per the system requirements and interface only. (SYS-REQ-030)
- SWE-REQ-021: The software shall command a distinctive LED indication in the event of position feedback loss or error. [Implied] (SYS-REQ-031)

# 3.0 Software Interface Requirements

- SWE-REQ-022: The software shall interact with UART for receiving user commands and (if required) transmitting user feedback. (SYS-REQ-040)
- SWE-REQ-023: The software shall read flap position feedback from the ADC. (SYS-REQ-016, SYS-REQ-042)
- SWE-REQ-024: The software shall control the motor by generating logical outputs (direction, enable/disable) via GPIOs. (SYS-REQ-011, SYS-REQ-041)
- SWE-REQ-025: The software shall drive system LEDs for power/status and position via logical GPIO outputs. (SYS-REQ-043)

# 4.0 Software Behavioral Requirements

- SWE-REQ-026: The software shall initialize all peripherals (ADC, UART, GPIO, PWM) on system startup before entering normal operating mode. (SYS-REQ-032)
- SWE-REQ-027: At power-up, the software shall set the motor OFF and determine current flap position based on ADC input. (SYS-REQ-033, SYS-REQ-034)
- SWE-REQ-028: The software shall remain in an idle state, holding current flap position until a valid command is received. (SYS-REQ-035)
- SWE-REQ-029: On receiving a valid command, the software shall initiate the sequence to move the flap to the target position and update position LEDs accordingly. (SYS-REQ-036)
- SWE-REQ-030: The software shall detect and handle invalid or unexpected input values by entering a safe state (idle, error indication, etc.). (SYS-REQ-038, SYS-REQ-054)
- SWE-REQ-031: The software shall ensure control logic leads to bounded and deterministic behavior for all user and feedback scenarios. (SYS-REQ-039)

# 5.0 Software Data and Configuration Requirements

- SWE-REQ-032: The software shall use fixed, statically configured mappings between ADC values and flap position indices. (SYS-REQ-007, SYS-REQ-017)
- SWE-REQ-033: The software shall use static, preset calibration constants and configuration parameters—no runtime calibration. (SYS-REQ-049)
- SWE-REQ-034 [Implied]: The software shall use only hard-coded, compile-time configuration values for interface and threshold settings. (SYS-REQ-050)

# 6.0 Software Error Handling Requirements

- SWE-REQ-035: The software shall deterministically ignore and take no further action on invalid or out-of-range UART commands. (SYS-REQ-023, SYS-REQ-053)
- SWE-REQ-036: The software shall command a fault indication through system LEDs if the ADC feedback is out of expected range. (SYS-REQ-054)
- SWE-REQ-037 [Implied]: The software shall avoid crashing or entering unstable states if the motor fails to reach target, e.g., by entering a safe idle or error state. (SYS-REQ-055)

# 7.0 Software Performance and Responsiveness Requirements

- SWE-REQ-038: The software shall process valid UART commands and complete the flap movement with software-internal actions that result in a user-perceived latency of less than 250 ms. (SYS-REQ-051)
- SWE-REQ-039: The software shall not introduce software-level blocking or unnecessary delays in command processing. [Implied] (SYS-REQ-052)

# 8.0 Software Resource Constraint Requirements

- SWE-REQ-040: The software shall avoid dynamic memory allocation and use static or stack-based buffers and variables only. (SYS-REQ-057)
- SWE-REQ-041: The software shall ensure predictable, bounded execution time for all major control paths. (SYS-REQ-058)
- SWE-REQ-042: The software shall strive for an efficient and lightweight design to minimize memory and processor resource use. (SYS-REQ-056)

# 9.0 Software Testability Requirements

- SWE-REQ-043: The software shall support manual and script-based functional testing using UART command injection and LED observation. (SYS-REQ-062, SYS-REQ-063)
- SWE-REQ-044 [Implied]: The software design shall allow observability (e.g., status reporting or logging through UART or GPIO) where reasonable for verification. (SYS-REQ-064)

# 10.0 Implied Software Requirements

All [Implied] requirements have been collected and identified within their relevant sections above, in accordance with the system-level definitions. No implementation, architecture, scheduling, or timing-assumptions have been introduced at the software requirement level.
