===== START sw-reqs/sw-reqs.txt =====
1. The software shall process user commands received via UART to select the target HVAC flap position (0-5).
2. The software shall move the flap to the valid commanded position using DC motor control via GPIO and PWM.
3. The software shall monitor real-time flap position using potentiometer feedback via ADC and translate ADC values to logical positions (0-5).
4. The system shall display the current position using designated green LEDs, ensuring only one is active at a time.
5. On startup, the software shall initialize peripherals (UART, ADC, GPIO, PWM) and reflect the initial flap position with LEDs.
6. Invalid UART commands or ADC readings outside expected range shall be ignored and the motor safely stopped.
7. The software shall implement state/logic for IDLE, MOVING, and HOLDING positions as defined in the system requirements.
8. The software shall never attempt dynamic memory allocation and comply with MISRA C guidelines for embedded systems.
9. The system power LED shall be turned on when the software is running.
10. The system shall allow static calibration of ADC-to-flap position mapping in source code.
11. The system shall be manually testable by UART commands and LED/motor observation.
12. Communication or error response for invalid commands is not required.
13. All motor and actuator control logic shall be encapsulated within software units/modules.

===== START sw-arch/sw-arch.txt =====
1. System Context
- Microcontroller: STM32F407G-DISC1
- UART input from user/PC
- Controls 12V DC geared motor via GPIO + PWM (L298N H-bridge)
- Monitors flap position using potentiometer (ADC input)
- Visual feedback by control of LEDs (GPIO)

2. Software Component decomposition:
- UART Command Handler: Receives and validates user position commands (0–5)
- Flap Position Manager: Maps ADC readings to flap positions, enforces valid range, triggers movement or stop
- Motor Controller: Controls motor direction/speed, generates PWM using Timer, handles motor ON/OFF
- ADC Manager: Initializes ADC, reads potentiometer values periodically
- LED Driver: Updates power LED and position LEDs
- Main Control Loop: State handler for IDLE / MOVING / HOLDING; calls all managers

3. Interfaces:
- UART: receive only
- ADC: read only (polling or interrupt)
- GPIO/PWM: output only (motor and LEDs)

4. Traceability:
- All modules correspond to one or more software requirements

5. No RTOS, Superloop architecture; all logic in main loop or static ISRs.
6. MISRA C/static memory usage enforced.

===== START sw-lld/sw-lld.txt =====
1. UART Command Handler (uart_handler.c/.h)
- Static receive buffer (one char or small queue)
- Command parser (0-5, otherwise invalid)
- API: int UART_GetCommand(void);

2. Flap Position Manager (flap_manager.c/.h)
- Function to map ADC value to logical position (0-5)
- API: int FLAP_MapADC(uint16_t value);
- Tracks and compares target vs current; issues move/stop commands

3. Motor Controller (motor_control.c/.h)
- Motor_Init(), Motor_Run(direction), Motor_Stop()
- Direction: enum type (CW, CCW)
- PWM setup static, no dynamic speed
- HAL abstraction

4. ADC Manager (adc_manager.c/.h)
- ADC_Init(), ADC_Read()
- Calibration values stored as #defines

5. LED Driver (led_driver.c/.h)
- led_init(), led_update_position(int pos), led_power_on()

6. main.c
- Infinite loop: read UART, check/command, map/compare position, update outputs, drive state transitions
- Handles init/startup logic, error/safe state (no movement on invalid ADC, timeout handler optional)
- No dynamic allocation; static file-scope/state vars only

Each unit gets its own .c/.h (code/src, code/inc).
