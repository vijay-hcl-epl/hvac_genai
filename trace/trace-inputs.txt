# 1.0 SWE.2 SOFTWARE ARCHITECTURE — HVAC FLAP ACTUATOR

## 1.1 Architecture Style Selection & Justification

### Candidate Styles Considered
- **Monolithic / Main-loop (Single Function Block)**
- **Layered Architecture (Interface-abstraction separation)**
- **Component-based (modular units with defined interfaces)**

### Evaluation
- **System complexity**: The system is simple, with discrete functional responsibilities; no dynamic tasking, OS, or concurrent scheduling. Component boundaries align with major abstractions only (I/O, Control Logic).
- **HW interaction**: Direct mapping to microcontroller peripherals (UART, GPIO/PWM, ADC). No abstraction needed beyond per-unit assignation.
- **Testability**: Modular structure at the function/unit level enables static and interface-level testing—especially for core logic and I/O.
- **Maintainability**: Layered/componentized units allow future extension (new sensor/motor, error logic) without design rupture.
- **ASPICE L3**: Component-based (unitized, testable, traceable, no invented behavior) satisfies L3 expectations while aligning tightly to SWE.1.

#### Style Decision
- **Selected:** Component-based (unitized abstraction: UART Interface, Position Feedback, Motor Actuation, Status Indication, Control Logic)
- **Rejected:**
  - Main-loop: Lacks modularity—a workaround for microcontroller projects, but not maintainable or ASPICE-suitable.
  - Layered: Overhead not justified—there are no cross-cutting platform services to separate (middleware, device drivers, etc).

Software Unit: UART Command Handler

1. Responsibilities  
   - Handles reception and validation of position commands over UART (SWE-REQ-001, SWE-REQ-002, SWE-REQ-003). 
   - Forwards validated commands to Control Logic.
   - Does not handle command queuing, timing, or error response output beyond ignoring invalid input.

2. Internal Data Design  
   - Input buffer: static char[] for UART RX.  
   - Validated input: static int for command value (0-5).
   - Receive state (IDLE, RECEIVING, COMPLETE/INVALID).

3. State Machine  
   - States: IDLE (waiting), RECEIVING (accumulating chars), VALIDATING (checking input), COMPLETE (valid, signal main), INVALID (ignore).
   - Events: UART RX, End-of-line/Receive complete, Out-of-range, Error.
   - Actions: Move from IDLE to RECEIVING on RX, accumulate data, validate on EOL; valid moves to COMPLETE, invalid to INVALID (then back to IDLE).

4. Algorithms & Control Flow  
   - On RX event: Read char, append if digit (max 1 char - single digit 0-5), signal EOL or buffer full.
   - If completed: Parse input, check range (0-5). If valid, forward to control logic; If invalid, clear buffer, return to IDLE.

5. Interfaces (APIs)  
   - Provided: uart_rx_handler(void* param) — receives UART input, triggers internal FSM.
   - Required: send_cmd_to_control_logic(int position).

6. Error Handling  
   - Invalid UART or out-of-range: Discard, return to idle. No error output generated.

7. Resource & Timing Considerations  
   - Invoked on each UART RX event; typical processing <100μs per char; no reentrancy needed; all state static.

8. Traceability  
   - SWE-REQ-001, SWE-REQ-002, SWE-REQ-003, SWE-REQ-016, SWE-REQ-028

Software Unit: Position Feedback Handler

1. Responsibilities
   - Handles ADC sampling. Maps value to [0-5] position. Flags error if out-of-range.
   - Provides logical position, error status to control logic.
   - Does not handle calibration storage (uses only constant data).

2. Internal Data Design
   - Static uint16_t adc_sample; static int logical_position (0-5 or -1 if invalid).
   - Const struct with calibration table: {min, max} per position.
   - Error flag: ADC_FAULT, boolean.

3. State Machine
   - States: IDLE (wait poll), SAMPLING (acquire ADC), MAPPING (lookup), OK (valid), FAULT (flag error).
   - Events: Poll trigger, ADC completion, out-of-range.
   - Actions: Sample ADC, check against calibration, set position/error, return to IDLE.
   - If value not in any calibrated range: set FAULT, position = -1.

4. Algorithms & Control Flow
   - When poll triggered: Read ADC, for each calibration slot check min ≤ sample ≤ max; if match, position=N. None: FAULT.
   - Signal position/error to control logic each time.

5. Interfaces (APIs)
   - Provided: get_flap_position(void) → int; get_adc_fault(void) → bool.
   - Required: adc_read(void).

6. Error Handling
   - If no match in calibration table: set error, position invalid.
   - All outputs default to safety if error.

7. Resource & Timing Considerations
   - Runs per periodic poll (typ. 10 ms or on demand).  < 20μs per acquisition. Not reentrant.

8. Traceability
   - SWE-REQ-011, SWE-REQ-012, SWE-REQ-024, SWE-REQ-027, SWE-REQ-018

#include "uart_command_handler.h"
#include "control_logic_state_manager.h"
#include <string.h>
#include <ctype.h>

#define RX_BUF_LEN 4

static char rx_buffer[RX_BUF_LEN];
static int rx_index = 0;
static bool cmd_ready = false;
static int last_cmd_value = -1;

void uart_rx_handler(void *param) {
    char c = *(char *)param;
    if (cmd_ready) return; // Ignore until cleared by logic
    if (isdigit((unsigned char)c) && rx_index < 2) {
        rx_buffer[rx_index++] = c;
    } else if (c == '\n' || c == '\r') {
        rx_buffer[rx_index] = '\0';
        int val = -1;
        if (sscanf(rx_buffer, "%d", &val) == 1 && val >= 0 && val <= 5) {
            last_cmd_value = val;
            cmd_ready = true;
        }
        rx_index = 0;
        memset(rx_buffer, 0, sizeof(rx_buffer));
    } else {
        rx_index = 0;
        memset(rx_buffer, 0, sizeof(rx_buffer));
    }
}

bool uart_get_last_command(int *cmd_out) {
    if (cmd_ready && cmd_out) {
        *cmd_out = last_cmd_value;
        return true;
    }
    return false;
}

void uart_clear_command(void) {
    cmd_ready = false;
    last_cmd_value = -1;
}

static system_state_t sys_state = SYS_STATE_IDLE;
static int target_position = -1;
static int current_position = -1;

void control_logic_init(void) {
    sys_state = SYS_STATE_IDLE;
    target_position = -1;
    current_position = -1;
    status_led_set(true);
    position_indicator_update(current_position);
    motor_stop();
}

void control_logic_poll(void) {
    // Poll for new UART command
    int cmd;
    if (uart_get_last_command(&cmd)) {
        if (cmd >= 0 && cmd <= 5) {
            target_position = cmd;
            uart_clear_command();
            sys_state = SYS_STATE_MOVE;
        }
    }
    // Poll feedback
    position_feedback_poll();
    current_position = get_flap_position();
    if (get_adc_fault()) {
        sys_state = SYS_STATE_ERROR;
        motor_handle_error();
        return;
    }
    if (sys_state == SYS_STATE_MOVE) {
        if (current_position == target_position && current_position != -1) {
            motor_stop();
            sys_state = SYS_STATE_IDLE;
        } else if (current_position != -1) {
            motor_move_to_position(target_position, current_position);
        }
    } else if (sys_state == SYS_STATE_IDLE) {
        motor_stop();
    }
    position_indicator_update(current_position);
}

system_state_t control_logic_get_state(void) {
    return sys_state;
}

## 4.0 Test Cases

### 4.1 Power-Up & Initialization
#### SYS-TC-001 Power-up Initialization
- Mapped System Requirement IDs: SYS-REQ-019, SYS-REQ-020, SYS-REQ-016, SYS-REQ-017
- Test Objective: Verify correct peripheral initialization, motor OFF, and correct flap position indication at startup.
- Preconditions: System powered OFF
- Test Inputs: Power ON
- Test Steps:
  1. Switch on bench power to the system.
  2. Observe the power/status LED.
  3. Observe green position LEDs.
  4. Observe motor activity and flap position.
- Expected Results:
  - Power/status LED turns ON immediately.
  - Only one position LED (matching actual flap position) turns ON.
  - Motor remains OFF at power-up.
  - UART commands prompt correct system response (system is responsive after init).
- Pass/Fail Criteria: All indicators and states conform on first power-up, with no misbehavior or unexpected movement.

### 4.2 Valid Flap Position Commands
#### SYS-TC-002 Flap Actuation (All Positions)
- Mapped System Requirement IDs: SYS-REQ-003, SYS-REQ-004, SYS-REQ-005, SYS-REQ-008
- Test Objective: Verify correct response to valid UART position commands 0–5; correct motor action and indication.
- Preconditions: System powered ON and idle; initial flap position arbitrary (note initial position).
- Test Inputs: UART commands for positions 0,1,2,3,4,5.
- Test Steps:
  1. For each position 0 to 5:
     a. Issue UART command for the position.
     b. Observe the motor direction.
     c. Monitor flap and LED indicator.
     d. Wait for motor stop.
  2. Repeat for all starting positions.
- Expected Results:
  - Flap moves to commanded position.
  - Motor rotates CW/CCW as appropriate.
  - Motor stops at target (no overshoot).
  - Only one green LED matches the target position after settling.
- Pass/Fail Criteria: No overshoot, correct motor stop, correct LED, no extraneous movement.

### 4.3 Invalid & Boundary Conditions
#### SYS-TC-003 Out-of-Range Command
- Mapped System Requirement IDs: SYS-REQ-006, SYS-REQ-015, SYS-REQ-029, SYS-REQ-033
- Test Objective: System ignores out-of-range UART position commands.
- Preconditions: System ON and in idle state.
- Test Inputs: UART commands with out-of-range values (e.g., -1, 6, 255, invalid ASCII).
- Test Steps:
  1. Issue invalid UART command.
  2. Monitor for any changes in flap, LEDs, motor activity.
- Expected Results: System ignores command, no action/movement/LED change.
- Pass/Fail Criteria: No visible system response or side effect for invalid input.

#### SYS-TC-004 UART During Motion
- Mapped System Requirement IDs: SYS-REQ-029, SYS-REQ-014
- Test Objective: Evaluate how the system handles new valid UART command while flap is moving.
- Preconditions: Flap moving following previous valid command.
- Test Inputs: UART command for new position during actuation.
- Test Steps:
  1. Issue valid move command.
  2. While motor is moving, issue another valid UART command (to another position).
  3. Observe system response (does it process/queue/ignore as per requirements).
- Expected Results: Only one command processed at a time; further commands ignored until movement completes.
- Pass/Fail Criteria: System does not attempt to execute multiple commands at once; no instabilities.

#### SYS-TC-005 ADC Out-of-Range
- Mapped System Requirement IDs: SYS-REQ-009, SYS-REQ-011, SYS-REQ-033, SYS-REQ-034
- Test Objective: System safety when ADC feedback is out-of-range (simulate unplug, faulty POT).
- Preconditions: System ON, flap in valid position.
- Test Inputs: Force ADC POT input to out-of-valid-band (disconnect, extreme voltage).
- Test Steps:
  1. Simulate ADC error during flap actuation and idle.
  2. Observe motor state and LEDs.
- Expected Results: Motor stops, system enters safe state, last valid position indicated on LED, system does not reset/lock-up.
- Pass/Fail Criteria: Proper error response; system remains stable.
