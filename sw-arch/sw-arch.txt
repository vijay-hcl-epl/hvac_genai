--------------------------------------------------------------------------------------
ARCHITECTURE STYLE SELECTION
--------------------------------------------------------------------------------------
Candidate Styles Considered:
1. Monolithic Procedural
2. Layered (Separation of Drivers/Logic/Interface)
3. Component-based (Logical function blocks)

Evaluation (per ASPICE L3, SWE.1 constraints):
- System complexity: Simple; single actuator, direct I/O. No multi-user interactions, network, or distributed control.
- HW Interaction: Direct MCU-peripheral use only; no abstraction layers.
- Testability: Layered/component-based eases unit/function isolation for test, as required in SWE.1 (SWE-REQ-040,035).
- Maintainability: Decomposition aids updates; layered or component-based favours modifiability as per SWE-REQ-040.

Selected: Layered modular architecture
- Rationale: Most closely matches SWE-REQ-040 (“Flap position mapping, UART command parsing, and motor control SHALL be implemented as separate functional modules to allow unit-level test and update.”). Also, enables clear requirements-to-unit traceability and testability. Monolithic rejected for maintainability; component-based is unnecessarily complex for current requirements.

--------------------------------------------------------------------------------------
ARCHITECTURE DEFINITION
--------------------------------------------------------------------------------------
Software Units and Responsibilities (all traced to SWE.1):

  [UART Command Handler]
    - Responsibilities: Receives/parses UART commands, validates, and signals user requests. (SWE-REQ-001,002,003,004,019,032)
    - Interface Provided: Command input (to Flap Control Logic)
    - Interface Used: UART HW, application configuration

  [Flap Control Logic]
    - Responsibilities: Main decision-making: translates user commands to target positions, manages state, instructs motor, summarizes error cases. (SWE-REQ-005,006,007,008,026,027,028)
    - Interfaces Provided: Target position output (to Motor Control), position indication signal (to LED Handler)
    - Interfaces Used: UART Command Handler, Position Feedback, Motor Control, LED Handler

  [Position Feedback]
    - Responsibilities: Regularly samples ADC, maps ADC values to physical position, detects errors. (SWE-REQ-013,014,015,029,030,031)
    - Interfaces Provided: Current position/validity (to Flap Control Logic, LED Handler)
    - Interfaces Used: ADC HW

  [Motor Control]
    - Responsibilities: Controls motor drive direction, PWM, enables/disable per flap logic. Enforces shoot-through protection and error actions. (SWE-REQ-009,010,011,012,021,025,027,034)
    - Interfaces Provided: Motor control signals (to hardware)
    - Interfaces Used: GPIO/PWM HW, Flap Control Logic

  [LED Handler]
    - Responsibilities: Drives system and position LEDs per feedback and logical state, implements all status indications. (SWE-REQ-016,017,018,022,024,028)
    - Interfaces Provided: LED signals (to hardware)
    - Interfaces Used: GPIO HW, Flap Control Logic, Position Feedback

  [Configuration/Data Store]
    - Responsibilities: Stores mapping tables, calibration ranges, constant data. No run-time modification. (SWE-REQ-029,030,034,035)
    - Interfaces Provided: Config value read
    - Interfaces Used: By all units as required
