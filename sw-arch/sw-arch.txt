====================
1. ARCHITECTURE STYLE SELECTION
====================

Candidate Styles Considered:
- (A) Monolithic
- (B) Layered
- (C) Component-based

Evaluation Criteria:
- System Complexity: Low (single actuator, single control flow)
- HW Interaction: Simple (UART, ADC, GPIO/PWM only)
- Testability: High (single-path control, direct interface exposure)
- Maintainability: Important for ASPICE traceability/modularity
- ASPICE L3: Requires explicit artifact traceability, interface definition, and testable, modular decomposition

Justification:
- Monolithic rejected: Does not support maintainability or modularity per SWE.1/testability and ASPICE goals.
- Layered viable, but creates artificial barriers for such a flat functional scope.
- Component-based SELECTED: Supports clear modularization for input, logic, actuator, and indication. Best fit to keep responsibilities testable and extendable as per SWE.1. Traceability is direct to functional decomposition and interfaces.

====================
2. SOFTWARE ARCHITECTURE DEFINITION
====================

Software Units (see Section 4 for mapping):
- UART Command Handler
- Position Manager
- Motor Control Unit
- ADC Acquisition & Mapping
- LED/Status Driver

Responsibilities and Traces:
- UART Command Handler: Receives and decodes UART commands; ignores out-of-range input. [SWE-REQ-001,002,003,004,019,034,038,039]
- Position Manager: Maintains target and current positions, manages state (idle/active). [SWE-REQ-005,006,007,024,025,026,027,028,029,031,043,044]
- ADC Acquisition & Mapping: Reads analog feedback, maps ADC to discrete position, flags out-of-range. [SWE-REQ-012,013,014,015,020,030,033]
- Motor Control Unit: Issues drive/stop/idle signals to DC motor as per target/feedback state, ensures safety rules. [SWE-REQ-008,009,010,011,021,035,040,041,042]
- LED/Status Driver: Sets "power ON" and position LEDs as required. [SWE-REQ-016,017,018,022]

Inter-unit Interfaces:
- UART Command Handler -> Position Manager (command pass)
- Position Manager <-> Motor Control Unit, ADC Acquisition
- Position Manager -> LED/Status Driver

Execution Model:
No explicit execution model or scheduling policy is mandated by the requirements at this stage.
