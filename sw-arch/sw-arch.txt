# Software Architecture for HVAC Flap Actuator System

## 1. Architecture Styles Considered

- **Monolithic**: All functionality implemented in a single large block with direct hardware interactions.
- **Layered**: Separation between hardware abstraction, application logic, and interfaces.
- **Component-Based**: Organized as discrete software units/modules each with a clear responsibility and explicit interfaces.

### Evaluation Against Criteria
| Criteria             | Monolithic         | Layered               | Component-Based      |
|---------------------|-------------------|-----------------------|---------------------|
| System Complexity   | Low-Moderate      | Moderate              | Low-Moderate (for this system)|
| Hardware Interaction| Direct            | Wrapper/Isolated      | Explicit Interfaces |
| Testability         | Poor/Fair         | Good                  | Excellent           |
| Maintainability     | Poor/Fair         | Good                  | Excellent           |
| ASPICE Compliance   | Weak              | Good                  | Strong              |

**Justification:**
Given ASPICE Level-3 expectations (traceability, modularity, testability, maintainability) and explicit requirements (e.g., SYS-REQ-054, SYS-REQ-055 for clear module separation), a **Component-Based Architecture** is selected. This ensures feature separation, supporting educational/review needs, and matches the indicated (non-layered, non-monolithic) philosophy from system/software requirements.

### Unit Arrangement
- User input reaches the Command Handler via the UART Interface.
- Command Handler interprets and validates input, passing actions to Position Control.
- Position Control compares states, orchestrates feedback/motor/LEDs.
- Motor Control provides abstracted access to driver (GPIO/PWM), ensuring safety and state per requirements.
- Feedback Handling abstracts ADC/position mapping.
- LED Indicate Unit drives power/status and position LEDs.

## 3. Software Unit Table
| Software Unit          | Responsibilities                                                                           | Interfaces Provided           | Interfaces Used                 |
|------------------------|------------------------------------------------------------------------------------------|-------------------------------|---------------------------------|
| UART Interface         | RX user commands from UART, expose to handler                                             | UART RX API                   | (HW) UART peripheral            |
| Command Handler Unit   | Parse, validate, and filter user commands. Reject invalid input per requirements.         | Command event/callback        | UART Interface                  |
| Position Control Unit  | Maintain state (target/current pos), compare, decide actions, coordinate safe operation  | Control requests to sub-units | Command Handler, Feedback, Motor, LED |
| Motor Control Unit     | Translate flap movement requests to GPIO/PWM. Manage state, motor enable/disable.         | Motor driver signals (GPIO/PWM)| Position Control                |
| Feedback Handling Unit | Acquire ADC, map/read positions, handle out-of-range conditions.                         | Flap position value interface | ADC peripheral                  |
| LED Indicate Unit      | Control power/status and position LEDs. Ensure correct/atomic indication.                 | LED control API               | Position Control                |

## 4. Execution & Scheduling Model
**No explicit execution model or scheduling policy is mandated by the requirements at this stage.**
- Requirements (esp. implied via SYS-REQ-023, SYS-REQ-031, SWE-REQ-005, SWE-REQ-009, SWE-REQ-038) call for single-command-at-a-time, directly interactive control and local feedback. No real-time or concurrency demands are present.

## 5. Traceability Statement
This architecture is fully traceable to SWE.1 requirements and tables above map units vs. responsibilities vs. interfaces. No new requirements are introduced. No system behaviors or functional intent are changed. No safety or cybersecurity logic is added. No code or algorithms are specified here (per instructions).
