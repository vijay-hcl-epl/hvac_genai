1. ARCHITECTURE STYLE SELECTION (WITH JUSTIFICATION)
==================

-- Candidate Styles Considered --
A) Layered Architecture
B) Component-based (modular, service-oriented)
C) Monolithic/single-loop procedural

-- Evaluation --
- System complexity: Simple, single actuator; discrete user commands; minimal cross-unit logic. (SWE-REQ-003, SWE-REQ-007). No networking or distributed dependencies (SWE-REQ-022).
- HW interaction: All cross-unit hardware accesses are simple, direct (UART, GPIO, ADC, PWM). (SWE-REQ-019, SWE-REQ-020, SWE-REQ-021)
- Testability & Maintainability: SWE.1 (SWE-REQ-036, SWE-REQ-037) and SYS-REQ-036 demand modularity and independent testability of feature blocks.
- ASPICE L3: Requires traceability, low inter-unit coupling, and clarity of interfaces.

-- Decisions --
Layered architecture is preferred: it allows clear separation between low-level HW interaction (drivers), application logic (flap/motor handling), and user interaction, maximizing maintainability and testability in line with SWE.1 without introducing unnecessary overhead for this simple system.

- Layered: Selected for clarity, modularity, and ease of independent test (SWE-REQ-036, SWE-REQ-037), even for this simple system.
- Component-based: Not adopted as there's little need for dynamic discovery or late binding—overhead unjustified by current requirements.
- Monolithic: Rejected due to maintainability/testability constraints in requirements (SWE-REQ-036, SWE-REQ-037).

2. SOFTWARE ARCHITECTURE DEFINITION
==================

-- SW UNITS --
1) User Command Handler (UCH)
   - Parses and validates UART input. (SWE-REQ-001, SWE-REQ-002, SWE-REQ-003)
   - Passes valid commands to Application Logic; ignores invalid. (SWE-REQ-025)
   - Interface: UART RX/validation only.

2) Application Logic (APPL)
   - Implements flap move sequence, checks ADC vs. target. (SWE-REQ-004-SWE-REQ-008)
   - Maintains overall state and sequence control. (SWE-REQ-026)
   - Triggers LED/status update, commands Motor Controller.
   - Interface: Receives user commands, exchanges data with Motor Controller, Feedback Acquisition, Status Indication.

3) Motor Controller (MC)
   - Drives/halts motor; generates GPIO/PWM waveforms. (SWE-REQ-009, SWE-REQ-010, SWE-REQ-011, SWE-REQ-020)
   - Responds to Application Logic only.

4) Feedback Acquisition (FA)
   - Reads ADC, determines flap's logical position. (SWE-REQ-012, SWE-REQ-013, SWE-REQ-014, SWE-REQ-019)
   - No transform/logic about state, just reads/map.

5) Status Indicator (SI)
   - Updates position/power LEDs via GPIO. (SWE-REQ-015, SWE-REQ-016, SWE-REQ-017, SWE-REQ-021)
   - Receives state only, no logic.

-- MANDATED EXECUTION MODEL --
No explicit execution or scheduling model is mandated by the software requirements at this stage. All single-command-driven logic can be implemented sequentially or event-driven. (SWE-REQ-034, implied)
