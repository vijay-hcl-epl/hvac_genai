SOFTWARE ARCHITECTURE DOCUMENT (SWE.2)
HVAC Flap Actuator – Infineon TLE9851QXW

1. ARCHITECTURE STYLE SELECTION
---------------------------------
Candidates:
 a. Layered architecture
 b. Component-based architecture
 c. Monolithic modular architecture

Evaluation:
* Layered: Testable, separates interface, control, driver, but overhead for small system.
* Component-based: Good for large/compositional. May over-complicate for atomic device.
* Monolithic modular: Aligns to system simplicity, requirements, allows explicit, testable module APIs and direct data flow.

Selection:
Monolithic modular architecture selected.
- System has single actuator, no dynamic expansion, no runtime composition, explicit data/control boundaries required for testability (SWE-REQ-040, SWE-REQ-041).
- Layered/component add no value for strictly sequenced position-control with direct HW interfaces and no asynchronous requirements.

2. ARCHITECTURE DEFINITION
----------------------------
Software Units and Responsibilities:
- Command Interface Unit: Receives/validates user commands via UART/LIN. (SWE-REQ-001, 002, 003, 017, 018)
- Control State Machine: Manages Idle/Move/Stopped/Fault, issues action to actuator unit. (SWE-REQ-004, 005, 026, 027, 028, 029)
- Actuator Driver Unit: Generates motor control signals using half-bridge, executes PWM/speed logic. (SWE-REQ-009, 010, 036)
- Feedback Processing Unit: Reads ADC, maps position, checks thresholds, detects errors. (SWE-REQ-011, 012, 013, 019, 029, 032)
- Status Indication Unit: Sets GPIO/LED, LIN, or UART indicators. (SWE-REQ-015, 016, 020)
- Configuration Data Unit: Reads, holds, shares config (from Flash only, static). (SWE-REQ-012, 032, 038, 039)
- Initialization/Startup Unit: System and chip bring-up, state entry. (SWE-REQ-021, 022, 023, 024)

Interfaces between Units:
- Command IF → State Machine: command_in (validated command)
- State Machine → Actuator Driver: position_cmd, enable, stop
- State Machine → Status Indicator: pos_status, fault_status
- Feedback→State Machine/Actuator: position, error_flags
- Config Data available to units at init
- Startup→others: triggers initialization, provides ready indication

Execution Model:
No explicit execution model or scheduling policy is mandated by the requirements at this stage.
