-----------------------
ARCHITECTURE STYLE SELECTION
-----------------------
Candidate styles:
- Monolithic
- Layered
- Component-based (modular units by responsibility)

Evaluation:
- System complexity: Low/Moderate; there are clear, distinct domains (command, actuation, feedback, indication, error handling).
- HW interaction: Direct, via MCU peripherals (UART, ADC, GPIO).
- Testability: Favor separation by domain to facilitate unit-level and integration tests.
- Maintainability: Maintainable through clear interface separation and modularization.
- ASPICE L3: Emphasizes traceability, interface clarity, and unit definition.

Selection: Component-based (responsibility-driven decomposition)
Justification: Layered is not warranted (no abstraction between HAL and application needed given simplicity); monolithic lacks modularity for testability and maintenance; component-based offers optimal clarity, ASPICE alignment, and matches explicitly modular non-functional requirements (SYS-REQ-023).

-----------------------
ARCHITECTURE DEFINITION
-----------------------
Software Unit Summary:
- User Command Manager
- Command Validator
- Flap Control Unit
- Motor Driver Interface
- Position Feedback Processor
- Status Indicator Control
- System Error Handler

Responsibilities & Trace:
1. User Command Manager
   - Receives position commands via UART. (SWE-REQ-001, SWE-REQ-010)
2. Command Validator
   - Validates syntax/range, ignores malformed/out-of-range. (SWE-REQ-002, SWE-REQ-003)
3. Flap Control Unit
   - Computes actuator setpoints, initiates motion, tracks target/tolerance. (SWE-REQ-004, SWE-REQ-005, SWE-REQ-006, SWE-REQ-015, SWE-REQ-016)
4. Motor Driver Interface
   - Drives MCU outputs to actuator driver, stops at target/tolerance. (SWE-REQ-005, SWE-REQ-006, SWE-REQ-012)
5. Position Feedback Processor
   - Acquires/validates sensor data, detects faults. (SWE-REQ-007, SWE-REQ-008, SWE-REQ-011)
6. Status Indicator Control
   - Drives LEDs for all relevant states. (SWE-REQ-009, SWE-REQ-013, SWE-REQ-018)
7. System Error Handler
   - Handles safe states, error transitions, fault indicators. (SWE-REQ-017, SWE-REQ-018, SWE-REQ-020, SWE-REQ-021)

Explicit Execution Model:
No explicit execution model or scheduling policy is mandated by the requirements at this stage.
