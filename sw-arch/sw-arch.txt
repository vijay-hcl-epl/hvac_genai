------------------------------------------------------------
ARCHITECTURE STYLE SELECTION AND JUSTIFICATION
------------------------------------------------------------

Candidate styles considered:
1. Monolithic (single-control, tightly coupled modules)
2. Component-based
3. Layered (HW abstraction, central logic, external interface)

Evaluation summary:
- System complexity: Low; all logic fits in a simple sequence without interleaved behaviors, threads, or services.
- HW interaction: Direct mapping from requirements to HW interface (UART, ADC, GPIO).
- Testability: Code must be testable by unit and at system level per requirements (§SW-REQ-039, SW-REQ-040).
- Maintainability: Changes (e.g., different HW, positions) require only localized/unit changes if separated.
- ASPICE L3 expectations: Modular, explicit interfaces, clear separation of responsibilities. No RTOS/services exposure.

Final Style: COMPONENT-BASED (Reject monolithic due to maintainability and testability. Layered provides no extra benefit as interface abstractions are lightweight and straightforward.)

Justification:
- Distinct responsibilities (UART command, actuator, feedback processing, LED output, main coordinator)
- Each HW interaction is easily encapsulated.
- Enables clear unit mapping per SWE.3 and supports atomic testability.

------------------------------------------------------------
EXECUTION MODEL DECLARATION
------------------------------------------------------------
“No explicit execution model or scheduling policy is mandated by the requirements at this stage.”

All interaction is assumed to follow a simple, invocation-driven process consistent with the system/testing expectations. No timing or RTOS model is implied in SWE.1.

------------------------------------------------------------
A) TEXT-BASED ARCHITECTURE DIAGRAM
------------------------------------------------------------

+------------------+
|   Main Control   |
|   Coordinator    |
+------------------+
     /   |   \   \
    /    |    \   \
    v    v     v   v
+---------+ +---------+ +---------+ +---------+
| UART    | | Motor   | | Feedback| | LED     |
| Command | | Control | | Proc.   | | Control |
+---------+ +---------+ +---------+ +---------+

Text key:
- Main Control Coordinator: supervises and routes control/data between units below.
- UART Command: receives user commands, parses/validates, notifies Main.
- Motor Control: receives movement/stop requests, manipulates GPIO/PWM.
- Feedback Processing: samples ADC, maps to logical position, notifies Main.
- LED Control: updates system/position LEDs per Main instruction.

Arrows: information/control flow. No direct peer-to-peer communication between lower-level units (all via Main except HW indirect reactions).
