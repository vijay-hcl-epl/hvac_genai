1.0 ARCHITECTURE STYLE SELECTION
===============================

Candidate Styles:
  - Component-Based
  - Layered
  - Monolithic

Evaluation:
- System complexity is low; all responsibilities fit one MCU; interfaces are simple (UART, ADC, GPIO/PWM).
- HW interaction occurs via explicit microcontroller peripherals and GPIOs, with discrete roles for command, actuation, feedback, and indication (trace: SWE-REQ-017, 018, 019, 020).
- SWE.1 mandates modular responsibility separation (SWE-REQ-042, SYS-REQ-043), but not strict layering.
- Testability and maintainability both favor modularization (component-based), not global monolithic design.

Selection:
  - Component-Based architecture is selected for clear separation of concerns and direct traceability to SWE.1’s modularization and separation-of-responsibility requirements.
  - Layered is rejected as excessive for scope and for offering no concrete test, maintenance, or traceability benefit per requirements.
  - Monolithic is rejected as anti-traceability and fails maintainability/testability required by SWE-REQ-042/031/043.


2.0 ARCHITECTURE DEFINITION
===========================

Software Units, Responsibilities, Interfaces:

- Command Interpreter
    - Responsibilities: Parses UART input, validates commands, forwards valid position requests, ignores invalid input (SWE-REQ-001,002,003,027,032).
    - Interfaces Provided: Command validation API.
    - Interfaces Used: UART interface API.

- Position Controller
    - Responsibilities: Receives target position, orchestrates movement by motor and feedback units, state tracking (SWE-REQ-004,005,006,024,025,026,028).
    - Interfaces Provided: Position movement API, flap state info.
    - Interfaces Used: Command API, Motor Actuator API, Feedback Processor API, Indicator API.

- Motor Actuator
    - Responsibilities: Sets GPIO direction, enables PWM, halts motor, per target/feedback (SWE-REQ-007,008,018,023,026).
    - Interfaces Provided: Motor control API.
    - Interfaces Used: Position Controller API.

- Feedback Processor
    - Responsibilities: Acquires ADC, maps feedback to discrete positions, detects errors, relays to controller (SWE-REQ-009,010,011,012,019,033).
    - Interfaces Provided: Flap position/status API.
    - Interfaces Used: ADC driver, Position Controller API.

- Indicator Manager
    - Responsibilities: Manages power and position LEDs (SWE-REQ-013,014,015,016,020,031,040,041).
    - Interfaces Provided: Status update API.
    - Interfaces Used: Position Controller API.

- System Init/Platform
    - Responsibilities: One-time peripheral setup/support, pin config, static calibration table access (SWE-REQ-021,022,029,030,037,038,039,043).
    - Interfaces Provided: Init APIs, calibration/read-only data.
    - Interfaces Used: None (lowest layer).


Execution Model:
----------------
No explicit execution model or scheduling policy is mandated by the requirements at this stage. (SWE-REQ-037)
