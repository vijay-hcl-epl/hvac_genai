SOFTWARE REQUIREMENTS SPECIFICATION

Automotive HVAC Flap Actuator — Software Requirements
Target Platform: MOTIX™ TLE9851QXW
Branch: hvdemo-143b

---

1.0 Software Scope & Responsibility
The software layer SHALL implement system-level requirements (see sys-reqs/sys-reqs.txt) for motor and position feedback control, user command handling (UART/LIN), status indication, and error handling. Scope includes MCU on-chip peripherals only (UART/LIN, ADC, GPIO, timers, motor driver). No RTOS/scheduling architecture is mandated. (Traces: SYS-REQ-001..141)

2.0 Software Functional Requirements
2.1 User Command Reception & Decoding
SWE-REQ-001: The software SHALL receive target flap position commands (0–5) via UART or LIN, decoding ASCII or binary numeric values as per selected mode. (Traces: SYS-REQ-040, SYS-REQ-041, SYS-REQ-042)
SWE-REQ-002: The software SHALL ignore malformed or out-of-range commands and maintain previous actuator state. (Traces: SYS-REQ-013, SYS-REQ-043, SYS-REQ-064)
SWE-REQ-003: The command handling routines SHALL NOT accept concurrent commands from UART and LIN. (Traces: SYS-REQ-015, SYS-REQ-040)
[Implied] SWE-REQ-004: User command decoding SHALL NOT constrain any specific message framing or baudrate. (SYS-REQ-041,042)

2.2 Flap Position & Motor Control
SWE-REQ-010: The software SHALL map decoded target positions to ADC thresholds in Flash, and initiate flap movements using the NFET half-bridge driver. (Traces: SYS-REQ-010, SYS-REQ-011, SYS-REQ-021)
SWE-REQ-011: The software SHALL support both clockwise and anti-clockwise motor rotation, as required to reach the desired position. (Traces: SYS-REQ-021)
SWE-REQ-012: Once feedback confirms target is reached, software SHALL de-energize the motor and optionally enter configured Hold/Brake mode. (Traces: SYS-REQ-012, SYS-REQ-023, SYS-REQ-063)
SWE-REQ-013: The motor drive SHALL be immediately de-energized on driver, ADC, or out-of-range position fault. (Traces: SYS-REQ-024, SYS-REQ-034, SYS-REQ-110, SYS-REQ-113)
[Implied] SWE-REQ-014: Flap movement algorithms SHALL exclusively use pre-configured motor driver and PWM settings. (SYS-REQ-020, SYS-REQ-022, SYS-REQ-121)

2.3 Feedback Acquisition & Processing
SWE-REQ-020: The software SHALL acquire position feedback by sampling the on-chip ADC (ADC1), mapping raw data to logical positions per Flash thresholds. (Traces: SYS-REQ-030, SYS-REQ-031)
SWE-REQ-021: Any detected open/short, or out-of-range sensor value SHALL be flagged as a fault and the motor SHALL be de-energized. (Traces: SYS-REQ-033, SYS-REQ-034, SYS-REQ-111, SYS-REQ-113)
SWE-REQ-022: During active/movement phases, flap position SHALL be repeatedly sampled and compared with the target until within tolerance. (Traces: SYS-REQ-032)
[Implied] SWE-REQ-023: ADC sampling/thresholds SHALL NOT be alterable at runtime; values are fixed in Flash. (SYS-REQ-011,031,081)

2.4 Status Indication
SWE-REQ-030: The software SHALL set GPIO outputs for flap position indicators and for system/fault status as commanded by application state. (Traces: SYS-REQ-050, SYS-REQ-052)
SWE-REQ-031: The software SHALL report current flap position and status via UART/LIN message (Traces: SYS-REQ-051,140)
[Implied] SWE-REQ-032: Only one position indicator output is set at a time. (SYS-REQ-050)

3.0 Software Interface Requirements
SWE-REQ-040: The software SHALL use only TLE9851QXW UART or LIN peripherals for user command reception, and SHALL configure only one active at a time. (Traces: SYS-REQ-015,070)
SWE-REQ-041: The software SHALL use the on-chip ADC (ADC1) for reading the position feedback potentiometer. (Traces: SYS-REQ-072)
SWE-REQ-042: The motor driver software interface SHALL control only the integrated half-bridge; no support for external power stages. (Traces: SYS-REQ-020,071)
SWE-REQ-043: Outputs for indicators/faults SHALL be set via dedicated GPIO or high-side driver. (Traces: SYS-REQ-052,073)
[Implied] SWE-REQ-044: Each interface SHALL allow external observation or test via pins/frames. (SYS-REQ-140)

4.0 Software Behavioral Requirements
SWE-REQ-050: On reset or power-up, software SHALL initialize and configure all required MCU peripherals, entering idle state, and disabling motor drive. (Traces: SYS-REQ-060,066)
SWE-REQ-051: During idle, software SHALL monitor for valid commands and flap position. (Traces: SYS-REQ-061)
SWE-REQ-052: On valid command, software SHALL move the flap to the requested logical position, based on feedback. (Traces: SYS-REQ-062)
SWE-REQ-053: Command completion/fault/invalid input SHALL result in motor de-energizing and status indication. (Traces: SYS-REQ-063,064)
SWE-REQ-054: All normal/fault states SHALL recover to idle with actuator off. (Traces: SYS-REQ-066,062,113)
[Implied] SWE-REQ-055: Startup and idle processing SHALL NOT assume/require periodic, super-loop, or interrupt models. (SYS-REQ-130)

5.0 Software Data & Configuration
SWE-REQ-060: ADC threshold values and motor driver configurables SHALL be stored in internal Flash and only modifiable offline. (Traces: SYS-REQ-011,031,081)
[Implied] SWE-REQ-061: The software SHALL NOT store or modify parameters in EEPROM or RAM for non-volatile settings. (Traces: SYS-REQ-081)

6.0 Software Error Handling
SWE-REQ-070: Software SHALL handle all driver, ADC, or sensor plausibility faults by immediately disabling motor drive and signaling status. (Traces: SYS-REQ-024, SYS-REQ-034, SYS-REQ-110-113)
SWE-REQ-071: Motor or interface faults SHALL NOT block further user command processing after reset/idle. (Traces: SYS-REQ-066,062)
SWE-REQ-072: The watchdog timer SHALL be serviced throughout all normal states unless deliberately in error/reset. (Traces: SYS-REQ-112)
[Implied] SWE-REQ-073: Software error handling SHALL NOT embed application-specific recovery logic other than stop/fault indication. (SYS-REQ-113,130)

7.0 Performance & Responsiveness
SWE-REQ-080: The software implementation SHALL ensure command-to-motion initiation within system-level <100 ms for valid commands, under nominal conditions. (Traces: SYS-REQ-100)
[Implied] SWE-REQ-081: No fixed execution period or main loop rate is prescribed. (SYS-REQ-130,131)

8.0 Resource Constraints
SWE-REQ-090: Complete software, including all logic, configuration, and tables, SHALL fit in available MCU resources. (Traces: SYS-REQ-120)
[Implied] SWE-REQ-091: No RAM/Flash over-allocation, nor support for dynamic allocation is required. (SYS-REQ-120,081)

9.0 Testability
SWE-REQ-100: All major states, commands, and detected faults SHALL be representable in status messages or indicator outputs for test. (Traces: SYS-REQ-051,140,141)
[Implied] SWE-REQ-101: Software SHALL allow trace outputs on unused pins/frame bytes for verification if configured. (Traces: SYS-REQ-140)

10.0 Implied Requirements
- [Implied] items above are explicitly marked within each section.

---
Note: Each software requirement is atomic, architecture/model neutral, testable, and directly traceable to system-level requirements. No scheduling, tasking, or periodic model is imposed; all system-mandated behaviors (flap motor control, command reception, feedback, status indication, error handling) are to be implemented exactly as required by SYS-REQ-xxx, with no extra safety, concurrency, or interface logic unless stipulated in the system-level requirements.
