# 1.0 Software Scope and Responsibility
The HVAC Flap Actuator software executes on a microcontroller, providing command-based control of a single air flap via a DC motor. The software interacts with peripherals (UART, ADC, GPIO, PWM), acquires position feedback, manages flap movement, drives LEDs for system and position indication, and supports clear, testable behavior for education and ASPICE demonstration. Hardware interaction is limited to logical, implementation-neutral responsibilities.

# 2.0 Software Functional Requirements
## 2.1 User Command Handling
- SWE-REQ-001: The software shall receive user commands representing target flap positions via UART. (SYS-REQ-001, SYS-REQ-018, SYS-REQ-036)
- SWE-REQ-002: The software shall validate each received user command to ensure it falls within the configured flap position range. (SYS-REQ-019, SYS-REQ-020)
- SWE-REQ-003: The software shall ignore any command with a value outside the valid flap position range. (SYS-REQ-020, SYS-REQ-048)
- SWE-REQ-004: The software shall interpret received commands as numeric target positions. (SYS-REQ-019)
- SWE-REQ-005: The software shall not transmit any acknowledgment or error in response to an invalid command. (SYS-REQ-021, SYS-REQ-050)
- SWE-REQ-006: The software shall process only one position command at a time; any further commands shall be ignored or queued until movement is complete. [Implied] (SYS-REQ-022, SYS-REQ-043)

## 2.2 Flap Position Control Logic
- SWE-REQ-007: The software shall map valid target commands to discrete, calibrated flap positions. (SYS-REQ-006, SYS-REQ-015, SYS-REQ-016)
- SWE-REQ-008: The software shall compare current flap position feedback against the target position. (SYS-REQ-003)
- SWE-REQ-009: The software shall initiate flap movement when the target position differs from the feedback value. (SYS-REQ-002, SYS-REQ-007)
- SWE-REQ-010: The software shall stop the flap movement when the measured position matches the target. (SYS-REQ-004, SYS-REQ-010)
- SWE-REQ-011: The software shall maintain the flap’s position after successful movement to target. (SYS-REQ-005)

## 2.3 Motor Control Logic
- SWE-REQ-012: The software shall control motor signals to drive the flap toward the target position. (SYS-REQ-008, SYS-REQ-009, SYS-REQ-037)
- SWE-REQ-013: The software shall disable the motor immediately on reaching the desired position. (SYS-REQ-010)
- SWE-REQ-014: The software shall disable the motor if position feedback is out of range. (SYS-REQ-011, SYS-REQ-049)
- SWE-REQ-015: The motor shall remain disabled except during active movement. [Implied] (SYS-REQ-012)

## 2.4 Position Feedback Processing
- SWE-REQ-016: The software shall acquire flap position feedback using ADC input from the potentiometer. (SYS-REQ-013, SYS-REQ-038)
- SWE-REQ-017: The software shall periodically sample ADC to obtain the latest position. (SYS-REQ-014)
- SWE-REQ-018: The software shall use calibration constants for ADC-to-position mapping. (SYS-REQ-016)
- SWE-REQ-019: No dynamic calibration or self-learning shall be performed during operation. [Implied] (SYS-REQ-017)

## 2.5 Status Indication Control
- SWE-REQ-020: The software shall illuminate a dedicated LED to indicate power-on status. (SYS-REQ-023, SYS-REQ-039)
- SWE-REQ-021: The software shall illuminate one LED to indicate the current flap position. (SYS-REQ-024, SYS-REQ-039)
- SWE-REQ-022: At most one position LED shall be illuminated at a time. (SYS-REQ-025)
- SWE-REQ-023: LED indications shall always reflect the latest available software state. (SYS-REQ-026)
- SWE-REQ-024: No blinking or complex visual status/position feedback shall be implemented. [Implied] (SYS-REQ-027)

# 3.0 Software Interface Requirements
- SWE-REQ-025: The software shall provide a UART interface for receiving user position commands. (SYS-REQ-036)
- SWE-REQ-026: The software shall acquire potentiometer feedback using a dedicated ADC channel. (SYS-REQ-038, SYS-REQ-013)
- SWE-REQ-027: The software shall control motor signals delivered to the motor driver module. (SYS-REQ-037, SYS-REQ-008)
- SWE-REQ-028: The software shall control GPIO-powered LEDs for system and position status. (SYS-REQ-039)
- SWE-REQ-029: All interface pins shall be statically configured at initialization. [Implied] (SYS-REQ-040)

# 4.0 Software Behavioral Requirements
- SWE-REQ-030: On startup, the software shall initialize all required peripherals (ADC, UART, GPIO, PWM). (SYS-REQ-028)
- SWE-REQ-031: The software shall ensure the motor is disabled upon initialization. (SYS-REQ-029)
- SWE-REQ-032: The software shall determine and display initial flap position at initialization using the indicator LED(s). (SYS-REQ-030)
- SWE-REQ-033: While idle, the software shall reflect the current position using position LED(s). (SYS-REQ-031)
- SWE-REQ-034: While processing a command, the software shall update position feedback and disable the motor upon reaching the requested position. (SYS-REQ-032, SYS-REQ-033)
- SWE-REQ-035: The software shall safely ignore invalid user commands and maintain safe state (motor disabled, LEDs valid). (SYS-REQ-034, SYS-REQ-048)
- SWE-REQ-036: The software shall never enter an undefined operation state even on unexpected input. [Implied] (SYS-REQ-035)

# 5.0 Software Data and Configuration Requirements
- SWE-REQ-037: The software shall store the list of supported flap positions and corresponding ADC thresholds as calibration data. (SYS-REQ-006, SYS-REQ-015, SYS-REQ-016)
- SWE-REQ-038: The software shall use only static memory for all data and configuration. (SYS-REQ-052)
- SWE-REQ-039: No dynamic memory allocation or self-modifying configuration shall be performed. [Implied] (SYS-REQ-052, SYS-REQ-017)

# 6.0 Software Error Handling Requirements
- SWE-REQ-040: Upon receiving an invalid command, the software shall not alter the current system or position state. (SYS-REQ-020, SYS-REQ-048)
- SWE-REQ-041: If the position feedback (ADC) is out of the expected range, the software shall immediately stop the motor and hold a safe state. (SYS-REQ-011, SYS-REQ-049)
- SWE-REQ-042: The software shall never generate error messages or warning codes in any scenario. (SYS-REQ-050)

# 7.0 Software Performance and Responsiveness Requirements
- SWE-REQ-043: The software shall respond to each valid UART position command with a change in motor/LED state shortly after receipt. (SYS-REQ-046)
- SWE-REQ-044: The software shall update ADC readings and LED indications in a manner that is responsive to human users. (SYS-REQ-047)

# 8.0 Software Resource Constraint Requirements
- SWE-REQ-045: The software shall not use dynamic memory allocation. (SYS-REQ-052)
- SWE-REQ-046: All processing behaviors shall be predictable and have bounded resource use. (SYS-REQ-053)
- SWE-REQ-047: Complexity shall be minimized for clarity, using only the memory and processing required for the listed functions. (SYS-REQ-051, SYS-REQ-054)

# 9.0 Software Testability Requirements
- SWE-REQ-048: The software shall support manual test by accepting UART command entry and providing LED/motor response for observation. (SYS-REQ-056)
- SWE-REQ-049: The software shall allow automated/scripted test cycles by UART interaction. (SYS-REQ-057)
- SWE-REQ-050: Software-controlled LEDs and motor behavior shall be fully observable for the verification of all requirements. (SYS-REQ-058)

# 10.0 Implied Software Requirements
### (All marked [Implied], see related system-level implied requirements)

- SWE-REQ-015: The motor shall remain disabled except while actively driving to a new position. (SYS-REQ-012)
- SWE-REQ-019: No dynamic calibration/self-learning shall be supported. (SYS-REQ-017)
- SWE-REQ-024: No blinking or complex LED behavior for indication. (SYS-REQ-027)
- SWE-REQ-029: All I/O pins statically configured at initialization. (SYS-REQ-040)
- SWE-REQ-036: Software never enters undefined operational state, even if unexpected input occurs. (SYS-REQ-035)
- SWE-REQ-039: No dynamic memory or configuration change. (SYS-REQ-052, SYS-REQ-017)
