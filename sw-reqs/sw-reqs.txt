# 1.0 Software Scope and Responsibility

The HVAC Flap Actuator software is responsible for receiving user commands via UART, translating these commands into flap position requests, controlling a DC motor to move the flap to the commanded positions, monitoring real-time flap position via ADC/potentiometer feedback, and driving LED indicators for mode and position. The software does not make architectural, tasking, or scheduling decisions, focusing instead on functional behavior and interface with hardware peripherals.

# 2.0 Software Functional Requirements

## 2.1 User Command Handling

- SWE-REQ-001: The software shall receive user flap position commands (numeric 0–5) via UART. (SYS-REQ-001, SYS-REQ-018)
- SWE-REQ-002: The software shall validate incoming UART commands and only act upon numeric values within the allowed flap position range. (SYS-REQ-019)
- SWE-REQ-003: The software shall ignore and not respond to any invalid or unsupported UART command, and shall not change system state in response. (SYS-REQ-020, SYS-REQ-033, SYS-REQ-047)
- SWE-REQ-004: The software shall process one user command at a time and only process a new command after completing the previous flap movement. (SYS-REQ-021, SYS-REQ-041)
- SWE-REQ-005: [Implied] The software shall not implement advanced UART protocols or error correction mechanisms. (SYS-REQ-022)

## 2.2 Flap Position Control Logic

- SWE-REQ-006: The software shall compare the requested target position to the currently detected position before actuating the motor. (SYS-REQ-002)
- SWE-REQ-007: The software shall initiate a sequence to move the flap to the target position only if it is different from the current position. (SYS-REQ-003, SYS-REQ-007)
- SWE-REQ-008: The software shall support at least 6 discrete flap positions (0–5). (SYS-REQ-005)
- SWE-REQ-009: The software shall confirm, using feedback, that the commanded final position is reached and hold that position after movement. (SYS-REQ-004, SYS-REQ-032)
- SWE-REQ-010: The software shall allow repeated position commands and shall execute movements accordingly. (SYS-REQ-006)

## 2.3 Motor Control Logic

- SWE-REQ-011: The software shall generate logical motor control signals to increase or decrease the flap position, controlling direction as needed. (SYS-REQ-008)
- SWE-REQ-012: The software shall enable or disable the DC motor to perform or stop the flap actuation. (SYS-REQ-009)
- SWE-REQ-013: The software shall stop the motor when the feedback indicates the requested target position is achieved. (SYS-REQ-010)
- SWE-REQ-014: [Implied] The software shall stop the motor if the feedback is invalid or out-of-range. (SYS-REQ-011)
- SWE-REQ-015: [Implied] The software shall set the motor OFF at system power-up/initialization. (SYS-REQ-012, SYS-REQ-028)

## 2.4 Position Feedback Processing

- SWE-REQ-016: The software shall acquire position feedback from a potentiometer via ADC channel. (SYS-REQ-013, SYS-REQ-038)
- SWE-REQ-017: The software shall convert ADC readings to logical flap positions using fixed, pre-configured ranges. (SYS-REQ-014, SYS-REQ-043)
- SWE-REQ-018: The software shall continuously (as often as needed) monitor and process ADC feedback to update flap status. (SYS-REQ-015)
- SWE-REQ-019: The software shall detect ADC readings outside of defined calibration ranges and shall enter a safe, non-actuating state. (SYS-REQ-016, SYS-REQ-048)
- SWE-REQ-020: [Implied] The software shall not implement dynamic self-calibration for position mapping. (SYS-REQ-017)

## 2.5 Status Indication Control

- SWE-REQ-021: The software shall control a status LED to indicate power-on state. (SYS-REQ-023)
- SWE-REQ-022: The software shall control position indicator LEDs such that one and only one green LED corresponding to the current detected position is ON. (SYS-REQ-024, SYS-REQ-025)
- SWE-REQ-023: The software shall update position indicator LEDs based on measured feedback (not just the last commanded position). (SYS-REQ-026, SYS-REQ-029)

# 3.0 Software Interface Requirements

- SWE-REQ-024: The software shall implement a UART receive interface for incoming commands from a PC. (SYS-REQ-018, SYS-REQ-036)
- SWE-REQ-025: The software shall acquire analog position signals from the potentiometer via ADC hardware abstraction. (SYS-REQ-013, SYS-REQ-038)
- SWE-REQ-026: The software shall control H-Bridge driver signals (direction, enable/disable) for motor actuation using logical GPIO and PWM functions. (SYS-REQ-037)
- SWE-REQ-027: The software shall control status and position LEDs using GPIO abstractions. (SYS-REQ-039)

# 4.0 Software Behavioral Requirements

- SWE-REQ-028: On power-up, the software shall initialize all required peripherals: ADC, UART, GPIO, PWM. (SYS-REQ-027)
- SWE-REQ-029: After initialization, the software shall set the actuator motor state to OFF and display the current position via the LEDs. (SYS-REQ-028, SYS-REQ-029)
- SWE-REQ-030: During idle state (awaiting command), the software shall not cause flap actuation. (SYS-REQ-030)
- SWE-REQ-031: Upon valid command receipt, the software shall activate movement toward the requested target position and stop when achieved. (SYS-REQ-031, SYS-REQ-032)
- SWE-REQ-032: If an invalid/unsupported command is received, the software shall not change its current output or hardware state. (SYS-REQ-033)
- SWE-REQ-033: [Implied] The software shall use a linear, auditable control structure suitable for demonstration. (SYS-REQ-034)

# 5.0 Software Data and Configuration Requirements

- SWE-REQ-034: The software shall store all flap position calibration mappings using fixed, pre-configured values for the ADC-to-position lookup. (SYS-REQ-043)
- SWE-REQ-035: The software shall use constants or equivalents for configuration; dynamic memory allocation shall not be used. (SYS-REQ-044)
- SWE-REQ-036: The software shall maintain internal state only as necessary to represent command status, flap position, and error flags. (SYS-REQ-041, SYS-REQ-048)

# 6.0 Software Error Handling Requirements

- SWE-REQ-037: The software shall deterministically ignore invalid user commands with no actuator or output change. (SYS-REQ-020, SYS-REQ-047)
- SWE-REQ-038: The software shall place the actuator in a safe, motor-OFF state if feedback (ADC) values are out-of-range. (SYS-REQ-048)
- SWE-REQ-039: If the requested position is already achieved, the software shall not actuate the motor. (SYS-REQ-007)
- SWE-REQ-040: [Implied] The software shall reliably avoid undefined or unsafe behavior under error conditions. (SYS-REQ-049)

# 7.0 Software Performance and Responsiveness Requirements

- SWE-REQ-041: The software shall update flap position following a valid command within a perceptible short delay. (SYS-REQ-046)
- SWE-REQ-042: Evaluation and actuation logic shall execute in a predictable and bounded fashion. (SYS-REQ-050)
- SWE-REQ-043: [Implied] The software shall not specify or depend on fixed control periods, cyclic scheduling, or specific execution rates. (SYS-REQ-050)

# 8.0 Software Resource Constraint Requirements

- SWE-REQ-044: The software shall use bounded, lightweight code and memory structures suitable for predictability and maintainability. (SYS-REQ-050, SYS-REQ-051)
- SWE-REQ-045: The software shall avoid dynamic memory allocation and unbounded resource consumption. (SYS-REQ-044, SYS-REQ-050)

# 9.0 Software Testability Requirements

- SWE-REQ-046: The software shall provide testability through observable status and position LEDs and controlled response to UART commands. (SYS-REQ-052)
- SWE-REQ-047: The software shall support manual or automated script-based test verification of system behaviors. (SYS-REQ-053)

# 10.0 Implied Software Requirements

- SWE-REQ-048: [Implied] The software shall not implement CAN, LIN, network, or diagnostics/protocols outside the prototype scope. (SYS-REQ-040, SYS-REQ-045)
- SWE-REQ-049: [Implied] The software shall not require a real-time operating system, multiple threads, or complex task scheduling. (SYS-REQ-035)
- SWE-REQ-050: [Implied] The software design shall be intentionally simple for learning, demonstration, and traceability purposes. (SYS-REQ-051)
