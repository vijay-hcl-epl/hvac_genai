# 1.0 Software Scope and Responsibility

The software for the HVAC Flap Actuator System executes on a microcontroller and is responsible for:
- Receiving user commands representing target flap positions via UART
- Validating and interpreting user commands
- Determining and signaling the correct motor actions required to achieve the requested flap position
- Acquiring, interpreting, and mapping position feedback from a potentiometer using an ADC
- Reporting system and actuator status using LEDs
- Ensuring safe handling of invalid inputs and error conditions
- Operating in a predictable, efficient, and testable manner per system requirements without making architectural or execution model assumptions

# 2.0 Software Functional Requirements

## 2.1 User Command Handling

- SWE-REQ-001: The software shall receive and interpret user commands for flap position targets via UART. (SYS-REQ-001, SYS-REQ-022, SYS-REQ-039)
- SWE-REQ-002: The software shall validate received user commands and only process those corresponding to flap positions 0–5. (SYS-REQ-006, SYS-REQ-023)
- SWE-REQ-003: The software shall ignore any user command outside the allowed flap position range (0–5). (SYS-REQ-006, SYS-REQ-024)
- SWE-REQ-004: The software shall not require acknowledgment for either valid or invalid commands. [Implied] (SYS-REQ-025)

## 2.2 Flap Position Control Logic

- SWE-REQ-005: The software shall, upon valid command, compare the current flap position against the requested target position. (SYS-REQ-002)
- SWE-REQ-006: The software shall initiate position control only when the flap must move to reach the new target. (SYS-REQ-003, SYS-REQ-009)
- SWE-REQ-007: The software shall activate the appropriate motor drive direction based on whether the target is greater than or less than the current position. (SYS-REQ-010)
- SWE-REQ-008: The software shall stop the motor when the requested position is reached within the defined tolerance. (SYS-REQ-004, SYS-REQ-012)
- SWE-REQ-009: The software shall maintain the flap in its last reached position after achieving the target. (SYS-REQ-007)
- SWE-REQ-010: The software shall monitor the flap's physical position and, if drift is detected, re-initiate movement to correct position. (SYS-REQ-005)
- SWE-REQ-011: The software shall ensure the flap actuator only controls a single actuator and motor. (SYS-REQ-044)
- SWE-REQ-012: The software shall process only one user command at a time. (SYS-REQ-045)
- SWE-REQ-013: The software shall not require a homing or calibration sequence upon power-up. [Implied] (SYS-REQ-008)

## 2.3 Motor Control Logic

- SWE-REQ-014: The software shall enable the DC motor only when movement is required to achieve a new flap position. (SYS-REQ-009, SYS-REQ-031)
- SWE-REQ-015: The software shall control the direction of the DC motor based on requested vs current position. (SYS-REQ-010)
- SWE-REQ-016: The software shall assert only one motor direction signal at any time and prevent conflicting signals. (SYS-REQ-014)
- SWE-REQ-017: The software shall keep the motor disabled after power-up and during idle or error states. (SYS-REQ-015, SYS-REQ-031)
- SWE-REQ-018: The software shall disable the motor immediately if an out-of-range position (ADC) or error is detected. (SYS-REQ-013, SYS-REQ-038)

## 2.4 Position Feedback Processing

- SWE-REQ-019: The software shall acquire analog voltage from the position feedback potentiometer using an ADC channel. (SYS-REQ-016, SYS-REQ-042)
- SWE-REQ-020: The software shall map ADC readings to discrete logical positions (0–5) per defined ADC value ranges. (SYS-REQ-017, SYS-REQ-018)
- SWE-REQ-021: The software shall detect and flag ADC or potentiometer readings outside the expected range as errors. (SYS-REQ-020)
- SWE-REQ-022: The software shall never accept ADC values that do not correspond to a valid logical position. [Implied] (SYS-REQ-021)
- SWE-REQ-023: The software shall utilize fixed, software-defined calibration constants for all logical positions. (SYS-REQ-047)

## 2.5 Status Indication Control

- SWE-REQ-024: The software shall control a dedicated status LED to indicate system power. (SYS-REQ-026)
- SWE-REQ-025: The software shall control a set of green LEDs to display the current flap position, ensuring only one green LED is ON at any time. (SYS-REQ-027)
- SWE-REQ-026: The software shall update LED indicators promptly whenever the flap position changes. (SYS-REQ-028)
- SWE-REQ-027: The software shall maintain simple LED behavior only as described, without elaborate patterns. [Implied] (SYS-REQ-029)

# 3.0 Software Interface Requirements

- SWE-REQ-028: The software shall receive all external user commands over UART. (SYS-REQ-039)
- SWE-REQ-029: The software shall acquire flap position feedback through ADC connected to the potentiometer. (SYS-REQ-016, SYS-REQ-042)
- SWE-REQ-030: The software shall control the DC motor enable/disable through PWM-capable GPIO outputs. (SYS-REQ-040)
- SWE-REQ-031: The software shall control motor direction and LEDs through dedicated GPIO outputs. (SYS-REQ-011, SYS-REQ-041)
- SWE-REQ-032: The software shall provide actuator position and status indication solely via status and green LEDs. [Implied] (SYS-REQ-043)

# 4.0 Software Behavioral Requirements

- SWE-REQ-033: Upon power-up or reset, the software shall initialize all peripherals and internal state (UART, ADC, GPIO, LEDs, motor control). (SYS-REQ-030)
- SWE-REQ-034: On power-up, the software shall ensure the motor remains disabled (OFF) until a valid command is received. (SYS-REQ-031)
- SWE-REQ-035: Upon power-up, the software shall display the detected current flap position on LEDs. (SYS-REQ-032)
- SWE-REQ-036: During idle, the software shall wait for user command input. (SYS-REQ-033)
- SWE-REQ-037: During normal operation, the software shall process user commands, initiate flap movement, and indicate the result via LEDs. (SYS-REQ-035)
- SWE-REQ-038: When the requested position is achieved, the software shall transition to a holding state with the motor OFF and update status LEDs. (SYS-REQ-036)
- SWE-REQ-039: The software shall handle invalid user commands gracefully by ignoring them. (SYS-REQ-034)
- SWE-REQ-040: The software shall never crash or behave unpredictably, even if continuous invalid commands are received. [Implied] (SYS-REQ-037)

# 5.0 Software Data and Configuration Requirements

- SWE-REQ-041: The software shall define and store calibration constants and threshold ADC values for discrete flap positions within the source code or configuration. (SYS-REQ-018, SYS-REQ-047)
- SWE-REQ-042: The software shall internally track current, requested, and last commanded flap positions. (SYS-REQ-002, SYS-REQ-005, SYS-REQ-033)

# 6.0 Software Error Handling Requirements

- SWE-REQ-043: The software shall ignore invalid user commands without generating error responses. (SYS-REQ-006, SYS-REQ-024, SYS-REQ-050)
- SWE-REQ-044: The software shall flag and handle position feedback that is outside expected ADC ranges by disabling the motor and not updating position. (SYS-REQ-020, SYS-REQ-038, SYS-REQ-050)
- SWE-REQ-045: The software shall not attempt to drive the motor if errors are detected in position feedback. (SYS-REQ-013, SYS-REQ-038)
- SWE-REQ-046: The software shall ensure a deterministic response to invalid or out-of-range inputs. (SYS-REQ-050)
- SWE-REQ-047: The software shall operate predictably even if hardware faults are suspected, by disabling output as needed. [Implied] (SYS-REQ-048)

# 7.0 Software Performance and Responsiveness Requirements

- SWE-REQ-048: The software shall process and respond to user commands with negligible and human-observable instantaneous responsiveness, per prototype expectations. (SYS-REQ-049)
- SWE-REQ-049: The software shall evaluate flap position and issue control actions in a timely manner, sufficient for reliable operation in this educational system. (SYS-REQ-051)

# 8.0 Software Resource Constraint Requirements

- SWE-REQ-050: The software shall avoid resource-intensive computations and operate efficiently within the limits of the microcontroller. (SYS-REQ-051)
- SWE-REQ-051: The software shall not implement any mechanism for multi-tasking, concurrent execution, or polling vs. interrupt, unless explicitly required by the system. [Implied] (SYS-REQ-048)
- SWE-REQ-052: The software shall avoid unbounded processing, ensuring all command and control operations complete predictably. (SYS-REQ-051)

# 9.0 Software Testability Requirements

- SWE-REQ-053: The software shall provide functional observability through UART responses and LED behavior to facilitate manual and scripted test cases. (SYS-REQ-053)
- SWE-REQ-054: The software shall allow for position indication and command handling to be externally verifiable for all supported cases. (SYS-REQ-053)

# 10.0 Implied Software Requirements

- SWE-REQ-055: [Implied] The software shall not include code for homing/calibration, diagnostics, or external vehicle communications. (SYS-REQ-008, SYS-REQ-046)
- SWE-REQ-056: [Implied] The software shall not depend on any RTOS, super-loop architecture, or assume execution model, unless explicitly specified in the system requirements. (SYS-REQ-052)
- SWE-REQ-057: [Implied] All functional separation (e.g., command handling vs. actuation vs. status) shall be maintained at a logical/software modularity level only, without constraining the architecture. (SYS-REQ-052)
