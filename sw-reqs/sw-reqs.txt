# 1.0 Software Scope and Responsibility
The software for the HVAC Flap Actuator System is responsible for interpreting user commands received over UART to control a DC motor-driven air flap. The software translates discrete user requests into actuator movement, acquires feedback via ADC from a potentiometer, and drives position and status LEDs to indicate system state. Its primary responsibilities are:
- Receiving and validating user commands
- Mapping target positions to ADC ranges
- Controlling the DC motor via GPIO/PWM to reach and maintain target positions
- Processing potentiometer feedback
- Providing feedback/observability to the user through LEDs
- Ensuring predictable, bounded, and observable behavior on a microcontroller

# 2.0 Software Functional Requirements

## 2.1 User Command Handling
- SWE-REQ-001: The software shall receive target flap position commands via UART (SYS-REQ-001, SYS-REQ-017).
- SWE-REQ-002: The software shall validate that each received command specifies a numeric position in the allowed range (0–5) (SYS-REQ-018, SYS-REQ-019).
- SWE-REQ-003: The software shall ignore invalid or out-of-range commands and shall not alter flap position in those cases (SYS-REQ-020, SYS-REQ-043).
- SWE-REQ-004: [Implied] The software shall support single-command operation, with no queuing or parallel processing (SYS-REQ-037).

## 2.2 Flap Position Control Logic
- SWE-REQ-005: The software shall compare the detected flap position with the most recently commanded target position (SYS-REQ-002).
- SWE-REQ-006: The software shall initiate movement towards the target position when a valid new command is received and the flap is not already at target (SYS-REQ-003, SYS-REQ-029).
- SWE-REQ-007: The software shall stop the flap motor when the target position is detected (SYS-REQ-004, SYS-REQ-011, SYS-REQ-030).
- SWE-REQ-008: The software shall maintain the flap at the new target position after stopping movement (SYS-REQ-005).
- SWE-REQ-009: [Implied] The software shall not require a homing routine at startup (SYS-REQ-007).

## 2.3 Motor Control Logic
- SWE-REQ-010: The software shall drive motor direction and enable signals using dedicated GPIO/PWM outputs (SYS-REQ-008, SYS-REQ-009, SYS-REQ-010, SYS-REQ-033).
- SWE-REQ-011: The software shall disable motor drive immediately upon reaching the commanded flap position (SYS-REQ-011).
- SWE-REQ-012: [Implied] The software shall prevent simultaneous activation of forward/reverse motor control lines (SYS-REQ-012).

## 2.4 Position Feedback Processing
- SWE-REQ-013: The software shall acquire the flap position using an ADC channel (SYS-REQ-013, SYS-REQ-034).
- SWE-REQ-014: The software shall sample ADC at intervals sufficient to detect position changes promptly (SYS-REQ-014).
- SWE-REQ-015: The software shall map ADC readings to discrete position indices (0–5) according to fixed value ranges (SYS-REQ-015, SYS-REQ-038).
- SWE-REQ-016: The software shall ignore ADC readings outside of the defined potentiometer range and not command motor movement in such cases (SYS-REQ-016, SYS-REQ-044, SYS-REQ-031).

## 2.5 Status Indication Control
- SWE-REQ-017: The software shall drive a power/status LED when system is powered and initialized (SYS-REQ-021).
- SWE-REQ-018: The software shall indicate current flap position using green LEDs, activating only the LED corresponding to the current discrete position index (SYS-REQ-022, SYS-REQ-023).
- SWE-REQ-019: [Implied] The software shall update LED indications promptly when the detected flap position changes (SYS-REQ-024).

# 3.0 Software Interface Requirements
- SWE-REQ-020: The software shall receive commands via the UART interface (SYS-REQ-017, SYS-REQ-032).
- SWE-REQ-021: The software shall acquire flap position feedback via ADC (SYS-REQ-013, SYS-REQ-034).
- SWE-REQ-022: The software shall control the DC motor via motor driver enable/direction pins (SYS-REQ-009, SYS-REQ-010, SYS-REQ-033).
- SWE-REQ-023: The software shall drive each discrete position/status LED using a dedicated GPIO output (SYS-REQ-022, SYS-REQ-035).

# 4.0 Software Behavioral Requirements
- SWE-REQ-024: On startup, the software shall initialize all peripherals (UART, ADC, GPIO, PWM) (SYS-REQ-025).
- SWE-REQ-025: On power-up, the software shall ensure the motor is deactivated (SYS-REQ-026).
- SWE-REQ-026: On power-up, the software shall acquire ADC readings to determine and indicate initial flap position (SYS-REQ-027, SYS-REQ-022).
- SWE-REQ-027: When no new valid user command is received, the software shall maintain last position and remain idle (SYS-REQ-028).
- SWE-REQ-028: When a valid user command is received, the software shall move the flap as needed to reach the requested position (SYS-REQ-029, SYS-REQ-003).
- SWE-REQ-029: If the flap is already at the requested position, the software shall not activate the motor (SYS-REQ-004, SYS-REQ-030).
- SWE-REQ-030: If invalid or out-of-range ADC values are detected, the software shall disable movement and maintain safe state (SYS-REQ-016, SYS-REQ-031, SYS-REQ-044).

# 5.0 Software Data and Configuration Requirements
- SWE-REQ-031: The software shall use pre-defined, software-fixed ADC ranges for each flap position index (SYS-REQ-038, SYS-REQ-015).
- SWE-REQ-032: The software shall maintain internal state: current position, last commanded position, and system initialization status (SYS-REQ-027, SYS-REQ-005, SYS-REQ-021).

# 6.0 Software Error Handling Requirements
- SWE-REQ-033: The software shall deterministically ignore and not respond to invalid UART commands (SYS-REQ-043).
- SWE-REQ-034: The software shall suspend all motion and maintain current position if ADC readings are outside valid range (SYS-REQ-016, SYS-REQ-044, SYS-REQ-031).
- SWE-REQ-035: [Implied] The software shall not implement or signal additional diagnostics beyond those observable via status LED and position LEDs (SYS-REQ-045).

# 7.0 Software Performance and Responsiveness Requirements
- SWE-REQ-036: The software shall process user commands and actuator movements with a responsiveness perceived as nearly instantaneous by the user (SYS-REQ-041).
- SWE-REQ-037: [Implied] The software shall not guarantee fixed control periods, deadlines, or real-time constraints (SYS-REQ-042).

# 8.0 Software Resource Constraint Requirements
- SWE-REQ-038: The software shall avoid dynamic memory allocation in all control and interface flows (SYS-REQ-046).
- SWE-REQ-039: The software shall ensure bounded, predictable software execution time (SYS-REQ-047).

# 9.0 Software Testability Requirements
- SWE-REQ-040: The software shall allow observation of all state transitions via position LEDs and UART-actuated actuations (SYS-REQ-049).
- SWE-REQ-041: The software shall support manual and script-based interaction with all major software functions using UART commands (SYS-REQ-050).

# 10.0 Implied Software Requirements
- SWE-REQ-009: [Implied] No homing at startup; last-known or detected position is used (SYS-REQ-007).
- SWE-REQ-012: [Implied] No simultaneous forward/reverse drive of the motor (SYS-REQ-012).
- SWE-REQ-019: [Implied] Prompt update of LED status (SYS-REQ-024).
- SWE-REQ-037: [Implied] No fixed periodic or deadline requirements; only "prompt" behavior (SYS-REQ-042).
- SWE-REQ-035: [Implied] No additional diagnostics, only LED/status indication (SYS-REQ-045).

# Explicit Exclusions
- No assumptions or requirements for RTOS, task/thread structure, cyclic/periodic control, scheduling policies, or priorities
- No requirements for multitasking, concurrency, or safety integrity levels
- No cybersecurity, diagnostics protocol, or vehicle network
