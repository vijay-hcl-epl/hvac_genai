# 1.0 Software Scope and Responsibility

The HVAC Flap Actuator software executes on a microcontroller and is responsible for receiving user commands, mapping commands to target flap positions, controlling a DC motor to achieve the requested flap position, acquiring position feedback via ADC, and providing visual status using LEDs. The software covers all logic needed for actuation, command interface, position sensing, feedback indication, error handling, and testability for a single-flap, single-user scenario. It interacts with UART, ADC, GPIO, and PWM peripherals. Architectural or execution-model decisions are expressly deferred to software architecture design (SWE.2).

# 2.0 Software Functional Requirements

## 2.1 User Command Handling

- SWE-REQ-001: The software shall accept a single-digit numeric command (0–5) received via UART as the target flap position. (SYS-REQ-001, SYS-REQ-017, SYS-REQ-033)
- SWE-REQ-002: The software shall validate each command for numeric integrity and supported value range (0–5), ignoring commands outside this range without response. (SYS-REQ-018, SYS-REQ-019, SYS-REQ-044)
- SWE-REQ-003: The software shall ensure only one command is processed at a time. [Implied] (SYS-REQ-020, SYS-REQ-038)

## 2.2 Flap Position Control Logic

- SWE-REQ-004: The software shall compare the requested target position to the current flap position determined from ADC feedback. (SYS-REQ-002, SYS-REQ-015)
- SWE-REQ-005: The software shall initiate flap movement only if the target position differs from the current position. [Implied] (SYS-REQ-031)
- SWE-REQ-006: The software shall support exactly six discrete flap positions (0–5) unless reconfigured. (SYS-REQ-006)
- SWE-REQ-007: The software shall maintain the flap at the last commanded position until a new valid command is received. (SYS-REQ-005)

## 2.3 Motor Control Logic

- SWE-REQ-008: The software shall actuate the DC motor to move the flap from the current to the commanded position using logical output signals. (SYS-REQ-003, SYS-REQ-034)
- SWE-REQ-009: The software shall control the motor's direction using two GPIO outputs. (SYS-REQ-008)
- SWE-REQ-010: The software shall enable and disable motor drive using one output (PWM or GPIO). (SYS-REQ-009)
- SWE-REQ-011: The software shall stop the motor promptly when the current position matches the commanded position. (SYS-REQ-004, SYS-REQ-010)
- SWE-REQ-012: The software shall stop the motor if the ADC feedback is outside valid calibration range. (SYS-REQ-011, SYS-REQ-016, SYS-REQ-043)
- SWE-REQ-013: The software shall ensure only one motor direction output is asserted at a time. [Implied] (SYS-REQ-012)

## 2.4 Position Feedback Processing

- SWE-REQ-014: The software shall read flap position using ADC measurements from the potentiometer. (SYS-REQ-013, SYS-REQ-014, SYS-REQ-035)
- SWE-REQ-015: The software shall map ADC readings to discrete positions using fixed software thresholds. (SYS-REQ-015, SYS-REQ-039)
- SWE-REQ-016: The software shall treat out-of-range ADC feedback as invalid and take safe action. (SYS-REQ-016, SYS-REQ-043)

## 2.5 Status Indication Control

- SWE-REQ-017: The software shall turn on a dedicated LED to indicate system power-on state. (SYS-REQ-021)
- SWE-REQ-018: The software shall display the current logical flap position by illuminating one of six position LEDs. (SYS-REQ-022)
- SWE-REQ-019: The software shall ensure that no more than one position LED is on at any given time. (SYS-REQ-023)
- SWE-REQ-020: Status and position LEDs shall be controlled only by software-driven GPIO output. [Implied] (SYS-REQ-024, SYS-REQ-036)

# 3.0 Software Interface Requirements

- SWE-REQ-021: The software shall receive user commands using the UART peripheral. (SYS-REQ-017, SYS-REQ-033)
- SWE-REQ-022: The software shall read the potentiometer via an ADC input. (SYS-REQ-014, SYS-REQ-035)
- SWE-REQ-023: The software shall output logical motor drive signals (direction, enable) using GPIO and/or PWM outputs. (SYS-REQ-008, SYS-REQ-009, SYS-REQ-034)
- SWE-REQ-024: The software shall provide position and status indication by driving LEDs via GPIO outputs. (SYS-REQ-021, SYS-REQ-022, SYS-REQ-036)

# 4.0 Software Behavioral Requirements

- SWE-REQ-025: The software shall initialize all required peripherals (UART, ADC, GPIO, PWM) on system startup. (SYS-REQ-025)
- SWE-REQ-026: The software shall ensure the motor is off at power-up/initialization. (SYS-REQ-026)
- SWE-REQ-027: On startup, the software shall read the current position via ADC and update LED indication accordingly. (SYS-REQ-027)
- SWE-REQ-028: The software shall only move the flap upon receiving a valid command for a new target position. (SYS-REQ-028, SYS-REQ-031)
- SWE-REQ-029: The software shall remain idle awaiting new commands except for continuous position monitoring. [Implied] (SYS-REQ-029, SYS-REQ-007)
- SWE-REQ-030: The software shall ignore invalid UART commands and invalid ADC input without adverse effect. (SYS-REQ-030, SYS-REQ-044)
- SWE-REQ-031: The software shall not attempt flap movement if the motor or feedback is in an invalid state. [Implied] (SYS-REQ-016, SYS-REQ-043)
- SWE-REQ-032: If the motor fails to reach the target position, the software shall not lock or crash. [Implied] (SYS-REQ-032)

# 5.0 Software Data and Configuration Requirements

- SWE-REQ-033: The software shall provide fixed configuration for ADC calibration thresholds mapping ADC values to logical flap positions. (SYS-REQ-015, SYS-REQ-039)
- SWE-REQ-034: The software shall store and use discrete position indices (0–5) mapped to ADC ranges. (SYS-REQ-006, SYS-REQ-015)
- SWE-REQ-035: The software shall hold internal state for current vs. target position for control logic. (SYS-REQ-002, SYS-REQ-028, SYS-REQ-037)
- SWE-REQ-036: The software shall not support dynamic calibration or learning of position thresholds. (SYS-REQ-040)

# 6.0 Software Error Handling Requirements

- SWE-REQ-037: The software shall ignore any user command with non-numeric or out-of-range value. (SYS-REQ-018, SYS-REQ-044)
- SWE-REQ-038: The software shall stop the motor and disregard movement commands if ADC values are out of valid calibration range. (SYS-REQ-043)
- SWE-REQ-039: The software shall not attempt further motor control if the current state or feedback indicates an error. [Implied] (SYS-REQ-011, SYS-REQ-016, SYS-REQ-043)
- SWE-REQ-040: The software shall avoid unhandled fault or crash conditions upon hardware or feedback anomalies (best-effort operation only). [Implied] (SYS-REQ-032, SYS-REQ-045)

# 7.0 Software Performance and Responsiveness Requirements

- SWE-REQ-041: The software shall process and begin acting on valid user commands within a timeframe that feels responsive to a human user, without specifying a fixed timing requirement. (SYS-REQ-042)
- SWE-REQ-042: The software shall evaluate position and make control decisions in bounded and predictable time. [Implied] (SYS-REQ-047)

# 8.0 Software Resource Constraint Requirements

- SWE-REQ-043: The software shall avoid dynamic memory allocation and use static or stack-based variables only. (SYS-REQ-046)
- SWE-REQ-044: The software shall ensure predictable, bounded execution. (SYS-REQ-047)
- SWE-REQ-045: The software shall minimize memory and CPU resource use consistent with prototype operation. (SYS-REQ-046, SYS-REQ-048)

# 9.0 Software Testability Requirements

- SWE-REQ-046: The software shall support manual testability by allowing commands to be sent via UART and status to be observed via LEDs. (SYS-REQ-050)
- SWE-REQ-047: The software shall support script-based testing by accepting valid command sequences and providing observable results. (SYS-REQ-051)

# Explicit Exclusions

- No assumptions or requirements for operating system, threads, tasks, priorities, or cyclic scheduling are included.
- No requirements are defined for communications protocols other than local UART.
- No requirements for vehicle diagnostics, security, or networking are included.
- Software-level diagnostics, fault codes, or recovery are not specified.
