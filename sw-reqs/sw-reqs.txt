# 1.0 Software Scope and Responsibility

The software executes on a microcontroller in the HVAC flap actuator system. Its responsibilities include:
- Receiving user commands for flap position selection via UART
- Mapping commands to discrete flap positions
- Acquiring position feedback through ADC
- Controlling a DC motor for flap actuation using GPIO and PWM
- Indicating flap position and status with LEDs 
- Providing bounded, deterministic operation with clear, observable feedback

# 2.0 Software Functional Requirements

## 2.1 User Command Handling

SWE-REQ-001: The software shall receive user flap position commands as numeric values over UART. (SYS-REQ-001, SYS-REQ-018)
SWE-REQ-002: The software shall validate that each command value corresponds to a supported discrete flap position. (SYS-REQ-019, SYS-REQ-020)
SWE-REQ-003: The software shall safely ignore any command that is invalid or out of range, taking no action in response. (SYS-REQ-021, SYS-REQ-048)
SWE-REQ-004: [Implied] The software shall not transmit acknowledgment or error messages for invalid commands. (SYS-REQ-022)

## 2.2 Flap Position Control Logic

SWE-REQ-005: The software shall compare the current flap position to the commanded target. (SYS-REQ-002)
SWE-REQ-006: When a valid command is received, the software shall initiate flap movement toward the target position. (SYS-REQ-003)
SWE-REQ-007: The software shall stop the motor when the target position is reached. (SYS-REQ-004, SYS-REQ-010, SYS-REQ-032)
SWE-REQ-008: The software shall hold the flap at the achieved target position. (SYS-REQ-005, SYS-REQ-030)
SWE-REQ-009: The software shall support a fixed number of discrete flap positions as mapped from ADC ranges. (SYS-REQ-006)
SWE-REQ-010: [Implied] Position limits shall be enforced in software based on statically configured ADC boundaries. (SYS-REQ-007, SYS-REQ-017)

## 2.3 Motor Control Logic

SWE-REQ-011: The software shall control the direction of the DC motor using GPIO outputs. (SYS-REQ-008, SYS-REQ-011)
SWE-REQ-012: The software shall enable and disable the DC motor via dedicated enable signal(s). (SYS-REQ-009, SYS-REQ-036)
SWE-REQ-013: The software shall stop the motor automatically upon feedback that the flap is at the target or if out-of-range feedback is detected. (SYS-REQ-010, SYS-REQ-012, SYS-REQ-049)
SWE-REQ-014: The software shall drive the motor in both clockwise and anti-clockwise directions as required. (SYS-REQ-011)
SWE-REQ-015: [Implied] The software shall prevent all motor movement if feedback is invalid or out-of-range. (SYS-REQ-012, SYS-REQ-049)

## 2.4 Position Feedback Processing

SWE-REQ-016: The software shall acquire flap position feedback using a potentiometer connected to an ADC channel. (SYS-REQ-013, SYS-REQ-014)
SWE-REQ-017: The software shall map ADC values to logical (discrete) flap positions. (SYS-REQ-015)
SWE-REQ-018: The software shall periodically or upon relevant event update the internal position state based on ADC readings. (SYS-REQ-016, SYS-REQ-029)
SWE-REQ-019: [Implied] The mapping of ADC ranges to supported positions shall use fixed, statically defined parameters. (SYS-REQ-017)

## 2.5 Status Indication Control

SWE-REQ-020: The software shall control a dedicated LED to indicate power-on/status. (SYS-REQ-023)
SWE-REQ-021: The software shall control a distinct green LED for each possible flap position. (SYS-REQ-024)
SWE-REQ-022: At most one green position LED shall be ON at any time, corresponding to the current detected position. (SYS-REQ-025)
SWE-REQ-023: [Implied] The status and position LED indication shall immediately reflect the latest detected system state. (SYS-REQ-026)

# 3.0 Software Interface Requirements

SWE-REQ-024: The software shall receive user commands over the UART interface. (SYS-REQ-035)
SWE-REQ-025: The software shall utilize a motor driver module through GPIO and/or PWM signals to control the DC motor. (SYS-REQ-036, SYS-REQ-039)
SWE-REQ-026: The software shall acquire analog position feedback using an ADC input channel. (SYS-REQ-037)
SWE-REQ-027: The software shall control status and position indicator LEDs using GPIO outputs. (SYS-REQ-038)

# 4.0 Software Behavioral Requirements

SWE-REQ-028: On startup, the software shall initialize all required peripherals (ADC, UART, GPIO, PWM). (SYS-REQ-027)
SWE-REQ-029: On startup, the motor shall remain OFF until a valid target position command is received. (SYS-REQ-028)
SWE-REQ-030: On startup, the software shall read initial flap position and set all relevant LED indicators accordingly. (SYS-REQ-029)
SWE-REQ-031: While idle (awaiting user command), the software shall maintain current flap position and LED status. (SYS-REQ-030)
SWE-REQ-032: During flap movement, the software shall update status and position LED indicators to reflect position changes. (SYS-REQ-031)
SWE-REQ-033: Upon reaching the target position, the software shall stop the motor and update the LED indication. (SYS-REQ-032)
SWE-REQ-034: The software shall handle invalid inputs and conditions without system fault or crash. (SYS-REQ-033)
SWE-REQ-035: [Implied] The software shall not require user reset to recover from invalid input. (SYS-REQ-034)

# 5.0 Software Data and Configuration Requirements

SWE-REQ-036: The software shall store discrete flap position mappings as static parameters. (SYS-REQ-006, SYS-REQ-015)
SWE-REQ-037: The software shall store and use ADC threshold values for mapping position. (SYS-REQ-007, SYS-REQ-017)
SWE-REQ-038: The software shall store calibration constants in code or NVM as needed. (SYS-REQ-044)
SWE-REQ-039: The software shall maintain internal state information for flap position and command validity. (SYS-REQ-016, SYS-REQ-019)

# 6.0 Software Error Handling Requirements

SWE-REQ-040: The software shall deterministically ignore or reject invalid user commands. (SYS-REQ-021, SYS-REQ-048)
SWE-REQ-041: If ADC feedback is outside expected range, the software shall stop the motor and indicate the state using LEDs. (SYS-REQ-012, SYS-REQ-049)
SWE-REQ-042: If the motor cannot reach the target position due to feedback outside allowable limits, the software shall not actuate the flap further. (SYS-REQ-049)
SWE-REQ-043: [Implied] The software shall ensure such error handling does not cause system crash or require reset. (SYS-REQ-050)

# 7.0 Software Performance and Responsiveness Requirements

SWE-REQ-044: The software shall process and act on received user commands with observable responsiveness in normal operating conditions. (SYS-REQ-046)
SWE-REQ-045: Position evaluation and control decisions shall be performed in a timely fashion, consistent with user expectations, but without enforcing fixed periods or cycles. (SYS-REQ-047)
SWE-REQ-046: [Implied] No fixed control periods or cyclic execution behavior is mandated. (SYS-REQ-047)

# 8.0 Software Resource Constraint Requirements

SWE-REQ-047: The software shall use memory and peripherals efficiently to maintain lightweight implementation. (SYS-REQ-051)
SWE-REQ-048: The software shall avoid unbounded or unpredictable processing. (SYS-REQ-052)
SWE-REQ-049: System behavior under normal conditions shall be limited to bounded, predictable operations. (SYS-REQ-052)

# 9.0 Software Testability Requirements

SWE-REQ-050: The software shall support verification of operation through UART command interaction. (SYS-REQ-055)
SWE-REQ-051: The software shall support observability and testing through status and position LEDs. (SYS-REQ-055)
SWE-REQ-052: The software shall support manual and script-based testing according to the use case. (SYS-REQ-056)
