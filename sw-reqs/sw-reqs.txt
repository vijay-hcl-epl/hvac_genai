# 1.0 Software Scope and Responsibility

The software for the HVAC Flap Actuator executes on a microcontroller, providing logic for interpreting user commands (UART), controlling a DC motor driving an air mixing flap, reading potentiometer-based feedback (ADC), and controlling LEDs for position/power indication. It implements all system requirements allocable to embedded software, excluding hardware/diagnostics/protocol behaviors and architecture.

# 2.0 Software Functional Requirements

## 2.1 User Command Handling
- SWE-REQ-001: The software shall accept discrete position commands (0-5) received via UART. (SYS-REQ-001, SYS-REQ-020, SYS-REQ-021)
- SWE-REQ-002: The software shall validate each received command, accepting only those in the permitted range (0-5). (SYS-REQ-007, SYS-REQ-022)
- SWE-REQ-003: The software shall ignore any command outside the valid range and shall not change the flap position in such cases. (SYS-REQ-007, SYS-REQ-023, SYS-REQ-047)
- SWE-REQ-004: The software shall map each valid user command to a unique logical flap position. (SYS-REQ-002, SYS-REQ-021)
[Implied] SWE-REQ-005: The software shall not recognize or act upon commands beyond the defined valid set of positions. (SYS-REQ-008, SYS-REQ-039)

## 2.2 Flap Position Control Logic
- SWE-REQ-006: The software shall compare the current flap position to the target position after each command or feedback update. (SYS-REQ-003)
- SWE-REQ-007: The software shall initiate flap movement if the target position differs from the current position. (SYS-REQ-004, SYS-REQ-012)
- SWE-REQ-008: The software shall stop the motor when the target position is achieved. (SYS-REQ-005, SYS-REQ-013)
- SWE-REQ-009: The software shall hold the flap at the last commanded position after movement. (SYS-REQ-006)

## 2.3 Motor Control Logic
- SWE-REQ-010: The software shall determine required motor direction (clockwise/anti-clockwise) to move toward the desired position. (SYS-REQ-012)
- SWE-REQ-011: The software shall enable or disable the motor using control signals. (SYS-REQ-010)
- SWE-REQ-012: The software shall disable the motor by default on power-up, and in error or idle states. (SYS-REQ-011, SYS-REQ-030, SYS-REQ-033)
[Implied] SWE-REQ-013: The software shall not drive the motor beyond the software-defined mechanical/feedback limits. (SYS-REQ-014)

## 2.4 Position Feedback Processing
- SWE-REQ-014: The software shall acquire the potentiometer signal using an ADC channel. (SYS-REQ-015, SYS-REQ-037)
- SWE-REQ-015: The software shall map raw ADC values into logical flap positions (0–5) per fixed, calibrated ranges. (SYS-REQ-017)
- SWE-REQ-016: The software shall recognize ADC readings outside valid operating range as errors. (SYS-REQ-018, SYS-REQ-046)
[Implied] SWE-REQ-017: The software shall not perform runtime calibration or learning sequences. (SYS-REQ-019)

## 2.5 Status Indication Control
- SWE-REQ-018: The software shall switch a dedicated LED to indicate power/status after system initialization. (SYS-REQ-024)
- SWE-REQ-019: The software shall use one of several LEDs to indicate logical flap position; only one position LED shall be ON under normal operation. (SYS-REQ-025, SYS-REQ-026)
[Implied] SWE-REQ-020: Status and position LEDs shall be controlled via GPIO outputs. (SYS-REQ-027)

# 3.0 Software Interface Requirements
- SWE-REQ-021: The software shall receive user position commands as ASCII digits via UART. (SYS-REQ-020, SYS-REQ-021, SYS-REQ-035)
- SWE-REQ-022: The software shall communicate with the DC motor driver by toggling GPIO outputs and providing motor enable/disable via PWM signals. (SYS-REQ-009, SYS-REQ-010, SYS-REQ-036)
- SWE-REQ-023: The software shall acquire flap position feedback by reading from an ADC channel. (SYS-REQ-015, SYS-REQ-037)
- SWE-REQ-024: The software shall control all status and position LEDs as GPIO-controlled outputs. (SYS-REQ-038, SYS-REQ-024, SYS-REQ-025)

# 4.0 Software Behavioral Requirements
- SWE-REQ-025: On power-up/reset, the software shall initialize all required peripherals (UART, ADC, GPIO, PWM) before processing position commands. (SYS-REQ-028)
- SWE-REQ-026: After initialization, the software shall read potentiometer feedback and set the LEDs to match the current position. (SYS-REQ-029)
- SWE-REQ-027: The software shall disable the motor after reset or power-up until a valid position command is received. (SYS-REQ-030)
- SWE-REQ-028: During idle, the software shall continue monitoring for user commands and position feedback updates without moving the flap. (SYS-REQ-031)
- SWE-REQ-029: The software shall stop the motor and update LED status when the target position has been achieved. (SYS-REQ-032)
- SWE-REQ-030: If invalid command or feedback is detected, the software shall stop the motor and maintain last known safe state. (SYS-REQ-033)
[Implied] SWE-REQ-031: The software shall not require a startup homing sequence. (SYS-REQ-034)

# 5.0 Software Data and Configuration Requirements
- SWE-REQ-032: The software shall use fixed, pre-configured calibration values for mapping ADC readings to logical positions. (SYS-REQ-017, SYS-REQ-042)
- SWE-REQ-033: The software shall store internal state comprising the current position, target position, and last commanded position. (SYS-REQ-003, SYS-REQ-009)

# 6.0 Software Error Handling Requirements
- SWE-REQ-034: The software shall stop the motor upon detection of invalid command or position feedback. (SYS-REQ-046, SYS-REQ-033)
- SWE-REQ-035: The software shall ignore and not act upon invalid UART commands. (SYS-REQ-007, SYS-REQ-022, SYS-REQ-047)
- SWE-REQ-036: The software shall maintain a safe idle state if the flap cannot reach the requested position or ADC is out-of-range. (SYS-REQ-048, SYS-REQ-018)
[Implied] SWE-REQ-037: No error code or diagnostic information shall be sent to the user or PC. (SYS-REQ-049)

# 7.0 Software Performance and Responsiveness Requirements
- SWE-REQ-038: The software shall process valid UART commands and respond by starting flap movement with prompt responsiveness observable to a human user. (SYS-REQ-044)
[Implied] SWE-REQ-039: The software shall avoid unnecessary latency between command reception and actuator movement. (SYS-REQ-045)

# 8.0 Software Resource Constraint Requirements
- SWE-REQ-040: The software shall avoid use of dynamic memory allocation. (SYS-REQ-050)
- SWE-REQ-041: The software shall be implemented to use predictable and bounded stack and memory resources. (SYS-REQ-051)
[Implied] SWE-REQ-042: The software design and data usage shall be lightweight for educational and demonstration purposes. (SYS-REQ-052)

# 9.0 Software Testability Requirements
- SWE-REQ-043: The software shall support manual testing through UART command input and visual observation of motor and LED response. (SYS-REQ-055)
- SWE-REQ-044: The software shall permit script-based automated test scenarios over UART. (SYS-REQ-056)
- SWE-REQ-045: The software shall provide status and feedback through observable LEDs and UART to support verification. (SYS-REQ-057)

# 10.0 Implied Software Requirements
[Implied] SWE-REQ-046: The software shall only support operation of a single actuator, motor, and user. (SYS-REQ-040)
[Implied] SWE-REQ-047: The software shall assume the hardware platform and environment function as designed; advanced self-diagnostic or recovery mechanisms are not required. (SYS-REQ-041)
[Implied] SWE-REQ-048: The software shall include separation of concerns between command handling, control logic, and interface management for clarity and maintainability. (SYS-REQ-053, SYS-REQ-054)
