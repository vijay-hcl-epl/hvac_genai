SOFTWARE REQUIREMENTS DOCUMENT – HVAC FLAP ACTUATOR (MOTIX™ TLE9851QXW)

1.0 Software Scope & Responsibility
This software implements command handling, actuator control, feedback acquisition, and status indication for the single-flap HVAC air management system using the Infineon TLE9851QXW MCU. Firmware responsibility includes processing user or LIN commands, driving the DC motor, and providing position/status reporting, with all required MCU interface handling. Implementation excludes scheduling, RTOS, and safety constructs, except as specified at system level.

2.0 Software Functional Requirements
2.1 User Commands
SWE-REQ-001: The software SHALL accept position commands (0…5) via UART1, UART2, or LIN transceiver using an 8-bit numeric protocol. [Traces: SYS-REQ-002, SYS-REQ-016, SYS-REQ-017]
SWE-REQ-002: Invalid or out-of-range commands SHALL be ignored with no software reset or crash. [SYS-REQ-018, SYS-REQ-028]
[Implied] SWE-REQ-003: All command interfaces SHALL operate with continuous MCU supply (no runtime reconfiguration). [SYS-REQ-036]

2.2 Flap Control
SWE-REQ-004: The software SHALL process valid position commands and signal the control processor to move the flap accordingly. [SYS-REQ-004, SYS-REQ-025]
SWE-REQ-005: The software SHALL signal holding status only after confirming actual position matches commanded. [SYS-REQ-005, SYS-REQ-027]
SWE-REQ-006: Upon successful movement, software SHALL not issue further motor commands until new input is received. [SYS-REQ-006]

2.3 Motor Control
SWE-REQ-007: Software SHALL output motor driver signals to enable/disable, set direction (CW/CCW), and pulse-width modulation as requested. [SYS-REQ-007, SYS-REQ-008, SYS-REQ-010]
SWE-REQ-008: In case of detected fault, software SHALL immediately stop motor output signals. [SYS-REQ-009, SYS-REQ-029, SYS-REQ-042]
SWE-REQ-009: The software SHALL never enable the motor output unless initialization is complete. [SYS-REQ-021]

2.4 Feedback Processing
SWE-REQ-010: Software SHALL periodically sample the potentiometer feedback through the integrated ADC1 (≥10 bits). [SYS-REQ-011, SYS-REQ-012, SYS-REQ-015]
SWE-REQ-011: Position thresholds SHALL be loaded from Flash and used to map actual feedback to discrete position. [SYS-REQ-013, SYS-REQ-036]
SWE-REQ-012: No runtime re-learning or calibration SHALL be implemented in feedback path. [SYS-REQ-014, SYS-REQ-039]
SWE-REQ-013: The measured position SHALL be internally available to status output and diagnostics functions. [SYS-REQ-014, SYS-REQ-019]

2.5 Status Indication
SWE-REQ-014: Software SHALL drive only one position indication output at a time: GPIO-controlled LED, High-Side Switch, UART or LIN frame. [SYS-REQ-019, SYS-REQ-020]
SWE-REQ-015: Status messages SHALL indicate valid/invalid command or detected system fault when possible. [SYS-REQ-041, SYS-REQ-047]

[Implied] SWE-REQ-016: Support for automated bench testing (status/command hooks) is recommended as a software extension. [SYS-REQ-048]

3.0 Software Interface Requirements
SWE-REQ-017: The software SHALL implement UART1/UART2 receive/transmit for commands and debug frames as per mapping table. [SYS-REQ-016, SYS-REQ-031]
SWE-REQ-018: The software SHALL implement LIN 2.2 protocol - slave mode only. [SYS-REQ-017, SYS-REQ-032]
SWE-REQ-019: ADC1 SHALL be set for potentiometer feedback, minimum 10 bits resolution, channel selection as per hardware config. [SYS-REQ-011, SYS-REQ-033]
SWE-REQ-020: At least 5 GPIOs SHALL be software-configurable for status or external control. [SYS-REQ-034]
SWE-REQ-021: All logical mapping/tables for serial commands, feedback thresholds, and indication selection SHALL be loaded from Flash at startup. [SYS-REQ-013, SYS-REQ-036]

[Implied] SWE-REQ-022: LIN, UART, and ADC1 interface error handling is required for robustness, except for ignored invalid commands. [SYS-REQ-041, SYS-REQ-042]

4.0 Software Behavioral Requirements
SWE-REQ-023: On MCU power-up/reset, firmware SHALL initialize all HW resources: clocks, peripherals, port assignments, Flash/config load, and leave motor off until ADC feedback and command logic are verified. [SYS-REQ-021]
SWE-REQ-024: After initialization, software SHALL sample the actual flap position and make it available. [SYS-REQ-022]
SWE-REQ-025: The software SHALL wait for valid command and not activate movement logic unless a command is received. [SYS-REQ-025, SYS-REQ-023]
SWE-REQ-026: Any ongoing movement SHALL be canceled and motor stopped as soon as target is reached or a fault is detected. [SYS-REQ-006, SYS-REQ-029, SYS-REQ-042]
SWE-REQ-027: The system SHALL not require mechanical homing at startup (all logic uses current measured position as valid). [SYS-REQ-024]
SWE-REQ-028: Sleep/Stop MCU modes MAY be supported if device low-power features are enabled, but are not required for operation. [SYS-REQ-030]

[Implied] SWE-REQ-029: No explicit task/thread or scheduler is implemented in the software logic. [SYS-REQ-024]

5.0 Software Data & Configuration
SWE-REQ-030: All command mappings, LIN node ID, UART settings, and position thresholds SHALL be stored in non-volatile Flash and read only at startup. [SYS-REQ-013, SYS-REQ-036]
SWE-REQ-031: Flap position configuration data SHALL be modifiable only through defined engineering process (compile-/flash-time). [SYS-REQ-036]
SWE-REQ-032: No runtime dynamic memory or buffer allocation SHALL be used anywhere in the software. [SYS-REQ-045]

6.0 Software Error Handling
SWE-REQ-033: The software SHALL detect and handle command input, feedback, and driver faults per mapped codes. [SYS-REQ-041]
SWE-REQ-034: Upon any detected dangerous motor driver, ADC, or supply fault, the software SHALL stop the actuator and report fault status. [SYS-REQ-042, SYS-REQ-043]

[Implied] SWE-REQ-035: Fault handling is restricted to reporting and actuator shut-off—no software-initiated recovery, limp, or fallback.

7.0 Performance & Responsiveness
SWE-REQ-036: The software SHALL respond to valid position command within 100 ms under nominal conditions. [SYS-REQ-040]
SWE-REQ-037: Control and feedback loops SHALL be implemented to ensure the system is responsive as required, but without hardcoded polling interval or task slot structure. [SYS-REQ-040]

8.0 Resource Constraints
SWE-REQ-038: The software plus tables/configuration SHALL not exceed 64 KB Flash and 4 KB RAM on the MCU. [SYS-REQ-044]
SWE-REQ-039: No use of dynamic memory or heap is allowed in the implementation. [SYS-REQ-045]

9.0 Testability
SWE-REQ-040: All software functions SHALL be testable by issuing UART/LIN commands and observing outputs or faults via debug mechanisms, GPIOs, or motor movement. [SYS-REQ-047]
[Implied] SWE-REQ-041: Manual and scripted test harness hooks MAY be implemented, but are not strictly required. [SYS-REQ-048]

10.0 Implied Requirements
[Implied] All requirements explicitly marked above or stated within section-level implied requirements.
