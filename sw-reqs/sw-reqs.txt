1.0 Software Scope & Responsibility

The software is responsible for managing all functions necessary to control and monitor the HVAC flap actuator according to user commands, feedback signals, and status indication requirements. It interprets user requests, processes sensor data, commands motor actuation, manages diagnostics, and coordinates system outputs within the context of an MCU (ADC, GPIO, UART, LEDs, timers). The software does not modify system-level requirements or physical system constraints, but implements, in a modular and testable way, the logic, interface management and data processing specified at the system level.


2.0 Software Functional Requirements

2.1 User Commands

SWE-REQ-001: The software SHALL interpret user command inputs for flap position between fully closed and fully open. [SYS-REQ-004, SYS-REQ-013]
SWE-REQ-002: The software SHALL reject and indicate any user command that is invalid or out of range. [SYS-REQ-015, SYS-REQ-020]
SWE-REQ-003: The software SHALL acknowledge receipt for each valid user command. [SYS-REQ-014]
[Implied] SWE-REQ-004: Software SHALL ignore further user commands while actuator is already moving to a previous user-requested position. [SYS-REQ-005]

2.2 Flap Control

SWE-REQ-005: The software SHALL calculate the target flap position based on the most recent valid user input. [SYS-REQ-004, SYS-REQ-005]
SWE-REQ-006: The software SHALL ensure target positions are always within actuator travel limits. [SYS-REQ-005, SYS-REQ-006]
SWE-REQ-007: The software SHALL not command movement beyond the detected hardware/feedback position limits. [SYS-REQ-006]

2.3 Motor Control

SWE-REQ-008: The software SHALL command the actuator motor to move the flap toward the requested target position. [SYS-REQ-007]
SWE-REQ-009: The software SHALL cease commanding the motor when the actuator position, per feedback, reaches the requested value within the allowed tolerance. [SYS-REQ-008]
SWE-REQ-010: The software SHALL implement logic to detect and indicate motor faults, including stall, open, or short condition, and report to status indication. [SYS-REQ-009]

2.4 Feedback Processing

SWE-REQ-011: The software SHALL acquire flap position feedback from ADC or digital sensor within ±3% of actuator scale. [SYS-REQ-010, SYS-REQ-011]
SWE-REQ-012: The software SHALL monitor sensor signal range and detect missing, out-of-range, or invalid sensor conditions. [SYS-REQ-012]

2.5 Status Indication

SWE-REQ-013: The software SHALL signal actuator/system status using LEDs or other logical outputs as required. [SYS-REQ-016]
SWE-REQ-014: The software SHALL signal ‘target reached’ and error status in response to achieved or invalid operating states. [SYS-REQ-019, SYS-REQ-020, SYS-REQ-028]
[Implied] SWE-REQ-015: Software SHALL indicate the state of data processing (initializing, ready, moving, error) on defined indicators. [SYS-REQ-019, SYS-REQ-020]


3.0 Software Interface Requirements

SWE-REQ-016: The software SHALL implement a logical UART interface for command/response messaging and status feedback. [SYS-REQ-021]
SWE-REQ-017: The software SHALL configure and utilize ADC for position sensor signal acquisition. [SYS-REQ-023] 
SWE-REQ-018: The software SHALL provide logical control outputs for the actuator driver. [SYS-REQ-022]
SWE-REQ-019: The software SHALL provide logical outputs to drive status LEDs. [SYS-REQ-024]
[Implied] SWE-REQ-020: Software SHALL abstract all external I/O at the interface level to ease portability and reduce direct hardware dependencies. [SYS-REQ-030]


4.0 Software Behavioral Requirements

SWE-REQ-021: Software SHALL perform full software state initialization of all variables, peripherals, and outputs at each power-up. [SYS-REQ-017]
SWE-REQ-022: Software SHALL idle in a low-activity/low-power state between user commands, maintaining feedback monitoring. [SYS-REQ-018]
SWE-REQ-023: Software SHALL process new user commands and update target position only when actuator is idle or at target. [SYS-REQ-005, SYS-REQ-019]
SWE-REQ-024: Software SHALL perform appropriate error indication and refuse actuation on detection of invalid input or sensor failure. [SYS-REQ-012, SYS-REQ-020]
SWE-REQ-025: Upon reaching requested target position, software SHALL maintain position and indicate status. [SYS-REQ-019]
[Implied] SWE-REQ-026: No requirement SHALL introduce assumptions regarding the periodicity, scheduling, or explicit concurrency in behavior beyond what is required by system-level responsiveness. [SYS-REQ-027]


5.0 Software Data & Configuration

SWE-REQ-027: The software SHALL allow configuration parameters for position sensor scaling, command range limits, and status timeouts to be modified in non-volatile or compile-time configuration. [SYS-REQ-026, SYS-REQ-030]
[Implied] SWE-REQ-028: The software SHALL restrict all shared or persistent variables to the minimal scope required to meet traceable requirements, to ease maintainability and test. [SYS-REQ-030]


6.0 Software Error Handling

SWE-REQ-029: The software SHALL indicate detected hardware, command, or sensor faults persistently via the specified status interface. [SYS-REQ-028]
SWE-REQ-030: The software SHALL log error codes retrievable at power cycle or via diagnostic command, if specified. [SYS-REQ-028]
[Implied] SWE-REQ-031: All software routines handling hardware or logic errors SHALL implement clear and recoverable exit states, minimizing software lock-up or undefined system state. [SYS-REQ-028]


7.0 Performance & Responsiveness

SWE-REQ-032: The software SHALL complete the user-command-to-motion-and-indication loop within 500ms, subject to hardware actuation and feedback limits. [SYS-REQ-027]
[Implied] SWE-REQ-033: Software SHALL avoid hard-coded time slicing or fixed execution cycle allocation beyond those imposed by requirements. [SYS-REQ-027]


8.0 Resource Constraints

SWE-REQ-034: The software SHALL execute within available MCU memory and processing resource allocation. [SYS-REQ-029]
[Implied] SWE-REQ-035: The software SHALL not maintain persistent data outside specified configuration/settings, and all dynamic memory shall be bounded. [SYS-REQ-029]


9.0 Testability

SWE-REQ-036: The software SHALL support software-in-the-loop, hardware-in-the-loop, and end-of-line functional testing modes. [SYS-REQ-031]
[Implied] SWE-REQ-037: All software requirements SHALL be atomic and independently verifiable through formal test, analysis, or inspection. [SYS-REQ-031]
