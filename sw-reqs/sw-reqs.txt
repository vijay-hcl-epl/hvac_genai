# 1.0 Software Scope and Responsibility
The HVAC Flap Actuator Demo software executes on a microcontroller platform and provides all logic required for:
- User command interpretation
- Flap position selection and validation
- Flap position control using a DC motor and position feedback
- Status/event indication via LEDs
- UART-based system interaction
No explicit architecture, execution model, or scheduling is defined at this level. The software directly realizes and allocates all functional responsibilities described by the system requirements.

# 2.0 Software Functional Requirements
## 2.1 User Command Handling
SWE-REQ-001: The software shall accept user commands for selecting a flap position via the UART interface. (SYS-REQ-001, SYS-REQ-016)
SWE-REQ-002: The software shall validate each user command for correct format and position range. (SYS-REQ-005, SYS-REQ-017)
SWE-REQ-003: The software shall reject and respond to invalid, malformed, or out-of-range commands. (SYS-REQ-018, SYS-REQ-019)
SWE-REQ-004: The software shall process only the most recent valid user command for position control. (SYS-REQ-006 [Implied])

## 2.2 Flap Position Control Logic
SWE-REQ-005: The software shall determine if the actual flap position matches the user-requested target position. (SYS-REQ-002)
SWE-REQ-006: The software shall compute the required actuation direction and initiate movement if needed based on position error. (SYS-REQ-003, SYS-REQ-007)
SWE-REQ-007: The software shall stop actuator movement promptly when the target position is reached. (SYS-REQ-004, SYS-REQ-009)
SWE-REQ-008: The software shall hold and maintain the flap at the achieved position, avoiding unnecessary actuator operations. (SYS-REQ-004)

## 2.3 Motor Control Logic
SWE-REQ-009: The software shall provide control signals to select forward/reverse motor direction for flap movement. (SYS-REQ-007)
SWE-REQ-010: The software shall generate enable and disable signals for the actuator motor. (SYS-REQ-008)
SWE-REQ-011: The software shall promptly disable motor drive upon position achievement or error detection. (SYS-REQ-009, SYS-REQ-010)
SWE-REQ-012: The software shall avoid simultaneous command of conflicting motor drive signals. (SYS-REQ-011 [Implied])

## 2.4 Position Feedback Processing
SWE-REQ-013: The software shall acquire real-time flap position data using an ADC channel. (SYS-REQ-012, SYS-REQ-013)
SWE-REQ-014: The software shall translate ADC values to logical flap positions within the valid mechanical range. (SYS-REQ-014)
SWE-REQ-015: The software shall filter or average ADC input where necessary to ensure reliable flap position data. (SYS-REQ-015 [Implied])

## 2.5 Status Indication Control
SWE-REQ-016: The software shall provide status feedback using LEDs to indicate power, error, and actual flap position states. (SYS-REQ-021, SYS-REQ-022, SYS-REQ-023)
SWE-REQ-017: The software shall update status indicator LEDs within 500ms of a status/position change. (SYS-REQ-024 [Implied])

# 3.0 Software Interface Requirements
SWE-REQ-018: The software shall provide UART input/output for all user interaction, command acceptance, and system feedback. (SYS-REQ-031)
SWE-REQ-019: The software shall acquire flap position using the ADC peripheral capturing data from the potentiometer. (SYS-REQ-033)
SWE-REQ-020: The software shall provide digital outputs to control the actuator motor. (SYS-REQ-032)
SWE-REQ-021: The software shall output digital control signals to drive LED indicators. (SYS-REQ-034)

# 4.0 Software Behavioral Requirements
SWE-REQ-022: The software shall initialize all I/O, peripherals, and internal states at power-up. (SYS-REQ-025)
SWE-REQ-023: The software shall remain idle after initialization until a valid user command is received. (SYS-REQ-026)
SWE-REQ-024: The software shall commence normal operation upon acceptance of a valid target position. (SYS-REQ-027)
SWE-REQ-025: The software shall return to the idle state when the target flap position is achieved, or upon error/fault. (SYS-REQ-028)
SWE-REQ-026: The software shall ignore unrecognized, malformed, or out-of-range commands and not execute any movement or status change for such commands. (SYS-REQ-029)
SWE-REQ-027: [Implied] The software shall log errors or invalid command attempts via UART or status indicators as feasible. (SYS-REQ-030 [Implied])

# 5.0 Software Data and Configuration Requirements
SWE-REQ-028: The software shall provide for storage and use of configuration values for mapping ADC readings to logical flap positions. (SYS-REQ-014)
SWE-REQ-029: The software shall support configuration/maintenance of ADC threshold values. (SYS-REQ-015, SYS-REQ-014)
SWE-REQ-030: The software shall utilize calibration constants for flap position computation where required. (SYS-REQ-014)
SWE-REQ-031: The software shall maintain internal state to track target, actual, and previous positions. (SYS-REQ-002, SYS-REQ-025)

# 6.0 Software Error Handling Requirements
SWE-REQ-032: The software shall deterministically reject and report any received invalid commands. (SYS-REQ-040)
SWE-REQ-033: The software shall detect and respond to position feedback data outside expected/measured range. (SYS-REQ-040)
SWE-REQ-034: The software shall default to a safe state if actuator control cannot be completed as requested. (SYS-REQ-041 [Implied])

# 7.0 Software Performance and Responsiveness Requirements
SWE-REQ-035: The software shall provide responsive feedback to user commands as promptly as possible. (SYS-REQ-039)
SWE-REQ-036: The software shall evaluate and act on new position or control commands within a user-perceivable response window. (SYS-REQ-039)

# 8.0 Software Resource Constraint Requirements
SWE-REQ-037: The software shall ensure all algorithms execute in a predictable, bounded time. (SYS-REQ-042)
SWE-REQ-038: The software shall avoid unbounded loops or recursions. (SYS-REQ-042)
SWE-REQ-039: The software shall optimize for minimal use of available microcontroller memory consistent with requirements. (SYS-REQ-042)

# 9.0 Software Testability Requirements
SWE-REQ-040: The software shall permit verification of system behavior via UART interaction alone. (SYS-REQ-044)
SWE-REQ-041: The software shall ensure that LED states are observable and mapped to test conditions. (SYS-REQ-044)
SWE-REQ-042: The software shall support both manual and automated/script-based test execution via the UART interface. (SYS-REQ-045 [Implied])

# 10.0 Implied Software Requirements
SWE-REQ-043: [Implied] The software shall treat user command input as coming from a single active user; no concurrent/multi-user management is required. (SYS-REQ-038 [Implied])
SWE-REQ-044: [Implied] The software shall isolate signal interfaces as needed for demonstration/learning safety, subject to hardware design. (SYS-REQ-035 [Implied])
SWE-REQ-045: [Implied] The software shall implement error handling and logging using only resources available via UART or LEDs. (SYS-REQ-030 [Implied])
