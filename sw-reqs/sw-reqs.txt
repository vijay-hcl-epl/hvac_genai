# 1.0 Software Scope & Responsibility
The HVAC flap actuator software implements the complete, MCU-resident logic for user-commanded air flap positioning as specified in system requirements. It interprets UART commands, performs ADC-based feedback, commands motor actuation (direction, enable/disable), and drives LED indicators. The software boundaries include all STM32 MCU code and firmware.

---

# 2.0 Software Functional Requirements

## 2.1 User Commands
- SWE-REQ-001: The software SHALL receive flap position commands as numeric values via UART. [SYS-REQ-002, SYS-REQ-021]
- SWE-REQ-002: The software SHALL ignore any UART commands that do not correspond to valid, defined flap positions. [SYS-REQ-009, SYS-REQ-022]
- SWE-REQ-003: The software SHALL NOT transmit any error response or acknowledgement for invalid UART commands. [SYS-REQ-023]

## 2.2 Flap Control
- SWE-REQ-004: The software SHALL map valid received command values to discrete flap positions as defined by ADC value ranges in configuration. [SYS-REQ-010, SYS-REQ-017]
- SWE-REQ-005: The software SHALL command movement of the flap to the user-requested position if valid and different from the current position. [SYS-REQ-007, SYS-REQ-030]
- SWE-REQ-006: The software SHALL not command the flap to move to a position outside the valid range. [SYS-REQ-009]

## 2.3 Motor Control
- SWE-REQ-007: The software SHALL drive the motor in the required direction (CW/CCW) to move toward the target position. [SYS-REQ-011]
- SWE-REQ-008: The software SHALL stop the motor when the current flap position matches the commanded target. [SYS-REQ-012, SYS-REQ-031]
- SWE-REQ-009: The software SHALL ensure the motor is OFF during power-up initialization. [SYS-REQ-014, SYS-REQ-027]
- SWE-REQ-010: The software SHALL stop the motor whenever the feedback position data (ADC) is invalid. [SYS-REQ-015, SYS-REQ-041]

## 2.4 Feedback Processing
- SWE-REQ-011: The software SHALL continuously/readily monitor the flap position using ADC feedback from the potentiometer. [SYS-REQ-016, SYS-REQ-029]
- SWE-REQ-012: The software SHALL determine validity of position by checking ADC readings against defined ranges. [SYS-REQ-017, SYS-REQ-018]

## 2.5 Status Indication
- SWE-REQ-013: The software SHALL control a dedicated LED to indicate system power. [SYS-REQ-024]
- SWE-REQ-014: The software SHALL control one green LED at a time to indicate the current flap position. [SYS-REQ-025]
- SWE-REQ-015: The software SHALL update LED indication in accordance with the detected (not commanded) flap position. [SYS-REQ-026, SYS-REQ-028, SYS-REQ-031]

## [Implied]
- SWE-REQ-016: The software design SHALL allow for extension of position ranges or position mapping via configuration. [SYS-REQ-010]

# 3.0 Software Interface Requirements
- SWE-REQ-017: The software SHALL receive user commands through the UART peripheral. [SYS-REQ-020]
- SWE-REQ-018: The software SHALL acquire position feedback from the ADC peripheral (potentiometer input). [SYS-REQ-016]
- SWE-REQ-019: The software SHALL control the DC motor via dedicated GPIOs (direction, enable) and PWM (speed/enable) outputs. [SYS-REQ-013, SYS-REQ-034]
- SWE-REQ-020: The software SHALL control one status LED and up to six position indicator LEDs using GPIO. [SYS-REQ-025, SYS-REQ-026, SYS-REQ-024]

## [Implied]
- SWE-REQ-021: The software interface design SHALL not utilize or reserve CAN, LIN, Ethernet, or other vehicle bus resources. [SYS-REQ-035]

---

# 4.0 Software Behavioral Requirements
- SWE-REQ-022: On startup, the software SHALL initialize all configured peripherals (UART, ADC, GPIO, PWM). [SYS-REQ-027]
- SWE-REQ-023: On startup, the software SHALL ensure the motor is OFF. [SYS-REQ-014]
- SWE-REQ-024: On startup, the software SHALL sample the initial flap position and set the corresponding LED indication. [SYS-REQ-028]
- SWE-REQ-025: The software SHALL process user UART commands by validating, mapping and, if needed, moving the flap. [SYS-REQ-029, SYS-REQ-030]
- SWE-REQ-026: The software SHALL monitor the feedback position and update LEDs any time the detected position changes. [SYS-REQ-026, SYS-REQ-031]
- SWE-REQ-027: The software SHALL ignore and take no action on invalid commands. [SYS-REQ-032, SYS-REQ-043]

## [Implied]
- SWE-REQ-028: All state transitions (idle, moving, completed, invalid) SHALL be handled by logic conforming to the allocated requirements. [SYS-REQ-033]

---

# 5.0 Software Data & Configuration
- SWE-REQ-029: The software SHALL maintain configuration values for ADC range mapping, UART baud, pin assignments, and number of supported positions. [SYS-REQ-010, SYS-REQ-017, SYS-REQ-038]
- SWE-REQ-030: The software SHALL NOT alter calibration/configuration data at runtime. [SYS-REQ-038]

## [Implied]
- SWE-REQ-031: Any change to position ranges or mapping SHALL be performed via static configuration (e.g., build-time constant update, no runtime reconfiguration). [SYS-REQ-038]

---

# 6.0 Software Error Handling
- SWE-REQ-032: The software SHALL treat all ADC readings outside defined position ranges as invalid and stop the motor. [SYS-REQ-018, SYS-REQ-041]
- SWE-REQ-033: The software SHALL ignore malformed or out-of-range UART input without impacting system state. [SYS-REQ-043]
- SWE-REQ-034: The software SHALL ensure the system does not enter any unrecoverable state due to invalid input or feedback. [SYS-REQ-042]

## [Implied]
- SWE-REQ-035: Any error handling implemented SHALL not prevent further operation after a valid command is received. [SYS-REQ-042]

---

# 7.0 Performance & Responsiveness
- SWE-REQ-036: The software SHALL respond to received valid commands with perceptible actuation and LED update within human-observable time (typ. <<1s). [SYS-REQ-040]

---

# 8.0 Resource Constraints
- SWE-REQ-037: The software SHALL NOT use dynamic memory allocation. [SYS-REQ-044]
- SWE-REQ-038: The software SHALL be compatible with the available RAM, ROM, and peripherals on the STM32F407 MCU platform. [SYS-REQ-044]

## [Implied]
- SWE-REQ-039: The software SHALL be implemented in MISRA-style embedded C, without OS/RTOS dependencies. [SYS-REQ-010, SYS-REQ-044]

---

# 9.0 Testability
- SWE-REQ-040: The software SHALL allow test by sending UART commands and observing flap movement and LED state as final output. [SYS-REQ-046]
- SWE-REQ-041: The software SHALL be organized so that all main features (command decode, actuation, feedback, indication) can be stimulated and observed separately. [SYS-REQ-045]

## [Implied]
- SWE-REQ-042: Automated testing and external scripting is possible but not required by this software, per system definition. [SYS-REQ-046]
