1.0 Software Scope & Responsibility
This software controls a single HVAC air flap actuator as specified in system requirements SYS-REQ-001 to SYS-REQ-038. It manages user input via UART, motor actuation through GPIO/PWM, flap position sensing through ADC, and status indication with LEDs on a microcontroller. All behaviors, constraints, and performance objectives are dictated by system-level requirements. No network or vehicle integration is included; the solution is intended for standalone prototype use.

2.0 Software Functional Requirements
2.1 User Commands
SWE-REQ-001 The software SHALL accept flap position commands (0-5) received over UART, mapping each numeric input to its corresponding discrete position. [SYS-REQ-013, SYS-REQ-014, SYS-REQ-024]
SWE-REQ-002 The software SHALL ignore and not acknowledge any invalid or out-of-range commands received via UART. [SYS-REQ-015, SYS-REQ-023]
SWE-REQ-003 The software SHALL process one command at a time, completing prior command execution before accepting a new command. [SYS-REQ-029]
[Implied] SWE-REQ-004 The software SHALL not process any command if hardware status is invalid or on startup/idle state. [SYS-REQ-031, SYS-REQ-021]

2.2 Flap Control
SWE-REQ-005 The software SHALL initiate flap movement upon a valid command and only as needed to reach a new target position. [SYS-REQ-003, SYS-REQ-022]
SWE-REQ-006 The software SHALL stop the motor when the target flap position is reached or if an error condition occurs (ADC/command fault). [SYS-REQ-005, SYS-REQ-009, SYS-REQ-033, SYS-REQ-034]
SWE-REQ-007 The software SHALL support movement among discrete positions 0-5 as defined, ensuring target accuracy. [SYS-REQ-004, SYS-REQ-011]
SWE-REQ-008 If the command is out of range (invalid position), the motor SHALL remain stopped and position unchanged. [SYS-REQ-006]

2.3 Motor Control
SWE-REQ-009 The software SHALL control DC motor direction (clockwise/anticlockwise) using GPIO and PWM outputs to the L298N motor driver to move towards target position. [SYS-REQ-007, SYS-REQ-008, SYS-REQ-025]
[Implied] SWE-REQ-010 On power-up, the software SHALL ensure the motor is disabled until initialization completes. [SYS-REQ-019]

2.4 Feedback Processing
SWE-REQ-011 The software SHALL periodically sample ADC corresponding to the position sensor and update internal position state. [SYS-REQ-010, SYS-REQ-011, SYS-REQ-012, SYS-REQ-026]
SWE-REQ-012 The software SHALL map ADC values to logical position 0-5 using fixed, pre-configured calibration ranges. [SYS-REQ-011, SYS-REQ-030]

2.5 Status Indication
SWE-REQ-013 The software SHALL set the power/status LED ON after successful startup and initialization. [SYS-REQ-016, SYS-REQ-020]
SWE-REQ-014 The software SHALL update the flap position indicators (max 1 green LED ON at any time) to reflect the logical position. [SYS-REQ-017, SYS-REQ-018, SYS-REQ-020, SYS-REQ-022]
[Implied] SWE-REQ-015 The software SHALL NOT generate any LED indication pattern or flashing. [SYS-REQ-018]

3.0 Software Interface Requirements
SWE-REQ-016 The software SHALL provide a UART RX interface for command input. [SYS-REQ-024]
SWE-REQ-017 The software SHALL provide GPIO/PWM outputs for controlling the DC motor (L298N) and status/indicator LEDs. [SYS-REQ-025, SYS-REQ-027]
SWE-REQ-018 The software SHALL provide ADC sampling of the position sensor input (potentiometer). [SYS-REQ-026]
[Implied] SWE-REQ-019 All interfaces SHALL rely on statically configured pins/channels as set in hardware abstraction; no runtime reconfiguration. [SYS-REQ-030]

4.0 Software Behavioral Requirements
SWE-REQ-020 On startup, the software SHALL initialize all configured peripherals, determine current flap position, set status LEDs, and ensure the motor output is disabled. [SYS-REQ-019, SYS-REQ-020]
SWE-REQ-021 In idle state, the software SHALL wait for valid UART input or error and reflect system state on all indicators. [SYS-REQ-021, SYS-REQ-016, SYS-REQ-017]
SWE-REQ-022 On receipt of a valid command, the software SHALL move the flap towards the target position and update the corresponding LED(s). [SYS-REQ-022]
SWE-REQ-023 The software SHALL cease all movement and return to idle if a command or ADC error occurs. [SYS-REQ-009, SYS-REQ-033, SYS-REQ-034]

5.0 Software Data & Configuration
SWE-REQ-024 The software SHALL use constant (read-only) calibration data for ADC-to-position mapping. [SYS-REQ-011, SYS-REQ-030]
SWE-REQ-025 The software SHALL store logical system state variables for current/target position, error flags, and user input buffer. [SYS-REQ-021, SYS-REQ-038]
[Implied] SWE-REQ-026 The software SHALL NOT implement persistent configuration storage (e.g., no EEPROM/flash usage). [SYS-REQ-030]

6.0 Software Error Handling
SWE-REQ-027 The software SHALL detect out-of-range ADC values and stop the motor in response. [SYS-REQ-009, SYS-REQ-033]
SWE-REQ-028 The software SHALL detect and ignore invalid UART/command inputs with no output or error response. [SYS-REQ-015, SYS-REQ-023, SYS-REQ-034]
SWE-REQ-029 The software SHALL assume hardware is healthy unless error input is received. [SYS-REQ-031]
SWE-REQ-030 The software SHALL ensure all outputs remain in a safe state upon any detected error. [SYS-REQ-034]
[Implied] SWE-REQ-031 The software SHALL NOT attempt advanced diagnostics or automated recovery. [SYS-REQ-035]

7.0 Performance & Responsiveness
SWE-REQ-032 The software SHALL process UART commands and update the flap and status outputs promptly, such that system action is transparent to the end user. [SYS-REQ-032]
[Implied] SWE-REQ-033 No strict real-time deadlines or periods are imposed by the software beyond perceptual responsiveness. [SYS-REQ-032]

8.0 Resource Constraints
SWE-REQ-034 The software SHALL avoid dynamic memory allocation; all state is stored as static/local variables. [SYS-REQ-036]
SWE-REQ-035 The software SHALL operate within the available memory and processing resources of the MCU. [SYS-REQ-036]
[Implied] SWE-REQ-036 The software SHALL NOT use or depend on any operating system features. [SYS-REQ-002]

9.0 Testability
SWE-REQ-037 The software SHALL allow test cases using UART commands, and state shall be verifiable using LED states and ADC readout. [SYS-REQ-038]
[Implied] SWE-REQ-038 The software design SHALL enable manual as well as script-driven testing using interfaces and outputs above. [SYS-REQ-037, SYS-REQ-038]
