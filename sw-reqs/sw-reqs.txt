# 1.0 Purpose

This document translates the system-level requirements for the HVAC flap actuator into software requirements, ensuring unambiguous, testable, atomic, and traceable requirements, without assuming any specific software architecture or implementation.

# 2.0 Software Requirements

SWE-REQ-001: The software shall parse and validate UART user commands for target flap position selection. (Trace: SYS-REQ-001, SYS-REQ-012, SYS-REQ-013)
SWE-REQ-002: The software shall store the last valid target position received from the user command interface. (SYS-REQ-004)
SWE-REQ-003: The software shall compare the current position feedback to the stored target position and determine the required actuation direction. (SYS-REQ-002, SYS-REQ-003, SYS-REQ-010, SYS-REQ-011)
SWE-REQ-004: The software shall drive outputs to enable forward/reverse DC motor operation per actuation direction indicated by the comparison logic. (SYS-REQ-005)
SWE-REQ-005: The software shall output enable signal to motor driver only when active repositioning is required, disabling when target reached. (SYS-REQ-006)
SWE-REQ-006: The software shall halt all motor driver outputs if flap at physical or logical positional limit is detected. (SYS-REQ-007)
SWE-REQ-007: The software shall periodically acquire ADC samples of potentiometer signal to determine actual flap position. (SYS-REQ-008, SYS-REQ-009)
SWE-REQ-008: The software shall use conversion logic to translate ADC readings to logical position states as per configuration. (SYS-REQ-010)
SWE-REQ-009: The software shall update LED status indicators according to current logical position. (SYS-REQ-011, SYS-REQ-016)
SWE-REQ-010: The software shall output power/status indication as per system state (e.g., power-up, idle, error). (SYS-REQ-015, SYS-REQ-021)
SWE-REQ-011: The software shall ignore or indicate as error any UART command that does not match the valid protocol or is out of range, without affecting the current target position. (SYS-REQ-014, SYS-REQ-029)
SWE-REQ-012: The software shall detect and treat out-of-range ADC feedback as an error, ceasing actuation and providing observable status. (SYS-REQ-029, SYS-REQ-030)
SWE-REQ-013: The software shall on startup perform system initialization, establish baseline position and indicators. (SYS-REQ-017)
SWE-REQ-014: The software shall enter and maintain a defined idle state with no motor activation if no valid movement command is pending. (SYS-REQ-018)
SWE-REQ-015: The software shall continuously monitor for system errors, unexpected feedback, or failures, and respond by entering a safe state with motor stopped and error indication. (SYS-REQ-021, SYS-REQ-031)
SWE-REQ-016: The software shall ensure software modules for command handling, position control, feedback processing, and status indication remain separately testable and logically decoupled. (SYS-REQ-033)
SWE-REQ-017: The software shall expose all configuration and calibration data for logical to physical mapping in a single testable module. (SYS-REQ-010, SYS-REQ-034)
SWE-REQ-018: The software design shall permit manual and automated test (UART and visual LEDs) for all functional aspects. (SYS-REQ-034)

# 3.0 Exclusions

- No assumptions are made regarding scheduling or execution models (event-driven, polling, periodic tasking, interrupts, etc.) beyond what is explicitly listed in system requirements.
- All resource, expansion, and testability constraints follow system-level requirements, with no new software-level non-functional requirements introduced.
- No architectural or driver timing assumptions are introduced at the software requirement level.

# 4.0 Traceability

A full trace matrix (SYS to SWE) can be generated upon request; requirements are strictly mapped (see parenthetical Trace references per item above).

# 5.0 Implied/Clarified Points

- Implied polling or reactive cycle for feedback and command acquisition is assumed solely to meet user perceptible responsiveness, not to fulfill specific hard real-time or time-triggered behavior.
- Protocol-specific elements (e.g., UART baud rate, format) are configuration/calibration and not requirements unless specified in the system-level specification.
