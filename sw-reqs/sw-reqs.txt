1.0 Software Scope & Responsibility
----------------------------------
The software controls a DC motor driven HVAC air flap actuator for automotive demo/learning systems. It interprets UART-based user commands to move a DC-motor-actuated flap to discrete physical positions, acquires analog position feedback via ADC, and drives status indication outputs by controlling LEDs—all on an STM32 MCU, using ADC, GPIO, UART and PWM peripheral interfaces, without real-time or OS binding.

2.0 Software Functional Requirements
-------------------------------------
2.1 User Commands
SWE-REQ-001: The software SHALL parse and accept numeric UART commands to set the flap position. [SYS-REQ-001, SYS-REQ-011]
SWE-REQ-002: The software SHALL validate input commands and reject commands outside the supported position range. [SYS-REQ-012, SYS-REQ-002]
SWE-REQ-003: The software SHALL process only one command at a time, ignoring new commands while executing or aborting an active operation. [SYS-REQ-004, SYS-REQ-013]
SWE-REQ-004: [Implied] The software SHALL operate as a command/response system, not requiring periodic polling from the host.

2.2 Flap Control
SWE-REQ-005: The software SHALL command flap motion to the requested position if and only if the new command differs from the measured current position. [SYS-REQ-002, SYS-REQ-007]
SWE-REQ-006: The software SHALL determine when the flap reaches the commanded position and immediately halt motion. [SYS-REQ-003, SYS-REQ-021, SYS-REQ-022]
SWE-REQ-007: [Implied] The software SHALL enforce that once target position is achieved, no further position/motion commands are executed until new input is received.

2.3 Motor Control
SWE-REQ-008: The software SHALL operate motor driver GPIO and PWM outputs to move the DC motor in both required directions. [SYS-REQ-005, SYS-REQ-025, SYS-REQ-027]
SWE-REQ-009: The software SHALL deactivate or stop the motor once the flap reaches target or when a command is invalid or deemed unsafe. [SYS-REQ-006, SYS-REQ-032]

2.4 Feedback Processing
SWE-REQ-010: The software SHALL acquire potentiometer voltage measurements via ADC, at sufficient intervals to detect flap movement in operational modes. [SYS-REQ-008, SYS-REQ-010]
SWE-REQ-011: The software SHALL map ADC readings to defined logical position indices using calibration data. [SYS-REQ-009]
SWE-REQ-012: [Implied] The software SHALL continue feedback acquisition/buffering during idle as well as movement states.

2.5 Status Indication
SWE-REQ-013: The software SHALL activate the power/status LED when powered. [SYS-REQ-014]
SWE-REQ-014: The software SHALL set only one green LED ON to indicate the detected position at all times; all others OFF. [SYS-REQ-015, SYS-REQ-016, SYS-REQ-017]
SWE-REQ-015: [Implied] No LED indication patterns beyond simple ON/OFF are provided.

3.0 Software Interface Requirements
-------------------------------------
SWE-REQ-016: The software SHALL use the UART peripheral to receive external user commands. [SYS-REQ-024]
SWE-REQ-017: The software SHALL use GPIO outputs to drive motor direction, enable, and LED status signals via L298N and LED circuits. [SYS-REQ-025]
SWE-REQ-018: The software SHALL use the ADC input to sample the position potentiometer. [SYS-REQ-026]
SWE-REQ-019: The software SHALL use PWM outputs to control motor operation as required by the driver. [SYS-REQ-027]
SWE-REQ-020: [Implied] Hardware abstraction shall enable future porting/adaptation without changes to control logic.

4.0 Software Behavioral Requirements
--------------------------------------
SWE-REQ-021: On startup, the software SHALL initialize all used MCU peripherals and ensure all actuator outputs are at safe (idle/off) states. [SYS-REQ-018]
SWE-REQ-022: On startup, the software SHALL read and interpret the potentiometer to set the initial position for indication/movement logic. [SYS-REQ-019]
SWE-REQ-023: While idle, the software SHALL continuously monitor and indicate current detected position. [SYS-REQ-020]
SWE-REQ-024: On receiving a valid command, the software SHALL actuate the motor/flap only as needed to reach the specified position and update indication on completion. [SYS-REQ-021, SYS-REQ-022]
SWE-REQ-025: On receiving or detecting invalid input/signals, the software SHALL handle the error as per Section 6.0, with safe outputs. [SYS-REQ-023, SYS-REQ-032]
SWE-REQ-026: [Implied] No periodic/cyclic control demands nor scheduling primitives are assumed; MCU behaves event-driven for command handling.

5.0 Software Data & Configuration
-----------------------------------
SWE-REQ-027: The software SHALL use calibration data in flash or ROM to map ADC readings to logical flap positions. [SYS-REQ-009, SYS-REQ-029]
SWE-REQ-028: The software SHALL allow for update of calibration values via build-time configuration. [SYS-REQ-029]
SWE-REQ-029: [Implied] No requirement for run-time re-calibration or homing operations at startup.

6.0 Software Error Handling
-----------------------------
SWE-REQ-030: The software SHALL detect ADC/value out-of-range and stop motor operation immediately if detected. [SYS-REQ-032]
SWE-REQ-031: The software SHALL ignore or reject unsupported command values or corrupted UART messages; system SHALL maintain safe actuator state. [SYS-REQ-023, SYS-REQ-012]
SWE-REQ-032: [Implied] The software SHALL recover from simple/expected errors without requiring reset; avoidance of hazardous or undefined actuator output in all non-fault scenarios.

7.0 Performance & Responsiveness
----------------------------------
SWE-REQ-033: The software SHALL process received UART commands and initiate change of flap position such that the control appears responsive to a human user. [SYS-REQ-031]
SWE-REQ-034: [Implied] No hard/real-time deadlines or cycle times are imposed by software; responsible forward progress suffices.

8.0 Resource Constraints
--------------------------
SWE-REQ-035: The software implementation SHALL operate within documented MCU RAM/ROM and peripheral limits. [SYS-REQ-035]
SWE-REQ-036: [Implied] The design SHALL permit maintainability by modular separation of command interface, feedback processing, motor/LED control.

9.0 Testability
-----------------
SWE-REQ-037: The software design SHALL permit end-to-end testing using visible LED state, UART input, and measurable flap motion as test points. [SYS-REQ-037]
SWE-REQ-038: [Implied] Built-in self-test, test points, or mocks for full coverage are not required in scope; only observable outputs per functional operation must be verifiable.
