1.0 Software Scope & Responsibility

The software component for the HVAC flap actuator system is responsible for implementing user-commanded flap positioning via a microcontroller, actuating a DC motor for flap movement, monitoring position via ADC (potentiometer), managing inputs from UART, and providing status feedback via LEDs. It operates entirely on a single MCU, interfacing with ADC, GPIO, PWM (timers), and UART. Hardware platform: STM32F407G.

2.0 Software Functional Requirements

2.1 User Commands
SWE-REQ-001: The software SHALL accept numeric single-byte UART commands from a PC, each representing one target flap position. [SYS-REQ-001, SYS-REQ-014]
SWE-REQ-002: The software SHALL ignore any UART command outside the valid position range. [SYS-REQ-004, SYS-REQ-016]
SWE-REQ-003: The software SHALL process only one command at a time and ignore new commands while an existing command is in progress. [SYS-REQ-005]
[Implied] SWE-REQ-004: The software SHALL make no assumption about timing or order of commands. [SYS-REQ-028]

2.2 Flap Control
SWE-REQ-005: The software SHALL initiate flap movement upon receipt of a valid target command. [SYS-REQ-002]
SWE-REQ-006: The software SHALL determine direction and enable the motor via GPIOs and PWM based on the comparison of actual versus target position. [SYS-REQ-006, SYS-REQ-007]
SWE-REQ-007: The software SHALL stop the motor once the target position has been reached. [SYS-REQ-003, SYS-REQ-023]
SWE-REQ-008: The software SHALL stop the motor if the ADC reading is out of valid range. [SYS-REQ-009, SYS-REQ-032]
[Implied] SWE-REQ-009: The software SHALL keep the motor OFF at initialization until current position is established. [SYS-REQ-008, SYS-REQ-020]
[Implied] SWE-REQ-010: The software SHALL not perform any homing sequence at startup. [Implementation context]

2.3 Motor Control
SWE-REQ-011: The software SHALL set the required motor GPIOs for direction and PWM for speed/enabling during movement toward the target. [SYS-REQ-006, SYS-REQ-007, SYS-REQ-027]
[Implied] SWE-REQ-012: Only one movement can be commanded and executed at a time. [SYS-REQ-005]

2.4 Feedback Processing
SWE-REQ-013: The software SHALL acquire the potentiometer value via ADC, map to logical position using fixed software-configurable calibration, and update actual position. [SYS-REQ-010, SYS-REQ-011, SYS-REQ-012, SYS-REQ-035]
SWE-REQ-014: The software SHALL update the position at a rate that supports human-perceptible responsiveness. [SYS-REQ-013, SYS-REQ-031]

2.5 Status Indication
SWE-REQ-015: The software SHALL turn ON the status LED if power is ON. [SYS-REQ-017]
SWE-REQ-016: The software SHALL update the green LED to indicate the actual/last known flap position, with only one green LED ON at any time. [SYS-REQ-018]

3.0 Software Interface Requirements

SWE-REQ-017: The software SHALL use the UART interface for receiving user target position commands. [SYS-REQ-024]
SWE-REQ-018: The software SHALL use the ADC input to obtain potentiometer (flap position) feedback. [SYS-REQ-025]
SWE-REQ-019: The software SHALL use designated GPIOs for motor direction control and for status/position LEDs. [SYS-REQ-026]
SWE-REQ-020: The software SHALL use PWM via a timer to control the motor driver enable/speed. [SYS-REQ-027]
[Implied] SWE-REQ-021: No other external or networked interface is used. [System context]

4.0 Software Behavioral Requirements

SWE-REQ-022: On system startup, the software SHALL initialize MCU peripherals (ADC, UART, GPIO, PWM), leave the motor OFF, indicate system power/ready via LED, and detect initial flap position. [SYS-REQ-019, SYS-REQ-020]
SWE-REQ-023: During idle, the software SHALL wait (blocking or event-driven) for a new valid target position command. [SYS-REQ-021]
SWE-REQ-024: When a valid user command is received, the software SHALL command the motor to move the flap to the target. [SYS-REQ-002]
SWE-REQ-025: The software SHALL, during movement, monitor actual and target positions and stop the motor once the target is reached or an error/out-of-range/invalid state is detected. [SYS-REQ-003, SYS-REQ-032]
SWE-REQ-026: Invalid UART commands SHALL be ignored and must not affect any system state or output. [SYS-REQ-022, SYS-REQ-016]
[Implied] SWE-REQ-027: The software SHALL support transitions: idle → moving → target reached/idle, etc., as required by user commands and position feedback. [SYS-REQ-023]

5.0 Software Data & Configuration

SWE-REQ-028: The ADC-to-position mapping and flap logical position definition SHALL be implemented as software-configurable constants. [SYS-REQ-011, SYS-REQ-012, SYS-REQ-035]
SWE-REQ-029: The valid ADC range for detecting errors SHALL be configurable in software. [SYS-REQ-009]
[Implied] SWE-REQ-030: All configuration data SHALL be stored as constants; no dynamic calibration at runtime. [SYS-REQ-030]

6.0 Software Error Handling

SWE-REQ-031: If an ADC or potentiometer reading is outside the valid calibrated range, the software SHALL stop the motor and ignore further movement until a valid reading resumes. [SYS-REQ-009, SYS-REQ-032]
SWE-REQ-032: If an invalid or out-of-range UART command is received, the software SHALL ignore it silently. [SYS-REQ-022, SYS-REQ-016]
[Implied] SWE-REQ-033: The software SHALL not crash or require reset upon any invalid UART or ADC input. [SYS-REQ-033]

7.0 Performance & Responsiveness

SWE-REQ-034: The software SHALL provide perceptible responsiveness to user commands (sub-second typical latency user-to-actuation and LED update). [SYS-REQ-031, SYS-REQ-013]
[Implied] SWE-REQ-035: No software real-time constraints or specific data acquisition rates are assumed; only human-perceptible responsiveness is required.

8.0 Resource Constraints

SWE-REQ-036: The software SHALL operate within available MCU RAM and ROM resources. [SYS-REQ-034]
SWE-REQ-037: The software implementation SHALL minimize memory and computation overhead. [Efficiency]

9.0 Testability

SWE-REQ-038: The software SHALL be testable by issuing UART commands and observing flap/motor movement and LED outputs. [SYS-REQ-036]
[Implied] SWE-REQ-039: No dedicated test/diagnostic mode or automated self-test is implemented. [System context]

10.0 Implied Requirements

SWE-REQ-040 [Implied]: The software SHALL support one actuator, one motor, and one user interface per instance. [SYS-REQ-029]
SWE-REQ-041 [Implied]: The software SHALL NOT implement any concurrency, RTOS, or thread-based model. [Architecture-Relevant Considerations]
SWE-REQ-042 [Implied]: The software SHALL NOT process or generate vehicle network (CAN, LIN) messages or diagnostics. [System context]
SWE-REQ-043 [Implied]: The software SHALL NOT take corrective actions beyond ignoring invalid input or feedback; no advanced error recovery is expected. [SYS-REQ-033]
