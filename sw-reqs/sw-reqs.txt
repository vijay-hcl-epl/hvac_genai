# 1.0 Software Scope and Responsibility

The software for the HVAC Flap Actuator System executes on a microcontroller. It is responsible for:
- Receiving user commands to set flap position via UART interface
- Acquiring and processing position feedback from a potentiometric sensor using the ADC
- Driving a DC motor for precise movement of the flap
- Validating, interpreting, and responding to commands, errors, and statuses
- Indicating system status and flap position via LEDs

# 2.0 Software Functional Requirements

## 2.1 User Command Handling
- SWE-REQ-001: The software shall receive and decode discrete user commands via UART. (SYS-REQ-001, SYS-REQ-012, SYS-REQ-022)
- SWE-REQ-002: The software shall validate user commands according to the specified protocol. (SYS-REQ-013)
- SWE-REQ-003: The software shall reject and safely ignore invalid or out-of-sequence commands, preserving the previous target position. (SYS-REQ-014)

## 2.2 Flap Position Control Logic
- SWE-REQ-004: The software shall select a target flap position in response to validated user commands. (SYS-REQ-001)
- SWE-REQ-005: The software shall compare the actual position to the target and determine if motion is required. (SYS-REQ-002, SYS-REQ-020 [Implied])
- SWE-REQ-006: The software shall determine and provide the required direction to reposition the flap via the motor. (SYS-REQ-003, SYS-REQ-005)
- SWE-REQ-007: The software shall hold the flap position after it reaches the target, unless a new user command is received. (SYS-REQ-004)

## 2.3 Motor Control Logic
- SWE-REQ-008: The software shall provide control outputs to enable motor forward or reverse movement to reposition the flap. (SYS-REQ-005, SYS-REQ-023)
- SWE-REQ-009: The software shall enable the motor only during active repositioning; it shall disable the driver when the target position is achieved or at rest. (SYS-REQ-006)
- SWE-REQ-010: The software shall stop the motor if a mechanical end-stop or positional limit is detected. (SYS-REQ-007, SYS-REQ-030 [Implied])

## 2.4 Position Feedback Processing
- SWE-REQ-011: The software shall acquire analog feedback values from the potentiometric sensor through the ADC. (SYS-REQ-008, SYS-REQ-009, SYS-REQ-024)
- SWE-REQ-012: The software shall map ADC digital values to logical flap positions as defined in system configuration. (SYS-REQ-010)
- SWE-REQ-013: The position acquisition and mapping shall be accurate enough to visibly reflect each position change on indicator LEDs. (SYS-REQ-011 [Implied])

## 2.5 Status Indication Control
- SWE-REQ-014: The software shall enable a power/status LED as a system health indicator. (SYS-REQ-015)
- SWE-REQ-015: The software shall provide signals to indicate the current flap position via one or more LEDs. (SYS-REQ-016)

# 3.0 Software Interface Requirements
- SWE-REQ-016: The software shall communicate with the user/test interface via UART to receive commands and provide observable feedback. (SYS-REQ-012, SYS-REQ-022)
- SWE-REQ-017: The software shall acquire analog flap-position feedback using the microcontroller ADC. (SYS-REQ-009, SYS-REQ-024)
- SWE-REQ-018: The software shall use digital motor control outputs for actuator drive, compatible with the connected H-bridge or driver circuit. (SYS-REQ-005, SYS-REQ-023)
- SWE-REQ-019: The software shall provide digital outputs to control and update flap position/status LEDs. (SYS-REQ-016, SYS-REQ-025)

# 4.0 Software Behavioral Requirements
- SWE-REQ-020: The software shall perform all necessary initialization, including position determination, configuration loading, and interface setup at system startup. (SYS-REQ-017)
- SWE-REQ-021: During normal operation, the software shall validate and act upon incoming user commands, operate the flap actuator, and update position/status indication. (SYS-REQ-019)
- SWE-REQ-022: The software shall minimize actuator movement and energy use during idle state. (SYS-REQ-018 [Implied])
- SWE-REQ-023: The software shall not take any action upon invalid or unrecognized input except to indicate an error and halt movement. (SYS-REQ-021, SYS-REQ-029)

# 5.0 Software Data and Configuration Requirements
- SWE-REQ-024: The software shall use configurable flap position mappings between ADC values and logical positions. (SYS-REQ-010)
- SWE-REQ-025: The software shall support storage and usage of calibration constants for position mapping and thresholding. (SYS-REQ-010)
- SWE-REQ-026: The software shall maintain the most recently requested target position as the system state. (SYS-REQ-004)

# 6.0 Software Error Handling Requirements
- SWE-REQ-027: The software shall deterministically reject and indicate invalid user commands without changing state. (SYS-REQ-014, SYS-REQ-029)
- SWE-REQ-028: The software shall handle position feedback outside expected range by halting operation and providing a status indication. (SYS-REQ-029)
- SWE-REQ-029: If the flap actuator cannot reach or hold a requested position, the software shall provide an explicit indication and prevent further movement until reset or new command is received. (SYS-REQ-030, SYS-REQ-031 [Implied])

# 7.0 Software Performance and Responsiveness Requirements
- SWE-REQ-030: The software shall provide a response to user commands that results in observable actuator and/or LED activity within a period suitable for demonstration (typically under 2 seconds). (SYS-REQ-028 [Implied])

# 8.0 Software Resource Constraint Requirements
- SWE-REQ-031: The software shall avoid unbounded iterations or blocking calls to ensure predictable execution. (SYS-REQ-032 [Implied])
- SWE-REQ-032: The software shall be lightweight in terms of RAM and code footprint and suited to resource-constrained embedded environments. (SYS-REQ-032, SYS-REQ-033 [Implied])

# 9.0 Software Testability Requirements
- SWE-REQ-033: The software shall provide observable outputs and behaviors to support both manual and script-based testing through UART interface and indicator LEDs. (SYS-REQ-034 [Implied])

# 10.0 Implied Software Requirements
- SWE-REQ-034: [Implied] The software shall separate position control, command handling, feedback processing, and indication logic in a way that enables clear correspondence to allocated requirements. (SYS-REQ-033 [Implied])

# Explicit Exclusions
- No software requirements define or assume any RTOS, super-loop, or specific execution/scheduling model.
- No requirements assign task/thread/priority-level implementation, real-time deadlines, or safety/cyber mechanisms.
- No requirements prescribe any diagnostic protocol, periodicity, or concurrency beyond responsiveness and correctness referenced above.
