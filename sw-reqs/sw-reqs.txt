SOFTWARE REQUIREMENTS SPECIFICATION (SWE.1) – HVAC FLAP ACTUATOR (Infineon TLE9851QXW)

1.0 Software Scope & Responsibility
The HVAC Flap Actuator software SHALL execute all position control, command interface, motor actuation, feedback processing, and status indication functions as defined for a single actuator instance.
It SHALL be responsible for all logic between user commands and motor control, regardless of interface (UART, LIN), without implementing user-facing displays or network protocols outside system scope.
[Traces: SYS-REQ-001, SYS-REQ-002, SYS-REQ-007, SYS-REQ-035]

2.0 Software Functional Requirements
2.1 User Commands
SWE-REQ-001: The software SHALL receive discrete position commands (0…5) for the flap via UART and LIN input channels.
[Traces: SYS-REQ-002, SYS-REQ-016, SYS-REQ-017]
SWE-REQ-002: The software SHALL validate each received command for in-range validity before processing.
[Traces: SYS-REQ-018]
SWE-REQ-003: The software SHALL ignore and not act on invalid or out-of-range commands, maintaining current state and stability.
[Traces: SYS-REQ-018, SYS-REQ-028]
[Implied]

2.2 Flap Control
SWE-REQ-004: The software SHALL actuate the DC motor to achieve the discrete position requested by a valid user command.
[Traces: SYS-REQ-004, SYS-REQ-005]
SWE-REQ-005: The software SHALL ensure the flap is kept at the most recently commanded position until another valid command is received.
[Traces: SYS-REQ-005, SYS-REQ-020]
SWE-REQ-006: The software SHALL cease driving the motor as soon as the target position is detected via feedback.
[Traces: SYS-REQ-006, SYS-REQ-027, SYS-REQ-042]
SWE-REQ-007: The software SHALL support both clockwise and counter-clockwise movement as required by the target position.
[Traces: SYS-REQ-008]
SWE-REQ-008: The software SHALL stop motor motion immediately upon detection of communication, position feedback, or actuator fault conditions.
[Traces: SYS-REQ-009, SYS-REQ-029, SYS-REQ-042]

2.3 Motor Control
SWE-REQ-009: The software SHALL generate integrated half-bridge driver control signals for the actuator motor, with no external driver logic required.
[Traces: SYS-REQ-007]
SWE-REQ-010: The software SHALL support PWM-based speed control per configuration.
[Traces: SYS-REQ-010]

2.4 Feedback Processing
SWE-REQ-011: The software SHALL acquire actuator position from the onboard potentiometer (via ADC1), using a minimum of 10 bits resolution.
[Traces: SYS-REQ-011, SYS-REQ-012]
SWE-REQ-012: Position thresholds for logical positions SHALL be read from Flash configuration and applied for state mapping.
[Traces: SYS-REQ-013]
SWE-REQ-013: The software SHALL not require runtime calibration or learning for feedback mapping.
[Traces: SYS-REQ-014, SYS-REQ-039]
SWE-REQ-014: The software SHALL support continuous or periodic position acquisition when powered, per system requirements.
[Traces: SYS-REQ-015]

2.5 Status Indication
SWE-REQ-015: The software SHALL assert one status output (LED, High-Side switch control, UART reply, or LIN message) indicating the current flap position.
[Traces: SYS-REQ-019]
SWE-REQ-016: The software SHALL ensure only one status indication channel is active at any time.
[Traces: SYS-REQ-020]
[Implied]

3.0 Software Interface Requirements
SWE-REQ-017: The software SHALL support UART1/UART2 for all command input and debug output.
[Traces: SYS-REQ-031]
SWE-REQ-018: The software SHALL configure and use the onboard LIN transceiver for LIN slave operation.
[Traces: SYS-REQ-032]
SWE-REQ-019: The software SHALL use ADC1 for position and diagnostic data acquisition.
[Traces: SYS-REQ-033]
SWE-REQ-020: Software status outputs SHALL use specified GPIOs to indicate actuator position or faults.
[Traces: SYS-REQ-034]
[Implied]

4.0 Software Behavioral Requirements
SWE-REQ-021: On startup, the software SHALL initialize voltage regulators, clocks, ADC1, UART/LIN interfaces, and configure all motor/GPIO drivers, with the motor driver disabled until initialization completes.
[Traces: SYS-REQ-021]
SWE-REQ-022: After initialization, the software SHALL acquire and store the current flap position using ADC1.
[Traces: SYS-REQ-022]
SWE-REQ-023: Upon completion of initialization, the software SHALL enter the Idle state and process valid input commands.
[Traces: SYS-REQ-023, SYS-REQ-025, SYS-REQ-028]
SWE-REQ-024: The software SHALL not require mechanical homing at startup.
[Traces: SYS-REQ-024]
SWE-REQ-025: Commanded position change SHALL always result in a state/position change only when input is valid and targets a distinct position.
[Traces: SYS-REQ-004, SYS-REQ-025]
SWE-REQ-026: When commanded, and in 'Moving to Target', the software SHALL continuously acquire position feedback and detect target arrival by threshold comparison.
[Traces: SYS-REQ-026]
SWE-REQ-027: On target arrival, the software SHALL immediately stop motor movement and indicate new state.
[Traces: SYS-REQ-027]
SWE-REQ-028: The software SHALL not reset or suspend system operation on invalid input but shall ignore and continue in the current valid state.
[Traces: SYS-REQ-028]
SWE-REQ-029: Software SHALL stop the actuator and set a fault status on any overcurrent, open/short load, overtemp, ADC/fault detection, or brownout.
[Traces: SYS-REQ-029, SYS-REQ-041, SYS-REQ-042, SYS-REQ-043]
SWE-REQ-030: The software SHALL enable sleep/stop mode functions as required by device configuration, but these are not required for regular operation.
[Traces: SYS-REQ-030]
SWE-REQ-031: The software SHALL not implement automatic runtime position range expansion or dynamic function upgrades.
[Traces: SYS-REQ-039]
[Implied]

5.0 Software Data & Configuration
SWE-REQ-032: All configuration data (LIN address, UART params, position thresholds) SHALL be read from Flash at startup and remain constant during operation.
[Traces: SYS-REQ-036]
SWE-REQ-033: No runtime resource allocation or dynamic mapping SHALL occur.
[Traces: SYS-REQ-045]
SWE-REQ-034: No CAN protocol data, structures, or interface code SHALL exist in any build.
[Traces: SYS-REQ-037]
[Implied]

6.0 Software Error Handling
SWE-REQ-035: The software SHALL detect and report driver, load, ADC, and supply voltage faults using the defined interface.
[Traces: SYS-REQ-041]
SWE-REQ-036: Upon any detected dangerous fault, software SHALL immediately stop the motor/output drivers.
[Traces: SYS-REQ-042]

7.0 Performance & Responsiveness
SWE-REQ-037: The software SHALL respond to valid user commands within 100 ms under normal operating conditions (excluding blocked/critical faults).
[Traces: SYS-REQ-040]

8.0 Resource Constraints
SWE-REQ-038: Program code and data SHALL fit within 64 KB Flash and 4 KB RAM.
[Traces: SYS-REQ-044]
SWE-REQ-039: No dynamic memory usage or runtime allocation (heap/malloc) SHALL be used in the software implementation.
[Traces: SYS-REQ-045]

9.0 Testability
SWE-REQ-040: The software SHALL allow command, feedback, and actuator test via UART, LIN, and ADC interfaces during validation.
[Traces: SYS-REQ-047]
SWE-REQ-041: The software SHALL support fault injection test scenarios using input/emulation.
[Traces: SYS-REQ-047]
[Implied]
