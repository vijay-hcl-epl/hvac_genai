# 1.0 Software Scope and Responsibility
The software for the HVAC flap actuator system is responsible for receiving user position commands via UART, controlling the DC motor to move the flap to requested discrete positions, processing feedback from a position potentiometer (via ADC), handling status indication using LEDs, and ensuring robust, observable, and demonstrable behavior for learning purposes. All logic and interfaces are managed by a single microcontroller, without assumptions about scheduling, multitasking, or external communication networks.

# 2.0 Software Functional Requirements
## 2.1 User Command Handling
- SWE-REQ-001: The software shall accept user flap position commands via UART (SYS-REQ-018).
- SWE-REQ-002: The software shall validate each received UART command for correctness and ensure it is within the supported flap position range (SYS-REQ-019).
- SWE-REQ-003: The software shall ignore invalid or out-of-range UART commands without acknowledgment or error response (SYS-REQ-020).
- SWE-REQ-004: The software shall map each valid user UART command to the corresponding target position (SYS-REQ-002, SYS-REQ-018, SYS-REQ-019).
- SWE-REQ-005 [Implied]: The software shall not change the current target position or activate the motor in response to invalid or ignored commands (SYS-REQ-021).

## 2.2 Flap Position Control Logic
- SWE-REQ-006: The software shall move the flap actuator to the requested target position as specified by a valid user command (SYS-REQ-003).
- SWE-REQ-007: The software shall compare the current flap position to the target and determine the required motor movement (SYS-REQ-004).
- SWE-REQ-008: The software shall stop the motor when the flap reaches the requested target position (SYS-REQ-005).
- SWE-REQ-009: The software shall hold the flap at the target position once it is reached (SYS-REQ-006).
- SWE-REQ-010 [Implied]: The software shall prevent overshooting of the requested position for all valid commanded positions (SYS-REQ-007).

## 2.3 Motor Control Logic
- SWE-REQ-011: The software shall control the direction of motor rotation via GPIO outputs to achieve proper flap movement (SYS-REQ-008).
- SWE-REQ-012: The software shall enable the motor only when movement toward the target position is required (SYS-REQ-009).
- SWE-REQ-013: The software shall disable the motor when the flap has reached the requested position (SYS-REQ-010).
- SWE-REQ-014: The software shall stop the motor if the position feedback (from the potentiometer) is invalid or outside the expected range (SYS-REQ-011).
- SWE-REQ-015 [Implied]: The software shall avoid unintentional or spurious motor activation when no target change has occurred (SYS-REQ-012).

## 2.4 Position Feedback Processing
- SWE-REQ-016: The software shall acquire flap position feedback from the rotary potentiometer using an ADC channel (SYS-REQ-013).
- SWE-REQ-017: The software shall use fixed ADC ranges mapped to each discrete flap position (SYS-REQ-014).
- SWE-REQ-018: The software shall process ADC readings to determine the current logical flap position (SYS-REQ-015).
- SWE-REQ-019: If an ADC reading falls outside all defined flap positions, the software shall treat the feedback as invalid (SYS-REQ-016).
- SWE-REQ-020 [Implied]: The software shall trigger a safe state and ignore ADC values not mapped to any legal position (SYS-REQ-017).

## 2.5 Status Indication Control
- SWE-REQ-021: The software shall control a status LED to indicate power ON (SYS-REQ-022).
- SWE-REQ-022: The software shall control green position indicator LEDs to reflect the current logical flap position (SYS-REQ-023).
- SWE-REQ-023: At most one green LED shall be ON at any given time (SYS-REQ-023).
- SWE-REQ-024: The software shall update position LEDs immediately when the logical flap position changes (SYS-REQ-024).
- SWE-REQ-025 [Implied]: If the current position is invalid or undefined, the software shall turn OFF all green position LEDs (SYS-REQ-025).

# 3.0 Software Interface Requirements
- SWE-REQ-026: The software shall receive position commands and optionally provide status or echo via a UART interface (SYS-REQ-035).
- SWE-REQ-027: The software shall acquire position feedback from the potentiometer using an ADC interface (SYS-REQ-037).
- SWE-REQ-028: The software shall interface with the DC motor using GPIO outputs for direction and enable signals (SYS-REQ-036).
- SWE-REQ-029: The software shall drive status and position LEDs using GPIO outputs (SYS-REQ-038).
- SWE-REQ-030 [Implied]: The software shall not require or support interaction with automotive communication networks such as CAN or LIN (SYS-REQ-039).

# 4.0 Software Behavioral Requirements
- SWE-REQ-031: Upon power-up, the software shall initialize all required peripherals: ADC, UART, GPIO, and PWM (SYS-REQ-026).
- SWE-REQ-032: Upon startup, the software shall ensure the motor remains OFF until a valid movement is requested (SYS-REQ-027).
- SWE-REQ-033: On startup, the software shall read the potentiometer (via ADC) to determine and indicate the current flap position (SYS-REQ-028).
- SWE-REQ-034: While idle, the software shall await user position commands (SYS-REQ-029).
- SWE-REQ-035: When a new valid command is received, the software shall drive the flap toward the new target position and update status indicators accordingly (SYS-REQ-030).
- SWE-REQ-036: Upon reaching the target position, the software shall stop the motor and update LEDs to reflect the new state (SYS-REQ-031).
- SWE-REQ-037: The software shall ignore invalid user commands gracefully, leaving the system state unchanged (SYS-REQ-032).
- SWE-REQ-038 [Implied]: The software shall not perform or require homing/calibration at startup (SYS-REQ-033).
- SWE-REQ-039 [Implied]: The software shall ensure predictable and bounded transitions between states: startup, idle, moving, and target-reached (SYS-REQ-034).

# 5.0 Software Data and Configuration Requirements
- SWE-REQ-040: The software shall statically define all ADC ranges and logical flap position mappings in its configuration (SYS-REQ-014, SYS-REQ-042).
- SWE-REQ-041: The software shall store calibration constants and position mappings internally (SYS-REQ-042).
- SWE-REQ-042: The software shall maintain software state for current and target positions (SYS-REQ-004, SYS-REQ-006).
- SWE-REQ-043 [Implied]: The software shall not support dynamic calibration or self-learning for ADC or position mapping (SYS-REQ-043).

# 6.0 Software Error Handling Requirements
- SWE-REQ-044: The software shall deterministically ignore invalid user commands without acknowledgment or error for protocol compliance (SYS-REQ-020, SYS-REQ-046).
- SWE-REQ-045: If potentiometer/ADC feedback is invalid, the software shall stop the motor and enter a safe state (SYS-REQ-011, SYS-REQ-016, SYS-REQ-047).
- SWE-REQ-046: The software shall prevent unsafe actions in any detected unexpected condition (e.g., invalid ADC, unknown command) (SYS-REQ-048).
- SWE-REQ-047 [Implied]: The software shall recover from non-critical faults such that further valid user commands may be processed (SYS-REQ-049).

# 7.0 Software Performance and Responsiveness Requirements
- SWE-REQ-048: The software shall respond to each user command over UART in a timeframe perceptibly fast to a human user (SYS-REQ-044).
- SWE-REQ-049 [Implied]: The software shall not enforce strict real-time or periodic constraints except as explicitly required by system requirements (SYS-REQ-045).

# 8.0 Software Resource Constraint Requirements
- SWE-REQ-050: The software shall avoid the use of dynamic memory allocation in all operations (SYS-REQ-050).
- SWE-REQ-051: The software shall execute all operations in a predictable and bounded manner suitable for embedded demonstration (SYS-REQ-051).

# 9.0 Software Testability Requirements
- SWE-REQ-052: The software shall make all relevant output states externally observable using LEDs and UART (SYS-REQ-054).
- SWE-REQ-053: The software shall support both manual and script-based testing using UART and LED interfaces (SYS-REQ-055).
- SWE-REQ-054 [Implied]: The software shall not require external test frameworks or vehicle network tools for testing (SYS-REQ-056).
