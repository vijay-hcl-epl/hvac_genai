# 1.0 Software Scope and Responsibility
The HVAC Flap Actuator software, running on a microcontroller, is responsible for interpreting user commands received over UART, managing the position of an automotive air flap through DC motor control, interpreting potentiometer-based position feedback acquired via ADC, providing status feedback via LEDs, and ensuring safe, bounded, and deterministic behavior during all operations. The software does not include any assumption about scheduling models, multitasking, or execution cycles; all such decisions are deferred to later lifecycle stages.

# 2.0 Software Functional Requirements
## User Command Handling
- SWE-REQ-001: The software shall accept user commands via UART to select a target flap position by numeric value. (SYS-REQ-001, SYS-REQ-013)
- SWE-REQ-002: The software shall validate received command values and accept only those corresponding to valid flap positions (0–5). (SYS-REQ-014)
- SWE-REQ-003: The software shall safely ignore and not acknowledge invalid commands. (SYS-REQ-015, SYS-REQ-038)
- SWE-REQ-004 [Implied]: The software shall ensure that buffer overruns, framing, or UART RX errors do not cause a system crash. (SYS-REQ-016)

## Flap Position Control Logic
- SWE-REQ-005: The software shall compare the current measured flap position with the target position. (SYS-REQ-002)
- SWE-REQ-006: The software shall command the actuator to move the flap from current to target position. (SYS-REQ-003, SYS-REQ-024)
- SWE-REQ-007: The software shall stop commanding movement once the target position is reached. (SYS-REQ-004, SYS-REQ-008)
- SWE-REQ-008 [Implied]: The software shall maintain the flap position once reached, within specified tolerances. (SYS-REQ-005)
- SWE-REQ-009 [Implied]: The software shall ensure the motor does not operate continuously when there is no position error. (SYS-REQ-009)

## Motor Control Logic
- SWE-REQ-010: The software shall select the direction of motor control to achieve the shortest path to the requested position. (SYS-REQ-006)
- SWE-REQ-011: The software shall enable or disable the motor driver (GPIO or PWM) as required by motion state. (SYS-REQ-007, SYS-REQ-028)

## Position Feedback Processing
- SWE-REQ-012: The software shall acquire potentiometer feedback using ADC to determine the current flap position. (SYS-REQ-010, SYS-REQ-029)
- SWE-REQ-013: The software shall map ADC values to valid logical positions (0–5). (SYS-REQ-011)
- SWE-REQ-014: The software shall detect and safely handle ADC values outside expected ranges by stopping motor actuation. (SYS-REQ-012, SYS-REQ-039)

## Status Indication Control
- SWE-REQ-015: The software shall turn on a status LED during power-on. (SYS-REQ-017)
- SWE-REQ-016: The software shall indicate the current flap position by activating one of six green LEDs, such that only the correct position’s LED is ON. (SYS-REQ-018)
- SWE-REQ-017 [Implied]: The software shall ensure the position LEDs remain mutually exclusive. (SYS-REQ-019)

# 3.0 Software Interface Requirements
- SWE-REQ-018: The software shall receive and transmit UART data for command and status operations. (SYS-REQ-027)
- SWE-REQ-019: The software shall control motor direction and enable signals using dedicated GPIO/PWM outputs. (SYS-REQ-028)
- SWE-REQ-020: The software shall read analog feedback signals from the potentiometer using microcontroller ADC input(s). (SYS-REQ-029)
- SWE-REQ-021: The software shall set or reset status LEDs using GPIO outputs only. (SYS-REQ-030)
- SWE-REQ-022 [Implied]: The software shall ensure no unintended conflicts on any shared peripheral pins at the software configuration level. (SYS-REQ-031)

# 4.0 Software Behavioral Requirements
- SWE-REQ-023: The software shall initialize all required I/O peripherals (ADC, UART, GPIO, PWM) on power-up, before command processing can occur. (SYS-REQ-020)
- SWE-REQ-024: The software shall ensure the motor is OFF during system startup/init. (SYS-REQ-021)
- SWE-REQ-025: The software shall read and display the actual flap position using the correct position-indicating LED at startup. (SYS-REQ-022)
- SWE-REQ-026: The software shall monitor for user commands and remain idle when not processing a valid command. (SYS-REQ-023)
- SWE-REQ-027: The software shall command and monitor actuator movement in response to valid user commands until target position is reached or error detected. (SYS-REQ-024)
- SWE-REQ-028: The software shall not enter a fault/reset state due to invalid command or transient ADC error. (SYS-REQ-025, SYS-REQ-040)
- SWE-REQ-029 [Implied]: The software shall prevent, when feasible, prolonged running of the motor in the event of extended failed movement. (SYS-REQ-026)

# 5.0 Software Data and Configuration Requirements
- SWE-REQ-030: The software shall store and use the mapping of ADC values to logical flap positions, with configuration constants fixed in software. (SYS-REQ-011, SYS-REQ-032)
- SWE-REQ-031: The software shall ensure all calibration values for ADC mapping are used as fixed, compile-time configuration. (SYS-REQ-032)
- SWE-REQ-032: The software shall store and track the current logical position and target logical position as internal state. (SYS-REQ-022, SYS-REQ-025)

# 6.0 Software Error Handling Requirements
- SWE-REQ-033: The software shall deterministically handle the receipt of invalid command values by ignoring them and not acknowledging. (SYS-REQ-015, SYS-REQ-038)
- SWE-REQ-034: The software shall handle out-of-range ADC feedback by stopping the motor and maintaining a safe state. (SYS-REQ-012, SYS-REQ-039)
- SWE-REQ-035: The software shall remain operable and recoverable from all handled error conditions. (SYS-REQ-040)

# 7.0 Software Performance and Responsiveness Requirements
- SWE-REQ-036: The software shall provide perceptibly responsive operation to valid user commands, typically ensuring visible actuator and LED response within less than 0.5 seconds of command. (SYS-REQ-037)
- SWE-REQ-037: The software shall make position evaluation and control decisions in a timely manner when executing flap movement or processing feedback. (SYS-REQ-037)

# 8.0 Software Resource Constraint Requirements
- SWE-REQ-038: The software shall operate without using dynamic memory allocation and within the memory/resources available in the STM32F407G-DISC1 MCU. (SYS-REQ-041)
- SWE-REQ-039: The software shall exhibit deterministic and bounded execution in every function and logic path. (SYS-REQ-042)
- SWE-REQ-040: The software shall process only one user command at a time. (SYS-REQ-034)

# 9.0 Software Testability Requirements
- SWE-REQ-041: The software shall support test and verification by sending UART commands and observing motor and LED behaviors. (SYS-REQ-044, SYS-REQ-045)
- SWE-REQ-042 [Implied]: The software shall ensure for every possible command or error, there is a visible or communicable outcome to support testing and learning. (SYS-REQ-045)
