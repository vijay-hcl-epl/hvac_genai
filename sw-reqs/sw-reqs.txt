# Software Requirements for HVAC Flap Actuator System

## 1. Overview
The following software requirements are derived strictly from the system-level requirements (sys-reqs.txt) for the HVAC Flap Actuator. All requirements are clear, atomic, testable, and free from architectural details. Each requirement is traced to one or more system requirements (SYS-REQ-XXX).

## 2. Functional Requirements

SWE-REQ-001: The software shall receive flap position commands as single-byte values (0–5) via UART. [SYS-REQ-001, SYS-REQ-017, SYS-REQ-018]

SWE-REQ-002: The software shall validate each received UART command is within the allowed values 0–5. [SYS-REQ-019]

SWE-REQ-003: The software shall, upon receiving a valid command, store the new target position and initiate movement if the current position does not match the target. [SYS-REQ-002, SYS-REQ-003, SYS-REQ-005]

SWE-REQ-004: The software shall read the flap position periodically from the potentiometer using the ADC. [SYS-REQ-013, SYS-REQ-014, SYS-REQ-015]

SWE-REQ-005: The software shall map ADC readings to indices 0–5 according to fixed lookup ranges. [SYS-REQ-015, SYS-REQ-038]

SWE-REQ-006: The software shall drive GPIO pins to set the DC motor direction as required to move the flap toward the target position. [SYS-REQ-008, SYS-REQ-009, SYS-REQ-033]

SWE-REQ-007: The software shall use PWM or GPIO to enable/disable the DC motor as needed. [SYS-REQ-010, SYS-REQ-011, SYS-REQ-033]

SWE-REQ-008: The software shall stop the motor when the current position matches the target position or ADC value is out of range. [SYS-REQ-004, SYS-REQ-016, SYS-REQ-031, SYS-REQ-044]

SWE-REQ-009: The software shall indicate the current flap position by turning on exactly one green LED linked to the detected position. [SYS-REQ-022, SYS-REQ-023]

SWE-REQ-010: The software shall turn the power/status LED ON when system initialization is complete. [SYS-REQ-021]

SWE-REQ-011: The software shall handle invalid (out-of-range) UART commands by ignoring them without any motor or indicator action. [SYS-REQ-020, SYS-REQ-043]

SWE-REQ-012: The software shall update status LEDs promptly if the detected position changes. [SYS-REQ-024]

SWE-REQ-013: The software shall initialize all MCU peripherals (ADC, UART, GPIO, PWM) at power-up. [SYS-REQ-025, SYS-REQ-026]

SWE-REQ-014: The software shall ensure the motor is off immediately on startup. [SYS-REQ-026]

SWE-REQ-015: The software shall store all configuration/calibration values (position ADC ranges, pin assignments) as source code constants. [SYS-REQ-038]

SWE-REQ-016: The software shall process only one user command at a time (no queuing). [SYS-REQ-037]

SWE-REQ-017: The software shall not use dynamic memory allocation. [SYS-REQ-046]

SWE-REQ-018: The software shall support testability through UART command execution and visual feedback. [SYS-REQ-049, SYS-REQ-050]

## 3. Non-Functional Requirements

SWE-REQ-019: The software shall be written in C, suitable for STM32Cube IDE, and conforming to MISRA-C style. [Platform Spec]

SWE-REQ-020: The software structure and logic shall be modular and clearly commented for maintainability. [SYS-REQ-048]

SWE-REQ-021: The software shall avoid direct manipulation of scheduling, timing, or execution model. [SYS-REQ-042]

SWE-REQ-022: All functions shall complete in bounded time, suitable for the targeted microcontroller. [SYS-REQ-047]

## 4. Exclusions and Out-of-Scope

SWE-REQ-023: The software shall not implement CAN/LIN bus communication or UDS diagnostics. [SYS-REQ-039, SYS-REQ-016]

SWE-REQ-024: The software does not implement timeout detection or safety-critical logic beyond what is described here. [SYS-REQ-045]
