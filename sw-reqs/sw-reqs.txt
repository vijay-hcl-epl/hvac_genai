# 1.0 Software Scope and Responsibility

The HVAC flap actuator software is responsible for receiving user flap position commands via UART, acquiring potentiometer-based position feedback via ADC, controlling a DC motor (via GPIO and PWM) to move and hold the flap at the commanded position, and providing visual status indication with LEDs. The software executes on a microcontroller and interprets device-level signals and commands as specified, within the limitations and definitions given by the system-level requirements.

# 2.0 Software Functional Requirements

## 2.1 User Command Handling
- SWE-REQ-001: The software shall receive user commands representing target flap positions via UART. (SYS-REQ-001, SYS-REQ-018)
- SWE-REQ-002: The software shall validate each received user command for correct numeric format before processing. (SYS-REQ-021, SYS-REQ-022)
- SWE-REQ-003: The software shall verify that each commanded position falls within the configured valid flap position range. (SYS-REQ-001, SYS-REQ-019)
- SWE-REQ-004: The software shall ignore commands that do not represent valid flap positions and proceed with current operation. (SYS-REQ-019, SYS-REQ-046)
- SWE-REQ-005: The software shall not transmit acknowledgments or error messages in response to invalid commands. (SYS-REQ-020)
- SWE-REQ-006: The software shall process only one user command at a time, ignoring concurrent or overlapping commands. (SYS-REQ-021, SYS-REQ-040)

## 2.2 Flap Position Control Logic
- SWE-REQ-007: The software shall determine the target position from the most recently validated user command. (SYS-REQ-002, SYS-REQ-005)
- SWE-REQ-008: The software shall continuously compare the measured flap position with the target position when the flap is moving. (SYS-REQ-003)
- SWE-REQ-009: The software shall command the motor to move the flap toward the target position. (SYS-REQ-002, SYS-REQ-007)
- SWE-REQ-010: The software shall hold the flap at the current position until a new valid command is received. (SYS-REQ-005, SYS-REQ-030)
- SWE-REQ-011: The software shall not act on commands requesting positions outside the supported range. (SYS-REQ-006)

## 2.3 Motor Control Logic
- SWE-REQ-012: The software shall control the motor direction via two GPIO outputs based on target and current positions. (SYS-REQ-008, SYS-REQ-007)
- SWE-REQ-013: The software shall control the motor enable via a PWM signal and disable it when target position is reached or invalid conditions are detected. (SYS-REQ-009, SYS-REQ-010, SYS-REQ-047)
- SWE-REQ-014: The software shall ensure the motor is OFF immediately upon software startup and after initialization. (SYS-REQ-011, SYS-REQ-029)
- SWE-REQ-015: [Implied] The software shall avoid reversing motor direction until the current movement to a previously commanded position has concluded. (SYS-REQ-012)

## 2.4 Position Feedback Processing
- SWE-REQ-016: The software shall acquire current flap position by sampling the potentiometer via ADC. (SYS-REQ-013)
- SWE-REQ-017: The software shall convert ADC readings to discrete logical flap positions using configured thresholds. (SYS-REQ-014, SYS-REQ-041)
- SWE-REQ-018: The software shall disregard ADC readings outside the defined valid position range. (SYS-REQ-016)
- SWE-REQ-019: [Implied] The software shall process ADC values to mitigate the effect of noise and avoid false position detection. (SYS-REQ-017)

## 2.5 Status Indication Control
- SWE-REQ-020: The software shall control a power status LED to indicate when the system is initialized and powered on. (SYS-REQ-023)
- SWE-REQ-021: The software shall control position indication LEDs such that exactly one green LED indicates the current flap position. (SYS-REQ-024, SYS-REQ-026)
- SWE-REQ-022: The software shall update position LEDs immediately after any confirmed flap position change. (SYS-REQ-025)

# 3.0 Software Interface Requirements
- SWE-REQ-023: The software shall interface with the UART peripheral to receive user command data. (SYS-REQ-035, SYS-REQ-037)
- SWE-REQ-024: The software shall interface with the ADC peripheral to acquire potentiometer voltage for flap position feedback. (SYS-REQ-035)
- SWE-REQ-025: The software shall control GPIO outputs to set motor direction and LED states. (SYS-REQ-035, SYS-REQ-008, SYS-REQ-023, SYS-REQ-024)
- SWE-REQ-026: The software shall control a timer-driven PWM output for motor enable/speed control. (SYS-REQ-035, SYS-REQ-009)
- SWE-REQ-027: The software shall issue motor control signals compatible with the required motor driver interface. (SYS-REQ-036)
- SWE-REQ-028: [Implied] The software shall not interface with CAN/LIN or vehicle network communication hardware. (SYS-REQ-038)

# 4.0 Software Behavioral Requirements
- SWE-REQ-029: Upon startup, the software shall initialize all necessary peripherals used for system operation. (SYS-REQ-027)
- SWE-REQ-030: Upon startup, the software shall acquire and store current flap position through ADC. (SYS-REQ-028)
- SWE-REQ-031: Upon startup and after initialization, the software shall set the motor to OFF. (SYS-REQ-011, SYS-REQ-029)
- SWE-REQ-032: While idle, the software shall wait for and process only valid user commands, holding the flap in the current position. (SYS-REQ-030)
- SWE-REQ-033: During normal operation, the software shall move the flap only in response to valid user commands, using position feedback for control. (SYS-REQ-031)
- SWE-REQ-034: When the commanded position is reached, the software shall stop the motor and update position LEDs. (SYS-REQ-032)
- SWE-REQ-035: The software shall ignore invalid user commands and invalid position feedback without error generation. (SYS-REQ-033)
- SWE-REQ-036: [Implied] If ADC feedback is out of range, the software shall stop the motor and set status LEDs to a safe state. (SYS-REQ-034, SYS-REQ-047)

# 5.0 Software Data and Configuration Requirements
- SWE-REQ-037: The software shall store mappings between logical flap positions and ADC threshold values as configuration data. (SYS-REQ-014, SYS-REQ-041)
- SWE-REQ-038: The software shall use constant, statically defined calibration values for ADC-to-position mapping. (SYS-REQ-041)
- SWE-REQ-039: The software shall maintain internal state variables for current position, target position, and motor state. (SYS-REQ-028, SYS-REQ-005)

# 6.0 Software Error Handling Requirements
- SWE-REQ-040: The software shall deterministically reject and safely ignore invalid or out-of-range user commands. (SYS-REQ-019, SYS-REQ-046)
- SWE-REQ-041: The software shall deterministically ignore ADC readings outside the valid operating range. (SYS-REQ-016, SYS-REQ-047)
- SWE-REQ-042: The software shall stop the motor and maintain last known safe state if position feedback is invalid. (SYS-REQ-047, SYS-REQ-034)
- SWE-REQ-043: The software shall not enter fault or diagnostic modes in response to command or hardware errors. (SYS-REQ-048)

# 7.0 Software Performance and Responsiveness Requirements
- SWE-REQ-044: The software shall process valid user commands and initiate observable system behavior in a timeframe perceivable as immediate by a human operator. (SYS-REQ-044)
- SWE-REQ-045: [Implied] The software shall update position feedback and actuator control as often as needed to ensure timely motor stopping and position indication in line with system non-functional requirements. (SYS-REQ-045)

# 8.0 Software Resource Constraint Requirements
- SWE-REQ-046: The software shall exhibit predictable execution behavior, avoiding unbounded loops or waiting. (SYS-REQ-049)
- SWE-REQ-047: The software shall avoid using dynamic memory allocation. (SYS-REQ-049)
- SWE-REQ-048: The software shall remain within the available memory and resource constraints of the target microcontroller platform. (SYS-REQ-050)

# 9.0 Software Testability Requirements
- SWE-REQ-049: The software shall support verification of correct operation using UART-based user command injection and observation of status/motor outputs. (SYS-REQ-053)
- SWE-REQ-050: The software shall support script-driven or manual testing using UART and observable state changes. (SYS-REQ-054)

# 10.0 Implied Software Requirements
- SWE-REQ-051 [Implied]: The software shall not implement multitasking, real-time scheduling, or priority-driven execution unless explicitly required in future design or system requirements. (SYS-REQ-043)
- SWE-REQ-052 [Implied]: The software shall separate core functions into logically distinct modules for maintainability to the extent practical. (SYS-REQ-051, SYS-REQ-052)
- SWE-REQ-053 [Implied]: The software shall support expansion (e.g., additional actuators/channels) via clear module patterns in future updates. (Architecture Considerations)
