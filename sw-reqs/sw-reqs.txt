1.0 Software Scope & Responsibility

The software for the HVAC Flap Actuator System implements user-driven control of an air flap via a DC motor, processing commands received over UART and using ADC-derived feedback from a potentiometer for precise positioning. The software is responsible for interpreting user commands, actuating the motor, acquiring position feedback, indicating status, handling errors, and ensuring bounded and robust operation on an MCU with ADC, GPIO, UART, and timer/PWM capability.

2.0 Software Functional Requirements

2.1 User Commands

SWE-REQ-001: The software SHALL interpret any UART command corresponding to a discrete supported position and initiate flap actuation to that position. [SYS-REQ-001, SYS-REQ-012, SYS-REQ-002]
SWE-REQ-002: The software SHALL ignore user commands received over UART which request positions outside the valid supported range. [SYS-REQ-004]
SWE-REQ-003: The software SHALL ignore malformed or non-numeric commands on UART. [SYS-REQ-013]
SWE-REQ-004: The software SHALL process only one command at a time; commands SHALL NOT preempt ongoing movement. [SYS-REQ-029] [Implied]

2.2 Flap Control

SWE-REQ-005: The software SHALL convert valid user position requests into target positions and command the motor accordingly. [SYS-REQ-001, SYS-REQ-009]
SWE-REQ-006: The software SHALL ensure the flap moves only between defined, discrete positions as mapped in the application. [SYS-REQ-002, SYS-REQ-009]
SWE-REQ-007: The software SHALL initiate stopping of the motor when the flap reaches the commanded position. [SYS-REQ-003]

2.3 Motor Control

SWE-REQ-008: The software SHALL command the motor for both directions as required by position targets. [SYS-REQ-005, SYS-REQ-006]
SWE-REQ-009: The software SHALL generate appropriate logical signals (PWM and GPIO) to start and stop the motor as per movement needs. [SYS-REQ-006]
SWE-REQ-010: The software SHALL ensure no logical signal is sent to keep the motor running except when movement is required. [SYS-REQ-007]

2.4 Feedback Processing

SWE-REQ-011: The software SHALL read ADC input from the position feedback potentiometer on demand whenever flap movement or target check is required. [SYS-REQ-008, SYS-REQ-019, SYS-REQ-010]
SWE-REQ-012: The software SHALL map ADC values to discrete logical flap positions using software-configured bounds and tolerances. [SYS-REQ-009]
SWE-REQ-013: The software SHALL detect and flag if feedback is out of a valid mapped range during movement or verification. [SYS-REQ-011] [Implied]

2.5 Status Indication

SWE-REQ-014: The software SHALL activate a power-status LED upon power-up initialization. [SYS-REQ-014, SYS-REQ-017]
SWE-REQ-015: The software SHALL control a single position-indicating green LED to match the most recent known flap position. [SYS-REQ-015, SYS-REQ-016]
SWE-REQ-016: The software SHALL update LED status each time the designated flap position changes as per user command and feedback. [SYS-REQ-016]

3.0 Software Interface Requirements

SWE-REQ-017: The software SHALL define logical UART receive protocols for numeric, single-value commands as user input. [SYS-REQ-012, SYS-REQ-022]
SWE-REQ-018: The software SHALL process ADC channel input for position feedback from the potentiometer. [SYS-REQ-023]
SWE-REQ-019: The software SHALL provide logical outputs (PWM/GPIO) to the motor driver circuit to generate requested movements. [SYS-REQ-024]
SWE-REQ-020: The software SHALL provide logical GPIO outputs to control all required indicator LEDs (position, status). [SYS-REQ-025]

4.0 Software Behavioral Requirements

SWE-REQ-021: On startup, the software SHALL initialize all relevant hardware drivers (UART, ADC, GPIO) and ensure the motor is stopped safely. [SYS-REQ-017, SYS-REQ-018]
SWE-REQ-022: On startup, the software SHALL acquire the current position by reading the ADC. [SYS-REQ-019]
SWE-REQ-023: The software SHALL not move the actuator until a valid user command is received. [SYS-REQ-020]
SWE-REQ-024: When a valid position command is received, the software SHALL check command validity, convert to a logical target position, and initiate actuation sequence if target differs from current position. [SYS-REQ-001, SYS-REQ-012]
SWE-REQ-025: When the current position matches the requested one, the software SHALL keep the motor off and indicate status. [SYS-REQ-003, SYS-REQ-015]
SWE-REQ-026: If a command is invalid, the software SHALL maintain its current state and take no action. [SYS-REQ-021]
SWE-REQ-027: If feedback cannot be acquired reliably, the software SHALL stop the motor and/or trigger an error indication. [SYS-REQ-031] [Implied]

5.0 Software Data & Configuration

SWE-REQ-028: The software SHALL allow configuration of the supported position set and mapping from ADC readings. [SYS-REQ-009]
SWE-REQ-029: The software SHALL maintain local state for current and target position, as well as any error flags. [SYS-REQ-034]
SWE-REQ-030: The software SHALL reference all logical position boundaries and LED assignments via software constants. [Implied]

6.0 Software Error Handling

SWE-REQ-031: If a commanded position is outside the configured set, the software SHALL ignore it. [SYS-REQ-004]
SWE-REQ-032: If feedback mapping fails or an ADC value is invalid/out-of-bounds, the software SHALL stop movement and indicate the error condition. [SYS-REQ-011, SYS-REQ-031]
SWE-REQ-033: The software SHALL ignore UART errors that do not impact safety or motor control. [SYS-REQ-032]
SWE-REQ-034: The software SHALL assume the hardware is functional/calibrated and SHALL NOT attempt self-diagnosis or recalibration. [SYS-REQ-028] [Implied]

7.0 Performance & Responsiveness

SWE-REQ-035: The software SHALL ensure user commands are processed with latency acceptable to the human operator. [SYS-REQ-030]
SWE-REQ-036: The software SHALL NOT implement timing dependencies beyond those required by electrical interface protocols; no periodic/cyclic execution mandated. [Implied]

8.0 Resource Constraints

SWE-REQ-037: The software SHALL NOT require dynamic (heap) memory allocation after initialization. [SYS-REQ-033]
SWE-REQ-038: The software SHALL limit stack, buffer, and state usage to a bounded/constant value for each function. [Implied]

9.0 Testability

SWE-REQ-039: All functional requirements SHALL be verifiable by external observation (UART commands, LED status, flap position, motor on/off) without requiring internal debug access. [SYS-REQ-035]
SWE-REQ-040: Test points and software hooks SHALL be configurable to allow repeatable verification of all logical states. [Implied]
