==================================================
ASPICE SYS.5 System Qualification Test Specification
for HVAC Flap Actuator System
==================================================

1. Introduction
--------------------------------------------------
This document specifies the end-to-end system qualification tests (ASPICE SYS.5) for the HVAC flap actuator system. The purpose is to verify that the integrated system implementation satisfies system-level requirements, as allocated from the IBM DOORS Next RM tool, and functions correctly on the defined hardware platform. This plan defines test cases, environment, traceability, and objectives—focusing on external interfaces with no internal or unit-level inspection.

2. Test Scope
--------------------------------------------------
The test verifies the full integration of all modules and their correct interactions (black-box approach), including:
 • Complete HVAC flap actuator hardware
 • UART command interface
 • Motor driver and power stage
 • ADC position feedback sensors
 • LED status outputs

Assumptions:
 • Tests run on hardware bench setup
 • Observations made only via external I/O (UART, ADC, LEDs)
 • No access to internal SW or unit code
 • No isolated component/unit testing

Interfaces under test:
 - UART commands
 - Motor driver outputs
 - ADC position feedback
 - LED status outputs

3. System Requirement Traceability
--------------------------------------------------
System Requirement from IBM DOORS Next:

 SYS-REQ-001
 • Source URI: https://jazz.net/sandbox01-rm/resources/TX_brBe0BlLEfGiE4wGh9TStA
 • Requirement text: The system SHALL provide defined electrical interfaces for all expected input and output signals as per system-level signal lists.

4. Test Environment Description
--------------------------------------------------
• HVAC flap actuator hardware bench
• PC with test control SW, UART interface
• Power supply (12V automotive)
• Oscilloscope for signal monitoring (optional)
• Logging for UART, ADC, LED states

5. System Test Cases
--------------------------------------------------
Legend: TCS-XXX; all cases trace to SYS-REQ-001

A. Power-Up and Initialization
------------------------------------------
TCS-001
- Mapped Requirement: SYS-REQ-001
- Objective: Verify the system initializes correctly and all electrical interfaces are set to safe/defined states.
- Test Environment: As above
- Preconditions: Power supply off, UART connected
- Inputs: Apply 12V, no UART commands
- Steps:
  1. Power on system.
  2. Observe outputs on motor, ADC, and LED lines.
- Expected Results:
  a) All outputs at defined inactive/safe level.
  b) UART interface ready to accept commands.
- Pass/Fail: All outputs match interface definition tables.

TCS-002
- Mapped Requirement: SYS-REQ-001
- Objective: Verify motor remains idle after power-up, system does not oscillate or move unless commanded.
- Test Environment: As above
- Preconditions: System powered off
- Inputs: None (except power-on)
- Steps:
  1. Apply power
  2. Monitor for unintended motor/actuator activation
- Expected Results: No movement, no oscillation.
- Pass/Fail: Pass if no activity for >5s post power-on.

TCS-003
- Mapped Requirement: SYS-REQ-001
- Objective: Initial flap position is detected and reported (on UART, ADC, or LED if available).
- Test Environment: As above
- Preconditions: Flap at a known position
- Inputs: Power on, read initial state
- Steps: Observe reported position
- Expected Results: Reported position matches flap
- Pass/Fail: Pass if match within 1 position increment

B. Valid Position Commands
----------------------------------------
TCS-004—TCS-009 (One for Position 0–5)

Each:
- Mapped Requirement: SYS-REQ-001
- Objective: Verify actuator moves to commanded position via UART command (0 through 5)
- Test Environment: As above
- Preconditions: System initialized, flap at arbitrary position
- Inputs: UART command for position N (N=0...5)
- Steps:
  1. Issue UART command for position N
  2. Await movement completion (observe motor outputs, ADC, or end indication)
- Expected Results: Flap moves to N, stops, feedback matches N, status LED as per signal list
- Pass/Fail: Pass if all results are per spec

C. Boundary/Invalid/Robustness Cases
-------------------------------------
TCS-010
- Mapped Requirement: SYS-REQ-001
- Objective: Out-of-range UART command
- Environment: As above
- Preconditions: Initialized
- Inputs: UART command (>5 or negative)
- Steps: Issue illegal command
- Expected Result: System rejects command, no movement, error LED/status output
- Pass/Fail: Pass if no movement, error indicated

TCS-011
- Mapped Requirement: SYS-REQ-001
- Objective: Invalid format command via UART
- Inputs: Corrupt/UART glitch/garbled string
- Steps: Issue malformed input
- Expected: System recognizes error, no movement, error LED/status
- Pass/Fail: Pass if no movement, error

TCS-012
- Mapped Requirement: SYS-REQ-001
- Objective: Sensor (ADC) out-of-range/invalid
- Inputs: Induce fault on sensor
- Steps: Observe response
- Expected: System flags error, does not move flap to unknown position
- Pass/Fail: Pass if safe state, error signaled

TCS-013
- Mapped Requirement: SYS-REQ-001
- Objective: Command during movement
- Inputs: UART position command, then another before completion
- Steps: Issue N, then another N'
- Expected: System queues/rejects, never enters undefined state
- Pass/Fail: As spec

TCS-014
- Mapped: SYS-REQ-001
- Objective: Robustness — system does not reset or hang on rapid sequence of valid and invalid commands
- Inputs: Issue rapid mix commands
- Steps: Observe
- Expected: No reset/hang, errors handled gracefully
- Pass/Fail: No hang/reset

TCS-015
- Mapped: SYS-REQ-001
- Objective: Motor stops correctly at commanded position
- Inputs: Commanded position, monitor after stop
- Steps: Move, then observe
- Expected: No further movement, stays in position
- Pass/Fail: Pass if steady

7. Pass/Fail Evaluation Criteria
--------------------------------------------------
A test is passed if the system behavior matches the expected results as specified per test case, without deviations. Each criterion includes interface states upon action, correct error signaling when appropriate, and no loss of system stability (no uncommanded reset, undefined state, or movement).
