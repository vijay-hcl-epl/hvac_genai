SYS.5 SYSTEM QUALIFICATION TEST SPECIFICATION (HVAC FLAP ACTUATOR)
==================================================

1. Scope
This document specifies system-level, end-to-end qualification test cases for the HVAC Flap Actuator system prototype per ASPICE SYS.5. Test cases validate system requirements as observable at interfaces, using only real inputs, outputs, and bench setup hardware.

2. References
- System Requirements (sys-reqs/sys-reqs.txt, branch hvdemo-142b)
- Software Architecture (sw-arch/sw-arch.txt, branch hvdemo-142b)

3. Test Environment
- Bench setup including STM32F407G-DISC1 board, DC motor, potentiometer feedback, UART connection, status LEDs.
- Powered by regulated 5V source. UART via PC terminal or custom tool.
- No connections to vehicle network (CAN/LIN).

5. Test Cases

--------------------------------------------------------------------
Test Case: SYS-TC-001 Power-Up & Initialization
Mapped SYS Requirement IDs: SYS-REQ-020, SYS-REQ-021, SYS-REQ-022
Test Objective: Verify system initializes peripherals (ADC, UART, GPIO, PWM), motor is OFF, and flap position is read on power-up.
Preconditions: Board powered OFF, setup complete.
Test Inputs: Apply power (5V DC).
Test Steps:
  1. Ensure bench setup is correct. Motor flap may be set to any position.
  2. Apply power to the system.
Expected Results:
  - Both power and position LEDs illuminate per current flap state.
  - No motor movement at power-up.
  - UART interface is silent (no output).
Pass/Fail Criteria: LEDs correct, motor OFF, UART silent.

--------------------------------------------------------------------
Test Case: SYS-TC-002 Valid Flap Position Commands
Mapped SYS Requirement IDs: SYS-REQ-001,002,003,004,006,007
Test Objective: Each valid UART position command (0–5) moves the flap to requested position, stops motor on arrival, no overshoot.
Preconditions: System powered, idle, setup as above.
Test Inputs: UART commands "0" through "5", one at a time with settle interval.
Test Steps:
  1. Send command 'n' (0≤n≤5) over UART, observe motion.
  2. Allow system to settle; repeat for each supported value.
Expected Results:
  - Flap always moves to requested position.
  - Correct motor direction/action for each move.
  - Motor stops at target; no overshoot/oscillation.
  - Corresponding position LED ON exclusively.
Pass/Fail Criteria: All requirements met for every command.

--------------------------------------------------------------------
Test Case: SYS-TC-003 Invalid & Boundary Conditions
Mapped SYS Requirement IDs: SYS-REQ-005,013,014,016,026,034,038
Test Objective: Invalid UART & range conditions are ignored; system stability maintained.
Preconditions: System powered, in idle or any state.
Test Inputs:
  - UART commands outside 0–5 (e.g., -1, 6, 100, 'A', etc.)
  - ADC wire temporarily disconnected (if safe/testable)
  - Send valid command during move
Test Steps:
  1. Send each invalid UART command during idle and motion.
  2. If feasible, disconnect ADC during operation to force out-of-range.
Expected Results:
  - No movement, state, or LED change on invalid command.
  - On out-of-range ADC, motor stops and system idles.
  - No crash or system reset.
Pass/Fail Criteria: System stable, error conditions non-destructive, as specified.

--------------------------------------------------------------------
Test Case: SYS-TC-004 Position Feedback & Monitoring
Mapped SYS Requirement IDs: SYS-REQ-009,010,011,012,042
Test Objective: Verify accurate ADC-to-flap position mapping & continuous monitoring.
Preconditions: System functional, flap movable by hand if safe.
Test Inputs: Physically move flap (simulate ADC feedback changes), UART commands 0–5.
Test Steps:
  1. Set flap manually to different positions if safe.
  2. Send commands, compare LED indication to expected position.
  3. Power cycle, repeat above.
Expected Results:
  - LED state always reflects ADC-detected position.
  - System adapts to manual moves/ADC changes as required.
Pass/Fail Criteria: Observable mapping matches system requirement.

--------------------------------------------------------------------
Test Case: SYS-TC-005 Motor Control Behavior
Mapped SYS Requirement IDs: SYS-REQ-006,007,008,029,040
Test Objective: Motor starts/stops as per command & feedback, correct direction, no unintended movement.
Preconditions: System functional, all connections.
Test Inputs: UART commands (various), flap position.
Test Steps:
  1. Issue command for new position; observe motor direction, start/stop points.
  2. Repeat for various command sequences (increasing/decreasing positions).
Expected Results:
  - Motor direction matches expected path.
  - Motor always stops at the right position.
  - No uncommanded or repeated actuation.
Pass/Fail Criteria: All actual motor events match required system behavior.

--------------------------------------------------------------------
Test Case: SYS-TC-006 LED Status Indication
Mapped SYS Requirement IDs: SYS-REQ-017,018,019,031
Test Objective: LEDs reflect power and position correctly at all times.
Preconditions: System powered, all LEDs functional.
Test Inputs: Power cycling, UART commands.
Test Steps:
  1. Observe LED on power-up.
  2. Issue series of UART position commands.
Expected Results:
  - Power LED always ON with system powered.
  - Only correct position LED ON, all others OFF.
Pass/Fail Criteria: Observed LED operation always matches requirements.

--------------------------------------------------------------------
Test Case: SYS-TC-007 End-to-End Scenario
Mapped SYS Requirement IDs: SYS-REQ-024,025,042
Test Objective: System executes entire chain: user command → flap move → feedback update → LED indication.
Preconditions: System powered, idle.
Test Inputs: Any valid UART position command.
Test Steps:
  1. Send valid command; observe complete actuator/LED response chain.
Expected Results:
  - Command recognition, motor action, feedback correction, LED update—all occur and align per spec.
Pass/Fail Criteria: All observable system behaviors in the flow comply end-to-end.

6. Exclusions
- No internal software module, task, or architectural logic tests.
- No fault-injection beyond explicit error handling in requirements.
- No functional safety or security tests (not required).
- All test validation is visibility-based (UART, motor, LEDs).

7. Review & Acceptance
- Document is suitable for system qualification per ASPICE Level 3 demonstration and formal traceability. All cases trace to system requirements.
