# System Qualification Test Specification (SYS.5) – HVAC Flap Actuator System

## 1. Introduction
This document specifies the system qualification tests (SYS.5) for the HVAC flap actuator system, covering full integrated behavior validation according to ASPICE Level 3 standards. Each test case maps to system requirement IDs and focuses strictly on end-to-end, observable system behavior—no unit or internal logic tests included.

## 3. Test Cases

### 3.1 Power-Up & Initialization

#### SYS-TC-001: Power-Up & Initialization
- **Mapped System Requirement ID(s):** SYS-REQ-016, SYS-REQ-002, SYS-REQ-008
- **Test Objective:** Verify that after power-on, all system peripherals initialize correctly, the motor is OFF, and flap feedback is correctly available.
- **Preconditions:** System powered OFF. Bench setup prepared.
- **Test Inputs:** Power ON (apply nominal supply voltage).
- **Test Steps:**
  1. Apply power.
  2. Observe peripheral initialization (status LEDs, UART response).
  3. Verify motor remains OFF.
  4. Read initial flap position (via feedback interface).
- **Expected Results:**
  - All peripherals initialize without fault indication.
  - Motor does not start.
  - Current flap position correctly reported/available.
- **Pass/Fail Criteria:** All expected results observed, no errors.


### 3.2 Valid Flap Position Commands

#### SYS-TC-002: Command Flap to Position 0
- **Mapped System Requirement ID(s):** SYS-REQ-001, SYS-REQ-003, SYS-REQ-005, SYS-REQ-006
- **Test Objective:** Validate correct movement to lowest flap position upon command.
- **Preconditions:** System powered, flap in mid-range.
- **Test Inputs:** UART command for position 0.
- **Test Steps:**
  1. Send position 0 command via UART.
  2. Observe motor direction and end/movement.
  3. Verify the flap stops at position 0.
  4. Check for overshoot.
- **Expected Results:**
  - Motor turns flap to position 0.
  - Motor stops at or within specified tolerance.
  - No overshoot.
- **Pass/Fail Criteria:** All actions and final position match expected behavior.


#### SYS-TC-003: Command Flap to Position 5
- **Mapped System Requirement ID(s):** SYS-REQ-001, SYS-REQ-003, SYS-REQ-005, SYS-REQ-006
- **Test Objective:** Validate correct movement to highest flap position upon command.
- **Preconditions:** System powered, flap in mid-range or other position.
- **Test Inputs:** UART command for position 5.
- **Test Steps:**
  1. Send position 5 command.
  2. Observe motor and end position.
  3. Verify the flap stops at position 5.
- **Expected Results:**
  - Motor reaches position 5 without overshoot.
- **Pass/Fail Criteria:** Flap reaches and holds position 5 accurately, no overshoot.


#### SYS-TC-004: Command to Intermediate Positions (1–4)
- **Mapped System Requirement ID(s):** SYS-REQ-001, SYS-REQ-002, SYS-REQ-003
- **Test Objective:** Validate motor brings flap to any supported intermediate position as commanded.
- **Preconditions:** System in a known state.
- **Test Inputs:** UART commands for positions 1, 2, 3, and 4, separately.
- **Test Steps:**
  1. Send each command and observe.
  2. Confirm accurate movement, direction, and no overshoot.
- **Expected Results:**
  - Flap moves and stops at each given position reliably.
- **Pass/Fail Criteria:** No errors at any step; motor acts per command with correct feedback.


#### SYS-TC-005: Multiple Valid Position Sequences
- **Mapped System Requirement ID(s):** SYS-REQ-002, SYS-REQ-003
- **Test Objective:** Validate system ability to execute multiple position changes reliably.
- **Preconditions:** System initialized and idle.
- **Test Inputs:** Sequence of position commands (e.g., 1 → 3 → 5 → 0).
- **Test Steps:**
  1. Send position commands in sequence.
  2. For each, observe actuation and feedback.
- **Expected Results:**
  - Correct movement, direction, stop, and feedback each time.
- **Pass/Fail Criteria:** All requested positions reached in turn, no error, each time.


### 3.3 Invalid & Boundary Conditions

#### SYS-TC-006: Command Out-of-Range Position
- **Mapped System Requirement ID(s):** SYS-REQ-004, SYS-REQ-020
- **Test Objective:** Verify system rejects and signals commands outside allowed position range.
- **Preconditions:** System operational.
- **Test Inputs:** UART command for positions below 0 or above 5.
- **Test Steps:**
  1. Send invalid position command.
  2. Observe system response.
- **Expected Results:**
  - Command is rejected, error indication or status provided, no movement.
- **Pass/Fail Criteria:** No movement, invalid input is detected/reported.

#### SYS-TC-007: Invalid UART Input
- **Mapped System Requirement ID(s):** SYS-REQ-013
- **Test Objective:** Validate handling/reporting of malformed or nonsensical UART data.
- **Preconditions:** System active, UART connected.
- **Test Inputs:** Nonsensical/invalid UART bytes or sequences.
- **Test Steps:**
  1. Send invalid/malformed UART data.
  2. Monitor error handling.
- **Expected Results:**
  - System does not act on invalid data and indicates error per requirements.
- **Pass/Fail Criteria:** No actuation, error status correctly signaled.

#### SYS-TC-008: ADC Out-of-Range Values
- **Mapped System Requirement ID(s):** SYS-REQ-009, SYS-REQ-010
- **Test Objective:** Validate detection/handling of out-of-range sensor feedback.
- **Preconditions:** System initialized, able to inject/test ADC conditions.
- **Test Inputs:** Simulated ADC out-of-range (HW or SW fault injection).
- **Test Steps:**
  1. Force ADC beyond valid range.
  2. Observe response.
- **Expected Results:**
  - System recognizes sensor fault/error.
  - Error indication/status given.
- **Pass/Fail Criteria:** Fault detected and signaled, no unsafe actuation.

#### SYS-TC-009: Command During Flap Movement
- **Mapped System Requirement ID(s):** SYS-REQ-020
- **Test Objective:** Ensure the system handles new/overlapping commands while the flap is in motion in a safe and robust manner.
- **Preconditions:** Flap moving following a previous command.
- **Test Inputs:** A second command (before the first concludes).
- **Test Steps:**
  1. Issue a new valid command while still moving.
  2. Observe/verify handling of overlapping input.
- **Expected Results:**
  - Overlapping or conflicting commands are safely rejected or queued per requirements; no erratic/flaky behavior.
- **Pass/Fail Criteria:** No system reset or lock-up; stable, correct operation.


### 3.4 Position Feedback & Monitoring

#### SYS-TC-010: Correct Feedback Under Motion
- **Mapped System Requirement ID(s):** SYS-REQ-008, SYS-REQ-009
- **Test Objective:** Confirm position feedback correctly follows actuator movement under normal conditions.
- **Preconditions:** System actively operating.
- **Test Inputs:** Commands for position moves (0, 5, mid-range).
- **Test Steps:**
  1. Issue move commands.
  2. Monitor position feedback (ADC readings).
- **Expected Results:**
  - Sensor feedback reflects actual position, ADC-to-position mapping correct throughout movement.
- **Pass/Fail Criteria:** Feedback remains correct; no mismatch observed.

### 3.5 Motor Control Behavior
#### SYS-TC-011: Start/Stop/Direction Logic
- **Mapped System Requirement ID(s):** SYS-REQ-005, SYS-REQ-006, SYS-REQ-007
- **Test Objective:** Validate motor starts, stops, and reverses as required, never moves unintentionally.
- **Preconditions:** System powered; commands available.
- **Test Inputs:** Normal and reverse commands; idle time monitoring.
- **Test Steps:**
  1. Issue normal and reverse movement commands.
  2. Observe motor start/stop, direction correctness, and idle behavior.
- **Expected Results:**
  - Motor operates only as commanded, correct direction; stops when target reached; no unwanted movements.
- **Pass/Fail Criteria:** All expected behavior verified; no dangerous/unintended action at any time.

### 3.6 LED Status Indication
#### SYS-TC-012: Power/Position LED Behavior
- **Mapped System Requirement ID(s):** SYS-REQ-014, SYS-REQ-015
- **Test Objective:** Verify Power/Position LEDs reflect system status and errors appropriately.
- **Preconditions:** System operational, LEDs connected.
- **Test Inputs:** Normal operation, error events.
- **Test Steps:**
  1. Cycle normal operation, inject error events.
  2. Observe LED response/status.
- **Expected Results:**
  - LEDs indicate power-on, current position, and errors/faults per requirements.
- **Pass/Fail Criteria:** LED indications match each mode/scenario.

### 3.7 End-to-End Behavior
#### SYS-TC-013: Full User Command Path
- **Mapped System Requirement ID(s):** SYS-REQ-001, SYS-REQ-008, SYS-REQ-014, SYS-REQ-021
- **Test Objective:** Validate the complete user command → motor action → feedback → LED update path, end-to-end.
- **Preconditions:** System powered, all interfaces connected.
- **Test Inputs:** UART commands for all supported positions (0–5).
- **Test Steps:**
  1. Send commands for various positions.
  2. Observe motor, feedback, and status LEDs throughout.
- **Expected Results:**
  - Every element in the command path works and is observable; feedback and LEDs match physical position.
- **Pass/Fail Criteria:** All stages covered, errors observed and signaled in realistic scenarios.


### 3.8 System Robustness (Stability, Power, and Error Handling)
#### SYS-TC-014: Power Interruption and Restart
- **Mapped System Requirement ID(s):** SYS-REQ-025, SYS-REQ-026, SYS-REQ-027
- **Test Objective:** Confirm resilience to short power interruptions and correct restart behavior.
- **Preconditions:** System running, movements underway.
- **Test Inputs:** Simulated power-off/power-on events.
- **Test Steps:**
  1. With actuator operating, remove then restore power quickly.
  2. Observe system behavior on restart.
- **Expected Results:**
  - System resumes safe/last-known state with stable outputs; no undefined operation or reset loop.
- **Pass/Fail Criteria:** Robust recovery, no loss of function/state, no errors.
