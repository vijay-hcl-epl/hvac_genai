# HVAC Flap Actuator System Qualification Test Specification (ASPICE SYS.5)

## 1. Introduction
This document specifies the System Qualification Test Specification (SYS.5) for the HVAC flap actuator system. The objective is to systematically verify the end-to-end behavior of the integrated system according to system-level requirements retrieved from IBM DOORS Next.

## 2. Test Scope
System qualification testing covers the complete HVAC flap actuator functionality as experienced at the system boundary, including user command input via UART, motor activation, flap position feedback via potentiometer/ADC, and feedback via status LEDs. Testing is performed on the hardware bench setup, observing only external interfaces. There is no inspection or instrumentation of the internal software; the focus is on observable system effects of system-level requirements.

## 3. System Requirement Traceability

| System Requirement ID    | Requirement Text |
|-------------------------|-----------------|
| SYS-REQ-001             | The system SHALL provide defined electrical interfaces for all expected input and output signals as per system-level signal lists. |

## 4. Test Environment Description
- Hardware: Bench setup including STM32 MCU, DC motor, potentiometer, L298N driver, status LEDs, UART interface
- Software: HVAC actuator firmware
- External PC or script to send UART commands
- Manual or automated (script-based) observation of motor and LED behavior

## 5. System Test Cases

### 5.1 Power-Up and Initialization
- **Test Case ID:** TC-001
- **Mapped System Requirement ID:** SYS-REQ-001
- **Objective:** Verify system initializes all electrical interfaces and enters a known safe state.
- **Preconditions:** System powered OFF
- **Test Inputs:** Power ON
- **Test Steps:**
   1. Power ON system
   2. Observe status LED, motor state, and position LED outputs
- **Expected Results:**
   - Status LED turns ON
   - Motor remains OFF
   - Position LEDs reflect initial detected position
- **Pass/Fail Criteria:** All conditions above are met

### 5.2 Valid Flap Position Commands
- **Test Case ID:** TC-002
- **Mapped System Requirement ID:** SYS-REQ-001
- **Objective:** Verify system moves flap to each defined position (0 to 5) on valid UART command
- **Preconditions:** System powered ON and initialized; Motor idle
- **Test Inputs:** UART commands: 0, 1, 2, 3, 4, 5 (sent individually)
- **Test Steps:**
   1. Send valid command (e.g., "3")
   2. Observe motor movement and position LED
   3. Repeat for all positions (0 to 5)
- **Expected Results:**
   - Motor moves flap to commanded position
   - Motor stops when position reached
   - Only correct position LED is ON
- **Pass/Fail Criteria:** Each command yields expected flap position, motor behavior, and correct LED indication

### 5.3 Boundary Position Command (Lowest/Highest)
- **Test Case ID:** TC-003
- **Mapped System Requirement ID:** SYS-REQ-001
- **Objective:** Verify system response to lowest (0) and highest (5) valid commands
- **Preconditions:** System ready
- **Test Inputs:** UART commands: 0 and 5
- **Test Steps:**
   1. Send "0" then "5"
   2. Observe motion and position LED
- **Expected Results:**
   - Flap moves to boundary positions correctly
   - Motor stops at boundary
- **Pass/Fail Criteria:** Flap reaches and holds at each boundary; system maintains correct indication

### 5.4 Invalid UART Command (Out-of-Range)
- **Test Case ID:** TC-004
- **Mapped System Requirement ID:** SYS-REQ-001
- **Objective:** Verify system ignores out-of-range UART commands
- **Preconditions:** System ready
- **Test Inputs:** UART command: 6, -1
- **Test Steps:**
   1. Send invalid value (e.g., "6", "-1")
   2. Observe motor and LED
- **Expected Results:**
   - No movement or change in state
   - No error indication required
- **Pass/Fail Criteria:** System ignores invalid commands without changing state

### 5.5 Invalid Command Format
- **Test Case ID:** TC-005
- **Mapped System Requirement ID:** SYS-REQ-001
- **Objective:** Ensure system ignores malformed UART input
- **Preconditions:** System ready
- **Test Inputs:** UART strings: "abc", "", "@!#"
- **Test Steps:**
   1. Send malformed command
   2. Observe system
- **Expected Results:** No change in system behavior
- **Pass/Fail Criteria:** System ignores malformed inputs

### 5.6 Sensor Range Error Handling
- **Test Case ID:** TC-006
- **Mapped System Requirement ID:** SYS-REQ-001
- **Objective:** Verify that system responds safely if potentiometer/ADC reading is outside expected range
- **Preconditions:** System ready
- **Test Inputs:** Simulate faulty (out-of-range) potentiometer value
- **Test Steps:**
   1. Inject/analyze ADC value out of expected bounds
   2. Observe system
- **Expected Results:**
   - Motor immediately stops
   - System enters safe state, does not crash
- **Pass/Fail Criteria:** System handles input safely, keeps motor off

### 5.7 Command During Movement
- **Test Case ID:** TC-007
- **Mapped System Requirement ID:** SYS-REQ-001
- **Objective:** Verify that system continues to handle valid/invalid commands while in transition
- **Preconditions:** Flap in motion (executing previous command)
- **Test Inputs:** UART command during movement
- **Test Steps:**
   1. Command flap to one extreme
   2. Before motion completes, send new command
   3. Observe behavior
- **Expected Results:** Most recent valid command accepted/processed; invalid ignored; no unsafe state
- **Pass/Fail Criteria:** System manages command queueing/prioritization safely

### 5.8 Robustness: No Unexpected Reset
- **Test Case ID:** TC-008
- **Mapped System Requirement ID:** SYS-REQ-001
- **Objective:** Ensure system does not reset, crash, or enter undefined state during normal or fault conditions
- **Preconditions:** System steady-state or under stress
- **Test Inputs:** Execution of all above test scenarios
- **Test Steps:**
   1. Execute all test cases in sequence
   2. Monitor system for resets/undefined states
- **Expected Results:**
   - No unexpected system reset or undefined state observed
- **Pass/Fail Criteria:** System remains operational

## 7. Pass/Fail Evaluation Criteria
- Each test case has documented expected results and binary Pass/Fail based on full criteria satisfaction.
- System passes qualification if all test cases pass without deviation.
