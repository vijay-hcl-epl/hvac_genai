SYSTEM QUALIFICATION TEST SPECIFICATION (ASPICE SYS.5)
HVAC Flap Actuator
=================================================================

1. INTRODUCTION
---------------
This document defines the ASPICE SYS.5 System Qualification Test Specification for the HVAC flap actuator system. The test cases are derived exclusively from formal System Requirements maintained in IBM DOORS Next (Project Area: thillaiv Project (Requirements Management)).

2. TEST SCOPE
---------------
System qualification testing focuses on the fully integrated HVAC flap actuator system, executed on a hardware bench with observations through system interfaces only. The testing does not inspect internal software or perform unit-level checks; it validates end-to-end behavioral correctness, robustness, and traceability to system requirements.

Interfaces covered:
 - UART (user commands)
 - Motor driver outputs
 - ADC (flap position feedback)
 - LED status outputs

Assumptions:
 - Tests run on prototype hardware
 - Observation via serial terminal and physical outputs
 - No real-time vehicle integration (CAN/LIN) is present

3. SYSTEM REQUIREMENT TRACEABILITY
----------------------------------
SYS-REQ-001: The system SHALL provide defined electrical interfaces for all expected input and output signals as per system-level signal lists.

4. TEST ENVIRONMENT
-------------------
 - Hardware: STM32F407G-DISC1, L298N Motor Driver, Rotary Potentiometer, LEDs
 - Communication: USB-to-UART interface (for PC commands)
 - Observation: Visual on LEDs, Serial command logs, Motor/flap movement
 - Power supply: Lab DC supply (12V/5V rails)

5. SYSTEM TEST CASES
--------------------
[Each test case traces to SYS-REQ-001 above.]

TC-01: System Power-Up Initialization
-------------------------------------
- Requirement: SYS-REQ-001
- Objective: Verify correct initialization of all electrical interfaces and system state at power-up.
- Preconditions: System powered off
- Test Inputs: Power on system
- Steps:
   1. Apply power to the system.
   2. Observe power/status LED.
   3. Check motor state (should be OFF).
   4. Inspect UART output for startup banner (if implemented).
   5. Observe that green LEDs reflect current flap position.
- Expected Results:
   - Status LED = ON.
   - Flap does not move unexpectedly.
   - System is idle and ready for command.
- Pass/Fail: All checkpoints above must pass.

TC-02: Valid Flap Position Command: Position 0
----------------------------------------------
- Requirement: SYS-REQ-001
- Objective: Verify system moves flap to Position 0 and indicates status.
- Preconditions: System powered and idle
- Test Inputs: UART command "0"
- Steps:
   1. Send command "0" from PC terminal.
   2. Observe motor moves flap to position 0.
   3. Observe green LED for position 0 lights up.
   4. Confirm motor stops after reaching position.
- Expected Results:
   - Flap moves to and holds position 0.
   - Only position 0 LED is ON.
   - Motor OFF upon position reached.
- Pass/Fail: All checkpoints must pass.

[Repeat above for positions 1–5: TC-03 through TC-07, same format, using UART commands from 1–5]

TC-08: Boundary Condition: Invalid UART Command (Out of Range)
-------------------------------------------------------------
- Requirement: SYS-REQ-001
- Objective: System handles command outside valid range (example: "7") safely.
- Preconditions: System powered
- Test Inputs: UART command "7"
- Steps:
   1. Send command "7".
   2. Observe system behavior.
- Expected Results:
   - Flap does not move.
   - No change in LEDs.
   - Motor remains OFF.
- Pass/Fail: System ignores input; no incorrect actuation or indication.

TC-09: Boundary Condition: Invalid Command Format
------------------------------------------------
- Requirement: SYS-REQ-001
- Objective: System safely ignores non-numeric or malformed UART input.
- Preconditions: System powered
- Test Inputs: UART command "A"
- Steps:
   1. Send command "A".
   2. Observe system behavior.
- Expected Results:
   - No actuation; no state change; no error crash.
- Pass/Fail: System ignores malformed input safely.

TC-10: Sensor Feedback Validation
--------------------------------
- Requirement: SYS-REQ-001
- Objective: Confirm ADC feedback matches actual flap position throughout movements.
- Preconditions: System powered, functional sensor
- Test Inputs: UART command "2", then observe
- Steps:
   1. Move flap through all positions.
   2. Monitor reported ADC/logical position.
- Expected Results:
   - ADC values are within expected ranges for all requested positions.
   - LEDs correspond with measured position.
- Pass/Fail: Sensor mapping and outputs consistent with requirements.

TC-11: Motor Stops Correctly at Target
--------------------------------------
- Requirement: SYS-REQ-001
- Objective: Verify that once the flap reaches the commanded position, the motor turns OFF and system holds the position.
- Preconditions: System in motion
- Test Inputs: Any valid position command
- Steps:
   1. Command flap to any position.
   2. Observe if motor stops on position reached.
- Expected Results:
   - No overshoot, no continued run.
- Pass/Fail: Motor reliably stops at each commanded position.

TC-12: Status Indication Behavior
--------------------------------
- Requirement: SYS-REQ-001
- Objective: Verify that only the correct position LED is ON at any point.
- Preconditions: System powered
- Test Inputs: Series of valid UART commands (0–5)
- Steps:
   1. Command system through all positions.
   2. Observe LEDs.
- Expected Results:
   - At most one position LED ON per command.
- Pass/Fail: Status indication is unambiguous and correct.

TC-13: System Robustness – Command During Movement
--------------------------------------------------
- Requirement: SYS-REQ-001
- Objective: Issue a new command while flap is in motion; system must respond acceptably and never enter an undefined state.
- Preconditions: System moving to a previous position
- Test Inputs: UART command "3", then during movement send "1"
- Steps:
   1. Send sequential commands as described
   2. Observe transition and system state
- Expected Results:
   - System either finishes prior or switches reliably, but never locks or resets.
- Pass/Fail: No crash/lockup; response as per system spec.

7. PASS/FAIL EVALUATION CRITERIA
--------------------------------
Each test case is passed if all defined expected results are achieved without deviation. Any failure to meet a pass criterion—such as incorrect actuation, unsafe handling of invalid commands, incorrect LED indication, or system instability—constitutes a test failure and shall be flagged for investigation and corrective action.
