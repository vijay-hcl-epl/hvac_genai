1.0 System Overview
-------------------
The HVAC Flap Actuator System is a microcontroller-based embedded system designed to position an air distribution flap for a vehicle HVAC prototype. The user sends target positions over UART, and the microcontroller drives a DC motor to move the flap to the commanded discrete position. Position is sensed via a potentiometer (ADC acquisition). Status and position are indicated via LEDs. Safety and correctness are prioritized through simple input validation and feedback.

2.0 Flap Position Control
-------------------------
SYS-REQ-001: The system SHALL allow selection of discrete flap positions (minimum 6 positions: 0-5, fully closed to fully open) as specified by user commands via UART.
SYS-REQ-002: The system SHALL move the flap to the commanded position as soon as possible and stop the motor when the position is reached.
SYS-REQ-003: The system SHALL ignore commands for unsupported positions.
[Implied] SYS-REQ-004: The system SHALL ensure that at most one position command is processed at a time.

3.0 Motor Control
------------------
SYS-REQ-005: The system SHALL provide control signals for clockwise/anti-clockwise motor rotation to reach the target position.
SYS-REQ-006: The system SHALL stop the motor immediately after the required position is attained.
SYS-REQ-007: The system SHALL keep the motor off after system power-up or reset unless a move is required.
[Implied] SYS-REQ-008: The system SHALL set/clear motor enable signals via GPIO/PWM as appropriate.

4.0 Position Feedback Acquisition & Processing
----------------------------------------------
SYS-REQ-009: The system SHALL use a potentiometer connected to an ADC input to continuously monitor current flap position.
SYS-REQ-010: The system SHALL map ADC readings to at least 6 discrete logical positions as per defined calibration.
SYS-REQ-011: The system SHALL treat ADC readings outside valid calibrated ranges as invalid and stop the motor.
[Implied] SYS-REQ-012: The system SHALL update the known position at a rate sufficient to enable responsive control.

5.0 User Command Interface
---------------------------
SYS-REQ-013: The system SHALL accept user commands for flap position via UART as single octet numerical values (0–5).
SYS-REQ-014: The system SHALL ignore invalid or malformed commands, taking no further action.
SYS-REQ-015: The system SHALL NOT send acknowledgments or errors for invalid commands.
[Implied] SYS-REQ-016: The system SHALL NOT process new commands while the flap is still moving to the prior target.

6.0 Status Indication
----------------------
SYS-REQ-017: The system SHALL turn on a dedicated LED to indicate system power-on status.
SYS-REQ-018: The system SHALL indicate current flap position by illuminating exactly one green LED at a time for the active position.
SYS-REQ-019: The system SHALL update LEDs promptly in response to flap movement or initialization.
[Implied] SYS-REQ-020: The system SHALL keep status LEDs simple, with no blinking/fading animations.

7.0 System Behavior (Power-up, Idle, Moving, Target Reached, Invalid Input)
----------------------
SYS-REQ-021: On power-up, the system SHALL initialize all required peripherals and determine current flap position from ADC input.
SYS-REQ-022: The system SHALL keep the motor off at startup and only actuate in response to a new user command.
SYS-REQ-023: The system SHALL handle invalid UART commands/data by ignoring them with no impact on current operation.
SYS-REQ-024: The system SHALL safely stop the motor if flap position cannot be determined (ADC out of range).
[Implied] SYS-REQ-025: The system SHALL respond to flap position requests as soon as reasonable after a command is received.

8.0 Interfaces (UART, Motor Driver, ADC, LEDs)
------------------
SYS-REQ-026: The system SHALL use UART (serial) as the sole user command input interface.
SYS-REQ-027: The system SHALL use GPIO/PWM pins for motor driver control as per hardware requirements.
SYS-REQ-028: The system SHALL use an ADC channel for flap position sensing via potentiometer input.
SYS-REQ-029: The system SHALL use GPIO for individual green LEDs to indicate the flap position, and a dedicated (any color) for system ON.
[Implied] SYS-REQ-030: The system SHALL NOT communicate with any external networks (CAN, LIN, Ethernet, etc.).

9.0 Constraints & Assumptions
-----------------------------
SYS-REQ-031: The system SHALL only control one actuator flap and one DC motor.
SYS-REQ-032: All ADC-to-position calibration is fixed in software and does not require dynamic calibration at runtime.
SYS-REQ-033: Hardware is presumed functional and no production-level fault diagnostics are required.
[Implied] SYS-REQ-034: Only one command may be processed at a time; queued/multiple command support is not required.

10.0 Non-Functional Requirements
-------------------------------
10.1 Responsiveness
SYS-REQ-035: The system SHALL respond to user position commands within a human-perceivable short time (e.g., within a second).

10.2 Error Handling & Edge Cases
SYS-REQ-036: The system SHALL stop the motor and indicate a safe state if flap position acquisition fails (e.g., ADC out of range).
SYS-REQ-037: The system SHALL ignore invalid UART commands without disrupting normal operation.

10.3 Resource Constraints
SYS-REQ-038: The system SHALL operate on available STM32F407 resources using STM32 HAL and avoid dynamic memory allocation at runtime.

10.4 Maintainability & Modularity
SYS-REQ-039: The system SHALL organize source code so that hardware abstraction, logic, and interfaces are separated for maintainability.

10.5 Testability
SYS-REQ-040: The system SHALL be testable via manual/scripted UART command injection and by observing motor action and LED outputs.
[Implied] SYS-REQ-041: The system SHALL NOT require HIL, SIL, or automated benches for test.

-----------------------------
Architecture-Relevant Considerations Derived from System Requirements
-----------------------------
Concurrency Presence/Absence:
The requirements do not mandate concurrent or parallel operations. All inputs, processing, and actions are strictly sequential per user command.

Interaction Complexity:
The interface and control flows are strictly unidirectional: command in, action, feedback out, with minimal cross-dependency or multi-channel interaction.

Control Complexity:
Control complexity remains low: single actuator, discrete states, no dynamic scheduling, and all behavior event-driven from UART user requests.

Expandability:
Requirements focus on single actuator and fixed logic only. Any expansion (multiple flaps, dynamic configuration, richer feedback) would require new system-level requirements and interface changes.
