1.0 System Overview 

The HVAC Flap Actuator System is a microcontroller-based prototype designed to move an air-control flap to discrete positions as commanded by a user through UART. The system controls a DC motor, acquires position feedback via a potentiometer using an ADC, and reports its status through LEDs.

2.0 Flap Position Control

SYS-REQ-001: The system SHALL allow the user to command the flap to any supported discrete position via UART.
SYS-REQ-002: The system SHALL move the flap only to the commanded positions defined in the requirements.
SYS-REQ-003: The system SHALL stop the motor upon reaching the target position.
SYS-REQ-004: The system SHALL ignore commands outside the supported position range. [Implied]

3.0 Motor Control

SYS-REQ-005: The system SHALL drive the DC motor in both clockwise and anti-clockwise directions as required to reach the target flap position.
SYS-REQ-006: The system SHALL control motor operation using GPIO and PWM signals.
SYS-REQ-007: The system SHALL ensure the motor is off when not actively moving the flap.

4.0 Position Feedback Acquisition & Processing

SYS-REQ-008: The system SHALL acquire position feedback using an ADC connected to the potentiometer.
SYS-REQ-009: The system SHALL map ADC values to logical flap positions (e.g., 0–5) according to defined software ranges.
SYS-REQ-010: The system SHALL continuously monitor actual flap position while powered on.
SYS-REQ-011: The system SHALL stop the motor if the ADC value is out of valid range. [Implied]

5.0 User Command Interface

SYS-REQ-012: The system SHALL receive user target position commands via UART as single numeric values.
SYS-REQ-013: The system SHALL ignore invalid or malformed UART commands. [Implied]

6.0 Status Indication

SYS-REQ-014: The system SHALL use one LED to indicate power status.
SYS-REQ-015: The system SHALL indicate the current flap position using up to one green LED at a time.
SYS-REQ-016: The system SHALL update the green LED indication upon position changes.

7.0 System Behavior (power-up, idle, normal, target reached, invalid input)

SYS-REQ-017: On power-up, the system SHALL initialize all required peripherals (ADC, UART, GPIO, PWM).
SYS-REQ-018: On power-up, the system SHALL ensure the motor is off.
SYS-REQ-019: On power-up, the system SHALL sample the current flap position from the potentiometer.
SYS-REQ-020: The system SHALL remain idle, with no actuator motion, until a valid user command is received.
SYS-REQ-021: Upon receiving an invalid command, the system SHALL maintain its previous state and take no action.

8.0 Interfaces (UART, motor driver, ADC, LEDs)

SYS-REQ-022: The system SHALL use UART for receiving position commands from a connected PC.
SYS-REQ-023: The system SHALL use ADC to measure potentiometer feedback for position acquisition.
SYS-REQ-024: The system SHALL use GPIO and PWM to command the motor driver.
SYS-REQ-025: The system SHALL use GPIO pins to control the power and position LEDs.

9.0 Constraints & Assumptions

SYS-REQ-026: The system SHALL operate a single flap using a single motor and a single potentiometer.
SYS-REQ-027: The system SHALL not communicate on any vehicle network such as CAN or LIN. [Implied]
SYS-REQ-028: The system SHALL assume hardware is functional and calibrated. [Implied]
SYS-REQ-029: User commands are non-concurrent and processed sequentially. [Implied]

10.0 Non-Functional Requirements
10.1 Responsiveness
SYS-REQ-030: The system SHALL process valid UART commands promptly with human-perceivable responsiveness.
10.2 Error Handling & Edge Cases
SYS-REQ-031: The system SHALL stop the motor if position feedback cannot be reliably acquired or mapped. [Implied]
SYS-REQ-032: The system SHALL ignore errors in UART communication or ADC measurement, provided safety is not compromised.
10.3 Resource Constraints
SYS-REQ-033: The system SHALL not require dynamic memory allocation at runtime.
10.4 Maintainability & Modularity
SYS-REQ-034: The system SHALL modularize functionality such that command handling, position monitoring, and indication may be independently tested. [Implied]
10.5 Testability
SYS-REQ-035: The system SHALL be testable via UART commands, LED feedback, and motor movement observable by a human or script. [Implied]

Architecture-Relevant Considerations Derived from System Requirements

Concurrency: Minimal concurrency is required, as only one command is processed at a time and no parallel motor actions occur. Data acquisition and actuation may be realized sequentially.
Interaction Complexity: Interaction is simple; input (UART) maps to motor actuation and LED output, with feedback acquired via ADC. No bidirectional or network communication is present.
Control Complexity: Position mapping, discrete position support, motor control, and error handling are straightforward; no hierarchical or distributed control.
Expandability: The architecture is easily expandable to more flap positions or additional interface types (e.g., CAN) with clear requirements separation, provided atomicity and safety are maintained.
