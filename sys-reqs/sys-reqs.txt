1.0 System Overview
------------------
The HVAC flap actuator system is designed to control the position of a single air flap in a vehicle's HVAC (Heating, Ventilation, and Air Conditioning) subsystem. The position is actuated by a DC motor, measured by a potentiometer, and commanded by a user from a PC via UART. The system provides visual feedback via LEDs on a microcontroller board. No networking or advanced diagnostics are included. This is a prototype and not a production-grade system.

2.0 Flap Position Control
-------------------------
SYS-REQ-001: The system SHALL move the HVAC flap to the user-commanded discrete position (0–5) upon receiving a valid command over UART.
SYS-REQ-002: The system SHALL keep the HVAC flap stationary when no new valid command is received.
SYS-REQ-003: The system SHALL maintain the flap position within its corresponding ADC range for the commanded position.
SYS-REQ-004: [Implied] The system SHALL not overshoot or oscillate between positions during normal operation.

3.0 Motor Control
-----------------
SYS-REQ-005: The system SHALL control the motor to rotate clockwise or anti-clockwise in order to reach the target flap position.
SYS-REQ-006: The system SHALL stop the motor once the measured flap position matches the target position.
SYS-REQ-007: [Implied] The motor SHALL be turned OFF during system initialization and whenever an invalid command, invalid input, or ADC out-of-range condition occurs.

4.0 Position Feedback Acquisition & Processing
---------------------------------------------
SYS-REQ-008: The system SHALL acquire the flap position via an analog potentiometer connected to an ADC channel.
SYS-REQ-009: The system SHALL map acquired ADC values to the logical flap positions (0–5) according to fixed, defined ranges.
SYS-REQ-010: If the ADC value is outside all defined ranges, the system SHALL stop the motor and not attempt to move it until the value is valid.

5.0 User Command Interface
-------------------------
SYS-REQ-011: The system SHALL receive flap target position commands via UART as simple numeric values (0–5).
SYS-REQ-012: Any received UART command outside the range 0–5 SHALL be ignored, and the system SHALL NOT respond or acknowledge it.
SYS-REQ-013: [Implied] The system SHALL process only one user command at a time.

6.0 Status Indication
---------------------
SYS-REQ-014: The system SHALL illuminate a dedicated LED to indicate when system power is ON.
SYS-REQ-015: The system SHALL illuminate, at any time, at most one green LED corresponding to the current logical flap position (0–5).
SYS-REQ-016: [Implied] The status indication SHALL be updated promptly to reflect the current flap position.

7.0 System Behavior
-------------------
SYS-REQ-017: On power-up, the system SHALL initialize peripherals (ADC, UART, GPIO, PWM) and ensure the motor is OFF.
SYS-REQ-018: On power-up, the system SHALL read the potentiometer to determine the initial flap position and set the appropriate position LED.
SYS-REQ-019: In idle state, the system SHALL wait for valid user input via UART.
SYS-REQ-020: Upon a valid movement command, the system SHALL move the flap and stop the motor when the target position is reached.
SYS-REQ-021: If an invalid command is received, the system SHALL ignore it and SHALL NOT change state or indicate an error.
SYS-REQ-022: [Implied] During motor movement toward a target, the system SHALL continue to monitor the ADC for position feedback.

8.0 Interfaces
--------------
SYS-REQ-023: The system SHALL use UART for receiving user position commands.
SYS-REQ-024: The system SHALL use an ADC channel for flap position feedback.
SYS-REQ-025: The system SHALL use GPIO pins to drive the motor and LED.
SYS-REQ-026: The system SHALL use PWM, if available, for motor enable and speed control.
SYS-REQ-027: [Implied] The system SHALL NOT implement communication over CAN, LIN, or other vehicle networks.

9.0 Constraints & Assumptions
------------------------------
SYS-REQ-028: The system SHALL assume a fixed calibration between potentiometer ADC values and flap positions as defined in software.
SYS-REQ-029: Only one HVAC flap and one user command stream SHALL be supported.
SYS-REQ-030: [Implied] The system SHALL assume hardware is functioning correctly during normal operation.

10.0 Non-Functional Requirements
-------------------------------
10.1 Responsiveness
SYS-REQ-031: The system SHALL process received UART commands and update the flap position promptly enough to feel responsive to a human user.

10.2 Error Handling & Edge Cases
SYS-REQ-032: If the ADC position feedback is not within any valid range, the system SHALL stop the motor and hold its last position until a valid input is available.
SYS-REQ-033: The system SHALL NOT crash or hang if the motor fails to reach the command target position.

10.3 Resource Constraints
SYS-REQ-034: The system SHALL operate without using dynamic memory allocation.
SYS-REQ-035: The system SHALL use only required resources on the STM32F407G-DISC1 hardware platform.

10.4 Maintainability & Modularity
SYS-REQ-036: The system SHALL structure functionality such that command handling, motor control, feedback acquisition, and status indication can be tested and maintained separately.

10.5 Testability
SYS-REQ-037: The system SHALL be testable by sending commands from a PC, observing motor position, and checking LED status.


Architecture-Relevant Considerations Derived from System Requirements
--------------------------------------------------------------------
- Concurrency: All interactions (command input, motor movement, feedback acquisition, status update) can be handled sequentially in simple prototyping; concurrency may only be required if true parallel handling is introduced in the future.
- Interaction complexity: System interactions are simple, driven by single commands, with direct feedback and indication; minimal cross-coupling or state management is present.
- Control complexity: Only direct movement to target, input-to-action processing, and safeties for out-of-range or invalid input are required. No advanced strategies or error recovery.
- Expandability: The modularity requirements permit future addition of network interfaces, multiple flap actuators, or advanced error diagnostics
[END OF REQUIREMENTS]
