1.0 System Overview
-------------------
The system is an HVAC air flap actuator prototype for a vehicle climate control application. It enables user-controlled airflow direction or mixing by rotating a flap to discrete positions. Positioning is achieved using a DC motor and feedback from a potentiometer, under microcontroller supervision. User input is received via UART commands from a PC connection. Visual status is provided via LEDs.

2.0 Flap Position Control
-------------------------
SYS-REQ-001: The system SHALL move the HVAC flap to the target position commanded by the user via UART.
SYS-REQ-002: The system SHALL support movement to at least six discrete flap positions, as defined by fixed ADC ranges.
SYS-REQ-003: The system SHALL ignore user commands for positions outside the valid range (e.g., out-of-range numeric values). [Implied]

3.0 Motor Control
-----------------
SYS-REQ-004: The system SHALL drive the DC motor in either direction to move the flap toward the target position.
SYS-REQ-005: The system SHALL stop the DC motor once the flap reaches the commanded position.
SYS-REQ-006: The system SHALL stop the DC motor if position feedback (ADC value) falls outside all valid ranges.

4.0 Position Feedback Acquisition & Processing
---------------------------------------------
SYS-REQ-007: The system SHALL acquire flap position using a potentiometer connected to an ADC input.
SYS-REQ-008: The system SHALL map the ADC value to the corresponding logical flap position according to preconfigured calibration values.
SYS-REQ-009: The system SHALL check and refresh the flap position feedback periodically during operation. [Implied]

5.0 User Command Interface
-------------------------
SYS-REQ-010: The system SHALL accept position commands from a PC via UART.
SYS-REQ-011: The system SHALL interpret only valid numeric commands within the supported range as new target positions.
SYS-REQ-012: The system SHALL ignore invalid or malformed commands; no error response SHALL be provided for such inputs.

6.0 Status Indication
---------------------
SYS-REQ-013: The system SHALL turn ON a dedicated LED to indicate system power-up and readiness.
SYS-REQ-014: The system SHALL indicate the current flap position using a set of green LEDs such that at most one position LED is ON at any time.
SYS-REQ-015: The system SHALL continuously update LED indications as positions change.

7.0 System Behavior
-------------------
SYS-REQ-016: On power-up, the system SHALL initialize all peripherals (ADC, UART, GPIO, PWM), ensure the motor is OFF, and display the current flap position and power status using LEDs.
SYS-REQ-017: When idle (waiting for user command), the system SHALL maintain its current state until new input is received. [Implied]
SYS-REQ-018: When moving toward a new position, the system SHALL actively control the motor until the target is reached or an out-of-range/invalid state occurs.
SYS-REQ-019: Upon detecting an invalid command or input, the system SHALL remain in the previous valid state without attempting further action.

8.0 Interfaces
--------------
SYS-REQ-020: The system SHALL utilize UART for receiving user position commands.
SYS-REQ-021: The system SHALL use the ADC to sample potentiometer feedback for position determination.
SYS-REQ-022: The system SHALL utilize GPIOs for motor driving logic and for LED indication output.
SYS-REQ-023: The system SHALL utilize PWM for motor enable/speed control. [Implied]

9.0 Constraints & Assumptions
-----------------------------
SYS-REQ-024: The system SHALL operate under the assumption of correct hardware connections for all interfaces (UART, ADC, motor driver, LEDs, potentiometer).
SYS-REQ-025: The system SHALL control only a single flap using one motor and one set of position LEDs. [Implied]
SYS-REQ-026: Only one command SHALL be processed at a time. [Implied]

10.0 Non-Functional Requirements
-------------------------------
10.1 Responsiveness
SYS-REQ-027: The system SHALL process UART commands and begin movement or feedback within a timeframe that feels responsive to a typical user (e.g., sub-second interaction time; no precise real-time constraint).

10.2 Error Handling & Edge Cases
SYS-REQ-028: The system SHALL stop the motor if the feedback ADC value becomes invalid or unrepresentative at any time.
SYS-REQ-029: The system SHALL remain safe and not crash if the flap does not reach the commanded position; no timeout or diagnostic action required. [Implied]

10.3 Resource Constraints
SYS-REQ-030: The system SHALL NOT utilize dynamic memory allocation at runtime. [Implied]
SYS-REQ-031: The system SHALL fit within the resource constraints of the target microcontroller (STM32F407G-DISC1).

10.4 Maintainability & Modularity
SYS-REQ-032: Design and requirement structure SHALL permit modular updates and clarity for future expansion. [Implied]

10.5 Testability
SYS-REQ-033: The system SHALL allow position command testing via UART, state observation via LEDs, and manual validation of motor response and flap position.

"Architecture-Relevant Considerations Derived from System Requirements"
---------------------------------------------------------------------
Concurrency Presence/Absence:
The system is mostly sequential; all actions are in response to user commands, feedback sampling, or system events. There is no explicit requirement for concurrent or real-time task execution.

Interaction Complexity:
Interactions remain simple: user (via UART), positional feedback (via ADC), motor/LED actuation (via GPIO/PWM). No cross-communications or networked protocols.

Control Complexity:
Control is state-driven (idle, moving, reached/holding, initialization), with straightforward transitions.

Expandability:
Requirements support future extension, such as more positions, fault logic, or alternate feedback, but no present complexity in task scheduling or interlocking.
