1.0 System Overview
The system is an HVAC flap actuator prototype for automotive use, designed to control the position of an air flap via a user interface. The system translates user commands into specific flap positions using a DC motor, with feedback provided by a potentiometer and visual status indicated by LEDs. 

2.0 Flap Position Control
SYS-REQ-001: The system SHALL control an air flap with discrete positions as specified by user input.
SYS-REQ-002: The system SHALL accept position commands in the range of 0 to 5, corresponding to defined flap positions.
SYS-REQ-003: The system SHALL stop the motor immediately once the requested position is reached.
SYS-REQ-004: The flap SHALL only move to positions within the supported range (0–5).
[Implied] SYS-REQ-005: The system SHALL ignore any command outside the valid range.

3.0 Motor Control
SYS-REQ-006: The system SHALL energize the DC motor in the required direction to move the flap to a new target position.
SYS-REQ-007: The system SHALL stop motor activity as soon as the flap is detected at the requested position.
SYS-REQ-008: The system SHALL only drive the DC motor for flap actuation; no other device shall be actuated by this output.

4.0 Position Feedback Acquisition & Processing
SYS-REQ-009: The system SHALL read analog position feedback from a potentiometer using an ADC channel.
SYS-REQ-010: The ADC reading SHALL be mapped to one of the six discrete logical positions (0 through 5).
SYS-REQ-011: The system SHALL continuously monitor the current flap position during operation.
SYS-REQ-012: The position mapping (ADC ranges to positions) SHALL be defined in software and statically configured.

5.0 User Command Interface
SYS-REQ-013: The system SHALL receive user position commands exclusively via a UART serial interface.
SYS-REQ-014: The system SHALL interpret received numeric commands 0–5 as target flap positions.
SYS-REQ-015: The system SHALL not generate acknowledgments or error messages for received UART commands.
SYS-REQ-016: Invalid UART commands SHALL be ignored and SHALL NOT cause system malfunction.

6.0 Status Indication
SYS-REQ-017: The system SHALL indicate "power ON" state with a dedicated LED.
SYS-REQ-018: The system SHALL use at most one green LED at a time to indicate the current flap position.
SYS-REQ-019: The LED corresponding to the current position SHALL be ON while others are OFF.

7.0 System Behavior (power-up, idle, normal, target reached, invalid input)
SYS-REQ-020: Upon power-up, the system SHALL initialize all peripherals (ADC, UART, GPIO, PWM) before accepting commands.
SYS-REQ-021: Upon power-up, the system SHALL ensure the motor is OFF.
SYS-REQ-022: Upon power-up, the system SHALL read the current flap position before operating the motor.
SYS-REQ-023: The system SHALL wait in an idle state for commands if no valid user command is received.
SYS-REQ-024: The system SHALL transition to target position when a valid command is received.
SYS-REQ-025: The system SHALL revert to idle once the target position is reached.
SYS-REQ-026: If an invalid command is received, the system SHALL remain in its current state without any activities.
[Implied] SYS-REQ-027: System states SHALL behave as logically described but need not be explicitly modeled.

8.0 Interfaces (UART, motor driver, ADC, LEDs)
SYS-REQ-028: The UART interface SHALL be used solely for receiving user position commands.
SYS-REQ-029: The motor driver interface (GPIO+PWM) SHALL be used exclusively for actuating the DC motor.
SYS-REQ-030: The ADC interface SHALL acquire analog signals from the potentiometer for flap position feedback.
SYS-REQ-031: GPIOs SHALL be used for controlling power/status and position LEDs.

9.0 Constraints & Assumptions
SYS-REQ-032: Only one flap and one actuator motor SHALL be present in the system.
SYS-REQ-033: Only one user command SHALL be handled at a time.
SYS-REQ-034: Hardware (motor driver, potentiometer, LEDs) is assumed to function correctly at all times.
SYS-REQ-035: Flap calibration ranges SHALL be static and fixed in software.
[Implied] SYS-REQ-036: The system SHALL NOT communicate with vehicle networks (CAN, LIN, etc.).

10.0 Non-Functional Requirements
10.1 Responsiveness
SYS-REQ-037: The system SHALL process UART commands within a short perceptible time for a human user.
10.2 Error Handling & Edge Cases
SYS-REQ-038: If ADC readings fall outside all defined position ranges, motor activity SHALL cease immediately and the system SHALL idle.
SYS-REQ-039: System SHALL not hang or crash if the motor fails to reach the requested position (no timeout required for prototype).
10.3 Resource Constraints
SYS-REQ-040: The system SHALL run within the resource limits of the STM32F407G-DISC1 platform.
10.4 Maintainability & Modularity
SYS-REQ-041: The requirements and functional structure SHALL allow software functions to be individually verified/tested.
10.5 Testability
SYS-REQ-042: The system SHALL allow testing of all functional requirements using UART commands, motor movement, and LEDs for feedback.

Architecture-Relevant Considerations Derived from System Requirements
- The system operates with low concurrency requirements: only one user command is handled at a time and only one actuator is moved.
- Interaction complexity is low: interfaces are UART, ADC, GPIO, and PWM.
- Control complexity is simple: user command triggers movement, feedback halts movement, and LEDs signal state.
- The system is readily expandable to more flap positions, more indicators, or additional diagnostics by refining requirements and extending I/O handling. No current requirement enforces such extensions.
