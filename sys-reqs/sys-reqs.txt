1.0 System Overview

The HVAC flap actuator system is designed as a prototype to demonstrate and validate embedded control processes. It enables user-controlled actuation of an air flap, common in automotive HVAC systems, by commanding a DC motor to rotate the flap between discrete, mapped positions. Position feedback is obtained via a potentiometer connected to an ADC, while a microcontroller coordinates the actions based on user input via UART. System states and flap position are indicated using LEDs. All system interactions are local; there is no vehicle network connectivity. The design emphasizes clarity, testability, and simplicity for learning and process demonstration purposes.

2.0 Flap Position Control Requirements

SYS-REQ-001: The system shall allow the user to select a target flap position via UART command input.
SYS-REQ-002: The system shall continuously compare the current flap position against the target position.
SYS-REQ-003: The system shall actuate the DC motor to move the flap toward the target position upon receiving a valid command.
SYS-REQ-004: The system shall stop the motor when the flap reaches the target position.
SYS-REQ-005: The system shall hold the flap in position once the target is reached.
SYS-REQ-006: The system shall support a fixed number of discrete flap positions, mapped from ADC ranges (e.g., 0 to 5 positions).
SYS-REQ-007: [Implied] The system shall define position boundaries in software using fixed ADC ranges.

3.0 Motor Control Requirements

SYS-REQ-008: The system shall control the motor direction using GPIO outputs to the motor driver.
SYS-REQ-009: The system shall enable or disable the motor via a dedicated enable signal (e.g., PWM or GPIO).
SYS-REQ-010: The motor shall stop automatically once the target flap position is detected.
SYS-REQ-011: The system shall be able to drive the motor clockwise or anti-clockwise to reach the requested flap position.
SYS-REQ-012: [Implied] The system shall prevent motor movement upon detection of invalid or out-of-range feedback values.

4.0 Position Feedback Acquisition and Processing

SYS-REQ-013: The flap position shall be measured using a potentiometer mechanically coupled to the flap.
SYS-REQ-014: The potentiometer output shall be acquired via an ADC channel of the microcontroller.
SYS-REQ-015: The system shall map the ADC readings to discrete logical flap positions.
SYS-REQ-016: The system shall periodically acquire position data to update the system state.
SYS-REQ-017: [Implied] The ADC range mapping shall be statically configured in software for each supported position.

5.0 User Command Interface Requirements

SYS-REQ-018: The system shall receive user commands as simple numeric values over UART.
SYS-REQ-019: Each received command value shall correspond to a supported flap position.
SYS-REQ-020: The system shall validate user commands for correctness and range.
SYS-REQ-021: On receipt of an invalid command, the system shall safely ignore the command and take no action or response.
SYS-REQ-022: [Implied] The system shall not transmit acknowledgment or error messages for invalid commands.

6.0 Status Indication Requirements

SYS-REQ-023: The system shall provide a visual indication of power-on/status using a dedicated LED.
SYS-REQ-024: The system shall indicate the current flap position through a distinct green LED for each possible position.
SYS-REQ-025: At most one green position LED shall be ON at any time, corresponding to the current flap position.
SYS-REQ-026: [Implied] LED indication shall be immediate and directly reflect the current detected system state.

7.0 System Behavioral Requirements

SYS-REQ-027: On power-up, the system shall initialize all necessary peripherals (ADC, UART, GPIO, PWM).
SYS-REQ-028: On power-up, the motor shall remain OFF until a valid target position command is received.
SYS-REQ-029: The system shall read flap position from the potentiometer during initialization and set initial LED indication accordingly.
SYS-REQ-030: While idle (awaiting command), the system shall maintain current flap position and status indication.
SYS-REQ-031: When moving the flap, the system shall update status indicators to reflect position changes.
SYS-REQ-032: Upon reaching the target position, the system shall stop the motor and update the LED indication.
SYS-REQ-033: Invalid input or conditions (e.g., illegal UART command, out-of-range ADC) shall be handled without resulting in system fault or crash.
SYS-REQ-034: [Implied] The system shall not require explicit user reset for recovery from invalid input.

8.0 System Interface Requirements

SYS-REQ-035: The system shall support UART as the input interface for user commands from a PC/laptop.
SYS-REQ-036: The system shall interface with a motor driver module to control a single DC motor.
SYS-REQ-037: The system shall acquire analog position feedback from the potentiometer through an ADC interface.
SYS-REQ-038: The system shall control LEDs for visual feedback using GPIO outputs.
SYS-REQ-039: [Implied] The motor enable and speed shall be controlled using a PWM-capable output or GPIO, as appropriate.

9.0 Constraints and Assumptions

SYS-REQ-040: Only one flap and one motor are used in the system.
SYS-REQ-041: Only one user command is processed at any time; concurrent user command handling is not required.
SYS-REQ-042: Hardware is assumed to operate correctly unless feedback is physically out of valid range.
SYS-REQ-043: No vehicle network integration (e.g., CAN, LIN) is required; all operations are local.
SYS-REQ-044: Dynamic calibration is not required; all configuration/calibration is fixed in software.
SYS-REQ-045: [Implied] System is designed primarily for learning and demonstration and may omit production diagnostics or safety features.

10.0 Non-Functional Requirements

10.1 Responsiveness Expectations
SYS-REQ-046: The system shall provide observable responsiveness to user input, such that commands are acted upon promptly in normal operating conditions.
SYS-REQ-047: No specific timing constraints are enforced unless explicitly stated elsewhere.

10.2 Error Handling and Edge Cases
SYS-REQ-048: The system shall safely ignore invalid UART commands.
SYS-REQ-049: If ADC feedback is out of range, the system shall stop the motor and indicate the state safely.
SYS-REQ-050: Unexpected but simple hardware or operating conditions shall not cause system crashes or require reset.

10.3 Resource Constraints
SYS-REQ-051: The system implementation shall be lightweight, using minimal embedded resources.
SYS-REQ-052: System behavior shall be predictable and bounded within normal operation.

10.4 Maintainability and Modularity
SYS-REQ-053: System software shall be organized to allow clear separation of functions (e.g., motor control, command processing, feedback mapping).
SYS-REQ-054: Implementation shall strive for clarity and ease of modification for education and demonstration.

10.5 Testability
SYS-REQ-055: The system shall support observability through both LEDs and UART.
SYS-REQ-056: The system shall support manual and script-based testing as described by the use case.


Architecture-Relevant Considerations Derived from System Requirements

The system operates a single concurrent control function (flap positioning) without external network obligations or multiple interacting subsystems. Interactions are limited to local hardware (motor, potentiometer, LEDs, UART interface). The control complexity remains low, determined primarily by mapping user commands to discrete positioning actions and updating indication status. The prototype nature enables straightforward expansion (e.g., more positions or interface sophistication), but requirements avoid prescribing execution models or periodic behavior. Software structure should remain modular to separate concerns (e.g., command input, motor logic, feedback processing), but there is no requirement for RTOS, state machines, or explicit task scheduling.
