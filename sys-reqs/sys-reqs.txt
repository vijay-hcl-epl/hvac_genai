1.0 System Overview
-------------------
SYS-REQ-001: The system SHALL control the position of a single HVAC flap using a DC motor.
SYS-REQ-002: The system SHALL receive user input commands for target flap position via UART serial interface.
SYS-REQ-003: The system SHALL provide position feedback by reading a potentiometer mechanically linked to the flap.
SYS-REQ-004: The system SHALL indicate system and flap position status using LEDs.
SYS-REQ-005: The system SHALL execute all functional requirements using only local and direct interaction; no vehicle network involvement is permitted.
[Implied] SYS-REQ-006: The system context assumes operation as a standalone prototype with no interaction with production ECUs or vehicle CAN/LIN networks.

2.0 Flap Position Control
-------------------------
SYS-REQ-007: The system SHALL move the flap to a user-commanded discrete position within the allowed range (e.g., 0–5).
SYS-REQ-008: The system SHALL ensure the flap is moved using only valid (allowed) position commands.
SYS-REQ-009: The system SHALL not respond to position commands outside of the defined allowed range.
[Implied] SYS-REQ-010: The mapping of commanded setpoints to physical positions SHALL be parameterized in software using ADC value ranges.

3.0 Motor Control
------------------
SYS-REQ-011: The system SHALL drive the DC motor in the required direction (clockwise or anti-clockwise) according to target flap position relative to current position.
SYS-REQ-012: The system SHALL stop the motor when the flap reaches the commanded position.
SYS-REQ-013: The system SHALL be capable of enabling or disabling the motor via software control.
SYS-REQ-014: The system SHALL ensure the motor is OFF during power-up initialization.
SYS-REQ-015: The system SHALL support stopping the motor if the current position feedback is invalid (e.g., impossible ADC values).

4.0 Position Feedback Acquisition & Processing
----------------------------------------------
SYS-REQ-016: The system SHALL acquire flap position information via ADC readings of the potentiometer.
SYS-REQ-017: The system SHALL define ADC value ranges that uniquely map to each discrete flap position.
SYS-REQ-018: The system SHALL treat ADC readings outside all defined position ranges as invalid.
[Implied] SYS-REQ-019: The system SHALL reject user commands whose execution cannot be verified with feedback.

5.0 User Command Interface
--------------------------
SYS-REQ-020: The system SHALL communicate with a user via UART serial interface.
SYS-REQ-021: The system SHALL interpret numeric UART data as discrete target flap position commands (e.g., 0–5).
SYS-REQ-022: The system SHALL ignore invalid UART data, i.e., commands that are not supported numeric values.
SYS-REQ-023: The system SHALL NOT transmit error responses for invalid commands; ignored silently.

6.0 Status Indication
----------------------
SYS-REQ-024: The system SHALL provide a visual indication of system power using a dedicated LED.
SYS-REQ-025: The system SHALL use at most one green LED to indicate the current flap position at any time.
SYS-REQ-026: The system SHALL update the green LED status in accordance with detected flap position per ADC feedback.

7.0 System Behavior (power-up, idle, normal, target reached, invalid input)
--------------------------------------------------------------------------
SYS-REQ-027: On power-up, the system SHALL initialize all required peripherals (ADC, UART, GPIO, PWM, etc.).
SYS-REQ-028: On power-up, the system SHALL read the flap position and indicate it via the appropriate green LED.
SYS-REQ-029: During idle, the system SHALL monitor for new UART commands.
SYS-REQ-030: When a valid command is received, the system SHALL move the flap toward the commanded position and indicate it.
SYS-REQ-031: When the target position is reached, the system SHALL stop the motor and indicate the new position by LED.
SYS-REQ-032: On receiving invalid command(s), the system SHALL ignore them and leave the system state unchanged.
[Implied] SYS-REQ-033: The behavioral state transitions are logical only, with no explicit requirement for software state machine implementation.

8.0 Interfaces (UART, motor driver, ADC, LEDs)
-----------------------------------------------
SYS-REQ-034: The system SHALL utilize the following interfaces:
  a) UART for PC/user command input
  b) ADC for flap position sensing
  c) GPIO for motor direction/enable and LED control
  d) PWM (timer-based) for motor speed control and enable
SYS-REQ-035: The system SHALL not implement or require use of CAN, LIN, or other vehicle communication busses.

9.0 Constraints & Assumptions
-----------------------------
SYS-REQ-036: The system SHALL be limited to one flap, one actuator (motor), one position sensor, and one user at a time.
SYS-REQ-037: The system SHALL assume correct mechanical linkage between motor, gear, flap, and potentiometer.
SYS-REQ-038: The system SHALL not provide for dynamic self-calibration or learn-in; all parameters are to be defined statically.
SYS-REQ-039: The system context is non-automotive production and is for demonstration or laboratory use only.

10.0 Non-Functional Requirements
-------------------------------
10.1 Responsiveness
SYS-REQ-040: The system SHALL process received UART commands and respond (move flap, update LEDs) in a timeframe reasonable to human perception (e.g., <<1 second typical; no strict real-time).

10.2 Error Handling & Edge Cases
SYS-REQ-041: The system SHALL stop the motor if any detected feedback (ADC reading) is outside all valid defined position ranges.
SYS-REQ-042: The system SHALL not enter fault or error states requiring user reset for the cases described in these requirements.
SYS-REQ-043: The system SHALL ignore and not act on any malformed or unexpected serial input.

10.3 Resource Constraints
SYS-REQ-044: The system SHALL operate using the limited resources available on the STM32F407G-DISC1 board (no dynamic memory allocation).

10.4 Maintainability & Modularity
SYS-REQ-045: The system SHALL separate and document logical functional areas (command handling, motor control, feedback processing, LED status) in software.

10.5 Testability
SYS-REQ-046: The system SHALL be testable by sending UART commands, observing flap movement, and visual LED feedback without additional automated test equipment or HIL/SIL infrastructure.


Architecture-Relevant Considerations Derived from System Requirements
-------------------------------------------------------------------
- The system is event-driven by user UART commands and hardware feedback (ADC, limit validation), with only localized, simple concurrent actions (e.g., move flap while polling feedback).
- Interaction complexity is low: user issues a command; system validates and executes, reporting only via physical LEDs.
- Control complexity is limited to basic state-handling for power-up, movement, command validation, and error avoidance; there is no escalation or mode change.
- System design is expandable by adding more positions or changing the feedback/indication mapping, but multi-flap, multi-user, or networked control extensions are out of scope for this requirements set.
