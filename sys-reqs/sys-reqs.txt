1.0 System Overview
-------------------
The system is an HVAC flap actuator controller prototype for automotive use. It allows a user to command and monitor the position of a single air flap, driven by a DC motor, using UART input. Flap position is measured by a potentiometer read through an ADC. Visual status and position feedback are provided using LEDs. This is a non-production, proof-of-concept system for learning and demonstration purposes.

2.0 Flap Position Control
------------------------
SYS-REQ-001: The system SHALL accept user commands to set the flap to one of six discrete positions (positions 0–5).
SYS-REQ-002: The system SHALL map valid received commands to corresponding target positions.
SYS-REQ-003: The system SHALL move the flap to the commanded position when a valid command is received.
SYS-REQ-004: The system SHALL keep the flap stationary when no new command is received.
[Implied] SYS-REQ-005: The system SHALL ignore invalid or out-of-range commands.

3.0 Motor Control
-----------------
SYS-REQ-006: The system SHALL control the DC motor direction using GPIO outputs, enabling clockwise or anti-clockwise rotation as required to reach the target position.
SYS-REQ-007: The system SHALL stop the motor when the target flap position is reached.
SYS-REQ-008: The system SHALL disable the motor when an invalid input is detected or at power-up/init.
[Implied] SYS-REQ-009: The system SHALL not attempt to move the flap if the current position matches the commanded position at command reception.

4.0 Position Feedback Acquisition & Processing
---------------------------------------------
SYS-REQ-010: The system SHALL acquire flap position by sampling the potentiometer through an ADC channel.
SYS-REQ-011: The system SHALL map ADC values to logical flap positions (0–5), using predefined, fixed ADC ranges.
SYS-REQ-012: The system SHALL continuously monitor the current flap position.
SYS-REQ-013: The system SHALL detect and treat out-of-range ADC values as an error, stopping the motor if such values are detected.

5.0 User Command Interface
-------------------------
SYS-REQ-014: The system SHALL receive target flap position commands via UART.
SYS-REQ-015: The system SHALL interpret commands sent as single numeric values in the valid range (0–5).
SYS-REQ-016: The system SHALL take no action and provide no acknowledgment for invalid commands.

6.0 Status Indication
---------------------
SYS-REQ-017: The system SHALL provide visual indication of power state using a dedicated LED.
SYS-REQ-018: The system SHALL use separate green LEDs to indicate the current flap position; only one such position LED is ON at any time.
[Implied] SYS-REQ-019: The system SHALL update position LEDs to match detected/confirmed flap position after movement or at start-up.

7.0 System Behavior (power-up, idle, normal, target reached, invalid input)
--------------------------------------------------------------------------
SYS-REQ-020: On power-up, the system SHALL initialize all required peripherals (ADC, UART, GPIO, PWM, LEDs).
SYS-REQ-021: On power-up, the system SHALL turn ON the power/status LED.
SYS-REQ-022: On power-up, the system SHALL not activate the motor until a valid command is received.
SYS-REQ-023: The system SHALL enter idle state after reaching the commanded target or if no command is pending.
SYS-REQ-024: The system SHALL ignore and not act on invalid commands.
SYS-REQ-025: The system SHALL remain responsive to new valid user commands during idle or after movement completes.

8.0 Interfaces (UART, motor driver, ADC, LEDs)
----------------------------------------------
SYS-REQ-026: The system SHALL interface with a PC via UART for command input.
SYS-REQ-027: The system SHALL interface with a DC motor driver module for flap actuation using GPIO and PWM as required.
SYS-REQ-028: The system SHALL read analog feedback from a potentiometer via an ADC channel.
SYS-REQ-029: The system SHALL drive LEDs via GPIO outputs for status and position indication.

9.0 Constraints & Assumptions
-----------------------------
SYS-REQ-030: The system SHALL support exactly one actuator, one DC motor, one potentiometer, and one set of position LEDs.
SYS-REQ-031: The system SHALL expect that only one user command is valid at a time.
[Implied] SYS-REQ-032: The system assumes hardware is functioning as specified; no advanced diagnostics or vehicle communication are included.
[Implied] SYS-REQ-033: The system calibration and ADC ranges are fixed in software for the prototype.

10.0 Non-Functional Requirements
-------------------------------
10.1 Responsiveness
SYS-REQ-034: The system SHALL process UART commands and initiate flap movement in a manner perceived as responsive by a human user, with no undue delay.
[Implied] SYS-REQ-035: The system SHALL perform ADC sampling to monitor position regularly enough to avoid visible lag.

10.2 Error Handling & Edge Cases
SYS-REQ-036: The system SHALL stop the motor and ignore out-of-range ADC readings.
SYS-REQ-037: The system SHALL ignore malformed or out-of-range UART commands without providing feedback.
[Implied] SYS-REQ-038: The system SHALL not execute any function if unexpected states persist, but may require manual intervention/reset.

10.3 Resource Constraints
SYS-REQ-039: The system SHALL operate within the memory, CPU, and throughput constraints of the STM32F407G-DISC1 demonstration hardware.
SYS-REQ-040: The system SHALL not use dynamic memory allocation.

10.4 Maintainability & Modularity
SYS-REQ-041: The system SHALL organize software so that command handling, motor control, position acquisition, and status indication are logically separated modules/components.
[Implied] SYS-REQ-042: All logic SHALL be implemented in C with MISRA-C style for clarity and maintainability.

10.5 Testability
SYS-REQ-043: The system SHALL be testable by issuing UART commands, observing motor movement, and verifying LED outputs.
[Implied] SYS-REQ-044: The system SHALL be operable for manual or script-based tests, without requiring automated HIL/SIL infrastructure.


Architecture-Relevant Considerations Derived from System Requirements
===================================================================
Concurrency presence/absence: The system primarily follows sequential control flow, with periodic sampling and command processing; concurrency may only be present in interrupt-driven I/O.
Interaction complexity: Interaction between subsystems (command, actuation, feedback, indication) is simple and direct, with explicit mapping between inputs and actions.
Control complexity: The system logic involves basic state transitions (idle, move, stop) without complex behavior or nested state hierarchies.
Expandability: The system is structured to support future extension (e.g., additional flap positions, more detailed feedback), but is limited to single-flap actuation in this prototype.
